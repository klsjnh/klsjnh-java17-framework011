# 015 — 项目信息（Project Info）

> 项目事实卡：定位 / 技术栈 / 骨架 / 构建与运行 / 当前能力。版本与键的事实来源是父 `pom.xml` 与 [015.topic-config](infrastructure011/015.topic-config.md)。

## 011.定位

`klsjnh-java17-framework011` —— Java 17 纯血 DDD 技术底座，Maven 多模块，供第三方业务系统 Maven 依赖引用。对外契约（响应信封 / 状态码 / 路由风格 / 公共表结构）稳定，见 [013.api-contract](013.api-contract.md)。

## 013.技术栈

| | |
|---|---|
| Java | 17 (LTS) |
| Spring Boot | 3.4.5（jakarta 体系） |
| MyBatis-Plus | 3.5.9（spring-boot3-starter） |
| 数据库 | MySQL 8（部署口径）· 本机亦可 docker 5.7+ 实测 · Druid 1.2.23；JDBC 驱动：mysql/oracle/sqlserver；分页方言 SPI 另含 postgresql（无预置 PG 驱动） |
| 鉴权 | JJWT 0.12.6（HS256）· spring-security-crypto（bcrypt） |
| 调度 | Quartz 2.5.0（RAMJobStore，spring-boot-starter-quartz） |
| 对象存储 | MinIO SDK 8.5.7（S3 兼容厂商适配基础） |
| 外部 HTTP | JDK HttpClient 薄封装 `common.util.HttpUtil011`（get / getBytes / postJson / postJsonBytes / postMultipart），零额外依赖 |
| API 文档 | knife4j 4.5.0（OpenAPI3 jakarta）+ springdoc 2.8.9 |

## 015.Maven 骨架

```
com.klsjnh:java17-framework011:1.0.0（父 POM，聚合器）
├── java17-bom011                      BOM（内部模块 + 三方版本基线，消费方 import）
├── java17-security-api011             安全 API（鉴权端口 / Operator011 / FrameworkStatus011）——纯 Java 零框架
├── java17-core011                     瘦 core：common + 持久化基座 + **用户 CRUD/登录/用户审计** + 导出/导入/备份内核 + 跨中心端口契约
│                                      （组织/菜单/角色/权限目录 → access；字典/配置 → platform；datasource 管理面 → center-datasource）
├── java17-security-autoconfigure011   安全装配（JWT / bcrypt / GlobalAuthFilter / AuditLogAspect / krt.jwt+status）
├── java17-security-starter011         安全启动（聚合 + jjwt + spring-security-crypto）
├── java17-data-mybatis011-starter     数据启动（Druid + 驱动 + 动态数据源 kernel 执行器 + 框架 Mapper 自动装配）
├── center-datasource011-starter       数据源中心（july_datasource / JulySql / Sync；kernel 端口留 core）
├── center-storage011-starter          完整存储中心（管理面 + local011/minio011；object 端口契约留 core）
├── center-access011-starter           访问中心（组织/角色/菜单/权限目录/授权；用户登录在 core）
├── center-platform011-starter         平台中心（字典 + 系统配置；不引则无管理面）
├── java17-scheduler-quartz011-starter 调度技术栈（管理面 + 执行审计 july_scheduler_audit/`pk_mt` + Quartz；非「调度中心」）
├── center-message011-starter          完整消息中心（出入两套 + 管理面 + 内置渠道）
├── center-ai011-starter               完整 AI 中心（管理面 + 能力引擎 + 媒体落盘；依赖 center-storage）
├── java17-observability011-starter    可观测性（actuator + Prometheus + traceId MDC + 健康指示器）
└── java17-app011            唯一 main + 配置 + demo11 样板；演示播种仅在 src/test（见下）
```

> **参考应用 classpath 诚实说明（2026-09-26）**：`java17-app011` 当前挂 security / data / **access** / scheduler / **message** / observability；`center-storage011-starter` 与 `center-ai011-starter` 在 pom 中为 **NEG-TEST-OFF（注释掉）**——本地 fat jar **无**存储/AI 管理面（404）。消费方按需自行引入，勿以参考应用默认依赖表当作「全中心已装配」。

## 017.构建与运行

```bash
./script011.sh gate      # 门禁：编码规范（正则 + AST）+ mvn -o clean install（含单测 + 装 .m2）
./script011.sh           # gate → .vf 版本自增（X.Y.Z，patch/minor 满 99 进位）→ commit（ver X.Y.Z）→ push
./script011.sh build011  # mvn clean install
./script011.sh dev011    # 启动应用：杀进程后直接执行现有 jar（不重编）
./script011.sh dev013    # 启动应用：杀进程后重新编译（clean 删旧 jar）再执行
./script011.sh stop|restart|status|log   # 运行态管理
java -jar java17-app011/target/java17-app011-1.0.0.jar   # 11160 端口
```

- 端口 11160；接口文档 `http://127.0.0.1:11160/doc.html`（分组：系统管理011 / IAM011 / 存储中心011 / 数据源011 / AI中心011 / 消息中心011）
- Druid 监控台 `/druid`（仅 dev 启用，klsjnh/klsjnh；⚠ allow 未配置默认只放 127.0.0.1，LAN 访问需显式配 allow，见配置体系文档）
- profile：默认 `development`（共享配置入库）+ `krt.status: debug`（鉴权放行 / PEP opt-in——**勿当生产契约**）；production 部署机自建、不入库；fat jar **excludes** `application-local*` / `application-production*`（gitignore 不够，见 [015.topic-config](infrastructure011/015.topic-config.md)）
- **Demo Seed**：`AuthPermissionDemoSeed011` 在 `java17-app011/src/test`，**仅测试阶段运行**；`dev011`/`dev013` / fat jar **不会**每次启动重置演示账号密码
- 环境依赖：Node 18+（门禁 AST：tree-sitter / tree-sitter-java，用户级 node_modules）· MySQL（docker 容器，宿主 33306；部署口径）
- 多库：JDBC 驱动随 data-starter 带 mysql / oracle / sqlserver；分页方言 SPI 另含 postgresql（**无预置 PG 驱动**，消费方自加）
- **容器化部署**（docker compose / ubuntu 26.04 基镜像 / 落地件 `docs/deploy/`）见 [infrastructure011/020](infrastructure011/020.topic-deploy-docker.md) · [deploy/README](deploy/README.md)

## 019.当前能力（截至 2026-09-25）

> 归属：aicenter / messagecenter / storagecenter 的全部代码已分属 `center-ai011-starter` / `center-message011-starter` / `center-storage011-starter`（storagecenter.object 端口契约留 core）。

- 持久化（2026-09-22/23）：PO 家族（`BasePo` / `BasePo011` / `TreePo` / `TreePo011` / `MasterLinked`）+ 仓库基座（`BaseRepository` / `BaseTreeRepository` / `BaseMasterSubRepository` / `BaseTreeSubRepository`；**排序走 `SortSupport`，无 `*Repository011` 排序基座**）+ 公共件 `TreeAssembler` / `MasterSubSupport` / `SortSupport` + 审计自动填充（时间 + 操作人）；主子三分 API 见 [011/018](infrastructure011/011.persistence-spec/018.topic-master-sub-api.md)
- **访问中心**（[013](infrastructure011/013.access-center/011.topic-design.md)，现称访问中心 · starter **`center-access011-starter`**）：组织 / 角色 / 菜单 / 权限目录 / `assignRoles` / `AuthorizationPort`；**用户 CRUD + 登录在 core**；**双模式 PEP**（生产写白名单仅 access 在场时生效，详 [016](infrastructure011/013.access-center/016.topic-dynamic-permission.md)）
- **system011 / 平台**：配置（july_config）与字典（july_dictionary）→ `center-platform011-starter`；**调度 julyScheduler** → `java17-scheduler-quartz011-starter`（整栈独立，见 [infrastructure011/022](infrastructure011/022.topic-july-scheduler.md)）
- 调度：julyScheduler 全链路（Quartz 内存模式，JobHandler 注册器，重启自愈，**执行审计子表 `july_scheduler_audit` / 链接列 `pk_mt`**）；参考应用内 `Demo011Scheduler` 30s 演示；消费方全量示例见兄弟工程 `java17-demo013-app013` 的 `Demo013Job`（端口 11163）；最小登录 + `july_demo011` CRUD 双态冒烟见 `java17-demo011-app011`（11161）+ 框架脚本 `tools/demo011-dual-mode-smoke.sh`（G9a）
- 动态数据源：yaml ci011 懒加载 + SqlRoutingPort 读写 / **分页方言为开放 SPI**（`SqlDialectPort011` + 注册表，内置 mysql/postgresql/oracle/sqlserver；`dbType` 开放字符串，2026-09-19）/ clamp [10,500] / 标量糖 selectStr / selectInt
- 存储中心：`ObjectStoragePort`（对象 + 桶 CRUD + stat）+ **工厂型 SPI**（`ObjectStorageProviderFactory` + `ObjectStorageProviderRegistry`，内置 local011/minio011/s3011，余由使用者扩展）；**主子表** `july_storage_provider` + `july_storage_provider_bucket`，实例/桶管理面；现行文档 → [015.storage-center](infrastructure011/015.storage-center/011.topic-design.md)；对象定位元数据见 [016 规约·非平台能力](archive011/infrastructure011/011.storage-center/016.topic-object-metadata-convention.md)（已归档备查）
- 配置管理：july_config（运行时键值参数，每次查库，getByCode 程序读取入口）
- AI 中心（aicenter，2026-09-20 重构）：provider + api 密钥（主子表）+ testConnection（OpenAI 兼容）
- AI 能力（aicenter，2026-09-20）：**能力 SPI + 通用 OpenAI 兼容适配器**。`AiCapabilityPort` + `AiCapabilityRegistry` 按 (capability, provider) 路由；四能力：`inference`（`AiInferencePort`，同步 + **SSE 流式**）、`image`（`AiImagePort`，文生图/图生图）、`tts`（`AiTtsPort`）、`asr`（`AiAsrPort`，**语音识别**）；产物经 `AiMediaStorePort` 落盘（**调用必传** `storageCode|storageId` + `bucketCode|bucketId`，无默认桶 / 无本地闸）；**model 由调用方直传**（框架不推理）。厂商 = 一行 provider 配置（通用适配器），非 OpenAI 兼容的厂商实现对应 SPI 即插
- 提示词管理（aicenter，2026-09-21 重构）：**主子表** `july_ai_domain`（业务域树，`domain_code` 全局唯一）+ `july_ai_domain_prompt`（提示词，`prompt_code` 全局唯一）；`content` `TEXT`（≤64KB inline，超则落对象存储）；`render(promptCode, params)` 公共件
- 消息中心（messagecenter，[016](infrastructure011/016.message-center/011.topic-design.md)）：**出入两套**。出站 `MessageChannelPort` SPI + `MessageChannelRegistry` + `JulyOutbound{Channel,Template,Message}` 三表 + send/分页/重发 + 内置 `inapp`/`webhook`；入站 `MessageInboundPort`/`InboundMessageListener` SPI + `MessageInboundRegistry` + `JulyInbound{Channel,Template,Message}` 三表 + `receive` 回调（去重/落库/分发/被动回复；**入站无内置渠道**）。包按 `inbound`/`outbound` 切分（含 `web.messagecenter.inbound|outbound.*`，勿写扁平 `web.messagecenter.controller`）。`messageType`/`payload` 为开放透传位；厂商渠道由使用者插件提供，**非框架能力**
- HTTP 工具：`common.util.HttpUtil011`（JDK HttpClient 薄封装：`get`/`getBytes`/`postJson`/`postJsonBytes`/`postJsonStream`/`postMultipart` → `HttpResponse011(status, body)` / `HttpResponseBytes011(status, bytes)`）；框架 `WebhookMessageChannel` / `AiModelProbe011` / 通用 OpenAI 兼容适配器（含推理 SSE 流式）均用它
- 平台导出（025）：注册制 ExportProvider + **json（已交付）/ xlsx（字典打样）**；`csv` 枚举预留、HTTP **未交付**；批大小 500（非总量封顶）+ EXPORT 审计
- 平台导入（032）：注册制 ImportProvider + xlsx；Controller **按需**（字典打样 `/import`）+ IMPORT 审计；失败 fail-fast 整单回滚
- 全局异常 → 统一信封（HTTP 与 statusCode 同步，errorMessage 仅 debug）；`traceId` 经 MDC 贯通
- 参考样板：`com.klsjnh.demo11` DDD 纵切面（第三方照抄入口）

> **DDL 债**：部分业务表 CREATE 仍 `UNIQUE(业务列)`，未统一 `alive_*` 生成列；见执行任务 [011/020](infrastructure011/011.persistence-spec/020.topic-alive-unique-ddl-complete.md)。
