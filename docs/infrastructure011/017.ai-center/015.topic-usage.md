# 015 — center-ai011-starter · 怎么使用

> 四篇一套：[011 设计](011.topic-design.md) · [013 架构](013.topic-architecture.md) · 本篇使用 · [016 二开手册](016.topic-secondary-dev.md)。

## 011.接入（业务项目）

```xml
<dependencyManagement>
  <dependency>
    <groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId>
    <version>1.0.0</version><type>pom</type><scope>import</scope>
  </dependency>
</dependencyManagement>

<dependency>
  <groupId>com.klsjnh</groupId><artifactId>center-ai011-starter</artifactId>
</dependency>
```

随后三步：

1. **建表**：执行 [july_center_ai011.sql](../../sql/july_center_ai011.sql)（模型接入主子表 + 提示词业务域主子表）。
2. **配置**（可选，均有默认值）：

```yaml
krt:
  ai-center:
    chat-timeout-seconds: 60
    inference:
      max-image-data-url-bytes: 10485760
      reasoning-effort-providers: [ sensenova ]
    media:
      key-prefix: ai/
```

3. **录入模型接入**：`POST /klsjnh/aicenter/julyAiModelProvider/v1/insert`（provider + api key，密钥出参脱敏），再经 `julyAiDomain` 配提示词。模型名**调用方直传**，框架不挑默认。

## 013.调用能力

| 能力 | 端点前缀 | 说明 |
|------|----------|------|
| 推理 | `/klsjnh/aicenter/julyAiInference/v1` | 纯文本 / 多模态 `text + image_url`；整包或 SSE 流式；`model` 必传 |
| 语音 | `/klsjnh/aicenter/julyAiAudio/v1` | tts（产物落盘）/ asr |
| 图片 | `/klsjnh/aicenter/julyAiImage/v1` | 文生图 / 图生图，调用必传存储实例 + 桶 |

落盘依赖存储中心：确保已引 `center-storage011-starter` 并配好实例 / 桶。

## 015.不引本 starter 的行为

- **`/klsjnh/aicenter/**` 整体 404（路由级）**——管理面与能力引擎一起消失；
- classpath 零 AI 代码、无需导 AI 表；其余中心与业务功能完全不受影响。

## 017.扩展：新厂商 / 新能力

- **OpenAI 兼容厂商**：管理面直配（base-url + api key + models 清单），零代码。
- **非 OpenAI 协议厂商**：实现 `AiCapabilityPort`（推理 / tts / asr / image 对应端口）注册为 bean，注册表自动收编——参照内置 `OpenAiCompatTtsAdapter` / `AgnesImageAdapter`。
- 厂商适配器全部用 `common.util.HttpUtil011`（JDK HttpClient），无 SDK 依赖。

## 019.多模态、JSON 输出与推理强度

**程序入口（推荐）**：

```java
List<AiChatContentPart> parts = List.of(
        AiChatContentPart.text("分析这张工单截图，输出 JSON"),
        AiChatContentPart.imageUrl(dataUrl));   // data:image/png;base64,... 或 https://

AiInferenceOutcome outcome = aiInferenceUseCase.chat(
        operatorId,
        new AiInvokeTarget("sensenova", null, null, null, "sensenova-6.8-flash-lite", null),
        AiInferenceUseCase.one(AiChatMessage.ROLE_USER, parts),
        0.1, 8192,
        new AiInferenceOptions(true, null));    // json_object；reasoning 见下
```

**HTTP 入口**（`POST /klsjnh/aicenter/julyAiInference/v1/chat`，stream 同理）：

```json
{
  "provider": "sensenova",
  "model": "sensenova-6.8-flash-lite",
  "messages": [{
    "role": "user",
    "contentParts": [
      { "type": "text", "text": "分析这张卡片" },
      { "type": "image_url", "imageUrl": "data:image/png;base64,..." }
    ]
  }],
  "responseFormatJson": true
}
```

规则：

| 项 | 规则 |
|----|------|
| 文本兼容 | 只传 `content` 的旧请求报文与行为不变 |
| 内容块 | `content` 与 `contentParts` 二选一；单条消息 1–20 块，且**至少一个 `text` 块** |
| 图片地址 | `data:image/(png\|jpeg\|jpg\|webp);base64,` 或 `https://`；拒绝 `http://` / `file://` / 相对路径 |
| 体积 | 单个 data URL 解码后 ≤ `max-image-data-url-bytes`（默认 10 MiB）；https 不下载、不限 |
| JSON 输出 | `responseFormatJson=true` → `response_format={"type":"json_object"}`；只保证 JSON 形态，业务 Schema 由调用方校验 |
| 流式 | `stream + JSON 输出` 组合直接 400（多数 OpenAI 兼容厂商不支持） |
| reasoning | `reasoningEffort` ∈ none/low/medium/high；**只有** provider code 在 `reasoning-effort-providers` 白名单内才发送，否则 400 |
| 视觉理解 | 归 `inference`（图片输入、文本输出），不是独立能力；**模型是否支持视觉由 provider/model 决定**，调用前用真实小图自测（`/testChat` 只发文本，不能证明视觉可用） |
| 脱敏 | 图片 URL / Base64 / API Key 不进日志与异常消息；失败信息只带 HTTP 状态与安全摘要 |

> 框架不压缩 / 不切图 / 不下载图片。大图建议先由业务侧压缩或上传存储中心后传 https URL。
