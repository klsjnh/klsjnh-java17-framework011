## 013.新厂商适配器（最常见）

**实现 `AiCapabilityPort`，注册为 bean 即接入**（`AiCapabilityRegistry` 以 `List` 自动收编，零配置改动）：

```java
@Component
public class MyVendorImageAdapter implements AiImagePort {   // capability = image

    // 密钥经管理面（july_ai_model_provider_api）解析，禁止硬编码
    // HTTP 统一走 common.util.HttpUtil011（JDK HttpClient，无 SDK）
    // 产物落盘走 AiMediaStorePort —— 调用方必传存储实例 + 桶，本类不挑默认
}
```

纪律（都由 gate 强制）：

- 文件头 `/* TypeName ... */` 块；Javadoc 英文；类名 `*Adapter` + `011` 后缀按包规则
- 方法内日志首占位符必须是 `funcName`
- 参照物：`OpenAiCompatTtsAdapter`（同构最简单）/ `AgnesImageAdapter`（含落盘）

**回归测试**：适配器是纯 HTTP 翻译层，最适合 Mockito 单测（`spring-boot-starter-test`）；参照 message 中心 `WebhookMessageChannelTest` 的写法。

## 015.新增一种能力

1. `domain.aicenter`：新增能力端口（如 `AiVideoPort`）+ Request / Result record——**纯 Java，禁框架**；
2. `application.aicenter`：`XxxUseCase`（编排 Resolver + Registry + 落盘端口），事务边界只在这里；
3. `infrastructure.aicenter.provider`：至少一个适配器实现；
4. `web.aicenter`：Controller（URL 前缀 `/klsjnh/aicenter/<新controller>/v1`，**无路径变量**，GET 查询 / POST 写语义）+ VO（`*Vo011`，`@Schema` 中文只在这一层）；
5. `AiCapabilityCodes` 补能力 code；落盘类能力**必传** locator，不落盘的能力不碰存储端口。

## 018.管理面扩展

- 新增管理字段：PO（`*Po`，主链字段 `pkMt`）→ Mapper → RepositoryImpl（基座对号入座）→ UseCase → VO → Converter；
- 表结构变更走 [july_center_ai011.sql](../../sql/july_center_ai011.sql)（DDL 单一真源）；
- 密钥类字段**出参类型层剔除**（参照 api key 的 VO 做法），日志零密钥。

## 021.红线（017 全文适用，本中心特别三条）

1. **模型名调用方直传**——框架不挑默认、不校验归属（见 011 设计 §015）；
2. **管理面只管 provider + api key**——能力映射不进管理面建模；
3. **审计失败不影响业务**——审计写失败仅告警（REQUIRES_NEW 例外模式，勿复制到别处）。
