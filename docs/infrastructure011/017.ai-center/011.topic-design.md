## 011.命题

**AI 中心 = 一个 starter。** `center-ai011-starter` 自包含 AI 中心的全部代码：管理面（模型接入主子表、提示词业务域）与能力引擎（推理 / 图片 / 语音适配器、媒体落盘）。消费方**引 starter 得到全部，不引则整个中心不存在**——无半初始化、无残留端点、无需导入 AI 表。

## 013.与 core 的边界（剥离后）

| 归属 | 内容 |
|------|------|
| **本 starter** | `com.klsjnh.domain.aicenter`（聚合 / 端口 / SPI）、`application.aicenter`（用例 / 注册表 / Resolver）、`infrastructure.aicenter`（PO/Mapper/RepositoryImpl + 探针 + PromptRender + 媒体落盘 + 厂商适配器）、`web.aicenter`（5 Controller + Converter + VO） |
| **core011（被本 starter 依赖）** | `common`（HttpUtil011 / FrameConst011 / Operator011）、`domain.shared`（EntityId / AuditInfo）、`domain.iam.user.UserAuditPort`（审计出口）、`domain.storagecenter`（产物落盘端口与仓储）、`platform011.export`（ExportProvider SPI 注册口） |
| **不再存在于 core** | 任何 `aicenter` 代码 —— core 对 AI **零残留** |

> 命名口径：中心类 starter 无 `java17-` 前缀，`center-<名>011-starter`。

## 016.依赖关系

```
center-ai011-starter ──► java17-core011 ──► java17-security-api011
（叶子模块：无人依赖本 starter）
```

对 core 的消费点（全部经 core 依赖获取，无环）：

| 消费点 | 用途 |
|--------|------|
| `StorageResolverPort` / `ObjectStoragePort` / 仓储 | 媒体产物落盘（调用必传实例 + 桶） |
| `UserAuditPort` | 用户审计落地 |
| `ExportProvider` 注册 | 模型接入随平台导出 |
| `HttpUtil011` 系列 | 厂商 HTTP 通道（纯 JDK HttpClient 封装） |

## 019.装配机制

- starter 代码在 `com.klsjnh.infrastructure/application/web.aicenter` 包树下，由 core 的 `CoreAutoConfiguration011` 定向扫描**随 classpath 收编**——starter 在，bean 全在；starter 不在，零注册。
- 宿主**不扫描任何框架包**；无独立 AutoConfiguration 需求（未来加条件装配时再经 imports 文件）。

## 022.能力与端点

| `AiInferenceController` | `/klsjnh/aicenter/julyAiInference/v1` | 提示词推理，SSE 流式 |

| 键 | 默认 | 说明 |
|----|------|------|
| `krt.ai-center.chat-timeout-seconds` | 60 | 推理请求超时 |

## 028.SPI 扩展点

| 端口 | 方向 | 说明 |
|------|------|------|
| `AiCapabilityPort` | 能力扩展 | 厂商能力适配器实现并注册为 bean，`AiCapabilityRegistry` 自动收编 |
| 模型接入 | 管理面 | provider/api key 全配置化，新增厂商通常**零代码**（OpenAI 兼容协议直配） |

## 031.消费方行为矩阵

| 场景 | 行为 |
|------|------|
| 引 starter | 管理面 + 引擎全量可用；导 `july_center_ai011.sql` |
| 不引 starter | **`/klsjnh/aicenter/**` 整体 404（路由级）**；不导 AI 表；classpath 零 AI 代码 |
