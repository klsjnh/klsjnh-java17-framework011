## 011.模型：RBAC（基于角色的访问控制）

```text
july_user ──< july_user_role >── july_role ──< july_role_permissions >── permission_code
                                                                              ▲
                                                                        july_menu（菜单/按钮，权限载体）
组织维度：july_organization（组织树，独立聚合）——july_user.pk_org 挂靠
审计旁路：july_user_audit（登录 / 登录失败 / 增删改 / 导出，append-only）
```

- **三张实体表**：菜单 / 用户 / 角色（一个不多）；两张附属关联表（user_role、role_permissions）挂靠在用户与角色主题文档内；
- **用户 → 角色**：N:N，单张 `july_user_role` 同时服务两个管理视角（用户维度分配角色 / 角色维度分配用户）；
- **角色 → 权限**：权限**挂在菜单上**——`july_role_permissions` 的 permission_code 即 `july_menu.permission_code`（`模块:对象:动作`），不单独建权限表；
- **鉴权判定**：用户权限码集合 = Σ(其所有角色的权限明细)；超级管理员角色（is_builtin='1' 的 admin）特判全量。

## 013.主子聚合与仓库基座对号入座

```text
聚合① july_user（主表，BaseMasterSubRepository021）
  ├── 子表 july_user_role    （pk_mt 链接）用户删除 → 关联 toggle 停用（dr='1'）
  └── 子表 july_user_audit   （pk_mt 链接）append-only —— 挂而不级联，永不删除
聚合② july_role（主表，BaseMasterSubRepository021）
  └── 子表 july_role_permissions（pk_menu 链接）角色删除 → toggle 停用
独立聚合 july_menu（树）—— BaseTreeRepository011
```

| 表 | PO 继承 | 仓库基座 | 说明 |
|----|---------|----------|------|
| july_user | BasePo | **BaseMasterSubRepository021** | 主表；getChildServices 含用户角色关联 |
| july_role | BasePo | **BaseMasterSubRepository021** | 主表；getChildServices 含角色权限关联；内置角色保护 |
| july_menu | TreePo011 | BaseTreeRepository011 | 菜单树（树 + 同级排序） |
| july_organization | TreePo011 | BaseTreeRepository011 | 组织树（树 + 同级排序 + 负责人 pk_user）；july_user.pk_org 引用 |
| july_user_role | BasePo + MasterLinked | BaseRepository | 关联子表；UNIQUE (pk_mt, pk_role)，toggle 替换 |
| july_user_audit | BasePo + MasterLinked | BaseRepository | **只插不改不删**；挂 pk_mt 但不入级联 |
| july_role_permissions | BasePo + MasterLinked | BaseRepository | UNIQUE (pk_mt, pk_menu, permission_code)，toggle 替换 |

> 注意：子表挂 pk_mt ≠ 加入级联。审计表是结构上的子表、行为上的例外（append-only），不注册进 getChildServices。

## 015.认证流程（与 krt.status 三态联动）

```text
POST login(user_account, password)
  → krt.status = debug      : 密码仍按 bcrypt 校验；loginByUserName 可免密
    krt.status = development: 校验密码（bcrypt）；loginByUserName 可免密
    krt.status = production : 校验密码（bcrypt）+ 账号启用（status='1'）；免密登录被拒
  → 成功：JWT 签发（jjwt，含 id / user_account）+ last_login_time 刷新 + 审计 LOGIN
  → 失败：审计 LOGIN_FAILED（含 IP）+ 401
登录联动：按登录人角色返回**树状菜单**（角色 → role_permissions → pk_menu 去重 → 组装树；超管全量）——🔜 待编码，现登录响应仅返回 token / 账号 / 用户名
后续请求：GlobalAuthFilter 校验 JWT（Authorization: Bearer）
         → 写请求属性 AuthAttribute011.OPERATOR_ID（登录人 id）
         → AuditMetaObjectHandler 读取并填充 create_by / update_by
         → 非 debug 态缺失 / 无效 / 过期 token 返回 401（debug 态不拒绝，有 token 仍尽力解析）
```
