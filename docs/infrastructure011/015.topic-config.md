# 015 — 配置体系（Configuration）

> 配置键的**事实来源**：新增 / 变更配置键必须先改本文档。
> 结构规则：`application.yml` **入库**（公共结构 + 开发默认值）；`application-development.yml` / `application-production.yml` 为**环境私有文件，不入库**（数据源、密码等）。

## 011.文件分层

| 文件 | 入库 | 用途 |
|------|------|------|
| `application.yml` | ✅ | 公共结构：port / 应用名 / 默认 profile / `krt.status: debug`（开发默认） |
| `application-development.yml` | ❌（已忽略） | 本地开发：数据源连接等私密配置，开发者自建 |
| `application-production.yml` | ❌（已忽略） | 生产部署：数据源 + `krt.status: production` |

`.gitignore` 已挡 `application-*.yml / application-*.yaml`（不影响 `application.yml` 本身）。

> 说明：当前工作副本中两个环境 yml 已存在（本地自建、未入库）；fresh clone 需按 §016 模板自建。

## 013.公共键（server / spring）

| 键 | 值 | 说明 |
|----|----|------|
| `server.port` | 11610 | 服务端口 |
| `spring.application.name` | java17-app011 | 应用名 |
| `spring.profiles.active` | development | 环境：development / production（生产部署时切换） |

## 015.框架键（krt.* → 绑定类 KrtConfig011）

| 键 | 默认 | 说明 |
|----|------|------|
| `krt.status` | yml 显式 `debug`；**代码缺省 PRODUCTION**（键完全缺失时） | 运行态三态，见 `FrameworkStatus011` |

三态语义：

| 值 | 鉴权行为 |
|----|----------|
| debug | 不拒绝，全放行；带 `${Authorization: Bearer}` 时仍尽力解析并记录操作人 |
| development | 强制验 token；免密登录（loginByUserName）可用 |
| production | 强制验 token；免密登录被拒；登录强制 bcrypt + 账号启用校验 |

登录失败、账号禁用、缺失/无效/过期 token 统一返回 401。

**生产卫兵**：`krt.status=debug` + production profile → 启动直接失败（忘改配置的代价是起不来，不是裸奔）。

## 016.本地开发模板（自建 `application-development.yml`，不入库）

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/klsjnh?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: <你的用户名>
    password: <你的密码>

krt:
  status: development
```

> 数据源依赖（Druid starter）尚未接入 pom；接入前 MyBatis-Plus 走默认 HikariCP 也能工作。Druid 连接池细化配置后续随持久化体系文档补充。

## 017.生产部署要点

1. `SPRING_PROFILES_ACTIVE=production`；
2. `krt.status=production`（production yml 或环境变量 `KRT_STATUS`）——启动卫兵强制；
3. 数据源用环境变量注入（`SPRING_DATASOURCE_URL` 等），不落盘。
