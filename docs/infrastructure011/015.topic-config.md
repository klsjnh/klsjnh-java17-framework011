# 015 — 配置体系（Configuration）

> 配置键的**事实来源**：新增 / 变更配置键必须先改本文档。
> 结构规则：`application.yml` **入库**（仅公共结构：port / 应用名 / 默认 profile，**不含密钥**）；`application-development.yml` **入库**（开发共享）；`application-local.yml`（本机私有覆盖）与 `application-production.yml`（生产部署）**不入库**。

## 011.文件分层

| 文件 | 入库 | 用途 |
|------|------|------|
| `application.yml` | ✅ | 公共结构：port / 应用名 / 默认 profile（`#active: local` / `#active: production` 注释切换 + `profiles.group.local`）；**不含任何密钥** |
| `application-development.yml` | ✅ | 开发共享：数据源 + `krt.status: development`（默认需 token；`KRT_STATUS=debug` 覆盖为全放行）+ dev JWT/crypto；**敏感值优先 `${ENV:default}`**（见仓库根 `.env.example`）；启动打 debug 醒目 WARN |
| `application-local.yml` | ❌（已忽略） | 本机私有覆盖：只写本机差异，未声明的键继承 development（经 `profiles.group.local` 叠加） |
| `application-production.yml` | ❌（已忽略） | 生产部署：数据源 + `krt.status: production` + 真实 secret |

`.gitignore` 已挡 `application-*.yml / application-*.yaml`，并放行 `!application-development.yml`（不影响 `application.yml` 本身）。

> **打包铁律（与 gitignore 正交）**：gitignore 只挡提交，**不挡 Maven 打包**。`java17-app011/pom.xml` 的 `resources/excludes` **必须**排除 `application-local*` / `application-production*`（含 yml/yaml/properties），否则本机/生产凭据仍会进 fat jar。保留入包：`application.yml` + `application-development.yml`。

> 说明：`application-local.yml` / `application-production.yml` 在当前工作副本中可能已存在（本地自建、未入库）；fresh clone 需按 §016 模板自建 local / production。

## 015.框架键（krt.* → 绑定类族，原 KrtConfig011 已拆分）

> `krt.*` 前缀的绑定类共 5 个：
> `KrtSecurityConfig011`（security-autoconfigure，prefix `krt`：krt.status / krt.jwt / krt.web / krt.crypto / krt.outbound / krt.allow-insecure-status，含生产启动卫兵）·
> `KrtDatasourceConfig011`（core，prefix `krt`：krt.ci011）·
> `KrtAiConfig011`（ai-starter，prefix `krt.ai-center`）·
> `StorageProperties`（storage-starter，prefix `krt.storage-center`：default-type / default-bucket / local011.base-path / minio011.*）·
> `SpringDocConfig011.Properties`（core，prefix `krt.springdoc`：分组开关）。

| 键 | 默认 | 说明 |
|----|------|------|
| `krt.status` | `application-development.yml` 默认 `development`（`KRT_STATUS` 可覆盖为 debug）；**代码缺省 PRODUCTION**（键完全缺失时） | 运行态三态，见 `FrameworkStatus011` |
| `krt.allow-insecure-status` | `false`（development yml 显式 `true`） | **非 production 运行态必须显式 `true`，否则启动卫兵拒绝**（防误把 debug/development 带上生产） |
| `krt.jwt.secret` | 无（必填） | HS256 签名密钥，≥32 字节；production 拒绝已知 dev 默认值 |
| `krt.jwt.expire-minutes` | 480 | token 有效期（分钟） |
| `krt.crypto.master-key` | 无（AI/渠道/数据源密码加密用） | AES-GCM 主密钥，≥32 字节；production 卫兵同上 |
| `krt.outbound.allow-http` | `false` | 出站 HTTP 允许明文（默认仅 https） |
| `krt.outbound.allow-private` | `false` | 出站允许私网地址；**production 卫兵拒绝 `true`** |
| `krt.outbound.max-response-bytes` | 10MiB | 出站响应体上限 |
| `krt.web.trusted-proxies` | `[]` | 可信代理 / CIDR；空 = 宽松取 XFF 最左 |
| `krt.web.auth-whitelist-paths` | `[]` | **额外** JWT 精确路径白名单（与登录等同 `shouldNotFilter`）；例：`/klsjnh/messagecenter/julyInboundMessage/v1/receive`（=`WebPaths011.MESSAGE_INBOUND_RECEIVE`，厂商匿名回调）。默认空 = 不开放。**打开后防灌归渠道 `MessageInboundPort.parse`（config token/secret）**，框架不代验签——边界见 [消息中心 015](016.message-center/015.topic-usage.md) |
| `krt.web.auth-whitelist-prefixes` | `[]` | **额外** JWT 前缀白名单；默认空 = 不开放。语义同 paths：旁路 JWT 后验签仍归渠道 `parse`，非框架职责 |

三态语义：

| 值 | 鉴权行为 | 权限 PEP |
|----|----------|----------|
| debug | **读类不拒**（GET/HEAD + select/get/stat/download 类 POST）；受保护写类请求仍需有效 token（401）；带 token 时仍尽力解析并记录操作人 | **no-op**（`assertHas`/`has` 直接放行，不查库） |
| development | 强制验 token；免密登录（loginByUserName）可用 | **真实校验**（与 production 同——无码 / 未分配角色 → 403） |
| production | 强制验 token；免密登录被拒；登录强制 bcrypt + 账号启用校验 | **真实校验 + 白名单**：受保护写请求未核对 → 403（读/select 暂豁免）；详 [013 · 016](013.access-center/016.topic-dynamic-permission.md) |

登录失败、账号禁用、缺失/无效/过期 token 统一返回 401。

**生产卫兵**（`KrtSecurityConfig011.validate`，fail-closed 共 6 条）：

| 组合 | 结果 |
|------|------|
| Spring `production` profile 且 `krt.status` ≠ `production`（含 debug / development） | 启动失败 |
| **非 production 运行态且 `krt.allow-insecure-status` ≠ `true`** | 启动失败（防误带弱态上生产） |
| `krt.status=production` 且 `krt.jwt.secret` 空白 | 启动失败 |
| `krt.status=production` 且 `krt.crypto.master-key` 空白 / 短于 32 字节 | 启动失败 |
| `krt.status=production` 且 secret 命中已知 dev 默认值或含 `change-me` | 启动失败 |
| `krt.status=production` 且 `krt.outbound.allow-private=true` | 启动失败 |

忘改配置的代价是起不来，不是裸奔。权限双模式切换只跟 `krt.status`，与 profile 绑定由上表卫兵保证。

## 016.本机覆盖模板（`application-local.yml`，不入库）

`application-development.yml` 已是入库的开发共享基线（数据源 + `krt.status: development` + dev secret）。需要本机差异化时，新建 `application-local.yml` 只写差异，并在 `application.yml` 打开 `#active: local`（`profiles.group.local` 会把 local 叠加在 development 之上）：

```yaml
# application-local.yml —— 本机私有覆盖，未声明的键继承 development
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/your_db?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
    username: <你的账号>
    password: <你的密码>
```

> 数据源依赖已接入（druid-spring-boot-3-starter）：主库与动态数据源池均为 Druid。

## 017.生产部署要点

1. `SPRING_PROFILES_ACTIVE=production`；
2. `krt.status=production`（production yml 或环境变量 `KRT_STATUS`）——启动卫兵强制；
3. 数据源用环境变量注入（`SPRING_DATASOURCE_URL` 等），不落盘。
