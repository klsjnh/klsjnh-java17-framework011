## 011.一句话

**目录可配、角色可授撤、用例 opt-in 才过滤**——不配核对点 = 不过滤；配了再按码放行/403。

## 013.动态权限模型

### 011.权限目录（真源）

| 表 | 用途 | DDL |
|----|------|-----|
| `july_perm_object` | 对象：`object_code` / `object_name` / `module_code` / … | [july_center_iam.sql](../../sql/july_center_iam.sql)（IAM 整域真源） |
| `july_perm_action` | 动作：`object_code` + `action_code` → **`permission_code` 唯一** | 同上 |

- **码格式**：`模块:对象:动作`（例 `system011:julyScheduler:start`）。
- 存活唯一：`alive` 下 `permission_code` 与 `(object_code, action_code)`。
- 种子：`JulyPermCatalogSeed011` / Runner；常量类与种子**同串**（`JulyConfigPermissionCodes011` · `JulySchedulerPermissionCodes011`）。

### 013.授权两通道（并存 · 写入同表）

| 通道 | API / 写法 | 用途 |
|------|------------|------|
| A. 角色 × 菜单 | `assignMenus` → `july_role_permissions(pk_menu, permission_code)` | 导航 + 按钮显隐 |
| B. 角色 × 动作 | `assignObjectActions` → 同表直授（`pk_menu` 可空） | **无菜单也能授码**（启停类） |

运行时 `listCodes`：**汇总角色下所有非空 `permission_code`**（两通道并集）。内置角色（`is_builtin='1'`）全量旁路。

### 015.蓝本对象（种子）

| 对象 | 代表动作 | permission_code 前缀 |
|------|----------|----------------------|
| julyConfig | select / insert / update / logicDelete / export / backup | `system011:julyConfig:*` |
| julyScheduler | select / insert / update / logicDelete / **start** / **stop** / executeOnce | `system011:julyScheduler:*` |

## 015.「配置才过滤」opt-in 语义

| 层 | 含义 | 代码 |
|----|------|------|
| **PEP opt-in** | 用例**挂了** `authorizationPort.assertHas(...)` → 该入口按码过滤；**没挂** → 只靠 JWT，**不过滤** | 全局 **无** Permission Filter |
| **PDP 授撤** | 已挂入口：有码放行、无码 403；`assignObjectActions` 授/撤**下一请求生效** | `AuthorizationAdapter.has` / `assertHas` |

```text
请求 → GlobalAuthFilter（身份 / 401）→ Controller → UseCase
                                              │
                         ┌────────────────────┴────────────────────┐
                         │ 未调用 assertHas → 不过滤，继续业务      │
                         │ 调用 assertHas(op, code)                 │
                         │   → 内置旁路 | 码 ∈ 角色汇总 | 否则 403  │
                         └─────────────────────────────────────────┘
```

| 结果 | statusCode |
|------|------------|
| 未认证（空 operatorId） | 401 |
| 无码 | 403 |
| 有码 / 内置 | 继续业务 |

**不是**「全站默认 deny」。目录进了码、角色勾了码，若用例未 `assertHas`，运行时仍不拦。

## 017.业务怎么挂码、怎么授撤

### 011.管理面步骤

1. 对象/动作进目录（或复用底座种子）。
2. 角色：`assignMenus` 和/或 `assignObjectActions`（按对象整存替换；`actionCodes:[]` = 撤光该对象直授）。
3. 用户 `assignRoles`；需要拦的用例入口写 `assertHas`；常量与种子同串。
4. Controller 只解析 `Operator011Resolver` → 把 `op.id()` 传入用例；**勿**只在 Controller 拦。

### 013.相关 API

| 端点 | 说明 |
|------|------|
| `GET /klsjnh/iam/julyPermCatalog/v1/selectObjects` | 对象目录 |
| `GET …/selectActions?objectCode=` | 对象下动作 |
| `POST /klsjnh/iam/julyRole/v1/assignObjectActions` | 按对象整存替换直授码 |
| （运行时）`AuthorizationPort` | `has` / `assertHas` / `listCodes` — **无 HTTP** |

包 / URL 骨架见 [013](013.topic-architecture.md)（文档 IAM = 代码 `…iam`，**不改包**）。

### 015.用例挂点示例

```java
authorizationPort.assertHas(operatorId, JulySchedulerPermissionCodes011.START);
```

## 019.完整蓝本：julyScheduler 任务启停

同一对象 `julyScheduler` 下拆 `start` / `stop` / … —— 角色可只授启动、不授停止；**用例内须事先写好核对点**。

| 角色种子 | 账号 | 意图 |
|----------|------|------|
| `role_scheduler_start` | `test017` | 仅 select + start（可动态撤） |

**闭环（E2E 已绿灯）**：

1. 管理面 / API：`assignObjectActions` 授 `select` + `start`
2. `test017` 调 start → **200**
3. `actionCodes:[]` 撤该对象直授 → start → **403**
4. 再授回 → 恢复

**脚本**：[`tools/auth-dynamic-scheduler.sh`](../../../tools/auth-dynamic-scheduler.sh)（WSL / `dev016`）。

## 021.业务仓接入清单（最短）

1. 目录登记对象/动作（或复用种子）。
2. 角色授码（菜单通道和/或 `assignObjectActions`）。
3. **需要拦的**入口写 `assertHas`；不需要拦的不要挂。
4. 常量 = 种子同串；扫描 `com.klsjnh`。
5. 验收可仿 `auth-dynamic-scheduler.sh`：授 → 200 → 撤 → 403。
