## 011.命题

**一个 IAM 中心，管「谁、在哪、能干什么」。**

- **谁**：用户（账号 / 认证 / 审计）
- **在哪**：组织树（挂靠，非数据权限）
- **能干什么**：权限目录 + 角色授码 + 菜单引用；用例 **opt-in** `assertHas` 才过滤 —— **动态配置与启停蓝本见 [016](016.topic-dynamic-permission.md)**，本文不展开。

> 代码包 `com.klsjnh.…iam`（`domain.iam` / `application.iam` / `infrastructure.iam` / `web.iam`）与文档「IAM 中心」一一对应；URL 前缀 `/klsjnh/iam/**`。**不改包路径。**

## 013.能力清单

| 能力 | 说明 | 状态 |
|------|------|------|
| 组织 | `july_organization` 树；用户 `pk_org` 挂靠 | ✅ |
| 用户 | 登录 / 启停 / 改密 / 分配角色 / 用户审计 | ✅（用例未挂 `assertHas` = 不过滤动作码） |
| 菜单 | 目录 / 页面 / 按钮；按钮 `permission_code` 引用目录 | ✅ |
| 角色 | 自定义 + 内置（全量旁路）；×菜单 / ×动作授权 | ✅ |
| 权限目录 + opt-in 核对 | 对象/动作目录 · `AuthorizationPort` · 授撤 | ✅ 详见 [016](016.topic-dynamic-permission.md) |
| 底座示范 | julyConfig 矩阵 · julyScheduler 启停授撤 | ✅ E2E → [016](016.topic-dynamic-permission.md) |
| 动态审计 | 业务审计有；目录变更审计可跟 | ⏳ 部分 |
| 角色组 | 组内角色并集再汇总码 | ⏳ P4 |
| 认证 | JWT / Filter / krt.status | ✅ |

**不在本中心**：配置 / 调度 / 字典等业务能力本身（它们是目录中的对象 + 码的消费者）；密钥可逆加密见 [033](../033.topic-platform-security.md)。

## 019.边界（否定清单）

- 不做数据权限 / 行级 ACL / 多租户隔离。
- 不做 OAuth2 / SSO（另案）。
- 不做「只配目录、用例零核对」的空壳安全（目录≠自动过滤）——见 [016](016.topic-dynamic-permission.md)。
- 不做登录响应内嵌菜单树。
- 不做密钥可逆加密（→ 033）。
