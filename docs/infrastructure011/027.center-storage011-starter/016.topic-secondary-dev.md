## 013.新存储厂商（最常见）

**实现两个类，注册为 bean 即接入**（`ObjectStorageProviderRegistry` List 自动收编；管理面建实例行、`default-type` 或实例级选择）：

```java
@Component
public class OssObjectStorageAdapter implements ObjectStoragePort { ... }

@Component
public class OssStorageProviderFactory implements ObjectStorageProviderFactory {
    // supports(StorageProviderCodes011.OSS) + build(StorageConnectionConfig)
}
```

**纪律与参照**：

- 参照物：`MinioObjectStorageAdapter` + `MinioStorageProviderFactory`（S3 型）/ `LocalObjectStorageAdapter`（文件系统型，含路径校验）；
- 适配器**无状态**：连接参数全部来自 `StorageConnectionConfig`（管理面行 + 配置默认值合并）；
- 新增 provider code：`StorageProviderCodes011` 增量常量（开放字符串 + 注册表，禁封闭枚举）；
- 密钥经管理面（出参脱敏），日志零密钥；HTTP/S3 客户端在适配器内部构建，Registry 负责缓存与驱逐。

## 015.管理面扩展

- 六表（provider / bucket 主子 + 对象相关）变更走 [july_center_storage.sql](../../sql/july_center_storage.sql)（DDL 单一真源）；
- 全链路：PO（`pkMt` 纪律）→ Mapper → RepositoryImpl（基座对号入座）→ UseCase → VO（`*Vo011`）→ Converter；
- `StorageSeed011` 负责 default 行播种——新增必配字段时同步播种逻辑。

## 018.端口契约变更（影响面最大，先评审）

`domain.storagecenter.object` 端口**留在 core**，被备份（platform011）、AI 落盘（center-ai）、observability 消费——**加方法 = 所有适配器必须实现 + 跨中心消费方评审**。步骤：

1. core 端口加方法（Javadoc 英文写清缺席语义）；
2. 本 starter 全部适配器实现；
3. `BackupUseCase`（core）与 `AiMediaStore011`（center-ai）按需消费——它们对实现缺席已有软依赖 / 传递依赖语义；
4. gate + 正向全量 + **负向**（摘 starter 验证 404 与软依赖提示）。

## 021.红线（本中心特别三条）

1. **路径校验黑名单勿"优化"**：local 适配器的 `..` / 分隔符拒绝是安全边界，改前必须威胁建模（017 登记）；
2. **大对象一律流式端点**：全量 `readAllBytes` 端点仅限小对象（017 已登记内存风险）；
3. **预签名 / 外链不过信封**：二进制载荷不进 JSON 信封（013 契约）。
