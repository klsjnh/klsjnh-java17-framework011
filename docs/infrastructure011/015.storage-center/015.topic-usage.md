# 015 — center-storage011-starter · 怎么使用

> 四篇一套：[011 设计](011.topic-design.md) · [013 架构](013.topic-architecture.md) · 本篇使用 · [016 二开手册](016.topic-secondary-dev.md)。历史设计（**已归档**，注册表口径不变）：[011.storage-center](../../archive011/infrastructure011/011.storage-center/011.topic-design.md)。

## 011.接入（业务项目）

```xml
<dependencyManagement>
  <dependency>
    <groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId>
    <version>1.0.0</version><type>pom</type><scope>import</scope>
  </dependency>
</dependencyManagement>

<dependency>
  <groupId>com.klsjnh</groupId><artifactId>center-storage011-starter</artifactId>
</dependency>
```

> 引 `center-ai011-starter` 会自动带入本 starter（AI 落盘依赖存储）。

随后三步：

1. **建表**：执行 [july_center_storage011.sql](../../sql/july_center_storage011.sql)。
2. **配默认 provider**（application.yml，选 local011 或 minio011）：

```yaml
krt:
  storage-center:
    default-type: local011        # 或 minio011
    local011:
      base-path: ./storage011
      default-bucket: backup011
    # minio011: { endpoint, access-key, secret-key, default-bucket }
```

3. **播种即用**：启动时 `StorageSeed011` 自动建 `default` provider 行与默认桶；`GET /klsjnh/storagecenter/julyStorage/v1/getByCode?storageCode=default` 可验证。

## 013.常用操作

| 操作 | 端点 |
|------|------|
| 实例 / 桶管理 | `/klsjnh/storagecenter/julyStorage/v1`（主子表 CRUD + 测试连接） |
| 对象上传 / 下载 | `/klsjnh/storagecenter/julyObject/v1`（下载有流式端点，大对象勿用全量端点） |
| 在线编辑 | `readText` / `saveText`（1MB 上限） |
| 预签名 | `julyObject/v1` 预签名端点（minio011） |

## 015.运行时切换 provider

改 `krt.storage-center.default-type` 后重启即切换——两个内置适配器都在 classpath，**无需改依赖**。备份（`platform011.backup`）与 AI 产物落盘都跟随此默认解析。

## 017.不引本 starter 的行为

- **`/klsjnh/storagecenter/**` 整体 404（路由级）**；
- `backup011` 端点存活（core），调用返回 403"存储能力未启用"；
- 引 `center-ai011-starter` 的项目会被自动带入本 starter（传递依赖）。

## 019.扩展：新 provider（如 s3011）

实现 `ObjectStorageProviderFactory` + `ObjectStoragePort`（参照 `MinioObjectStorageAdapter` + `MinioStorageProviderFactory`），注册为 bean 即被注册表收编；`StorageProviderCodes011` 增量常量。
