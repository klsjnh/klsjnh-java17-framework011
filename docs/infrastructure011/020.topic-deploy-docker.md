# 020.topic-deploy-docker（容器化部署）

> 定位：**部署机制沉淀** —— 基镜像 + 项目依赖两方案 + 项目内 docker compose 编排 + 日志/脱敏。
> 参照：`klsjnh-devops-java17-011` 技能（alpine+JDK17 金标准）；本项目**底座改为 ubuntu:26.04**，编排**落在项目内**（不依赖外部目录）。
> 落地件：`deploy/`（`Dockerfile.base` / `build-base.sh` / `Dockerfile.project` / `deploy.sh` / `docker-compose.yml` / `docker-compose.bake.yml`）。

## 011.产物与端口

| 项 | 值 |
|---|---|
| 可执行产物 | `java17-app011`（唯一 main） |
| 镜像 | 基镜像 `klsjnh/java17:v0.0.1`；bake 时另有项目镜像 `<project>:v<ver>` |
| 端口 | `SERVER_PORT`（测试用 **23333**；默认配置 11610） |
| 编排 | **项目内** `deploy/docker-compose*.yml` |

## 013.基镜像（ubuntu:26.04 + JDK17）

- `deploy/Dockerfile.base`：`FROM ubuntu:26.04` + apt(bash/tzdata/ca-certificates) + 拷 JDK17 介质到 `/environment/java17`。
- `deploy/build-base.sh`：已存在则跳过（`--force` 重建）；JDK 介质取用优先级：
  1. `MEDIA_DIR` 已有介质；
  2. **MinIO 桶下载**（`mc` 或 `python3-minio`）——参数走环境变量（见 §021 脱敏）；
  3. 回退：打包本机 `JDK_SRC`（默认 `/usr/local/java17`）。
- 验证：`docker run --rm --entrypoint java klsjnh/java17:v0.0.1 -version`。

## 015.项目依赖两方案

| 方案 | 编排 | 机制 | 取舍 |
|---|---|---|---|
| **mount（默认）** | `deploy/docker-compose.yml` | jar 从构建产物挂入 `/klsjnh/app/app.jar:ro` | 换 jar 只重启，无重建；依赖宿主文件 |
| bake | `deploy/docker-compose.bake.yml` | `deploy/Dockerfile.project` COPY `app_v<ver>.jar` | 自包含可交付；改 jar 要重建镜像 |

`deploy.sh [mount|bake]` 自动选编排并 `docker compose up -d`。

## 017.编排要点（项目内 compose）

- `network_mode: host`：容器内 `127.0.0.1` = 宿主 → 直连宿主 MySQL。
- `entrypoint` 覆盖：`exec java $$JAVA_OPTS -jar /klsjnh/app/app.jar --spring.config.additional-location=/klsjnh/volume/config/`（`$$` 防 compose 插值）。
- 挂载：`config`（配置，只读）、`runtime/logs`、`runtime/data`、`runtime/storage011`。
- `restart: unless-stopped`。

## 019.配置 / 端口 / 日志

- 配置：`java17-app011/src/main/resources/`（`application.yml` + `application-development.yml`）挂为 `/klsjnh/volume/config`；profile 文件经 `additional-location`（目录）一并生效。
- 端口：`SERVER_PORT` 环境变量覆盖 `server.port`。
- 日志：
  - 容器 stdout：`docker compose -f deploy/docker-compose.yml logs -f app`
  - 文件：`deploy/runtime/logs/java17-app011.log`（`LOGGING_FILE_PATH` 控制；logback `logging.file.path`）。

## 021.脱敏与红线（上 git）

- `deploy/` 内**无内网 IP、无凭据**；MinIO 参数（endpoint/bucket/AK/SK）**一律环境变量**：
  `MINIO_ENDPOINT` / `MINIO_BUCKET` / `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY`。
- 敏感运行配置（生产 DB 密码、JWT secret）**部署机自建、不入库**（沿用 `.gitignore` 对 `application-*.yml` 的忽略）。
- `deploy/runtime/`（logs/data/storage011）**gitignore**。
- 红线：`mvn` 报错只提醒不私自处理；镜像标签用 `v<ver>`（禁 git hash）。

## 023.操作手册

```bash
cd <项目根>
bash deploy/build-base.sh              # 基镜像（缺则建）
bash deploy/deploy.sh                  # mount（默认）→ docker compose up -d
# 或 bash deploy/deploy.sh bake
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f app
docker compose -f deploy/docker-compose.yml down
# 访问 http://<host>:23333/doc.html
```

## 025.镜像归档（MinIO `docker-images`）

镜像可 `docker save` 归档到对象存储桶 `docker-images`，命名 `<repo>_<tag>.tar`（ubuntu 系用下划线，如 `ubuntu_26.04.tar`、`klsjnh_java17_v0.0.1.tar`）。上传凭据同 §021 环境变量。
