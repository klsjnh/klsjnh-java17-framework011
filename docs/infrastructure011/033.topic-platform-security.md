## 013.现状缺口（密钥）

| 载体 | 库内 | 出参 | 配置预埋 |
|------|------|------|----------|
| `july_ai_model_provider_api.api_key` | `enc:v1:`（存量明文兼容读） | 类型层剔除 | `krt.crypto.master-key` |
| `july_storage_provider.secret_key` / `access_key` | 同上 | `******`；**update 回传 mask / blank 保留库内旧值** | 同上 |
| `july_datasource.password` | 同上 | 不回显 / 空则保持 | 同上 |
| `july_message_*_channel.config` JSON | 敏感键字段级 `enc:v1:`（`secret` / `token` / `password` / `apiKey` / `accessKey` / `secretKey` / `corpSecret` / `appSecret` / `clientSecret` / `privateKey` 等；大小写/下划线/连字符不敏感，复合键后缀匹配） | 敏感键打码 `******` | 同上 |

## 015.能力 B — 机密加密存储

### 011.目标

库内敏感列 **可逆加密**；运行时解密后仅在内存用于连接 / 调厂商；**出参与日志永不出现明文**（维持现有打码 / 剔除口径）。

### 013.机制（已落地）

```text
domain.crypto
  SecretCipherPort
    encrypt(plain) → cipherText   // 带版本前缀，可识别明文存量
    decrypt(stored) → plain       // 无前缀则视为历史明文（兼容读）

infrastructure
  AesGcmSecretCipher011           // AES-256-GCM；主密钥来自配置/环境变量
  ChannelConfigCipher011          // 消息渠道 config JSON 字段级加解密 / 打码

配置（单一主密钥，禁止按中心分叉多把除非二期 KMS）
  krt.crypto.master-key           // 必填于 production（启动卫兵，对齐 jwt.secret）
```

| 决策点 | 建议默认 | 说明 |
|--------|----------|------|
| 算法 | AES-256-GCM + 随机 IV | 密文格式：`enc:v1:<base64(iv+ciphertext+tag)>` |
| 主密钥 | 环境变量 / 部署机 yml（**不入库 git**） | production 缺失 → 启动失败 |
| 写入 | Repository 落库前 `encrypt`（消息 JSON 仅敏感键） | 空串 / 「保持原值」语义不变；更新时 `******` 保留旧密钥 |
| 读取 | 组装连接或调 SPI **直前** `decrypt`；聚合内存可暂存明文（短生命周期） | PO 层存密文 |
| 存量迁移 | **读时兼容**：无前缀当明文；**下次 update 写回密文**；可选运维批刷脚本 | 禁止强制停机全表重写作为唯一路径 |
| 覆盖列 | ① `july_datasource.password` ② `july_ai_model_provider_api.api_key` ③ `july_storage_provider.secret_key` **+ `access_key`** ④ 消息渠道 `config` 敏感键 | 库内列 `VARCHAR(512)`（单列密钥）；消息 `config` 为 TEXT/JSON，字段级加密 |
| **不覆盖** | `july_user.password`（bcrypt）· JWT secret（配置） |

### 015.分期

| 期 | 内容 | 状态 |
|----|------|------|
| B0 | `SecretCipherPort` + AES 实现 + `krt.crypto.master-key` + production 卫兵 | ✅ |
| B1 | 数据源 `password` 加解密贯通（管理面 + 动态注册连库） | ✅ |
| B2 | AI `api_key` + 存储 `secretKey` / `accessKey`（均加密） | ✅ |
| B3 | 消息渠道 JSON `config` 字段级；运维批刷与轮换主密钥流程（批刷/轮换仍可选） | ✅ 字段级落地；批刷/轮换流程仍可选 |

### 017.否定清单（B）

- 不做 HSM / 云 KMS 适配（主密钥文件/环境变量够用；KMS 列远期）。
- 不做「加密即脱敏」——出参打码规则独立保留。
- 不把主密钥写入业务表或 `july_config`（防鸡生蛋 + 权限绕过）。
- 不把权限核对逻辑写进本文 / 本模块（→ [013 · 016](013.access-center/016.topic-dynamic-permission.md)）。

## 017.风险与先行审查点

1. **主密钥丢失 = 库内凭据不可恢复** —— 部署文档必须写备份与轮换。
2. **与动态数据源**：解密在建池 / 探测前；与 `reloadRegistry` 对齐。
3. **显式核对漏挂**（权限侧）——纪律问题，见 [013 · 016](013.access-center/016.topic-dynamic-permission.md)；不做全局拦截器兜底。
