# 013 — 项目结构与目录说明

> 六个 Maven 模块对应 DDD 分层；本文描述每个目录放什么、命名怎么起、加一个业务功能时从哪个目录动笔。


## 2. 模块与包结构

### ① java17-common011 — `com.klsjnh.common.*`

跨层契约，零 Spring。所有层可依赖。

```
common.enums      # FrameworkStatus011 / HttpCodeEnum011 / Status011 / AuditType011 / ExportFormat011
common.response   # Response011 统一响应信封
common.vo         # IdVo011 / BatchDeleteErrorVo011 / BatchDeleteResultVo011
common.exception  # BusinessException（携带契约状态码 + 安全消息，含静态工厂）
common.page       # PageQuery011 / PageResult011 分页对
common.constant   # FrameConst011；开放字符串常量 DatabaseTypes011（dbType）/ StorageProviderCodes011（storage provider）
common.identity   # Operator011 操作人值对象（审计走 request attribute，无 ThreadLocal 全局上下文）
common.util       # StringUtil011 等纯工具
```

### ② java17-domain011 — `com.klsjnh.domain.*`（纯净内核）

纯内核：只有聚合、值对象、仓储接口、Port。**纯 Java + record**，仅可依赖 common 的纯枚举（Status011 等），禁 Lombok 与一切框架。
包规划（2026-09-13 定案）：**框架级子域在顶层，URL 业务域收敛到 system011 包**。

```
domain.shared             # EntityId / AuditInfo —— 跨域共享值对象
domain.iam                # IAM 中心（Identity and Access Management）：user / role / auth（AuthorizationPort）/ perm（权限目录 object+action）；文档 018.iam-center
domain.datasource         # 动态数据源设施：kernel（ConnectionInfo / RegistryPort / SqlRoutingPort / SqlDialectPort011 SPI）/ management（JulyDatasource）
domain.storagecenter      # 对象存储设施：object（ObjectStoragePort / ObjectStorageProviderFactory SPI / StorageProviderCodes011）/ storage（JulyStorageProvider / JulyStorageProviderBucket）
domain.messagecenter      # 消息中心（出入两套）：outbound.{channel,template,message}（MessageChannelPort SPI / JulyOutbound*）/ inbound.{channel,template,message}（MessageInboundPort + InboundMessageListener SPI / JulyInbound*）
domain.aicenter           # AI 中心：modelprovider（AiModelProvider + Api + Probe）/ inference（AiInferencePort + AiChatMessage）/ image（AiImagePort）/ audio（AiTtsPort + AiAsrPort）/ capability（AiInvokeTarget / AiMedia / AiCapabilityPort / AiCapabilityCodes）/ media（AiMediaStorePort）
domain.system011          # ★ 系统管理业务域（URL /klsjnh/system011/**）
  system011.config        #   JulyConfig + 仓储（运行时键值参数）
  system011.menu          #   JulyMenu + 仓储 + JulyRolePermissionsRepository
  system011.organization  #   JulyOrganization + 仓储
  system011.scheduler     #   JulyScheduler + 仓储 + SchedulerPort + JobHandler + JobHandlerRegistryPort
  system011.dictionary    #   JulyDictionary + JulyDictionaryItem + 仓储
domain.platform011        # 平台能力：export / importdata / backup
```

### ③ java17-application011 — `com.klsjnh.application.*`

用例编排 + 事务边界。依赖 domain 接口，**不 import 任何 Po/Mapper**。

```
application.<能力>.<子域>      # 按能力分包：iam.{user,role,perm} · datasource.{kernel,management}
                              #   storagecenter.storage · messagecenter.{outbound,inbound}.{channel,template,message}
                              #   aicenter.{inference,image,audio,modelprovider,media,prompt} · system011.{config,menu,organization,scheduler,dictionary} · platform011.{export,importdata,backup}
```

### ④ java17-infrastructure011 — `com.klsjnh.infrastructure.*`

PO、Mapper、RepositoryImpl、技术适配。

```
infrastructure.config                # KrtConfig011 / MybatisPlusConfig011（★ 分页插件必须注册：
                                     #   MP 3.5.9 的 PaginationInnerInterceptor 在独立构件 mybatis-plus-jsqlparser，
                                     #   不注册则 selectPage 静默返回全表——100 用户测试数据揪出）+ 启动卫兵
infrastructure.persistence.entity    # BasePo 家族（BasePo / BasePo011 / TreePo / TreePo011）+ MasterLinked（pk_mt 契约）
infrastructure.persistence.handler   # AuditMetaObjectHandler 审计自动填充（时间 + 请求作用域操作人）
infrastructure.persistence.mapper    # MP BaseMapper 接口 + CommonMapper（原生 SQL，带白名单约束）
infrastructure.persistence.repository# BaseRepository 家族基座（8 形态，含主子表 / 树+主子表）+ support 公共件 + RepositoryImpl
infrastructure.iam / system011 / datasource / storagecenter / messagecenter / aicenter
                                     # 各能力按子域分包：{entity,mapper,repository}（+ 适配器）
                                     #   messagecenter.{outbound,inbound}.channel（内置/厂商渠道·接收适配）
                                     #   aicenter.modelprovider.probe（AiModelProbe011）· aicenter.provider.openai（通用 OpenAI 兼容适配器：inference/image/tts/asr）· aicenter.media（AiMediaStore011）· aicenter.prompt（提示词主子表 Po/Mapper/RepositoryImpl + PromptRender011）
```

### ⑤ java17-web011 — `com.klsjnh.web.*`

Controller、请求/响应 VO、全局异常、鉴权过滤器。

```
web.<业务域>.controller   # 只注入 application 服务（URL 首段 = 模块名，见 016 §6.4）
web.<业务域>.vo           # 请求/响应 VO（@Schema 中文描述只在这里）
web.config               # SpringDocConfig011（Swagger 6 个固定组：system011 / iam / storagecenter / datasource / aicenter / messagecenter；+ 可选 app 组，`krt.springdoc.app.group-name` 配置时生效）
web.global               # 全局异常处理器、响应切面、GlobalAuthFilter、AuditLogAspect
```

### ⑥ java17-app011 — `com.klsjnh.app011` + 参考样板

唯一 main：`Framework011Application`（`scanBasePackages = "com.klsjnh"` + `@MapperScan` 三包）；`application.yml` 承载公共结构（port / krt.springdoc / krt.status / jwt / storage-center），`application-development.yml` 为入库的开发共享配置（数据源 + ci011 + minio011），`application-production.yml` 部署机自建（不入库）。注：`debug` 是 `krt.status` 的取值，不是 profile 文件名。

```
app011.config                   # SpringDocConfig011？（否——在 web.config）此处仅 main 装配
com.klsjnh.scheduler            # Demo011Scheduler——JobHandler 参考实现（30s tick 演示）
com.klsjnh.demo11               # ★ DDD 参考样板纵切面（第三方照抄入口）：
  demo11.domain                 #   Demo011 聚合 + Demo011Repository 接口
  demo11.infrastructure.persistence.entity|mapper|repository
  demo11.application            #   Demo011UseCase（@Transactional）
  demo11.web                    #   Demo011Controller（VO 内联单文件示范）
```

## 3. 命名规范

| 后缀 | 含义 | 所在层 |
|------|------|--------|
| `*011` | 本代框架标记（BasePo011 / Response011…） | 全部 |
| `*Po` | MyBatis-Plus 持久化对象 | infrastructure |
| `*Vo011` | 请求/响应载荷（入参出参都算，方向由类名语义表达） | web.<域>.vo / common.vo |
| `*Repository` / `*RepositoryImpl` | 仓储接口 / 实现 | domain / infrastructure |
| `*UseCase` | 应用层用例 | application |

## 4. 新增一个业务功能的动线

以新聚合 `Foo` 为例，按依赖方向从内到外（**完整可运行的参照物：`java17-app011` 的 `com.klsjnh.demo11` 纵切面**）：

1. `domain011`：`domain.foo.Foo`（聚合根，EntityId + AuditInfo 组合）+ `FooRepository` 接口
2. `infrastructure011`：`FooPo`（继承 BasePo 家族）+ `FooMapper` + `FooRepositoryImpl`（基座对号入座）
3. `application011`：`FooUseCase`（@Transactional，编排聚合与仓储）
4. `web011`：`FooController` + 请求/响应 VO（@Schema 中文）
5. `docs/013.api-contract.md`：新端点涉及的契约确认
6. `docs/sql/`：建表 DDL（含公共列模板）
