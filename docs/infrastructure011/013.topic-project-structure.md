# 013 — 项目结构与目录说明

> 六个 Maven 模块对应 DDD 分层；本文描述每个目录放什么、命名怎么起、加一个业务功能时从哪个目录动笔。

## 1. 顶层结构

```
klsjnh-java17-framework011/
├── Agent.md                            # AI 助手手册（项目入口，先读我）
├── pom.xml                             # 父 POM：版本统一 dependencyManagement
├── docs/
│   ├── 011.topic-infrastructure.md     # 架构选型与设计思路
│   ├── 013.topic-project-structure.md  # 本文件
│   ├── 016.api-contract.md             # API 契约（信封六键 + 状态码表）
│   └── sql/
│       └── base-entity-columns.sql     # PO 四件套对应公共列 DDL 模板
├── tools/                              # 提交门禁（check / fix / push-gate / hooks）
├── java17-common011/                   # ① 公共层
├── java17-domain011/                   # ② 领域层（零依赖）
├── java17-application011/              # ③ 应用层
├── java17-infrastructure011/           # ④ 基础设施层
├── java17-web011/                      # ⑤ 接口层
└── java17-app011/                      # ⑥ 启动器（唯一 main）
```

## 2. 模块与包结构

### ① java17-common011 — `com.klsjnh.common.*`

跨层契约，零 Spring。所有层可依赖。

```
common.enums      # FrameworkStatus011 / DatabaseType011 / HttpCodeEnum011
common.response   # Response011 统一响应信封
common.vo         # IdVo 等共享载荷 VO（后续：分页对、批量删除结果）
common.exception  # BusinessException（将落）
common.util       # IdUtil 等纯工具（将落）
```

### ② java17-domain011 — `com.klsjnh.domain.*`（零依赖）

纯内核：只有聚合、值对象、仓储接口、Port。**只允许纯 Java + record**。

```
domain.shared     # EntityId / AuditInfo —— 跨聚合共享的值对象
domain.<业务域>    # 聚合根/实体/领域服务（按业务域分包，如 iam、config）
domain.<业务域>.repository  # 仓储接口（返回聚合，不暴露 PO）
```

### ③ java17-application011 — `com.klsjnh.application.*`

用例编排 + 事务边界。依赖 domain 接口，**不 import 任何 Po/Mapper**。

```
application.<业务域>.usecase   # 用例（XxxUseCase / Command / Result）
application.<业务域>.query     # 查询侧（CQRS 读路径，将落）
```

### ④ java17-infrastructure011 — `com.klsjnh.infrastructure.*`

PO、Mapper、RepositoryImpl、技术适配。

```
infrastructure.persistence.entity    # BasePo / BasePo011 / TreePo / TreePo011（公共列）
infrastructure.persistence.mapper    # MP BaseMapper 接口
infrastructure.persistence.repository# RepositoryImpl（实现 domain 仓储接口）
infrastructure.persistence.support   # 通用仓库基座（待设计，替代旧 BaseCrudService011）
```

### ⑤ java17-web011 — `com.klsjnh.web.*`

Controller、请求/响应 VO、全局异常、鉴权过滤器。

```
web.<业务域>.controller   # 只注入 application 服务
web.<业务域>.vo           # 请求/响应 VO（@Schema 中文描述只在这里）
web.global               # 全局异常处理器、响应切面、GlobalAuthFilter
```

### ⑥ java17-app011 — `com.klsjnh.app011`

唯一 main：`Framework011Application`；三套 profile yml（debug / development / production）后续落此模块。

## 3. 命名规范

| 后缀 | 含义 | 所在层 |
|------|------|--------|
| `*011` | 本代框架标记（BasePo011 / Response011…） | 全部 |
| `*Po` | MyBatis-Plus 持久化对象 | infrastructure |
| `*Vo` | 请求/响应载荷 | web / common.vo |
| `*Repository` / `*RepositoryImpl` | 仓储接口 / 实现 | domain / infrastructure |
| `*UseCase` | 应用层用例 | application |

## 4. 新增一个业务功能的动线

以新聚合 `Foo` 为例，按依赖方向从内到外：

1. `domain011`：`domain.foo.Foo`（聚合根，EntityId + AuditInfo 组合）+ `FooRepository` 接口
2. `infrastructure011`：`FooPo`（继承 BasePo 家族）+ `FooMapper` + `FooRepositoryImpl`
3. `application011`：`FooUseCase`（@Transactional，编排聚合与仓储）
4. `web011`：`FooController` + 请求/响应 VO（@Schema 中文）
5. `docs/016.api-contract.md`：新端点涉及的契约确认
6. `docs/sql/`：建表 DDL（含公共列模板）
