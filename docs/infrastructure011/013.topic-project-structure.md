# 013 — 项目结构与目录说明

> **BOM + 胖核心 + 瘦 starter** 共 14 个 Maven 模块承载 DDD 分层；**Java 包结构仍是六层洋葱且不变**（门禁按包名锚定）。本文描述每个模块放什么、命名怎么起、加一个业务功能时从哪个目录动笔。

## 2. 模块与包结构

> 包名与类的归属（哪些包在哪个模块）见下；**依赖方向严格单向**：starter → core → security-api。

### ① java17-security-api011 — 纯 Java 安全 API（零框架依赖）

```
common.identity             # Operator011 操作人值对象（审计走 request attribute，无 ThreadLocal 全局上下文）
common.enums（部分）        # FrameworkStatus011（运行态三态；其余枚举仍在 core 的 common.enums）
domain.iam.auth             # AuthTokenPort / AuthorizationPort / PasswordPort / RuntimeStatusPort
```

### ② java17-core011 — `com.klsjnh.{common,domain,application,web,infrastructure}.*`（胖核心）

## 3. 命名规范

| 后缀 | 含义 | 所在层 |
|------|------|--------|
| `*011` | 本代框架标记（BasePo011 / Response011…） | 全部 |
| `*Po` | MyBatis-Plus 持久化对象 | infrastructure |
| `*Vo011` | 请求/响应载荷（入参出参都算，方向由类名语义表达） | web.<域>.vo / common.vo |
| `*Repository` / `*RepositoryImpl` | 仓储接口 / 实现 | domain / infrastructure |
| `*UseCase` | 应用层用例 | application |

## 4. 新增一个业务功能的动线

以新聚合 `Foo` 为例，按依赖方向从内到外（**完整可运行的参照物：`java17-reference-app011` 的 `com.klsjnh.demo11` 纵切面**）。业务工程的四个分层模块照旧自建（`*-domain011 / *-application011 / *-infrastructure011 / *-web011`），框架代码只在 core / starter 里：

1. 业务 `*-domain011`：`domain.foo.Foo`（聚合根，EntityId + AuditInfo 组合）+ `FooRepository` 接口
2. 业务 `*-infrastructure011`：`FooPo`（继承 core 的 BasePo 家族）+ `FooMapper` + `FooRepositoryImpl`（基座对号入座；`@MapperScan` 写自己的 mapper 包）
3. 业务 `*-application011`：`FooUseCase`（@Transactional，编排聚合与仓储）
4. 业务 `*-web011`：`FooController` + 请求/响应 VO（@Schema 中文）
5. `docs/013.api-contract.md`：新端点涉及的契约确认
6. `docs/sql/`：建表 DDL（含公共列模板）
