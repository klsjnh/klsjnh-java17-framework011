# 013 — 项目结构与目录说明

> 六个 Maven 模块对应 DDD 分层；本文描述每个目录放什么、命名怎么起、加一个业务功能时从哪个目录动笔。

## 1. 顶层结构

```
klsjnh-java17-framework011/
├── Agent.md                            # AI 助手手册（项目入口，先读我）
├── pom.xml                             # 父 POM：版本统一 dependencyManagement
├── docs/                               # 知识库（体系与编号见 docs/011.agreements.md）
│   ├── 013.project-info.md             # 项目信息（定位 / 技术栈 / 构建运行）
│   ├── 015.coding-standards.md         # 编码规则（门禁映射）
│   ├── 016.api-contract.md             # API 契约
│   ├── infrastructure011/              # 架构专题（011 选型 / 013 结构 / 015 配置 / 016 持久化 / 017 数据源 / 018 IAM / 019 存储）
│   ├── requirement011/ · requirement013/  # 业务设计 / 技术方案（主题同号贯穿）
│   └── sql/                            # DDL 模板
├── script011.sh                        # 唯一操作入口（gate / push / build011）
├── tools/                              # 编码规范门禁（check；脚本只查不改，规则见 docs/015）
├── java17-common011/                   # ① 公共层
├── java17-domain011/                   # ② 领域层（仅依赖 common 共享内核枚举）
├── java17-application011/              # ③ 应用层
├── java17-infrastructure011/           # ④ 基础设施层
├── java17-web011/                      # ⑤ 接口层
└── java17-app011/                      # ⑥ 启动器（唯一 main）
```

## 2. 模块与包结构

### ① java17-common011 — `com.klsjnh.common.*`

跨层契约，零 Spring。所有层可依赖。

```
common.enums      # FrameworkStatus011 / DatabaseType011 / HttpCodeEnum011 / Status011 / StorageType011
common.response   # Response011 统一响应信封
common.vo         # IdVo011 / BatchDeleteErrorVo011 / BatchDeleteResultVo011
common.exception  # BusinessException（携带契约状态码 + 安全消息，含静态工厂）
common.page       # PageQuery011 / PageResult011 分页对
common.constant   # FrameConst011 跨层常量（准入规则见 015 §7）
common.security   # （已废弃 OperatorContext——走 request attribute 方案）
common.util       # StringUtil011 等纯工具
```

### ② java17-domain011 — `com.klsjnh.domain.*`（纯净内核）

纯内核：只有聚合、值对象、仓储接口、Port。**纯 Java + record**，仅可依赖 common 的纯枚举（Status011 等），禁 Lombok 与一切框架。

```
domain.shared     # EntityId / AuditInfo —— 跨聚合共享的值对象
domain.<业务域>    # 聚合根/实体/领域服务（按业务域分包，如 iam、config）
domain.<业务域>.repository  # 仓储接口（返回聚合，不暴露 PO）
```

### ③ java17-application011 — `com.klsjnh.application.*`

用例编排 + 事务边界。依赖 domain 接口，**不 import 任何 Po/Mapper**。

```
application.<业务域>.usecase   # 用例（XxxUseCase / Command / Result）
application.<业务域>.query     # 查询侧（CQRS 读路径，将落）
```

### ④ java17-infrastructure011 — `com.klsjnh.infrastructure.*`

PO、Mapper、RepositoryImpl、技术适配。

```
infrastructure.config                # KrtConfig011 等 @ConfigurationProperties 绑定 + 启动卫兵
infrastructure.persistence.entity    # BasePo 四件套 / MasterLinked（pk_mt 契约）
infrastructure.persistence.handler   # AuditMetaObjectHandler 审计自动填充（时间 + 请求作用域操作人）
infrastructure.persistence.mapper    # MP BaseMapper 接口 + CommonMapper（原生 SQL，带白名单约束）
infrastructure.persistence.repository# BaseRepository 家族基座（含 021 主子表层）+ RepositoryImpl
```

### ⑤ java17-web011 — `com.klsjnh.web.*`

Controller、请求/响应 VO、全局异常、鉴权过滤器。

```
web.<业务域>.controller   # 只注入 application 服务
web.<业务域>.vo           # 请求/响应 VO（@Schema 中文描述只在这里）
web.config               # SpringDocConfig011 等 web 层配置（Swagger 分组）
web.global               # 全局异常处理器、响应切面、GlobalAuthFilter
```

### ⑥ java17-app011 — `com.klsjnh.app011` + 参考样板

唯一 main：`Framework011Application`（`scanBasePackages = "com.klsjnh"` + `@MapperScan` 三包）；`application.yml` 承载公共结构（port / krt.springdoc / krt.status / jwt / storage-center），`application-development.yml` 为入库的开发共享配置（数据源 + ci011 + minio011），`application-production.yml` 部署机自建（不入库）。注：`debug` 是 `krt.status` 的取值，不是 profile 文件名。

```
app011.config                   # SpringDocConfig011？（否——在 web.config）此处仅 main 装配
com.klsjnh.scheduler            # Demo011Scheduler——JobHandler 参考实现（30s tick 演示）
com.klsjnh.demo11               # ★ DDD 参考样板纵切面（第三方照抄入口）：
  demo11.domain                 #   Demo011 聚合 + Demo011Repository 接口
  demo11.infrastructure.persistence.entity|mapper|repository
  demo11.application            #   Demo011UseCase（@Transactional）
  demo11.web                    #   Demo011Controller（VO 内联单文件示范）
```

## 3. 命名规范

| 后缀 | 含义 | 所在层 |
|------|------|--------|
| `*011` | 本代框架标记（BasePo011 / Response011…） | 全部 |
| `*Po` | MyBatis-Plus 持久化对象 | infrastructure |
| `*Vo011` | 请求/响应载荷（入参出参都算，方向由类名语义表达） | web.<域>.vo / common.vo |
| `*Repository` / `*RepositoryImpl` | 仓储接口 / 实现 | domain / infrastructure |
| `*UseCase` | 应用层用例 | application |

## 4. 新增一个业务功能的动线

以新聚合 `Foo` 为例，按依赖方向从内到外（**完整可运行的参照物：`java17-app011` 的 `com.klsjnh.demo11` 纵切面**）：

1. `domain011`：`domain.foo.Foo`（聚合根，EntityId + AuditInfo 组合）+ `FooRepository` 接口
2. `infrastructure011`：`FooPo`（继承 BasePo 家族）+ `FooMapper` + `FooRepositoryImpl`（基座对号入座）
3. `application011`：`FooUseCase`（@Transactional，编排聚合与仓储）
4. `web011`：`FooController` + 请求/响应 VO（@Schema 中文）
5. `docs/016.api-contract.md`：新端点涉及的契约确认
6. `docs/sql/`：建表 DDL（含公共列模板）
