# 022.topic-ai-lowcode-pipeline（AI 低代码机制 · 端到端）

> 目的：说明本体底座当前把「**数据类简单开发**」变成**声明式流水线**到什么程度、AI 该怎么用、有哪些闸门与坑。
> 相关：[038](../requirement013/038.topic-lowcode-core.md) / [039](../requirement013/039.topic-lowcode-designer-runtime.md) / [040](../requirement013/040.topic-metadata-template.md) / [021 前端对接](021.topic-lowcode011-frontend-guide.md)。

## 011.一句话

底座已经把「**探源 → 建模 → 审核 → 发布建表 → 导数据 → 对外开放**」打通为**声明式**链路（输入是一份**模板**：JSON/CSV/Markdown，产物是一个可读写的对象），**不生成代码**、**不执行 DROP**——这是最适合 AI 驱动的形态。

## 013.端到端流水线

```
数据源(如 bpm011) ──SQL──► 探测/建模 ──► 模板(JSON/CSV/Markdown) ──► 审核(upload) ──► 部署(deploy) ──► 物理表 ──► 导数据 ──► 开放 API
                          033/039        040          零副作用校验+previewDdl   落库+发布     <obj>   幂等 upsert   api_key CRUD+meta
```

| 步 | 动作 | 端点 | 产物 |
|----|------|------|------|
| 1 | 探源推断 | `POST /klsjnh/dataservice011/julyBusinessModeling/v1/probe` | fieldData（类型推断） |
| 2 | 取默认模板 / 导出 | `GET .../julyMetadata/v1/getTemplate011` · `/downloadTemplate011?objectName=&format=json\|csv\|md` | 多格式模板（json/csv/md；xlsx 占位） |
| 3 | **审核** | `POST .../uploadTemplate011` | `{valid, errors[], plan, previewDdl}`（零副作用） |
| 4 | **部署** | `POST .../deployObject` | 元数据落库 + 建表/ALTER + 版本 |
| 5 | 导数据 | `POST .../importDataFromSql` | 按业务键幂等 upsert |
| 6 | 对外开放 | `/klsjnh/open/v1`（`X-Api-Key`） | meta + query/insert/update/delete |

## 017.端点即"AI 工具"

把下面这些当作 AI 可调用的 tool（全部 HTTP + JSON，统一信封）：

| tool | 端点 | 关键入参 |
|------|------|----------|
| probe | `dataservice011/julyBusinessModeling/v1/probe` | `{dataSourceCode, sqlContent, objectName}` |
| getTemplate | `lowcode011/julyMetadata/v1/getTemplate011` | — |
| exportTemplate | `.../downloadTemplate011` | `objectName` |
| reviewTemplate | `.../uploadTemplate011` | 模板 JSON（或文件） |
| deployObject | `.../deployObject` | `{template| objectName, overwrite}` |
| importData | `.../importDataFromSql` | `{objectName, dataSourceCode, sqlCode, pageNum, pageSize}` |
| openMeta | `open/v1/getMeta` | `objectName` + `X-Api-Key` |
| openCrud | `open/v1/query|insert|update|delete` | `{objectName, ...}` + `X-Api-Key` |

## 019.标准 AI 流程（推荐）

1. **探源**：对目标数据源跑 `probe`，拿到字段与类型（注意过滤 `KLSJNH_RN` 行号伪列）。
2. **成型**：用 `getTemplate011` 作为骨架，或 `downloadTemplate011` 复制既有对象，改 `objectName`/字段/`source`。
3. **审核**：`uploadTemplate011` → 看 `errors` 与 `previewDdl`+`plan`（**只读，不改库**）。
4. **人确认**：把 `previewDdl` 给用户确认（这一步是安全闸门）。
5. **部署**：`deployObject`（`overwrite=false` 保护既有对象）。
6. **导数据**：`importDataFromSql` 分页循环直到 `hasMore=false`。
7. **对外**：按需 `saveOpenApiConfig` 开 `api_key` 的 CRUD/meta。

## 021.安全闸门（必须遵守）

- **预演先行**：任何建表/改表前先 `uploadTemplate011` / `previewDdl`；把 DDL 文本交给用户确认。
- **开关**：`krt.lowcode.ddl-execute.enabled`（默认 false，生产暗发）——未开则 `publish/deploy` 拒绝执行。
- **DDL 白名单**：首次 `CREATE TABLE IF NOT EXISTS`；其后仅 `ALTER ... ADD COLUMN`；**禁 `DROP`/`DROP COLUMN`/`MODIFY`/`RENAME`**。
- **不可回滚**：DDL 隐式提交、无事务；失败可**重跑**（幂等），但不能"撤销"。
- **审计**：`publish/deploy/import` 落审计（UPDATE/BACKUP 类）。
- **生产**：应用账号是否具备 DDL 权限需 DBA 决策；生产建议走工单。

## 023.约束与坑（血泪清单）

1. **基列**：`id/status/dr/create_by/update_by/create_time/update_time` 是平台基列，模板 `fieldData` 里**允许一次**、**类型被归一**；再加同名（含大小写）= 撞键（`july_metadata_field` 唯一键大小写不敏感）→ 400。
2. **业务键**：`businessField`（如 `sid`）固定 `VARCHAR(33)`，同步按它 upsert；`pk_*` 外键列也固定 `VARCHAR(33)`。
3. **业务 ↔ 基列映射（B 口径）**：要把业务列映射到平台基列（如 `status`），做法是**导入 SQL 带该列**（列名大小写不敏感匹配），**不加元数据字段**；代价是语义合并（admin 启停与同步互相覆盖）。
4. **映射靠列名**：同步按目标列名匹配；源列名不一致时用 **SQL 别名**（`orgid pk_organization`）。
5. **探测伪列**：033 分页探针会带出 `KLSJNH_RN`，建模前剔除。
6. **objectName**：`^[a-z][a-z0-9_]{0,49}$`，不可变；物理表 `<objectName>`。
7. **禁 path variable**：`objectName` 走 query/body。
8. **`previewDdl` 是全量 CREATE**，`publish` 在表已存在时走 ALTER——两者语义不同，别混。

## 025.示例：`bpm011.tuser → bpm_user011 → bpm_user011`

```bash
# 1) 探源
POST /klsjnh/dataservice011/julyBusinessModeling/v1/probe
  {"dataSourceCode":"bpm011","objectName":"bpm_user011",
   "sqlContent":"select id sid, userid username, name, status, orgid pk_organization from tuser"}

# 2) 取骨架 → 填 metaData/fieldData/...（见 021/040 文档）
GET  /klsjnh/lowcode011/julyMetadata/v1/getTemplate011

# 3) 审核（零副作用）
POST /klsjnh/lowcode011/julyMetadata/v1/uploadTemplate011   <template.json>
#   → {"valid":true,"plan":"create","previewDdl":"CREATE TABLE IF NOT EXISTS bpm_user011 (...)"}

# 4) 部署（受开关约束）
POST /klsjnh/lowcode011/julyMetadata/v1/deployObject
  {"template":{...},"overwrite":false}
#   → {"saved":true,"published":true,"version":"0.0.1","physicalTable":"bpm_user011"}

# 5) 导数据（分页循环）
POST /klsjnh/lowcode011/julyMetadata/v1/importDataFromSql
  {"objectName":"bpm_user011","dataSourceCode":"bpm011",
   "sqlCode":"select id sid, userid username, name, status, orgid pk_organization from tuser",
   "pageNum":1,"pageSize":500}
#   → 4579 行，plan 幂等（重复导同页不翻倍）

# 6) 对外开放（管理端配置 apiKey 后）
GET  /klsjnh/open/v1/getMeta?objectName=bpm_user011   (X-Api-Key: ****)
POST /klsjnh/open/v1/query  {"objectName":"bpm_user011","pageIndex":1,"pageSize":20}
```

## 027.未来（补齐后即可称"AI 直接做简单应用"）

1. **运行时段**：`publishMenu/listRuntimeMenus/initialize` + `/runtime` 动态页 → AI 一键出"可点的页面"。
2. **真字段映射**：`sourceColumn → targetColumn` 配置，摆脱"列名匹配/别名"。
3. **运行时校验 + 对象级权限**：required/类型/唯一 + 操作权限。
4. **MCP/工具面**：把上表端点包成 MCP server，AI 直接调用（无需拼 HTTP）。
5. **沙箱/预发库 + 一键重建**：让 AI 可"试错式开发"，生产仍走 DBA 闸门。
6. **开放 API 限流 + 行级权限**。
