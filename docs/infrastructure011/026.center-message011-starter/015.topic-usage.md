# 015 — center-message011-starter · 怎么使用

> 四篇一套：[011 设计](011.topic-design.md) · [013 架构](013.topic-architecture.md) · 本篇使用 · [016 二开手册](016.topic-secondary-dev.md)。历史设计（出入两套口径不变）：[013.message-center](../013.message-center/015.topic-usage.md)。

## 011.接入（业务项目）

```xml
<dependencyManagement>
  <dependency>
    <groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId>
    <version>1.0.0</version><type>pom</type><scope>import</scope>
  </dependency>
</dependencyManagement>

<dependency>
  <groupId>com.klsjnh</groupId><artifactId>center-message011-starter</artifactId>
</dependency>
```

随后两步：

1. **建表**：执行 [july_center_message.sql](../../sql/july_center_message.sql)（出入两套共 6 表）。
2. **配渠道**：`POST /klsjnh/messagecenter/julyOutboundChannel/v1/insert` 录入渠道（内置 `inapp` / `webhook` 直选；config JSON 存 endpoint / 认证等参数）。

## 013.发消息

- **模板渲染**：`julyOutboundTemplate/v1` 维护模板（render 公共件，主子表参数）。
- **发送**：`julyOutboundMessage/v1` —— 选渠道 + 模板 + 参数发送；结果（成功 / 失败 / 重试语义）落消息记录表。
- webhook 渠道走 `common.util.HttpUtil011`（JDK HttpClient），无 SDK；出站 HTTP 的安全治理（allowlist / 出口代理）见 [033 平台安全](../033.topic-platform-security.md)。

## 015.收消息

- 入站渠道与监听：实现 `MessageInboundPort` + `InboundMessageListener`（或使用 webhook 接收），消息经**去重**后**分发**给业务监听者；`julyInboundMessage/v1` 管理入站记录。

## 017.扩展：新渠道

实现 `MessageChannelPort`（出站）或 `MessageInboundPort`（入站）并注册为 bean——Registry `List` 注入自动收编，零配置改动。参照内置 `InAppMessageChannel` / `WebhookMessageChannel`（含 JSON 转义回归测试 `WebhookMessageChannelTest`）。

## 019.不引本 starter 的行为

- **`/klsjnh/messagecenter/**` 整体 404（路由级）**；
- 不导 6 表；classpath 零消息代码；业务代码**不要**注入消息相关用例（编译期即不可见）。
