## 011.环境铁律（踩过的坑）

1. WSL 非登录 shell **必须显式** `export JAVA_HOME=/usr/local/java17`，否则 mvn 静默失败（报 JAVA_HOME not defined，退出码却可能为 0）；
2. 长命令脱钩后台跑、日志落 `tmp/`（Agent.md 铁律）；Git Bash 侧调 WSL 用 `MSYS_NO_PATHCONV=1`，多步操作写成脚本文件执行，勿 inline 转义；
3. **区分两种 404**：路由级 404（`resource not found`，端点不存在）与业务 404（`record not found, id=...`，端点活着）——探测断言以响应 message 为准；
4. 框架装 .m2 用 **`mvn -o clean install`**——勿写 `clean package install`（Maven 3.9 多阶段 CLI 会二次遍历反应堆，空 jar 的 starter 第二遍撞车报 classifier 错误）；
5. mysql 客户端连 33306 需 **`--ssl-mode=DISABLED`**（与 JDBC `useSSL=false` 同理），否则 SSL protocol 报错。

## 017.G4：demo11 CRUD 全链路（基线脚本 `tmp/dev016-golden-e2e.sh`）

登录：`POST /klsjnh/iam/julyUser/v1/loginByUserName {"userAccount":"klsjnh"}` → 取 `data.token`。
随后全部带 `Authorization: Bearer <token>`，基址 `/klsjnh/demo11/v1`，入参 `{"code","name","id"}`：

| 步骤 | 请求 | 预期 |
|------|------|------|
| 1 insert | `POST /insert {"code":"golden011","name":"golden e2e v1"}` | 200，返回 id |
| 2 getById | `GET /getById?id=<id>` | 200，`name=golden e2e v1` |
| 3 update | `POST /update {"id","name":"golden e2e v2"}` | 200 |
| 4 re-get | `GET /getById?id=<id>` | 200，`name=golden e2e v2` |
| 5 page | `POST /selectListByPage {"pageIndex":1,"pageSize":10,"keyword":"golden011"}` | 200，`total=1` |
| 6 logicDelete | `POST /logicDelete {"id"}` | 200 |
| 7 re-get | `GET /getById?id=<id>` | 404，message `record not found, id=...` |

> 2026-09-25 实测：7/7 通过（唯一 CRUD 语义 + 逻辑删除 + 墓碑不挡重插由唯一键生成列保证）。

## 019.G5：调度真实触发（基线脚本 `tmp/dev016-golden-g5.sh`）

**必须自建任务**，不要复用历史行（旧行 cron 不可知；插入字段名是 `schedulerCron`，不是 `cron`）：

```text
POST /klsjnh/system011/julyScheduler/v1/insert
  {"schedulerCode":"golden.sched.e2e","schedulerName":"golden e2e tick",
   "schedulerHandler":"demo011scheduler","schedulerCron":"0/30 * * * * ?"}
→ 200，返回 id（新任务默认停止态）
POST .../start  {"id":...}                        → 200（status=1 运行态）
GET  .../getById?id=...                           → executeTimes=0（t0）
等待 65 秒
GET  .../getById?id=...                           → executeTimes ≥ 2（t1）★核心断言
POST .../stop  {"id":...}                         → 200
POST .../logicDelete {"id":...}                   → 200（清理）
```

> 2026-09-25 实测：t0=0 → t1=2 ✅。原理：start 把任务注册进 Quartz（RAMJobStore），0/30 触发 → `SchedulerHandlerJob` 经 `JobHandlerRegistry` 找到 `demo011scheduler` → 执行 + 原子 SQL `execute_times+1`（finally 必计数，handler 缺失/失败仅 WARN 不中断）。

## 027.已知非缺陷（勿当回归误报）

| 现象 | 解释 |
|------|------|
| debug 态无 token 调业务接口返回 401/400 | 操作人为空的业务层校验，端点存活的表现 |
