## 011.选型速查（30 秒）

看 DDL 三个特征，对号入座：

| 有 `sort_order`？ | 有 `parent_id`？ | 有子表（`pk_mt`）？ | PO | 基座 |
|---|---|---|---|---|
| 否 | 否 | 否 | `BasePo` | `BaseRepository` |
| 是 | 否 | 否 | `BasePo011` | `BaseRepository011` |
| 否 | 是 | 否 | `TreePo<T>` | `BaseTreeRepository` |
| 是 | 是 | 否 | `TreePo011<T>` | `BaseTreeRepository011` |
| 否 | 否 | 是 | `BasePo` + 子 `MasterLinked` | `BaseMasterSubRepository011` |
| 是 | 否 | 是 | `BasePo011` + 子 `MasterLinked` | `BaseMasterSubRepository011`（界为 `BasePo`，排序由具体 wrapper 提供） |
| 否 | 是 | 是 | `TreePo<T>` + 子 `MasterLinked` | `BaseTreeSubRepository` |
| 是 | 是 | 是 | `TreePo011<T>` + 子 `MasterLinked` | `BaseTreeSubRepository011` |

## 013.形态 1 / 2：平表 / 排序表

仓储实现继承基座，填四个"身份"方法：

```java
@Repository
public class JulyConfigRepositoryImpl extends BaseRepository011<JulyConfigPo, JulyConfigMapper>
        implements JulyConfigRepository {

    /** {@inheritDoc} */
    @Override
    protected String getTableName() {
        return "july_config";
    }

    /** {@inheritDoc} */
    @Override
    protected String getBusinessColumn() {
        return "config_code";          // 无业务唯一列则返回 null
    }

    /** {@inheritDoc} */
    @Override
    protected Object getBusinessValue(JulyConfigPo entity) {
        return entity.getConfigCode();
    }

    /** {@inheritDoc} */
    @Override
    protected String duplicateMessage() {
        return "config code already exists";
    }
}
```

- **排序**：`BaseRepository011` 提供 `sortedWrapper()`（`order by sort_order, id`）——分页 / 列表查询复用它；
- **主键**：由用例调 `EntityId.generate()` 显式生成（`ASSIGN_UUID` 仅空值兜底）；
- **逻辑删**：`logicDelete(entity)` / `batchLogicDelete(ids)`；物理删只走 `physicalDelete(id)`（维护场景）。

## 015.形态 3 / 4：树 / 树 + 排序

PO 继承 `TreePo<T>`（或 `TreePo011<T>`），仓储继承 `BaseTreeRepository`（或 `BaseTreeRepository011`）：

```java
@Repository
public class JulyOrganizationRepositoryImpl extends BaseTreeRepository011<JulyOrganizationPo, JulyOrganizationMapper>
        implements JulyOrganizationRepository {

    /** {@inheritDoc} */
    @Override
    protected QueryWrapper<JulyOrganizationPo> treeWrapper() {
        // 011 层已默认 order by sort_order, id；需要额外过滤时覆写
        return super.treeWrapper().eq("status", "1");
    }
}
```

- **`selectTree()`**：一次性读全量存活行 → 内存装配成嵌套树（根 = `parent_id` 空串）；
  - **孤儿回退**：父节点缺失 / 已软删 → 该行**回退到根**，不丢数据；
  - **环回退**：环上不可达的行 → 也回退到根（`collectIds` 截断）；
- **`children` 不是表列**：`@TableField(exist=false)`，只在装配后填充，别指望它从 DB 来；
- **跨层映射**：仓储返回 PO 树，用例/转换器再映射成 domain 聚合树（如 `JulyOrganizationRepositoryImpl` 的 `toAggregateTree(super.selectTree())`）。

## 016.形态 5：主子表（021 层）

**子表 PO 必须 `implements MasterLinked`**（固定链接列 `pk_mt`）：

```java
@TableName("july_dictionary_item")
public class JulyDictionaryItemPo extends BasePo implements MasterLinked {

    private String pkMt;   // getPkMt / setPkMt

    // ... 其他列
}
```

主表仓储继承 `BaseMasterSubRepository011`，声明子仓储：

```java
@Repository
public class JulyDictionaryRepositoryImpl
        extends BaseMasterSubRepository011<JulyDictionaryPo, JulyDictionaryMapper>
        implements JulyDictionaryRepository {

    private final JulyDictionaryItemRepositoryImpl itemRepository;

    /** {@inheritDoc} */
    @Override
    protected List<BaseRepository<?, ?>> getChildServices() {
        return List.of(itemRepository);
    }
}
```

得到四个级联动作：

| 方法 | 行为 |
|------|------|
| `saveMaster(master)` | 只存主表行（更新） |
| `saveChildren(masterId, childService, children)` | 该子表**先逻辑删旧、再整插新**（替换策略） |
| `saveWhole(master, childrenByService)` | 主 + 多子表**整存**（一个事务内，由用例开事务） |
| `getWithChildren(id)` | 主 + 各子表整查（`Map`：`"master"` + 子表 key） |
| `cascadeDelete(id)` | **先子后主**级联逻辑删 |

> **事务归用例**：级联写只在**一个用例事务**内安全（`@Transactional` 只在 application，见红线 [017 §013](../../017.tech-debt-redlines.md)）。
> **审计表例外**：结构上是子表但 append-only → **不注册**进 `getChildServices()`。

## 017.形态 6 / 7 / 8：排序主表 / 树主表 + 子表（已实现）

与形态 5 同样的 `getChildServices()` 契约，只是主表 PO / 基座换成带排序 / 带树的版本：

```java
// 形态 8：树 + 排序 + 主子表（july_ai_domain 即此形态）
@TableName("july_ai_domain")
public class JulyAiDomainPo extends TreePo011<JulyAiDomainPo> { /* parentId / sortOrder 来自基类 */ }

@Repository
public class JulyAiDomainRepositoryImpl
        extends BaseTreeSubRepository011<JulyAiDomainPo, JulyAiDomainMapper>
        implements JulyAiDomainRepository {

    /** {@inheritDoc} */
    @Override
    protected List<BaseRepository<?, ?>> getChildServices() {
        return List.of(promptRepository);      // july_ai_domain_prompt
    }
}
```

同时获得：`selectTree()`（树装配，按 `sort_order` / `id`）+ `saveChildren` / `saveWhole` / `getWithChildren` / `cascadeDelete`（主子级联）。

> **形态 6（排序主表 + 子表）不需要新基座**：`BaseMasterSubRepository011` 的类型界是 `BasePo`，`BasePo011` 天然可挂；排序只是具体仓储 wrapper 的事。
> **形态 7** 用 `BaseTreeSubRepository`（树 + 主子表，树序按 `id`）。

## 019.注意与限制

- **`@Transactional` 只在 application**：domain / infrastructure / web 一律不出现；
- **PO 不出 infrastructure**：application / web 禁止 import `*Po` / `*Mapper`（红线 [017 §015](../../017.tech-debt-redlines.md)）；
- **唯一性靠 DB 索引**：`getBusinessColumn` 断言只是预检；
- **树根用空串**：`parent_id=''`，别用 `null`（`null` 在 `parent_id=''` 查询里永不匹配）；
- **`sort_order` 默认值交给 DDL**（9999），Java 侧不设初值——否则"未指定"与"显式 9999"无法区分；
- **新增形态只做加法**：不改既有 5 形态语义；公共件（树装配 / 主子级联）先抽再组合（见 [011 §017](011.topic-design.md)）。
