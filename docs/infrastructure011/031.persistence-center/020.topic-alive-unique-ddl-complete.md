## 011.定案（不可自行改口径）

1. **红线**：带业务唯一键的表，唯一索引**只约束存活行**（`dr='0'`）。手段 = 生成列 `alive_*`（`dr='0'` 时 = 业务键，否则 `NULL`）+ `UNIQUE(alive_*)`。
2. **双轨交付**（都要做）：
   - **A. CREATE 真源**：各 `docs/sql/july_*.sql` 新建表就必须直接写 `alive_*` + `UNIQUE(alive_*)`（对齐 `july_demo011.sql`），**禁止**再写裸 `UNIQUE(业务列)`。
   - **B. 存量 ALTER**：`logic-delete-unique-fix.sql` 补全**尚未覆盖**的表（幂等说明见 §015）。
3. **默认值**：`sort_order` 模板默认 `9999`；字典等主题若业务定案为 `0`，**保持该主题 CREATE 已有默认**，不要为对齐模板而改业务默认。
4. **不做**：不物理删墓碑；不改业务列；不写 Java 双写；不碰无业务唯一键的表。

## 015.执行要点

1. **CREATE**：每个业务唯一键旁增加 `GENERATED ALWAYS AS (...) STORED` 列 + `UNIQUE KEY ... (alive_*)`；删掉裸业务列 UNIQUE。
2. **ALTER 脚本**：仅追加缺失段；头部注释更新「覆盖表清单」；对已跑过环境，缺失段应可单独执行。若某环境已手工改过，脚本需注明「列/索引已存在则跳过」——**优先**用清晰分段 + 人工判断，勿写破坏性 DROP 业务列。
3. **列宽**：单列 `alive_*` 与源业务列同宽；复合 `alive_key` 取够 `CONCAT_WS` 最大合理长度（现有脚本 200/300）。
4. **注释**：中文 COMMENT 与现网风格一致。
5. **文档同步（最小）**：
   - `base-entity-columns.sql` 底部注明「全表 CREATE 须原生 alive_*；存量见 fix 脚本；020 任务收口」；
   - 若红线有「已全量」字样，改为「以 020 验收为准」。
