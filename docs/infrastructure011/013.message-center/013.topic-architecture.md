## 011.领域与技术形态（**出入两套**：SPI + 注册表 + 表驱动）

**出站（outbound）与入站（inbound）各自独立、对称**——渠道/模板/记录各两套，东向（发）与西向（收）不共用实体。

```
domain.messagecenter
  outbound.channel
    MessageChannelPort   channelCode() ；send(MessageCommand) → MessageResult   ★ 出站 SPI
    MessageCommand       record（channelCode / to / messageType / config / payload / templateCode / params / title / content）
    MessageResult        record（success / channelMessageId / error）
    JulyOutboundChannel  渠道配置聚合（+ QuerySpec / Repository）
  outbound.template
    JulyOutboundTemplate 模板聚合（+ QuerySpec / Repository）
  outbound.message
    JulyOutboundMessage  发送记录聚合（+ QuerySpec / Repository；status = MessageStatus011 1/2/3）
  inbound.channel
    MessageInboundPort   channelCode() ；parse(config, rawBody) → InboundMessage ；encodeReply(InboundReply) → String  ★ 入站 SPI
    InboundMessageListener  supports(channelCode) ；onMessage(InboundMessage) → InboundReply（null=不回）  ★ 业务桥接 SPI
    InboundMessage        record（channelCode / providerType / fromId / messageType / payload / content / rawMessageId / remark）
    InboundReply          record（messageType / payload / content）
    JulyInboundChannel    入站渠道配置聚合（+ QuerySpec / Repository）
  inbound.template
    JulyInboundTemplate   入站模板聚合（+ QuerySpec / Repository）
  inbound.message
    JulyInboundMessage    接收记录聚合（+ QuerySpec / Repository；status = MessageInboundStatus011 1/2/3）

application.messagecenter
  outbound.channel : MessageChannelRegistry(List<MessageChannelPort>) · JulyOutboundChannelUseCase
  outbound.message : MessageOutboundUseCase（解析渠道 → 渲染模板 → 发送 → 落记录）
  outbound.template: JulyOutboundTemplateUseCase
  inbound.channel  : MessageInboundRegistry(List<MessageInboundPort> + List<InboundMessageListener>) · JulyInboundChannelUseCase
  inbound.message  : MessageInboundUseCase（解析 → 去重 → 落库 → 分发监听 → 被动回复）
  inbound.template : JulyInboundTemplateUseCase

infrastructure.messagecenter
  outbound.{entity,mapper,repository} : JulyOutbound{Channel,Template,Message}Po/…
  outbound.channel : InAppMessageChannel · WebhookMessageChannel（内置出站渠道）
  inbound.{entity,mapper,repository}  : JulyInbound{Channel,Template,Message}Po/…
  （厂商渠道/接收适配：使用者实现 MessageChannelPort / MessageInboundPort 并 @Component 即注册）
```

## 015.报文形态：`messageType` + `payload`（**通用透传位，非厂商标准**）

框架**不认识任何厂商形态**。发送契约只开两个中性字段，原样透传给渠道端口（`MessageCommand`）：

- **`messageType`**（开放字符串）：**渠道自定义**的报文形态名，框架**不校验、不解释**；
- **`payload`**（键值 map，落库为 JSON）：形态专属参数，键由渠道自定。

| 维度 | 谁定义 | 示例（**渠道自定，非框架约定**） |
|------|--------|----------------------------------|
| `messageType` | 渠道插件 | `text` / `image` / `file` / `audio` / `card` …（各厂商叫法不同） |
| `payload` | 渠道插件 | `image_key` / `file_key` / `url` / `btntxt` … |
| `config` | 渠道实例（表） | `url` / `corpId` / `appKey` … |

> **否定清单**：厂商专属形态名、素材上传（换 `media_key`/`image_key`）、消息接收（回调/**长连接 WebSocket**）、回复/撤回/加急/Pin —— **都不是框架能力**，归渠道插件/使用者（见 [011 设计思路](011.topic-design.md) §017）。

## 016.端点（前缀 `/klsjnh/messagecenter`）

**出站（outbound）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `julyOutboundMessage/v1/send` | POST | `{channelCode, to, messageType?, payload?, templateCode?, params?, title?, content?}` |
| `julyOutboundMessage/v1/selectListByPage` | POST | 发送记录分页（含 status） |
| `julyOutboundMessage/v1/resend` | POST | 失败重发（沿用记录的 messageType/payload） |
| `julyOutboundMessage/v1/logicDelete` / `logicDeleteBatch` | POST | 删除记录 |
| `julyOutboundChannel/v1/*` | — | 出站渠道配置 CRUD |
| `julyOutboundTemplate/v1/*` | — | 出站模板 CRUD |

**入站（inbound）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `julyInboundMessage/v1/receive?channelCode=xxx` | POST | **统一回调入口**（query 传 channelCode；body 为渠道原始报文）；解析→去重→落库→分发监听→被动回复 |
| `julyInboundMessage/v1/selectListByPage` / `logicDelete` / `logicDeleteBatch` | POST | 接收记录管理 |
| `julyInboundChannel/v1/*` | — | 入站渠道配置 CRUD |
| `julyInboundTemplate/v1/*` | — | 入站模板 CRUD |

> 长连（WebSocket）**无独立端点**：由渠道插件自持连接，把事件交给 `MessageInboundPort.parse(...)`。

## 017.扩展与运行

- **出站扩展**：实现 `MessageChannelPort` + `@Component` + 插一行 `july_message_outbound_channel`；**无需改框架**。
- **入站扩展**：实现 `MessageInboundPort`（解析渠道报文/长连事件）+ `InboundMessageListener`（业务桥接，可返回被动回复）+ 插一行 `july_message_inbound_channel`；**无需改框架**。
- **入站流程**（`MessageInboundUseCase.receive`）：解析 → **去重**（`uk(channel_code,raw_message_id)`）→ 落库（`status=1 已接收`）→ 遍历监听器分发（异常隔离，返回首个非空 `InboundReply`）→ `MessageInboundPort.encodeReply` 写回 HTTP 响应（同步被动回复）；异步回复由监听器自行调**出站 send**。
- **异步/重试**：出站先同步发送 + 记录；`retry_count` 接 [022 julyScheduler](../../requirement011/022.topic-july-scheduler.md) 做定时重试。
- **模板**：轻量 `${var}` 替换，不引模板引擎。
- **密钥**：`config` JSON 中密钥出参打码；加密二期（与存储/AI 密钥同口径）。
- **HTTP**：渠道的 HTTP 调用统一走 `com.klsjnh.common.util.HttpUtil011`（JDK HttpClient 薄封装，`get`/`postJson`，返回 `HttpResponse011(status, body)`）。

## 018.状态（**出入两套 · 已实现** · 2026-09-19）

- **域命名** `messagecenter`，**分 `outbound` / `inbound` 两套**，渠道/模板/记录各两张表（6 张，见 §013）；旧 3 表已删。
- **包结构**（按能力分包）：
  - `domain.messagecenter.outbound.{channel,template,message}`：`MessageChannelPort`(SPI) + `MessageCommand`/`MessageResult` + `JulyOutbound*` + 仓储端口；
  - `domain.messagecenter.inbound.{channel,template,message}`：`MessageInboundPort`/`InboundMessageListener`(SPI) + `InboundMessage`/`InboundReply` + `JulyInbound*` + 仓储端口；
  - `application.messagecenter.{outbound,inbound.*}`：`MessageChannelRegistry` + `MessageOutboundUseCase`；`MessageInboundRegistry` + `MessageInboundUseCase` + 各 CRUD；
  - `infrastructure.messagecenter.{outbound,inbound}.{entity,mapper,repository,channel}`：各三 PO/Mapper/RepositoryImpl + 内置出站渠道 `InAppMessageChannel`/`WebhookMessageChannel`；
  - `web.messagecenter.*`：出站控制器 + 入站控制器（含 `receive` 回调入口）。
- **内置渠道**：出站 `inapp`（落库即收件箱）、`webhook`（HTTP POST JSON 到 `config.url`，走 `HttpUtil011`）。入站**无内置**（全属厂商）。
- **常量**：`MessageProviderTypes011`（出站内置 code）、`MessageStatus011`（出站状态 1/2/3）、`MessageInboundStatus011`（入站状态 1/2/3）；审计对象码 `AuditObjectCodes011.JULY_MESSAGE_OUTBOUND*` / `JULY_MESSAGE_INBOUND*`。
