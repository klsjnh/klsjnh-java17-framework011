# 016 — 数据源中心 · 数据类型与对照契约

> 定位：**契约文档** —— 同步（[013 §016 能力三](013.topic-architecture.md)）所依赖的"**类型 + 对照**"的唯一定义。
> 归属：**框架定义，产品消费**（低代码按本契约实现/映射，不再自持一套）。
> 三篇一套：[011 设计思路](011.topic-design.md) · [013 系统整体架构](013.topic-architecture.md) · [015 怎么使用](015.topic-usage.md)。

## 011.为什么需要这份契约

- 同步 = `source 读 → 对照 → sink 写`；**对照要类型**（源列类型 → 目标列类型）；
- 类型/对照此前长在低代码（`FieldType011` / `DialectRegistry011` / 字段对照器）；
- 但**同步是框架能力**，框架**不能反向依赖产品** → 类型与对照必须**上收框架**；
- 且它**通用**（中性类型 + 各库类型方言 + 列对照，无业务语义），多产品共用。

> 一句话：**类型 + 类型方言 + 对照 = 框架能力；契约由框架定义、低代码消费。**

## 013.中性类型词表 `FieldTypeCodes011`（框架 common）

开放字符串常量（**非枚举**，同 `DatabaseTypes011` 口径）——各库 JDBC 类型、各产品的字段类型都**映射到它**：

| code | 说明 |
|------|------|
| `string` | 变长字符串 |
| `int` | 32 位整数 |
| `long` | 64 位整数 |
| `float` / `double` | 浮点 |
| `decimal` | 定点（金额等） |
| `date` | 日期 |
| `datetime` | 日期时间 |
| `boolean` | 布尔 |
| `text` | 长文本 |
| `binary` | 二进制 |
| `json` | JSON |

> 低代码 `FieldType011` **收敛**到本词表（映射或退役）。

## 015.列元数据 `ColumnMeta`

```
ColumnMeta { name, type(FieldTypeCodes011), length, precision, scale, nullable }
```

用于：读源表列、生成目标列型、值转换。

## 016.类型方言 SPI `TypeDialectPort011`（框架）

按 `dbType` 路由（同 `SqlDialectPort011` 的注册表模式），与**读分页方言**并列：

| 方法 | 说明 |
|------|------|
| `jdbcToNeutral(jdbcType, ...) → FieldTypeCodes011` | 源库列型 → 中性类型 |
| `columnDdl(ColumnMeta) → String` | 中性类型 → 目标库列型（建表/加列） |
| `coerce(value, FieldTypeCodes011) → Object` | 值转换（写入前） |

内置：mysql / postgresql / oracle / sqlserver。低代码 `DialectRegistry011` 的目标侧方言**并入**此处。

## 017.对照：主子表（不是扁平数组）

源可能是 **SQL / 表 / 内部对象**，目标有自己的列型——扁平 `ColumnMapping[]` 装不下，故用**主子表**。

### 017.1 主表 `july_sync_rule`（从哪到哪、怎么同步）

| 列 | 说明 |
|----|------|
| `sync_code` | 同步编码（不可变） |
| `sync_name` | 名称 |
| `source_ds_code` | 源头数据源（内部对象表 = 主库） |
| `source_kind` | `sql` / `table` / `object` |
| `source_data` | SQL 文本 / 表名 / 对象名 |
| `target_ds_code` | 目标数据源 |
| `target_kind` | `table` / `object` |
| `target_data` | 表名 / 对象名 |
| `mode` | `full` / `incr` |
| `sync_key` | **业务键（判重键）**：目标侧列名 CSV，单列或复合；upsert 用它判存在 |
| `conflict` | `upsert` / `append` |
| `options` | **JSON 扩展位（预留）**：S2/S3 的 `group` / `parentSyncCode` / `fk*` / `rowTransform` 先塞这里 |
| `page_size` / `sort_order` / `status` / 审计 / `dr` | |

### 017.2 子表 `july_sync_rule_column`（哪列对哪列、什么类型）

| 列 | 说明 |
|----|------|
| `pk_mt` | 主表链接 |
| `source_column` | 原表列 |
| `source_type` | 原表列类型（`FieldTypeCodes011`） |
| `target_column` | 目标列 |
| `target_type` | 目标列类型（`FieldTypeCodes011`） |
| `transform` | 可选（trim / 日期格式 / 表达式） |
| `sort_order` / `status` / `dr` | |

> **业务键那行也要在子表里列**：`source_column` = 源业务字段 → `target_column` = 目标业务字段（且 `target_column ∈ sync_key`）。

### 017.3 业务键与 upsert（判重口径）

- **业务键** = 主表 `sync_key`（**目标侧**列名）；目标对象表若来自低代码，应对齐其 `businessField`（业务唯一键，如 `sid`）；
- **upsert**：按 `sync_key` 在目标查 →
  - **存在** → `UPDATE`（其余列按子表对照覆盖）；
  - **不存在** → `INSERT`；
- `conflict=append` 时不做判重，直接追加；
- **复合键**：`sync_key` 多列（CSV），目标侧建**对应唯一索引**保证幂等。

### 017.4 Endpoint 同构

`source` 与 `target` 用**同一套** `Endpoint`：

```
Endpoint { dsCode, kind(sql/table/object), data, readOnly }
```

- 内部对象表：`dsCode` = 主库 + `kind=object` + `data=对象名`；
- 外库 SQL：`kind=sql` + `data=SQL 文本`；
- 外库表：`kind=table` + `data=表名`。

## 018.分步与口子（复杂形态）

**S1 只做单表同步**；一主一子 / 一对多 / 多源为 S2/S3，**先不实现、但留口子**。

| 步 | 内容 | 表增量 |
|----|------|--------|
| **S1** | 单表：外库 SQL / 表 → 本地表 | ✅ **已实现**（主 `july_sync_rule` + 子 `july_sync_rule_column` + 引擎 + CRUD/run） |
| **S2** | **一主一子**：同步组 + 父子 + 外键回填 | 先写进 `options`（`group`/`parentSyncCode`/`fkTargetColumn`/`fkSourceColumn`）；稳定后提升独立列 |
| **S3** | **一对多 / 多源**：rule 级 `rowTransform` / 合并键 | 先写进 `options`（`rowTransform` / 多源）；稳定后提升列 |

**口子口径**：

- **一个 JSON 扩展列 `options`**（预留）——本仓惯用（storage/message 的 `config`、datasource 的 `poolConfig` 列预留）；
- **命名留语义空间**：`sync_rule`（非 `sync_table`），为"组 / 多规则"留名；
- **端口可扩展**：`Endpoint.kind` 已含 `sql / table / object`。

> 提升列 = 一次增量 `ALTER`（本仓已有 `logic-delete-unique-fix.sql` 先例），成本低；故**不预埋具体空列**，只留 `options`。

## 019.本期范围

**外库 → 本地库**：`source` = 外库 SQL / 表（或内部对象），`target` = 本地对象表；子表把源列（含类型）对到目标列（含类型）。

## 021.归属与收敛

| 东西 | 归属 |
|------|------|
| `FieldTypeCodes011` / `ColumnMeta` / `TypeDialectPort011` / `Endpoint` / 主子表结构 | **框架（数据源中心）** |
| 低代码 `FieldType011` | 低代码，**映射**到中性词表 |
| 低代码 `DialectRegistry011`（目标侧） | **并入** `TypeDialectPort011` |
| 业务建模的字段定义（某模型有哪些字段） | 低代码（业务） |

## 023.边界（本期不做）

- **不做** CDC / 实时（批量分页）；
- **不做** 调度（接 [022 julyScheduler](../../requirement011/022.topic-july-scheduler.md)）；
- **不做** 多方向 / 一对多（结构留口子，见 [013 §016](013.topic-architecture.md)）；
- **不做** 反向对照（导出/回放回源）——留待。
