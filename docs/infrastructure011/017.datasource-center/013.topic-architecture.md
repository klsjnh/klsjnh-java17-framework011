## 013.能力一：多数据源管理（已实现）

> 详见 [017 动态数据源](../017.topic-datasource.md)；本节只给架构定位。

- **表驱动**：`july_datasource` 为运行时唯一真源；`krt.ci011` 降级为**引导**（同一 `dsCode` 只允许一个家）；
- **动态多实例**：`DynamicDataSource011`（`AbstractRoutingDataSource` + ThreadLocal 路由键 + 注册表），Druid 池**懒加载**（首次调用才建池）；
- **注册表**：`DynamicDataSourceRegistryPort.reloadAll(...)` → `ReloadResult`（配置未变则保留旧池）；
- **方言 SPI**：`SqlDialectPort011`（`dbType()` + `pageSql(sql, offset, pageSize)`）+ 注册表 `SqlDialect011`，内置 mysql / postgresql / oracle / sqlserver；新增库 = 加一个方言 bean；
- **探测**：`DataSourceProbePort` / `DataSourceProbe011`（临时池，不回灌注册表）；
- **播种**：`DatasourceSeedPort` / `DatasourceSeed011` / `DatasourceSeedRunner`（`existsIncludingDeleted` 判重，存在即跳）。

## 015.能力二：多数据源读写（分页）——设计

### 015.1 端口（参数化）

```
SqlRoutingPort（domain.datasource.kernel）
  selectListByPage(dsCode, sql, params, pageIndex, pageSize) → PageResult011<Map<String,Object>>   ★ 新增（参数化）
  selectList(dsCode, sql, params) · selectOne(dsCode, sql, params)                                  ★ 新增（参数化）
  execute(dsCode, sql, params)                                                                      ★ 写（不对外）
  （既有裸 SQL 变体保留，仅供内部：探针 / 管理面看数）
```

- **参数绑定**：`PreparedStatement` 真绑定（不是拼接）；这是"内核 → 对外"的前置；
- **分页**：`SqlDialectPort011.pageSql(...)` 生成方言分页 SQL + `COUNT(*)`；
- **clamp**：`pageSize ∈ [10, 500]`。

### 015.2 只读校验（归口框架）

`READ` 操作类硬校验（`probe` / `selectByPage` 共用）：必须以 `SELECT` 开头、禁 `;`、禁 DDL/DML 关键字。

## 016.能力三：同步体系——S1 已实现

> **类型与对照契约**（同步的依赖，先读）：[016 数据类型与对照契约](016.topic-type-contract.md)。

**已实现（S1 单表）**：`july_sync_rule` + `july_sync_rule_column` + `SyncEnginePort`/`SyncSourcePort`/`SyncSinkPort`（`SyncEngine011`/`SyncSource011`/`SyncSink011`）+ 规则 CRUD / `run` 端点；外库 SQL/表 → 本地表，按 `syncKey` upsert（E2E：read/written 一致、幂等、更新回写）。

```
sync.Endpoint        源/目标同构：{ dsCode, kind(sql/table/object), data }
sync.JulySyncRule    主表聚合：{ source, target, mode, syncKey, conflict, pageSize, options }
sync.JulySyncRuleColumn  子表聚合：{ sourceColumn, sourceType, targetColumn, targetType, transform }
sync.SyncSourcePort  readPage(Endpoint, pageSize, pageIndex) → rows
sync.SyncSinkPort    writePage(Endpoint, table, keyColumns, upsert, rows) → written
sync.SyncEnginePort  run(JulySyncRule) → SyncRunResult
```

- **方向无关**：`source` / `target` 只是端点，外部库与本地对象表同构；
- **对照 = 主子表**：主 `july_sync_rule` + 子 `july_sync_rule_column`（列 + 类型，见契约 [§017](016.topic-type-contract.md)）；
- **分步**：S1 单表 → S2 一主一子 → S3 一对多 / 多源（口子见契约 [§018](016.topic-type-contract.md)）；
- **复用方言**：分页读走 `SqlDialectPort011`；写入 / 列型走 `TypeDialectPort011`；
- **幂等**：按 `syncKey` upsert。

## 019.关系与联动

- **与主库隔离（铁律）**：主数据源（MyBatis-Plus，承载 `july_*` 表）不感知动态数据源；动态库只能经 `SqlRoutingPort` 按 `dsCode` 访问；
- **与产品**：低代码 `importDataFromSql` / `executeSqlByPage` 是"同步 / 查询"的第一种特化，改为复用本中心；
- **与调度**：同步/重试接 [022 julyScheduler](../../requirement011/022.topic-july-scheduler.md)。
