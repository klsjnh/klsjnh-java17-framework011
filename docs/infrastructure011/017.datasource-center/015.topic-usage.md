## 013.执行 SQL 分页查询（设计 · 只读）

**端口（框架内部 / AI 开发可直接注入）**：

```java
// 参数化，PreparedStatement 真绑定
PageResult011<Map<String, Object>> page =
    sqlRoutingPort.selectListByPage("business011", "select * from t_order where status = ?", List.of("1"),
            pageIndex, pageSize);
```

**HTTP（只读已实现）**：

```
POST /klsjnh/datasource/julySql/v1/selectByPage
{ "dsCode": "business011", "sql": "select * from t_order where status = ?", "params": ["1"],
  "pageIndex": 1, "pageSize": 20 }
→ { "pageIndex": 1, "pageSize": 20, "total": 137, "totalPages": 7, "rows": [ ... ] }
```

- **只读**：SQL 必须以 `SELECT` 开头、禁 `;`、禁 DDL/DML；
- **clamp**：`pageSize` 越界夹到 `[10, 500]`；
- **方言**：按 `dbType` 自动生成分页 SQL（mysql / postgresql / oracle / sqlserver）。

> **未来**：非 SELECT（DML/DDL）走**独立端点** `…/julySql/v1/execute`，**独立权限**（分接口放权）。

## 015.配置一次同步（设计 · 任意方向）

**概念**：`source` 与 `target` 只是两个端点，规则可配——外→内 / 内→外 / 内→内 / 一对多 都成立。**对照是主子表**（[契约 §017](016.topic-type-contract.md)）：

```
SyncRule（主 july_sync_rule） {
  source:  Endpoint { dsCode, kind(sql/table/object), data, readOnly }
  target:  Endpoint { dsCode, kind(table/object), data }
  mode:    full | incr
  syncKey: [ "biz_id" ]            // 幂等 upsert 的业务键
  conflict: upsert | append
  pageSize: 500
}
SyncRuleColumn（子 july_sync_rule_column） {
  sourceColumn, sourceType, targetColumn, targetType, transform?
}
```

**执行链**：`source 分页读 → 按子表对照 + 类型转换 → target 按 syncKey 幂等写`（`SyncEngine`，可续传）。

> **本期边界**：不做调度 / CDC / 实时；调度接 [022 julyScheduler](../../requirement011/022.topic-july-scheduler.md)。

## 016.低代码如何复用

- `executeSqlByPage`（业务建模/数据同步）= 本中心"只读分页查询"的第一种特化 → **改为复用**框架能力（去掉重复的校验/分页）；
- `importDataFromSql` = 同步"外→内"的第一种特化 → 未来复用 `SyncEngine`；
- 低代码不再自带 SQL 执行/同步的底层实现。

## 017.限制与注意事项

- **参数化必用**：对外只提供 `sql + params`，禁裸 SQL 拼接（防注入）；
- **只读先行**：非 SELECT 未开放；开放时走独立端点 + 独立权限；
- **主库隔离**：动态库经 `SqlRoutingPort` 按 `dsCode` 访问，主库（`july_*`）不感知；
- **大结果集**：`COUNT(*)` 包子查询，超大表由调用方优化（加索引 / 收窄条件）；
- **超时/行数**：端点侧设超时与行数上限（设计）。
