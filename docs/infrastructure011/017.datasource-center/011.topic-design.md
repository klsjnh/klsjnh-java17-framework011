## 011.命题

**数据源中心 = 数据源 + 读写 + 同步。**

统一**管理**多个数据源，在其上**读写（分页）**，并在**任意两个数据源之间**做数据**同步**——三者是同一件事的三个层次。

> 此前：能力一在框架（`datasource` 域）；能力二被划到产品侧；能力三只在低代码有提案。本中心把三者收拢。
> **命名**：叫「数据源中心」而非「数据中心」——后者在中文里=机房/IDC、技术语境=数仓/数据湖，名不副实。

## 015.设计思路

### 015.1 为何上收框架

- **横切机制，非业务**：连接/池/方言/分页/校验/同步编排，任何接入方都要用；
- **低代码只是使用者**：`importDataFromSql` / `executeSqlByPage` 是"同步/查询"的第一种特化，不该私有化在产品；
- **框架定位 = 供第三方依赖**：通用数据访问留在产品，等于每个产品重复实现校验/分页/安全。

### 015.2 读写：只读先行，未来分接口放权

- **现在**：只放**只读**（`SELECT` 开头、禁 `;`、禁 DDL/DML）；
- **未来**：一定会执行非 SELECT（DML/DDL）→ **分接口 + 分权限**（见 [013 §015](013.topic-architecture.md)）；
- **端口**：`SqlRoutingPort` 加**参数化重载**（`sql + params`，PreparedStatement 真绑定）；裸 SQL 变体仅供内部（探针/管理面）。

### 015.3 同步：方向无关

**同步是一个抽象能力，不是一个方向。** `source` 与 `sink` 只是两个端点 + 可动态配置的规则：

- **不分内外、不分方向**：外部库与本地对象表都是 `EndpointSpec`；
- **复用方言**：分页读走 `SqlDialectPort011` 族；写入未来走 `WriterDialect`（Oracle/SQLServer `MERGE`）；
- **映射**：`mapping[]` = `sourceColumn → targetColumn`，归同步规则。

### 015.4 边界（不做 / 否定清单）

- 读写：**不做**裸 SQL 无参数的对外暴露；**不做**跨库分布式事务；
- 同步：**不做**调度（复用 [022](../../requirement011/022.topic-july-scheduler.md)）、**不做** CDC/实时（本期批量分页）；
- 管理：**不做**读写分离 / 负载均衡 / 多租户路由。
