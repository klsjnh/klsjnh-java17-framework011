## 011.命题

**一套端口，多厂商适配。** 框架只提供 `ObjectStoragePort` 统一契约 + **工厂型 provider 注册表** + 表驱动多实例；本地盘与 S3 兼容系（MinIO / 云厂商）由适配器承载，**厂商可插拔、不改底座**。

> 业务侧只管"存哪个对象、放哪个桶"；**怎么存**交给厂商适配器（与"消息渠道可插拔"同思路，但形态不同——见 §017）。

## 013.核心诉求（用户定）

- 兼容 **local + MinIO + 腾讯 COS + 火山 TOS + 各主流厂商 S3/OSS**；
- 同一套业务代码，**换厂商不改调用方**；
- 新厂商**用到即落**，由使用者实现 SPI 扩展，**不动框架**。

## 015.架构形态：工厂型 + provider 注册表

存储形态 = **工厂型**：`provider` 是**开放字符串**（`StorageProviderCodes011` 常量，**不是枚举**）；使用者实现 `ObjectStorageProviderFactory` bean 即插即用。

- **端口** `ObjectStoragePort`：对象 + 桶 + 探活 + 预签名，第一天定死；
- **工厂端口** `ObjectStorageFactoryPort`：连接配置 → 适配器；注册表实现它；
- **SPI** `ObjectStorageProviderFactory`：`providers()` 返回厂商 code（开放字符串）+ `create(config)`；
- **注册表** `ObjectStorageProviderRegistry`：注入 `List<ObjectStorageProviderFactory>`，按 code 查厂造适配器；**未知 code 大声失败**；
- **解析器** `StorageResolverPort` / `StorageResolver011`：把 `storageCode` 解析成有状态适配器并缓存。

## 016.多厂商策略

**每个厂商 = 一个 `ObjectStorageProviderFactory`（+ 其适配器）**。命名：SPI 用 **ProviderFactory**（供给者语义），端口实现用 **Adapter**（六边形惯例）。

| provider code | 工厂 / 适配器 | 后端 | SDK | 节奏 |
|---------------|---------------|------|-----|------|
| `local011` | LocalStorageProviderFactory / LocalObjectStorageAdapter | 本地盘 | `java.nio.file` | ✅ 内置 |
| `minio011`、`s3011` | MinioStorageProviderFactory / MinioObjectStorageAdapter | 自部署 MinIO / S3 兼容 | MinIO SDK | ✅ 内置 |
| `cos011` | 使用者实现 | 腾讯云 | cos_java_sdk | 用到即落（**不动底座**） |
| `tos011` | 使用者实现 | 火山 TOS | tos-java-sdk | 同上 |
| `oss011` | 使用者实现 | 阿里 OSS | oss-java-sdk | 同上 |

端口与 SPI 第一天定死；provider code 用**开放字符串**、按需生长，**不用封闭枚举**。

## 017.工厂型 vs 实现型（判据）

**判据 = 是否需要「同技术多实例 + 每实例一份连接配置」**：

| | 工厂型（存储中心 / 数据源） | 实现型（消息中心） |
|---|---|---|
| 扩展方式 | 框架按 `provider` 查工厂 `create(config)` **造适配器** | 使用者实现 SPI 端口 + `@Component`，**注册表自动收集** |
| 适用 | 技术种类少、**每实例一套连接配置**（多实例） | 厂商多且长尾、**每渠道一份配置、实例单一** |
| 发现 | `ObjectStorageProviderRegistry(List<ObjectStorageProviderFactory>)` | `MessageChannelRegistry(List<MessageChannelPort>)` |

> 存储/数据源走工厂型；消息渠道走实现型。**本判据是跨专题口径**，新增能力先按它定形态。

## 018.决策点（2026-09-13 讨论定案）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 架构形态 | ✅ **每厂商一个 Adapter**（不做单 S3 通吃）：MinIO011 专门服务自部署；原生 SDK 保留厂商能力；命名 Adapter 非 Provider |
| 2 | 类型值口径 | ✅ **011 后缀 + 开放字符串**（`StorageProviderCodes011` 常量）；~~StorageType011 枚举~~ 已删除（2026-09-19） |
| 3 | 落地节奏 | ✅ 本期落 local011 + minio011（Docker MinIO 实测）；厂商适配器用到即落，端口不动 |
| 4 | bucket 不存在 | ✅ **自建**（default-bucket），不报错 |
| 5 | 配置模型 | ✅ **表驱动多实例 + yaml 播种**；表为运行时唯一真源 |
| 6 | 端口形态 | ✅ 维持 `byte[]` 为主；**已补流式** `getStream` / `putStream`（2026-09-20） |
| 7 | 在线编辑 | ✅ sql / markdown 两种 + ≤1MB |
| 8 | 预签名 | ✅ 本期做（local→`file:` URI；S3/minio→真实预签名） |

## 019.分期

| 期 | 内容 |
|----|------|
| P0（2026-09-13） | 端口 + 双适配器 local/minio + 桶 CRUD + stat + get/delete 语义对齐 |
| P1（2026-09-17） | 表驱动多实例 + 实例/桶/对象管理面 + 在线编辑 + 预签名 + 启动播种 |
| P2 | ✅ **已实现（2026-09-20）**：流式上传下载（`getStream` / `putStream`，不整对象进堆）· **端口 `listPage` 原生分页 + delimiter 目录 + marker 续传** · **copy / rename（move）** |

## 020.边界外（不做 · 否定清单）

- 预签名 URL **直传前端**（本期只出 GET URL）、分片上传 / 断点续传 / 秒传；
- 桶生命周期 / 配额 / 策略 / 跨域；
- 多 provider 并存路由（老 java8 providers map 形态）；
- 在线编辑的多用户协同 / 版本历史。

> **`byte[]` 的代价**：整个对象进堆，大文件有 OOM 风险——流式 `InputStream` 形态列 P2，管理面下载本期先限大小。
