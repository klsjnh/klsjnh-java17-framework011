# 015 — 存储中心 · 怎么使用

> 面向使用者的操作手册：配置、建实例、调管理面 API、扩展新厂商。

> 业务侧如何持久化文件定位（instance/bucket/objectKey 等）：[016 对象元数据记录规约](016.topic-object-metadata-convention.md)（**规约，非平台能力**）。
> 详细设计（对接代码）：[requirement013/029](../../requirement013/029.topic-storage-migration.md)。

## 011.快速开始（内置 local011 / minio011）

内置两种 provider，**开箱即用**。在 `application.yml` 配好即可：

```yaml
krt:
  storage-center:
    default-type: local011
    local011:
      base-path: ./storage011
      default-bucket: backup011
    # 或切自部署 MinIO：
    # default-type: minio011
    # minio011:
    #   endpoint: http://192.168.1.88:11230
    #   access-key: <ak>
    #   secret-key: <sk>
    #   default-bucket: demo011
```

**首次启动会发生什么**：`StorageSeed011` 把上面的配置写成一条 `storageCode=default` 的实例 + 默认桶子行；**存在即跳、不覆盖**。此后改配置不再影响运行时——**表是唯一真源**，要改就调管理面。

- 对象 `put` 时空白 bucket 自动落到默认桶；
- 业务侧注入 `ObjectStoragePort`（或经 `StorageResolverPort.resolve(code)`）即可读写，不用管下面用的是什么盘；
- **业务表只记定位信息**（`storageCode` / `bucket` / `objectKey` 等），不向存储中心要全站 `july_files`——见 [016](016.topic-object-metadata-convention.md)。

## 013.新增一个存储实例

两种方式，二选一：

**方式一：管理面 API（推荐）**

```
POST /klsjnh/storagecenter/julyStorage/v1/insert
{
  "storageCode": "backup-local",
  "storageName": "备份-本地盘",
  "provider": "local011",
  "basePath": "/klsjnh/volume/storage011",
  "presignExpirySeconds": 3600,
  "sortOrder": 10,
  "status": "1"
}
```

**方式二：直接插表** `july_storage_provider`（`provider` 填开放字符串 code）。

**字段要求**（domain 校验，违反即失败）：

| provider | 必填 |
|----------|------|
| `local011` | `basePath` |
| S3 系（`minio011` / `s3011` / 自定义） | `endpoint` + `accessKey` + `secretKey` |

- `storageCode` **全局唯一、不可变**（`update` 改不了它）；长度 ≤60；
- `accessKey` / `secretKey` 出参打码 `******`；`update` 时 **secretKey 留空 = 保持原值**；
- 建实例**不会**自动建桶，桶单独管（见下）。

**桶**：一个实例下可有多个桶，默认桶用 `is_default=1` 标记（同实例至多一个）。

```
POST /klsjnh/storagecenter/julyStorage/v1/insertBucket
{ "storageCode": "backup-local", "bucketCode": "backup011", "bucketName": "备份桶", "isDefault": true }
```

## 015.管理面 API（实例 / 桶 / 对象）

前缀 `…/julyStorage/v1`（实例 + 桶，`storageCode` 走参数/query）：

| 调用 | 说明 |
|------|------|
| `/insert` `/update` `/logicDelete` `/logicDeleteBatch` | 实例增改删 |
| `/getById?id=` `/getByCode?code=` | 点查（AK/SK 打码） |
| `/selectListByPage` | 分页（keyword / provider / status） |
| `/testConnection` | 探活（传 `id` 测已存实例，否则测草稿） |
| `/selectBucketList` `/selectBucketListByPage` `/getBucket?bucketCode=` | 桶查 |
| `/insertBucket` `/removeBucket` | 桶增删（删非空桶**大声失败**） |
| `/testBucketConnection` | 桶层探活 |

前缀 `…/julyObject/v1`（对象）：`selectObjectList` / `selectObjectListByPage` / `statObject` / `uploadObject`(multipart) / `downloadObject`(二进制流) / `presignObjectUrl` / `removeObject` / `batchRemoveObject` / `readObjectText` / `saveObjectText`。

> 多实例调用：以上对象端点都支持可选 `storageCode`（不传 = `default` 实例）。

**探活返回**（HTTP 恒 200，失败在载荷里）：

```json
{ "success": true, "bucketCount": 3, "basePath": "/klsjnh/volume/storage011", "message": "ok" }
```
> `local011` 回 `basePath`，S3 / MinIO 回 `endpoint`。

## 016.在线编辑

对象可当纯文本在线编辑（管理面/前端用）：

- `GET /readObjectText?storageCode=&bucket=&key=` → `{content, editorKind, contentType, size}`；
- `POST /saveObjectText` → 写回；
- 规则：**≤1MB**（`EditableTextPolicy.MAX_SIZE_BYTES`），UTF-8；`.sql`→`sql` 编辑器，其余→`markdown`；超限即 400。**不做**多用户协同 / 版本历史。

## 017.扩展一个新厂商（SPI 三步，不改框架）

以新增阿里 OSS（`oss011`）为例：

**1) 依赖框架构件**（框架已 `mvn install` 进本机 `.m2`）
```xml
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId><version>1.0.0</version><type>pom</type><scope>import</scope></dependency>
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-core011</artifactId></dependency>
<!-- 存储适配器按需：java17-storage-local011-starter / java17-storage-minio011-starter -->
```

**2) 实现 SPI + 适配器，`@Component` 注册**
```java
package com.yourcompany.storage;

import com.klsjnh.domain.storagecenter.object.*;
import org.springframework.stereotype.Component;
import java.util.List;

@Component
public class OssProviderFactory implements ObjectStorageProviderFactory {

    @Override
    public List<String> providers() {
        return List.of("oss011");                 // ← 路由键：与 july_storage_provider.provider 一致
    }

    @Override
    public ObjectStoragePort create(StorageConnectionConfig c) {
        return new OssObjectStorageAdapter(c);    // 你的适配器，实现 ObjectStoragePort
    }
}
```
> 关键：应用的 `@SpringBootApplication(scanBasePackages=…)` 必须**包含你的包**，否则 `@Component` 不被收集，SPI 挂不上。框架内置包 `com.klsjnh` 与你的包一起扫。

**3) 插一行实例配置**

```
POST /klsjnh/storagecenter/julyStorage/v1/insert
{ "storageCode": "oss-prod", "storageName": "OSS 生产", "provider": "oss011",
  "endpoint": "https://oss-cn-hangzhou.aliyuncs.com", "accessKey": "<ak>", "secretKey": "<sk>" }
```
或直接 `INSERT INTO july_storage_provider (…, provider, endpoint, access_key, secret_key, …) VALUES (…, 'oss011', …, '1');`

**路由链路**：`july_storage_provider.provider = "oss011"` → `OssProviderFactory.providers()` 命中 → `create(config)` 造 `OssObjectStorageAdapter`。**全程不改框架代码**。

> 适配器要实现 `ObjectStoragePort` 的全部方法（对象 / 桶 / `testConnection` / `presignedGetUrl`）。只需常用能力的，可参考内置 `MinioObjectStorageAdapter`。

## 018.默认桶与解析优先级

调用带 `storageCode` → 解析该实例；不带 → 落 `default` 实例。实例的默认桶按此优先级取：

1. `july_storage_provider_bucket.is_default=1`（该实例下）；
2. 配置 `krt.storage-center.<type>.default-bucket`；
3. 顶层 `krt.storage-center.default-bucket`。

对象 `put` 时 bucket 传空白 → 用上面的默认桶。

## 019.限制与注意事项

- **大文件**：`byte[]` 形态整个对象进堆有 OOM 风险；**已提供流式** `downloadObjectStream` / `putStream`（端口 `getStream` / `putStream`），大文件走流式；
- **停用实例**：`status=0` 的实例无法解析，调用即 400；
- **实例改动要清缓存**：改完实例配置需 `StorageResolverPort.evict(code)`（管理面 update 内部处理），否则旧适配器仍在缓存；
- **删桶**：只删**空桶**，非空桶大声失败（数据不会被静默孤儿化）；
- **删对象**：物理删除，不进存储中心业务表（没有逻辑删除）；调用域自管指针与生命周期，见 [016](016.topic-object-metadata-convention.md)；
- **密钥**：出参打码 `******`；日志不打印明文；加密二期（与消息/AI 密钥同口径）；
- **换厂商不改业务**：业务侧只依赖 `ObjectStoragePort`，换 provider 只动配置实例，不动调用方。
