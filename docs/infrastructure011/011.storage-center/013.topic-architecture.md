## 011.分层总览

```
web          JulyStorageProviderController（实例+桶）· JulyObjectController（对象）
              │
application  JulyStorageProviderUseCase · StorageBucketUseCase · StorageObjectUseCase（@Transactional）
              │
domain       ObjectStoragePort ◄── ObjectStorageFactoryPort
             ObjectStorageProviderFactory（SPI）· StorageResolverPort（code → 适配器）
             JulyStorageProvider / JulyStorageProviderBucket（聚合）· EditableTextPolicy
              ▲
infrastructure  ObjectStorageProviderRegistry（实现 ObjectStorageFactoryPort）
                StorageResolver011（解析 + 缓存）· StorageDefaults011
                Local/Minio StorageProviderFactory + ObjectStorageAdapter
                Po / Mapper / RepositoryImpl · StorageSeed011
```

依赖铁律不变：`web → application → domain ← infrastructure`；业务侧只依赖 domain 端口，不感知厂商。

## 015.表结构（july_storage_provider / july_storage_provider_bucket）

- **`july_storage_provider`（主）**：一行一个存储实例。`storage_code` 全局唯一且**不可变**；`provider` 开放字符串；`base_path`（local011）/ `endpoint`+`access_key`+`secret_key`+`secure`（S3 系）；`presign_expiry_seconds`；`sort_order`/`status`/审计/`dr`。
- **`july_storage_provider_bucket`（子）**：以 `pk_mt` 挂主表；`bucket_code` 同实例内唯一；`is_default` 标记默认桶（同实例至多一个，应用层保证）。
- 对象**不落业务表**（物理存在于存储后端）；实例与桶落业务表并**逻辑删除**。

> DDL 全文见 [docs/sql/july_storage_provider.sql](../../sql/july_storage_provider.sql)（本项目公共列口径：`id VARCHAR(33)` / `dr '0'/'1'` / 审计四列）。

## 016.配置体系（krt.storage-center）

```yaml
krt:
  storage-center:
    default-type: local011       # 本期：local011 | minio011（cos011 / tos011 / oss011 / s3011 预留）
    local011:
      base-path: ./storage011    # 本地对象根目录
      default-bucket: backup011  # 本地默认桶（物理位置 = base-path/default-bucket）
    minio011:                    # 自部署 MinIO011
      endpoint: http://192.168.1.88:11230
      access-key: <ak>
      secret-key: <sk>
      default-bucket: demo011
```

> **yaml 是播种来源，不是运行时真源**：启动由 `StorageSeed011` 写成 `default` 实例 + 默认桶子行；此后以 `july_storage_provider*` 表为准。

**默认桶优先级**：`july_storage_provider_bucket.is_default=1`（该实例）→ 配置 `krt.storage-center.<type>.default-bucket` → 顶层 `default-bucket`。

## 017.解析链路（表驱动多实例）

```
storageCode → StorageResolverPort.resolve(code)
  → 缓存命中即返回
  → JulyStorageProviderRepository.findEnabledByCode(code)   （缺失/停用 → IllegalStateException → 400）
  → JulyStorageProviderBucketRepository.findDefault(pkMt)    （取该实例默认桶）
  → JulyStorageProvider.toConnectionConfig(defaultBucket)
  → ObjectStorageFactoryPort.create(config) → 适配器
  → 入缓存（ConcurrentHashMap）
```

- 空白 `storageCode` → 落到 `default` 实例（即 yaml 播种那条）；
- 实例 `update` 后需 `evict(code)` 使缓存失效（否则改配置不生效）；
- 未知 provider code 在**构造时**报错（内置引导默认值用 `StorageProviderCodes011` 判断）。

## 018.适配器工厂（不是单例 bean）

- 适配器构造入参由 `StorageProperties` 改为 **`StorageConnectionConfig`**（与实例解耦，可多实例）；
- 由 `ObjectStorageProviderRegistry` 按 `config.provider` 查 provider 工厂**按需造** adapter；
- 适配器**不再是 `@ConditionalOnProperty` 单例 bean**，由工厂造 + `StorageResolver011` 缓存；
- `default-type` 只决定**播种实例**的 provider。

## 019.启动播种（yaml → 表）

`StorageSeed011`：把 `krt.storage-center.*` 写成 `default` 实例及其默认桶子行。

- **存在即跳，绝不覆盖**（`existsIncludingDeleted`，含逻辑删除行）；
- `default-type` 非内置（local011/minio011/s3011）→ 跳过并 `WARN`；
- 播种失败只 `WARN`，不阻断启动；
- 播种后**表为唯一运行时真源**（对齐数据源 026 的 seed 口径）。

## 020.在线编辑与密钥收口

- `EditableTextPolicy`（domain，纯 Java）：对象 ≤ **1MB**；`.sql`→`sql` 编辑器，其余→`markdown`；`contentType` 按扩展名（`text/plain` / `text/markdown`）；
- `readObjectText`：`stat` 校验 ≤1MB → `get` → UTF-8 解码；
- `saveObjectText`：`content` UTF-8 字节校验 ≤1MB → `put`；
- **密钥收口**：`accessKey` / `secretKey` 出参一律打码 `******`；`update` 留空保持原值；日志不打印明文。

## 022.关系与联动

- 适配器选择由 `provider` code ↔ `krt.storage-center.default-type`（引导默认）/ `july_storage_provider.provider`（运行时实例）绑定，经注册表查厂构造；
- **业务侧**（附件/导出/备份等）只依赖 domain 的 `ObjectStoragePort`，不感知具体厂商；
- 消费方注入 `ObjectStorageFactoryPort` / `StorageResolverPort` 端口（注册表实现），**换注册表实现对调用方零改动**；
- 数据导出/备份经 `StorageResolverPort` 取适配器（不再直连单例 bean）。
