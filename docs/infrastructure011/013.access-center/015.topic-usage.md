# 015 — 访问中心（原 IAM）· 怎么使用

> 面向底座与业务仓。架构见 [013](013.topic-architecture.md)，设计见 [011](011.topic-design.md)。
> **现称「访问中心」**；依赖 **`center-access011-starter`**。文档目录：`013.access-center`。
> **动态权限、双模式 PEP（开发 opt-in / 生产写白名单）、授撤、julyScheduler 启停蓝本 → 一律见 [016](016.topic-dynamic-permission.md)**。
> **DDL**：用户 [july_core011.sql](../../sql/july_core011.sql)；访问中心 [july_center_access011.sql](../../sql/july_center_access011.sql)。

## 依赖

```xml
<dependency>
  <groupId>com.klsjnh</groupId>
  <artifactId>center-access011-starter</artifactId>
</dependency>
```

- **不引**该 starter：classpath **无**组织/角色/菜单/权限目录/`assertHas` 管理面；**用户登录仍可用**；生产写操作白名单门闸**不生效**。
- **引入**后：行为与拆分前大致相当（含 `assignRoles`、权限目录种子、`AuthorizationAdapter`）。

## 管理面（身份与导航）

1. 组织树 → 用户挂靠（可选）。
2. 菜单（目录/页面/按钮）→ 按钮 `permissionCode` 与目录一致（导航显隐）。
3. 角色 → `assignMenus`；用户 → `assignRoles`；内置角色 = 全权限。
4. 登录拿 token（core）→ `getUserMenuTree`（access）看导航。

权限目录登记、按对象授撤、用例挂码、启停闭环、**生产前挂齐写入口**：**[016](016.topic-dynamic-permission.md)**。

## 后期：角色组（P4）

用户 ∈ 组 → 组含角色 → 有效码 = 直授 ∪ 组内；`assertHas` 调用点不变（语义仍见 [016](016.topic-dynamic-permission.md)）。
