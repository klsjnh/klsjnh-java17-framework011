# 016 — 访问中心（原 IAM）· 动态权限配置与使用

> **本文是动态权限 / 双模式 PEP / 授撤蓝本的唯一详篇。** 011 / 013 / 015 与其它专题只点一句并链到此处，不复述。
> 归属：[访问中心](011.topic-design.md)（原 IAM；starter = **`center-access011-starter`**）。
> 状态：**已实现并 E2E（2026-09-24）**；**双模式 PEP（2026-09-26）**；**门闸随 access starter（2026-09-26）**；**开发 assertHas no-op + 管理面挂齐（2026-09-26）**。

## 一句话

**目录可配、角色可授撤；管理面尽量全挂 `assertHas`；真正拦不拦只看 `krt.status`。** 开发/测试 = **调用也不拦**（no-op）；生产 = **真校验 + 写白名单**（未核对 → 403）。**仅当引入 `center-access011-starter` 时白名单门闸生效**；仅有用户、无 access 时不要求 `assertHas`。

## 权限控制双模式（按运行状态）

| 环境 | `krt.status`（`FrameworkStatus011`） | `assertHas` / `has` | 写白名单门闸 |
|------|--------------------------------------|---------------------|--------------|
| **生产** | 必须是 **production**（与 Spring `production` profile **绑定**） | **真校验**（无码 → 403） | **开**（access starter 在场）：写请求结束前必须打过标，否则 **403** |
| **开发 / 测试** | `debug` / `development` | **no-op / 直接放行**（不查库；方便联调） | **关**（不因「未核对」403） |
| **无 access starter** | 任意 | `PermissiveAuthorizationPort` 放行 | **关** |

### 何时切换

- 键：`krt.status`（绑定类 `KrtSecurityConfig011`；缺省键缺失时代码落 **PRODUCTION**）。
- 解析：`FrameworkStatus011.fromString` → `isPermissionWhitelistMode()`（仅 PRODUCTION 为 true）**且** classpath 存在访问中心标记 bean（`AccessCenterMarker011`）。
- **生产启动卫兵**：Spring profile = `production` 时 **必须** `krt.status=production`；`debug` / `development` 与 production profile 组合 → **启动失败**（`IllegalStateException`）。另：production 状态要求非空 `krt.jwt.secret`。
- 配置事实见 [015 配置体系](../015.topic-config.md)。
- 实现：`AuthorizationAdapter`（access；**非 production 时 `has`/`assertHas` 开头直接成功**）· `PermissiveAuthorizationPort`（无 access）· `PermissionWhitelistGate011` · `GlobalAuthFilter.enforcePermissionWhitelist`。

### 生产白名单落地（fail-closed 写 / 读暂豁免）

```text
请求 → GlobalAuthFilter（身份 / 401）
         → Controller → UseCase
              │
              │  assertHas(op, code)
              │    · debug/development → 打标（可选）+ 直接放行，不查库
              │    · production        → 打标 + 有码放行 / 无码 403
              ▼
         GlobalAuthFilter 返回前（仅 krt.status=production）：
              受保护写路径且从未 assertHas → 403「permission not checked」
```

| 范围 | 规则 |
|------|------|
| 受保护前缀 | `/klsjnh/**`（登录、doc、`/klsjnh/open/`、`/actuator/health` 等身份白名单路径不进本闸） |
| **写操作 fail-closed** | 非安全 HTTP 方法（POST/PUT/PATCH/DELETE…）且末段 **不是** select/get/stat/download/logout → 必须本请求内 `assertHas`，否则 403 |
| **读类暂豁免门闸** | GET/HEAD/OPTIONS/TRACE；以及路径末段以 `select*` / `get*` / `stat*` / `download*` 开头或 `logout`（仍建议 UseCase 挂 SELECT，生产按码过滤） |
| 开发/测试 | **不**因「未核对」而 403；**已挂的 `assertHas` 也不拦**（no-op） |

代码：`PermissionWhitelistGate011`（判定）· `PermissionCheckContext011`（打标）· `AuthorizationAdapter.assertHas` / `has`（非 production no-op）· `GlobalAuthFilter.enforcePermissionWhitelist`。

> **生产前须挂齐写入口的 `assertHas`**（或等价声明）。未挂的写接口在生产会被白名单闸 403——这是预期。管理面已尽量挂齐（见下表）；登录等公开入口除外。

## 动态权限模型

### 权限目录（真源）

| 表 | 用途 | DDL |
|----|------|-----|
| `july_perm_object` | 对象：`object_code` / `object_name` / `module_code` / … | [july_center_access011.sql](../../sql/july_center_access011.sql) |
| `july_perm_action` | 动作：`object_code` + `action_code` → **`permission_code` 唯一** | 同上 |

- **码格式**：`模块:对象:动作`（例 `system011:julyScheduler:start`）。
- 存活唯一：`alive` 下 `permission_code` 与 `(object_code, action_code)`。
- 种子：access 只播 IAM 自身 `JulyPermCatalogSeed011`；各中心自带 `*PermCatalogSeed011`（platform / scheduler / ai / message / storage / datasource），`@ConditionalOnBean(JulyPermObjectRepository)` —— **中心 + access 同时在场**才播种。常量类与种子**同串**。

### 授权两通道（并存 · 写入同表）

| 通道 | API / 写法 | 用途 |
|------|------------|------|
| A. 角色 × 菜单 | `assignMenus` → `july_role_permissions(pk_menu, permission_code)` | 导航 + 按钮显隐 |
| B. 角色 × 动作 | `assignObjectActions` → 同表直授（`pk_menu` 可空） | **无菜单也能授码**（启停类） |

运行时 `listCodes`：**汇总角色下所有非空 `permission_code`**（两通道并集）。内置角色（`is_builtin='1'`）全量旁路。`listCodes` 始终查库（不受 debug no-op 影响）。

### 已挂管理面（assertHas）

| 模块 | 对象 / 码前缀 | 说明 |
|------|---------------|------|
| IAM | `iam:julyUser:*` · `julyUserAudit` · `julyRole` · `julyMenu` · `julyOrganization` | CRUD / assign* / reset·changePassword / export·backup；**login 除外**；`getUserMenuTree` 不拦 |
| system011 | `system011:julyConfig:*` · `julyDictionary:*` · `julyScheduler:*` | Config / Dictionary / Scheduler（含 start/stop） |
| datasource | `datasource:julyDatasource:*` · `julySyncRule:*` · `julySql:select` | 含 testConnection / reloadRegistry / run |
| platform | 经各对象 `export` / `import` / `backup` 码 | 挂在对应对象 UseCase，非裸调平台 |
| aicenter | `aicenter:julyAiModelProvider:*` · `julyAiDomain:*` · `aiInference:chat` · `aiImage:generate` · `aiAudio:*` | 管理写 + 能力调用 |
| messagecenter | outbound/inbound channel·template·message | 含 send / resend / receive |
| storagecenter | provider · bucket · object | 含 upload / remove / copy / rename / saveText |

## 「配置才过滤」与双模式的关系

| 层 | 含义 | 代码 |
|----|------|------|
| **PEP 双模式** | 开发 no-op；生产真校验 + 写白名单 | `FrameworkStatus011` · `AuthorizationAdapter` · `PermissionWhitelistGate011` · `GlobalAuthFilter` |
| **PDP 授撤** | 生产已挂入口：有码放行、无码 403；`assignObjectActions` 授/撤**下一请求生效** | `AuthorizationAdapter.has` / `assertHas`（仅 production） |

| 结果 | statusCode |
|------|------------|
| 未认证（空 operatorId / 无 token；**仅 production assertHas**） | 401 |
| 无码 / 生产未核对写入口 | 403 |
| 有码 / 内置 / **开发任意 assertHas** | 继续业务 |

目录进了码、角色勾了码，**不等于**自动过滤：仍须用例 `assertHas`。生产额外要求：写入口**必须**挂过核对，否则过滤器直接 403。开发挂了也不拦——为联调，不是漏网。

## 业务怎么挂码、怎么授撤

### 管理面步骤

1. 对象/动作进目录（或复用底座种子）。
2. 角色：`assignMenus` 和/或 `assignObjectActions`（按对象整存替换；`actionCodes:[]` = 撤光该对象直授）。
3. 用户 `assignRoles`；**写用例入口写 `assertHas`**（生产强制生效；开发 no-op）；常量与种子同串。
4. Controller 只解析 `Operator011Resolver` → 把 `op.id()` 传入用例；**勿**只在 Controller 拦。

### 相关 API

| 端点 | 说明 |
|------|------|
| `GET /klsjnh/iam/julyPermCatalog/v1/selectObjects` | 对象目录 |
| `GET …/selectActions?objectCode=` | 对象下动作 |
| `POST /klsjnh/iam/julyRole/v1/assignObjectActions` | 按对象整存替换直授码 |
| （运行时）`AuthorizationPort` | `has` / `assertHas` / `listCodes` — **无 HTTP** |

包 / URL 骨架见 [013](013.topic-architecture.md)（文档 IAM = 代码 `…iam`，**不改包**）。

### 用例挂点示例

```java
authorizationPort.assertHas(operatorId, JulySchedulerPermissionCodes011.START);
```

## 完整蓝本：julyScheduler 任务启停

同一对象 `julyScheduler` 下拆 `start` / `stop` / … —— 角色可只授启动、不授停止；**用例内须事先写好核对点**。

| 角色种子 | 账号 | 意图 |
|----------|------|------|
| `role_scheduler_start` | `test017` | 仅 select + start（可动态撤） |

**闭环（E2E 已绿灯；须 `krt.status=production` 才验码）**：

1. 管理面 / API：`assignObjectActions` 授 `select` + `start`
2. `test017` 调 start → **200**
3. `actionCodes:[]` 撤该对象直授 → start → **403**
4. 再授回 → 恢复

**脚本**：[`tools/auth-dynamic-scheduler.sh`](../../../tools/auth-dynamic-scheduler.sh)（WSL / `dev016`）。

### 顺带：julyConfig 矩阵

| 码 | UseCase |
|----|---------|
| `system011:julyConfig:select` | getById / selectListByPage |
| `…:insert` / `update` / `logicDelete` | 写 |
| `…:export` / `backup` | export / backup011（backup 成功只回 key） |

演示账号（密码 `Test011!`）：`klsjnh` 全权 · `test011` 无导出备份 · `test013` 无删 · `test015` 只读 · `test016` **只备份**。码过滤仅在 **production** 生效；debug 下矩阵也会「全过」——预期。

**脚本**：[`tools/auth-demo-matrix.sh`](../../../tools/auth-demo-matrix.sh)。单测：`AuthorizationAdapterTest`（含 debug no-op）· `PermissionWhitelistGate011Test` · `KrtSecurityConfigValidateTest011`。

## 业务仓接入清单（最短）

1. 目录登记对象/动作（或复用种子）。
2. 角色授码（菜单通道和/或 `assignObjectActions`）。
3. **入口写 `assertHas`**（生产未挂写入口 = 白名单 403；开发调用不拦）。
4. 常量 = 种子同串；扫描 `com.klsjnh`。
5. 验收：在 **production** 下仿 `auth-dynamic-scheduler.sh`：授 → 200 → 撤 → 403；另验「未挂写入口 → 403」。debug 下勿用「没 403」当生产契约。
