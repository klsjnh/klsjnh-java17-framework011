## 命题

**一个访问中心，管「在哪、能干什么」；「谁」的账号登录留在 core。**

- **谁（core）**：用户（账号 / 认证 / 审计）
- **在哪（access）**：组织树（挂靠，非数据权限）
- **能干什么（access）**：权限目录 + 角色授码 + 菜单引用；PEP **按运行状态双模式**（开发 opt-in / 生产写白名单）—— **动态配置与启停蓝本见 [016](016.topic-dynamic-permission.md)**，本文不展开。

> 代码包仍为 `com.klsjnh.…iam`（少改包）；URL 前缀 `/klsjnh/iam/**`。**不改包路径。** 不引 `center-access011-starter` 时 classpath 无组织/角色/菜单/权限目录管理面。

## 边界（否定清单）

- 不做数据权限 / 行级 ACL / 多租户隔离。
- 不做 OAuth2 / SSO（另案）。
- 不做「只配目录、用例零核对」的空壳安全（目录≠自动过滤；生产写还强制核对）——见 [016](016.topic-dynamic-permission.md)。
- 不做登录响应内嵌菜单树。
- 不做密钥可逆加密（→ 033）。
