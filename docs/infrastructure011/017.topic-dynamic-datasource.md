> 阶段：**架构底册（横切视角）** —— 持久化之外的另一条数据通道：业务库连接注册与 SQL 路由。
> 参考来源：java17011 最新 DDD 实现（`/klsjnh/s202609/java17011`）+ java8 ci011 口径。
> **2026-09-15 修订**：本期起 **`july_datasource` 表驱动为运行时唯一真源**，`krt.ci011` 降级为引导用途。业务设计见 [requirement011/031](../requirement011/031.topic-dataservice011.md)，技术方案见 [requirement013/031](../requirement013/031.topic-dataservice011.md)。

## 013.配置定义

### 013.1 krt.ci011（yaml，引导数据源）

启动期即需存在的库；**不再是管理对象**。字段口径见 `ConnectionInfo`。

| fieldCode | fieldName | fieldType | fieldLength | requiredField | defaultValue |
| --------- | --------- | --------- | ----------- | ------------- | ------------ |
| dsCode    | 数据源编码 | String    | 60          | true          | -            |
| dsName    | 数据源名称 | String    | 100         | false         | -            |
| dsType    | 数据库类型 | String    | 20          | true          | -            |
| dsUrl     | JDBC URL  | String    | 500         | true          | -            |
| username  | 用户名     | String    | 100         | true          | -            |
| password  | 密码       | String    | 300         | true          | -            |

```yaml
krt:
  ci011:
    - ds-code: business011
      ds-name: 业务库
      ds-type: mysql
      ds-url: jdbc:mysql://127.0.0.1:33306/db202608270001?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false
      username: dev202608011
      password: dev202608011
```

### 013.2 july_datasource（表，运行时真源）

字段定义见 [requirement011/031 §013](../requirement011/031.topic-dataservice011.md)；DDL 见 [docs/sql/july_datasource.sql](../sql/july_datasource.sql)。

**分工红线：同一 `dsCode` 只允许一个家** —— 已在 `ci011` 声明的不得再进表，反之亦然。

## 015.方案（现有实现 + 表驱动改造）

```
java17-domain011
  com.klsjnh.domain.datasource.ConnectionInfo                 record（dsCode/dsName/dsType/dsUrl/username/password
                                                                → 扩 schemaName/driverClass/poolConfig）
  com.klsjnh.domain.datasource.DynamicDataSourceRegistryPort  register / unregister / isRegistered / testConnection
                                                                → 扩 reloadAll(List) → ReloadResult（2026-09-15）
  com.klsjnh.domain.datasource.ReloadResult                   新增（enabled/registered/reused/closed/failed；2026-09-15）
  com.klsjnh.domain.datasource.DataSourceProbePort            新增探测端口 + ProbeResult（2026-09-15）
  com.klsjnh.domain.datasource.SqlRoutingPort                 selectList / selectOne / execute / selectListByPage（读写俱备）
  com.klsjnh.domain.dataservice011.JulyDatasource             聚合根（表驱动对象，见 031 主题）
  com.klsjnh.domain.dataservice011.DatasourceSeedPort         新增播种端口 + SeedResult011（2026-09-15）
  com.klsjnh.domain.dataservice011.SeedResult011              新增（total/inserted/skipped/failed；2026-09-15）
java17-infrastructure011
  com.klsjnh.infrastructure.datasource.DataSourcePools011     Druid 池构造器（DatabaseType011 枚举定驱动）
                                                                → buildForProbe 补 maxActive 1 / maxWait 10s；新增 isBuilt()（2026-09-15）
  com.klsjnh.infrastructure.datasource.DynamicDataSource011   AbstractRoutingDataSource + ThreadLocal 路由键 + ConcurrentHashMap 注册表（add 换旧关旧）
  com.klsjnh.infrastructure.datasource.DynamicDataSourceRegistryImpl  端口实现
                                                                → 改造：表驱动 reloadAll（配置未变则保留旧池）
  com.klsjnh.infrastructure.datasource.DataSourceProbe011     临时池探测（新增，不回灌注册表）
  com.klsjnh.infrastructure.datasource.SqlRoutingExecutor     JdbcTemplate + set(dsCode) / finally clear()
  com.klsjnh.infrastructure.datasource.SqlDialect011          分页方言策略（按 DatabaseType011 生成页化 SQL + count 包装）
                                                                → oracle 分支改 rownum 双层（兼容 11g~21c；2026-09-15）
  com.klsjnh.infrastructure.datasource.DynamicDataSourceConfig  路由数据源 Bean + 独立 JdbcTemplate（不污染 MP 主链路）
  com.klsjnh.infrastructure.dataservice011.seed.DatasourceSeed011    播种实现（实现 DatasourceSeedPort；2026-09-15）
  com.klsjnh.infrastructure.dataservice011.runner.DatasourceSeedRunner 启动播种 Runner（ApplicationRunner @Order 100；2026-09-15）
  com.klsjnh.infrastructure.persistence.mapper.CommonMapper   扩 countBy(sql)：绕开逻辑删除过滤的存在性计数（2026-09-15）
  com.klsjnh.infrastructure.persistence.sql.QuotedLiteral     原生 SQL 字符串字面量转义（新增；2026-09-15）
java17-infrastructure011（config）
  KrtConfig011 扩 ci011 绑定：List<ConnectionInfo>（type 走 DatabaseType011.fromString，未知值启动即失败）
               ⏸ dataservice011.secretKey：本期未动，留二期加密存储时预埋
表驱动 reloadAll（2026-09-15 新增）
  触发：启动 / 管理面 reloadRegistry / 每次写库后自动
  → repository.findAllEnabled()（dr='0' and status='1'）
  → 逐条转 ConnectionInfo → registry.reloadAll(List<ConnectionInfo>)
       ├── 先构建 nextMap（null / 空 dsCode 跳过），再整体替换 configs
       ├── Pass 1：快照内且物理目标未变（ConnectionInfo.sameTarget：jdbcUrl/username/password/dbType 四值全等）
       │          → 保留旧池，不断连（reused++）
       ├── Pass 1：快照内但目标变了且已建池 → DynamicDataSource011.remove + pools.close（closed++）
       ├── Pass 2：旧声明集里快照中消失的（删 / 停用）→ 关池（closed++）；两 pass 不重叠，不会关两次
       └── 回报 ReloadResult { enabled, registered, reused, closed, failed } 并落一条日志
  池创建仍为懒加载（DataSourcePools011.get 的 computeIfAbsent），reloadAll 不预建新池
懒加载（决策点 1，已定案）
  启动零连接：配置仅声明；Druid 池在 dsCode 第一次真正被调用时才创建
  首次连接失败 → 该次调用抛错（illegalState → 500 信封）；未知 dsCode → badRequest
分页（决策点 2，已定案）
  SqlRoutingPort.selectListByPage(dsCode, sql, pageIndex, pageSize) → PageResult011
  pageSize 代码限死 [10, 500]（越界夹取，常量注释"产品决定"）
  方言：infra 内 SqlDialect011 策略按 DatabaseType011 生成页化 SQL
    mysql / postgresql  → 原SQL包子查询 + LIMIT n OFFSET m
    oracle  → rownum 双层嵌套（兼容 11g~21c，不用 12c 的 OFFSET/FETCH NEXT）
              SELECT * FROM ( SELECT klsjnh_inner.*, ROWNUM klsjnh_rn FROM ( 原SQL ) klsjnh_inner
                              WHERE ROWNUM <= offset+size ) WHERE klsjnh_rn >= offset+1
              内层别名不用 rn，避免与开发者 SQL 已暴露的 rn 列冲突
    sqlserver → 包子查询 + OFFSET m ROWS FETCH NEXT n ROWS ONLY（2012+ 原生支持）
    count = SELECT COUNT(*) FROM ( 原SQL ) cnt（大结果集由调用方优化）
yaml 播种（2026-09-15 新增）
  定位：krt.ci011 是「一次性种子」，july_datasource 表是运行时唯一真源
  入口：com.klsjnh.infrastructure.dataservice011.runner.DatasourceSeedRunner（ApplicationRunner，@Order 100）
        → com.klsjnh.infrastructure.dataservice011.seed.DatasourceSeed011（实现 domain 端口 DatasourceSeedPort）
  逐条按 dsCode 判重（existsIncludingDeleted，刻意绕过逻辑删除过滤）：
    表里没有该 dsCode            → INSERT（种子落地）
    表里有（含 dr='1' 墓碑行）    → 跳过，不更新不复活（管理页删掉的不会被重启复活）
    内容不一致（dsName/jdbcUrl/dbType）→ 表赢，记 WARN 列出差异字段
  失败策略：单条失败一律 log.error(带 dsCode + 堆栈) 后继续，绝不抛异常阻断启动
            —— 服务必须能起来，人进管理页手工修
  启动时序：Runner 先播种 → 再 reloadAll(表内容) → 注册表切到表驱动快照
           两步各自 try/catch，播种挂了仍尝试 reload
  Runner 只依赖 domain 端口，不依赖 application 层（infrastructure 不反向依赖 application）
```

- **双世界隔离（铁律）**：主数据源（MyBatis-Plus，承载 july_* 表）完全不感知动态数据源；动态库只能经 `SqlRoutingPort` 按 dsCode 访问。**注意例外**：`july_datasource` **表本身**在主库，由 MP 读写（它是"数据源的目录"，不是业务库）；
- **连接池参数**（沿 java17011）：initialSize 0 / minIdle 0 / maxActive 100 / maxWait 60s / testWhileIdle / 池化 PreparedStatement；
- **无 wall filter**（有意）：跨库 DDL / 多语句场景 wall 易误伤；
- **pom 增量**：druid-spring-boot-3-starter（版本已管理，infrastructure 引入）。

## 017.关系与联动

- `DatabaseType011`（已有枚举）：驱动类名唯一真源，替代 java17011 硬编码 DRIVERS Map；
- 与 KrtConfig011 的关系：ci011 与 dataservice011 配置组都是框架配置的一部分，绑定进 KrtConfig011（业务代码禁 `@Value` 的红线不变）；
- 与 `july_datasource` 表的关系：**表是运行时真源，ci011 是引导**（2026-09-15 起）；
- 与审计链路的关系：写表走 MP + `AuditMetaObjectHandler`（request attribute 方案），不用老项目的手工 `OperatorContext`。

## 019.二期预告（业务建模：`july_business_modeling`）

> **2026-09-15 修订**：原「`july_sql` + `july_model` 两表照搬」的预告**已作废**。
> 用户裁定机制变更：**两表合并为一张 `july_business_modeling`，产物交 lowcode011 域，由低代码操作表**；
> **产物形状收敛为 `MetaData011` + `List<FieldInfo011>` 一份 JSON（`metaData` + `fieldData` 两个键），除公共列、`object_name`、`sql_text` 外整体存 `model_data` 一列**；
> **一期能力含「执行 SQL」与「分页执行 SQL」**（复用本文档 §013 的 `SqlRoutingPort.selectList` / `selectListByPage`）；
> 本项目**不再自建物理表、不再维护 `july_metadata` 运行时注册表**。
> 具体方案见 [requirement013/033.topic-business-modeling](../requirement013/033.topic-business-modeling.md)。

老项目 `kj17-f016_20260719_a011` 有完整三表实现；本项目的对应关系：

| 老项目表 | 本项目 | 本期 |
|----------|--------|------|
| `july_datasource` | `july_datasource` | ✅ 已编码（见 [031](../requirement013/031.topic-dataservice011.md)） |
| `july_sql` + `july_model` | **合并为** `july_business_modeling` | 📄 方案态（[033](../requirement013/033.topic-business-modeling.md)） |
| `july_metadata` | **不存在**（表自身即运行时真源） | ❌ 不做 |

动态 SQL 的**参数化执行**（`PreparedStatement` 真绑定）→ **移交 lowcode011 域的运行时能力**，不在本模块；
本模块的「执行 SQL / 分页执行 SQL」走 `SqlRoutingPort` 裸 SQL（**强制 `SELECT`**，见方案 §018.4），
只服务管理面的看数与推断，不做对外数据服务。

## 021.边界外（本期不做）

- 业务建模的**物理建表**（`DdlBuilder` / 老表改名备份 / 迁移交集）→ 机制改为交 lowcode；
- `july_metadata` 运行时注册表（本项目不造第二张表）；
- 读写分离、负载均衡、多租户路由；
- 分布式事务（动态库上只跑业务查询，不参与主库事务）；
- 密码加密存储（密钥配置位本期预埋，加解密二期）。

## 023.决策点

| # | 决策点 | 结论 |
|---|------|------|
| 1 | 启动注册失败策略 | ✅ **懒加载**：启动零连接，dsCode 第一次真正调用才建池连接；配置错误/连不上在调用时报错（2026-09-13） |
| 2 | SqlRoutingPort 能力边界 | ✅ **读写俱备 + 分页**：selectList / selectOne（读）、execute（写/DDL）、selectListByPage（方言分页，pageSize 代码限死 [10, 500]）；SQL 注入边界维持内部管理场景定位（2026-09-13） |
| 3 | 密码明文在 yaml | ✅ 生产用环境变量注入（015 配置文档既有口径）（2026-09-13） |
| 4 | 运行时真源 | ✅ **`july_datasource` 表驱动**；`krt.ci011` 降级为引导数据源；同一 dsCode 只允许一个家（2026-09-15） |
| 5 | reload 时既有池处理 | ✅ **配置未变则保留旧池**（避免改 remark 断所有连接）；变更/消失才关旧池（2026-09-15） |
| 6 | 测试连接口径 | ✅ 临时池 `initialSize 0` / `maxActive 1` / `maxWait 10s`，**不回灌注册表**，`finally` 关池（2026-09-15） |
