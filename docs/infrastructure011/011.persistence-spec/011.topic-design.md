## 011.命题

**持久化规约 = 一套 PO 家族 + 一套仓库基座家族；选型是机械动作。**

看 DDL 的三个特征——**有无 `sort_order`** / **有无 `parent_id`** / **有无子表（`pk_mt`）**——对号入座，得到唯一形态。

> 叫「持久化规约」而不是「ORM」：这里沉淀的是**表形态 → 基座**的映射规约，ORM（MyBatis-Plus）只是实现手段。
> 与「数据源中心」分工：数据源中心管**连接与跨库读写同步**；本规约管**单库内的表形态与仓储基座**。

## 013.表形态矩阵（全量 · 8 形态）

| # | 形态 | DDL 特征 | PO | 仓库基座 | 现状 |
|---|------|----------|----|----------|------|
| 1 | 平表 | — | `BasePo` | `BaseRepository` | ✅ |
| 2 | 排序表 | `sort_order` | `BasePo011` | `BaseRepository`（列表排序走 `SortSupport`） | ✅ |
| 3 | 树（无排序） | `parent_id` | `TreePo<T>` | `BaseTreeRepository`（**须 override `treeWrapper`**；不推荐） | ⚠️ 理论格 |
| 4 | 树 + 排序 | `parent_id` + `sort_order` | `TreePo011<T>` | `BaseTreeRepository`（默认 `sort_order, id`） | ✅ |
| 5 | 主子表 | 子表 `pk_mt` | `BasePo` + 子 `MasterLinked` | `BaseMasterSubRepository` | ✅ |
| 6 | 主子表 + 排序 | `sort_order` + 子 `pk_mt` | `BasePo011` + 子 `MasterLinked` | `BaseMasterSubRepository`（排序走 `SortSupport`） | ✅ |
| 7 | 树 + 主子表（无排序） | `parent_id` + 子 `pk_mt` | `TreePo<T>` + 子 `MasterLinked` | `BaseTreeSubRepository`（**须 override `treeWrapper`**） | ⚠️ 理论格 |
| 8 | 树 + 排序 + 主子表 | `parent_id` + `sort_order` + 子 `pk_mt` | `TreePo011<T>` + 子 `MasterLinked` | `BaseTreeSubRepository`（默认 `sort_order, id`） | ✅ |

> **形态 5 与 6 共用同一基座**：`BaseMasterSubRepository` 的类型界是 `BasePo`（不是 `BasePo011`），故排序主表（`BasePo011`）与不排序主表（`BasePo`）都能挂；排序能力由具体仓储的 wrapper 提供，级联与排序无关。
> **排序不再有基座**（2026-09-22）：`sort_order` 是**列约定 + 查询习惯**，由 PO（`BasePo011` / `TreePo011`）声明列、由静态 `SortSupport` 施加排序——**不存在** `BaseRepository011` 这类排序基座。

## 015.曾经的缺口与根因（已解决 · 留档）

曾用「排序 Repo 继承轴」与「树 / 主子各写一套」叠在一起，Java 单继承下无法同时获得排序 + 主子。现口径：排序走 `SortSupport`（见 [017](017.topic-sort-support-simplify.md)）；树/主子走公共件组合（§017）；主子操作面见 [018](018.topic-master-sub-api.md)。

## 017.补齐方案（已落地 · 2026-09-21）

**目标：让"能力"可组合，而不是让继承链越接越长。**

1. **抽公共件**（静态工具类，无 Spring）：
   - `TreeAssembler`：树装配（原 `BaseTreeRepository` 私有 `buildTree` 外提，孤儿/环回退规则不变）；
   - `MasterSubSupport`：主子级联（`saveChildren` / `saveChildrenRaw` / `selectChildrenByMaster` / `deleteChildrenByMaster` / `childKey`）；
   - `SortSupport`（2026-09-22）：默认业务排序 `sort_order ASC, id ASC`（`orderBySortThenId` / `sortedWrapper`）。
2. **既有基座改为委托公共件**（行为不变）：
   - `BaseTreeRepository.selectTree()` → `TreeAssembler.build(...)`；`treeWrapper()` → `SortSupport`；
   - `BaseMasterSubRepository`（原 `…021`）→ 级联全部委托 `MasterSubSupport`。
3. **组合出新基座**：
   - **`BaseTreeSubRepository`** = `BaseMasterSubRepository` + 树读侧（`selectTree()` / `treeWrapper()`）—— 形态 7、8；
   - **继承方向说明**：因 Java 单继承，树 + 主子表只能二选一继承；**选择继承主子链**（级联编排代码量更大），树读侧用 `TreeAssembler` 重新加回。`BaseTreeRepository` 仍是**无子表树**的基座。
4. **命名统一**：`BaseMasterSubRepository021` → **`BaseMasterSubRepository`**（suffix 只标"基座家族"，不再暗示 tier 能力）。
5. **排序去继承化**（2026-09-22）：删除 `BaseRepository011` / `BaseTreeRepository011` / `BaseTreeSubRepository011`，排序统一走 `SortSupport`；PO 排序层（`BasePo011` / `TreePo011`）保留。

## 019.首个落地场景：提示词（主 = 业务域树 / 子 = 提示词）

- 主 `july_ai_domain`：`parent_id` + `sort_order` → 形态 **8**（树 + 排序 + 主子表）；
- 子 `july_ai_domain_prompt`：`pk_mt` → `MasterLinked`；
- 落地：`JulyAiDomainPo extends TreePo011`，`JulyAiDomainRepositoryImpl extends BaseTreeSubRepository`，子仓储进 `getChildServices()`；
- 此前实现是**手搓**（`extends BaseRepository` + 用例里自装树），正是"缺基座"的证据；基座就位后已改回框架形态。

> 详细设计（对接代码）落 `requirement013`；本中心只定形态与基座。

## 021.边界（不做 / 否定清单）

- **不做**多级继承链堆叠——用组合 + 抽公共件；
- **不做**通用 QueryDSL / Criteria 抽象（各仓储自写 `specWrapper`，保持简单）；
- **不做**物理删（除维护场景 `physicalDelete`，白名单校验）；
- **不做**跨库分布式事务（属数据源中心边界）。

## 023.决策（已定案 · 2026-09-21）

1. **新基座命名**：**不带后缀** —— `BaseMasterSubRepository` / `BaseTreeSubRepository`（`…021` 先更名 `…011`，再由 [019 任务 A](019.topic-persistence-followups.md) 去后缀）。
2. **公共件形态**：**静态工具类** —— `TreeAssembler` / `MasterSubSupport` / `SortSupport`（非默认方法接口）。
3. **落地范围**：**形态 6/7/8 一次补齐**（形态 6 复用 `BaseMasterSubRepository`，无需新类）。
4. **排序去继承化（2026-09-22，见 [017](017.topic-sort-support-simplify.md)）**：删 `BaseRepository011` / `BaseTreeRepository011` / `BaseTreeSubRepository011`；树默认序 `sort_order, id`；无排序树须 override（当前无真实表）；PO 层 `BasePo011` / `TreePo011` 保留；主子基座现名 `BaseMasterSubRepository`（曾用名 `BaseMasterSubRepository011`；[019 任务 A](019.topic-persistence-followups.md) **已落地**）。
