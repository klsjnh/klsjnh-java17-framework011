## 011.分层总览

```text
web         Controller            ── 只注入 application，不碰 PO / Mapper
application UseCase               ── @Transactional 唯一落点；编排仓储
domain      Aggregate + RepoPort  ── 纯 Java；仓储接口在这
infrastructure  Po / Mapper / RepoImpl ── 实现 domain 仓储端口；本中心全部在此
```

本中心只管 **infrastructure 的最底一层**：`persistence.entity`（PO 家族）与 `persistence.repository`（仓库基座家族）。

## 013.PO 家族（`infrastructure.persistence.entity`）

| PO | 继承 | 非公共列 | 适用表形态 |
|----|------|----------|------------|
| `BasePo` | — | — | 全部表的公共底座（形态 1） |
| `BasePo011` | `BasePo` | `sortOrder` | 排序表（形态 2） |
| `TreePo<T>` | `BasePo` | `parentId` + `children`（`@TableField(exist=false)`，非表列） | 树（形态 3） |
| `TreePo011<T>` | `TreePo<T>` | `sortOrder` | 树 + 排序（形态 4） |
| `MasterLinked`（接口） | — | `pkMt` 契约（`getPkMt` / `setPkMt`） | 一切主子表的**子表 PO** |

- **`BasePo` 公共列**：`id`（varchar33 / 32 位无连字符 UUID / `ASSIGN_UUID` 仅空值兜底）/ `status` / `create_by` / `update_by` / `create_time` / `update_time` / `dr`；
- **逻辑删除**：`@TableLogic(value="0", delval="1")`，查询自动过滤 `dr='0'`；
- **树根**：`parent_id` 用**空串**（非 `null`）。

## 015.仓库基座家族（`infrastructure.persistence.repository`）

```text
BaseRepository                         ← BasePo        基础 CRUD / 分页 / 逻辑删 / 批量逻辑删 / physicalDelete（白名单防注入）
├── BaseTreeRepository                 ← TreePo        树层（selectTree → TreeAssembler；treeWrapper → SortSupport）—— 形态 3/4
└── BaseMasterSubRepository           ← BasePo        主子表层（三分 API；规则在 MasterSubSupport）—— 形态 5/6
     └── BaseTreeSubRepository         ← TreePo        主子 + 树层（selectTree + 三分 API）—— **形态 7/8**（无形态 6）

命名口径（2026-09-22）：
  · 基座家族 —— 不带后缀：BaseRepository / BaseTreeRepository / BaseMasterSubRepository / BaseTreeSubRepository
  · PO 家族 —— 排序层保留 011：BasePo011 / TreePo011（列形状，不是「批次」）

派生（PO）
    BasePo011            PO 侧排序列（sort_order）
    TreePo011            PO 侧树 + 排序列（parent_id + sort_order）

公共件（persistence.support）
    TreeAssembler       树装配（孤儿 / 环回退）
    MasterSubSupport    主子级联（saveChildren / selectChildrenByMaster / deleteChildrenByMaster / childKey）
    SortSupport         默认业务排序（orderBySortThenId / sortedWrapper：sort_order, id）
```

**两条能力线怎么合的**：排序**不再是继承轴**（2026-09-22 精简，见 [017](017.topic-sort-support-simplify.md)）—— `sort_order` 由 PO（`BasePo011` / `TreePo011`）声明列、由 `SortSupport` 施加排序；**树 + 主子表**因 Java 单继承选择**继承主子链**（级联编排代码量大），树读侧用 `TreeAssembler` 重新加回——见 [011 §017](011.topic-design.md)。

### 015.1 主子表三分 API（主 / 子 / 主+子）

`BaseMasterSubRepository`（及继承它的 `BaseTreeSubRepository`）把三种粒度做成一等公民，写 / 读 / 删对称（定案见 [018 主子表 API 对称化](018.topic-master-sub-api.md)）：

| 粒度 | 写 | 读 | 删 |
|------|----|----|----|
| **只主** | `saveMaster`（空 id insert / 有 id update；不碰子） | `getMaster`（= `getById` 别名） | `logicDelete`（仅主） |
| **只子** | `saveChildren`（**Replace**） | `getChildren` | 子仓 `logicDelete`（可逐条） |
| **主+子** | `saveWhole` | `getWithChildren` | `cascadeDelete`（先子后主） |

- **两轴正交**：主子轴（`pk_mt`）与树轴（`parent_id` / `selectTree`）不合并——**禁止**「整棵树挂全部子表」的基座方法；
- **注册 ≠ 必须级联**：只有 `getChildServices()` 注册的子表参与 `getWithChildren` / `cascadeDelete`；删不删由**用例护栏**决定（如字典「仍有明细则拒绝」）；审计 append-only / toggle-dr 关联表结构上是子表但**不注册**；
- **子表写策略**：整单覆盖走 **Replace**（`saveChildren` / `saveWhole`）；逐条增改删走 **Incremental**（直调子仓 `insert`/`update`/`logicDelete`），**两者禁混**；
- **Map 键**：`getWithChildren` 返回 `"master"` + 各子表键（= 子仓类名去 `RepositoryImpl` 首字母小写，如 `JulyDictionaryItemRepositoryImpl` → `julyDictionaryItem`）——重命名子仓 = **改契约**（演进见 [019 后续](019.topic-persistence-followups.md)）；
- **主键口径**：调用方先 `EntityId.generate()`；「空 id → insert」只是 `ASSIGN_UUID` 兜底。
- **Replace ≠ toggle-dr**：明细 Replace 插新 id；关联分配/取消走 revive/stop，见 §018。
- **`selectTree` 全量**：内存装配，大树另案。

### 016.1 三分落点与子写策略（各域现状）

| 域 | 主+子整存 `saveWhole` | `getWithChildren` | 子写策略 |
|----|:---:|:---:|----------|
| AI 提示词 | ✅ `julyAiDomain/v1/saveWhole` | ✅ | Replace |
| 模型接入 | ✅ `julyAiModelProvider/v1/saveWhole` | ✅ | Replace（密钥 = 配置明细） |
| 同步规则 | ✅ `julySync/v1/saveWhole` | ✅ | Replace（列映射 = 纯元数据） |
| 存储提供方 | ❌ **不适用** | ✅ `julyStorageProvider/v1/getWithChildren` | **Incremental**（桶 = 物理资源，走 `insertBucket` / `removeBucket`） |
| 字典 | ❌ **不适用** | ❌ | **Incremental**（[027](../../requirement013/027.topic-dictionary.md) 明文禁 Replace） |
| 用户 / 角色 | ❌ **不适用** | ❌ | **toggle-dr**（`assignRoles` / `assignMenus`，非级联子表） |

> **子写策略按语义二选一**（见 [018 §011.016](018.topic-master-sub-api.md)）：可整单覆盖的**配置明细** → Replace；有独立生命周期 / 外部副作用的**实体** → Incremental。**「不适用」不是漏做**。

## 017.链接列规约 `pk_<目标表>`

跨表链接列统一 `pk_` 前缀 + 目标表名，PO 字段驼峰：

| 列 | 指向 | PO 字段 |
|----|------|---------|
| `pk_mt` | 主表 id（`MasterLinked`） | `pkMt` |
| `pk_menu` | july_menu.id | `pkMenu` |
| `pk_role` | july_role.id | `pkRole` |
| `pk_org` | july_organization.id | `pkOrg` |
| `pk_user` | july_user.id | `pkUser` |

PO 中**禁止**其他 `*Id` 形态字段（门禁 `pk-mt`；白名单 `id` / `pkMt` / `parentId` / `serialVersionUID`）。

## 018.关联表替换策略 = toggle dr（不删不插）

UNIQUE 键覆盖全部行（含 `dr='1'`）——同一组合**永远只有一行**：

```sql
-- 分配：行存在则复活，不存在才插入（Mapper.revive + insert）
UPDATE july_user_role SET dr = '0' WHERE pk_mt = ? AND pk_role = ?;
-- 取消：置 dr='1'（Mapper.stop）
UPDATE july_user_role SET dr = '1' WHERE pk_mt = ? AND pk_role = ?;
```

杜绝"删旧 + 插新"在唯一键下的第二次整存冲突与行堆积。

> **挂 `pk_mt` ≠ 加入级联**：审计表（july_user_audit）结构上是子表、行为上例外（append-only，**不注册**进 `getChildServices()`）。

## 019.审计填充链路

```text
GlobalAuthFilter 验签 → request.setAttribute(FrameConst011.OPERATOR_ID, userId)
  → AuditMetaObjectHandler（MyBatis-Plus 回调）经 RequestContextHolder 读出
  → create_by / update_by / create_time / update_time 自动填充
application 层需要身份时：Controller 读 attribute 显式传参（application 不碰 web 概念）
```

- 自定义 ThreadLocal `OperatorContext011` **已删除**（只写不读的死代码；`RequestContextHolder` + `FrameConst011.OPERATOR_ID` 即 Spring 自带的请求级载体）；
- 审计写入（july_user_audit）走 `UserAuditRecorder`：`REQUIRES_NEW` 独立事务——业务回滚绝不吞审计行；append-only 只插不改不删。

## 020.CommonMapper 约束

原生 SQL 仅限**维护场景**（如 `physicalDelete`）：`${sql}` 裸拼，**调用点必须白名单校验**（`SAFE_ID` `[A-Za-z0-9_-]{1,33}`）；表名只能来自开发者常量 `getTableName()`。

## 021.唯一性

业务层唯一性断言（`getBusinessColumn` / `getBusinessValue` / `duplicateMessage`）**只是友好预检**，真正的保证是**数据库唯一索引**——并发下"先查后插"必然穿透。
