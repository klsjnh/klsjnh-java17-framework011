## 011.定案（不可自行改口径）

### 011.正式操作面 = 三分（主 / 子 / 主子）

主子基座（`BaseMasterSubRepository` 及继承它的 `BaseTreeSubRepository*`）必须把下列粒度写成**一等公民 API**（写 + 读对称）：

| 粒度 | 写 | 读 | 删 |
|------|----|----|----|
| **只主** | `saveMaster` | `getMaster`（可委托 `getById`） | —（一般走 `logicDelete` 仅主，慎用） |
| **只子** | `saveChildren`（**Replace**） | `getChildren` | 子仓 `logicDelete` / Support 删某主下子 |
| **主+子** | `saveWhole` | `getWithChildren` | `cascadeDelete`（先子后主） |

### 013.两条轴正交（禁止混成上帝方法）

```text
主子轴（pk_mt）  → 上表三分 API
树轴（parent_id）→ selectTree / treeWrapper
形态 8 = 两轴组合调用，不合并成 saveTreeWhole / getTreeWithAllChildren
```

**禁止**在基座新增「整棵树每个节点挂全部子表」的默认方法（N+1 / 大包；产品层自装配）。

### 015.`saveMaster` 语义

- **改为**：无 id / 空 id → `insert`；有 id → `update`；**永不碰子表**。
- 现实现只 `update` 且强制 id —— **必须改**（与 `saveWhole` 对主表的分支一致）。

### 016.子表写策略写死（两种，勿混）

| 策略 | 何时用 | 怎么做 |
|------|--------|--------|
| **Replace** | 整单覆盖提交（配置明细一次提交） | `saveChildren` / `saveWhole` 内对子列表：先按 `pk_mt` 逻辑删旧，再全量 insert |
| **Incremental** | 逐条增改删（字典明细等） | **直接**子仓储 `insert` / `update` / `logicDelete`；**禁止**走 `saveChildren` |

- 方法名 **保留** `saveChildren`（避免大范围改名），Javadoc / 文档标题必须写清 **Replace strategy**。
- 可选：增加同义方法 `replaceChildren(...)` 委托 `saveChildren`（不强制；若加，两处行为必须完全一致）。

### 017.`getChildren` 抬升为一等公民

- 在 `BaseMasterSubRepository` 增加公开方法，委托 `MasterSubSupport.selectChildrenByMaster`。
- 签名建议：

```java
public <C extends BasePo> List<C> getChildren(String masterId, BaseRepository<C, ?> childService)
```

- `getWithChildren` **本次保留** `Map<String, Object>`（`"master"` + `childKey`）；强类型 Bundle 继续放 **domain/application**（如已有 `JulyAiDomainBundle`）。**本次不**在基座引入泛型 Bundle 大改。

### 018.注册边界不变

- 仅 `getChildServices()` **注册**的子仓参与 `getWithChildren` / `saveWhole` 未显式传入时的约定 / `cascadeDelete`。
- 审计 append-only、toggle-dr 关联表：结构可有 `pk_mt`，**不注册**则不参与级联（现行口径保留）。

### 019.类名

- **类名**：`BaseMasterSubRepository`（曾用名 `BaseMasterSubRepository011`；[019 任务 A](019.topic-persistence-followups.md) **已落地**）。

## 013.背景（现状缺口）

| 能力 | 现状 | 缺口 |
|------|------|------|
| 保存主 | `saveMaster` 只 update | 不能建主；与三分叙事「保存主表」不符 |
| 保存子 | `saveChildren` = Replace | 文档/用法未把 Incremental 写成对称路径 |
| 保存主子 | `saveWhole` | 可用 |
| 查主 | `getById` | 缺与写侧对称的命名（可选 `getMaster`） |
| 查子 | 仅 `MasterSubSupport.selectChildrenByMaster` | 基座未暴露，读侧三分不齐 |
| 查主子 | `getWithChildren` → `Map` | 弱类型可接受本期；域层已有 Bundle 先例 |
| 树 | `selectTree` | 与主子无关；AI 域用例层已用手搓三分，基座需对齐叙事 |

参考实现（应用层已接近三分，**不必为对齐而强行改成调基座 saveWhole**）：

- `JulyAiDomainUseCase`：`insert`/`update`（主）、`insertDetail`/`updateDetail`（子增量）、`saveWhole`（主+子）、`getWithChildren`（主+子读）
- HTTP：`AiDomainController` 已暴露 `saveWhole` / `getWithChildren` 等

本期焦点 = **基座 API + 持久化规约文档**；业务用例**无强制**迁移到基座方法（能编译、行为不回退即可）。

## 015.目标 API 一览（改后）

```text
BaseMasterSubRepository
  // 主
  saveMaster(T)              // insert | update；不碰子
  getMaster(String id)       // = getById；命名对称

  // 子（Replace）
  saveChildren(masterId, childService, children)
  getChildren(masterId, childService)

  // 主+子
  saveWhole(master, childrenByService)
  getWithChildren(id)        // Map 保留
  cascadeDelete(id)

MasterSubSupport（保持）
  saveChildren / saveChildrenRaw / selectChildrenByMaster / deleteChildrenByMaster / childKey
```

`BaseTreeSubRepository`（及精简后的树主子基座）**继承**上述 API，另加 `selectTree()`——文档须写明两轴。
