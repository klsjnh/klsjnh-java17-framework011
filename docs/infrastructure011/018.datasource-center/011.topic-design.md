## 011.命题

**数据源中心 = 数据源 + 读写 + 同步。**

统一**管理**多个数据源，在其上**读写（分页）**，并在**任意两个数据源之间**做数据**同步**——三者是同一件事的三个层次。

> 此前：能力一在框架（`datasource` 域）；能力二被划到产品侧；能力三只在低代码有提案。本中心把三者收拢。
> **命名**：叫「数据源中心」而非「数据中心」——后者在中文里=机房/IDC、技术语境=数仓/数据湖，名不副实。

## 015.设计思路

### 015.1 为何上收框架

- **横切机制，非业务**：连接/池/方言/分页/校验/同步编排，任何接入方都要用；
- **低代码只是使用者**：`importDataFromSql` / `executeSqlByPage` 是"同步/查询"的第一种特化，不该私有化在产品；
- **框架定位 = 供第三方依赖**：通用数据访问留在产品，等于每个产品重复实现校验/分页/安全。

### 015.2 读写：只读先行，未来分接口放权

- **只读**：`SELECT` 开头、禁 `;`、禁 DDL/DML、禁 `INTO OUTFILE/DUMPFILE` 与 `LOAD_FILE()` 服务端文件访问；
- **写接口放权（D3 已实现）**：`POST …/julySql/v1/execute` —— 单条语句、PreparedStatement 绑定、禁 `;` 多语句走私（`SqlGuard011.assertSingleStatement`）；权限码 `datasource:julySql:execute`（种子同步）。**语句形态不再设只读限制——授权即放行**，凭据管控交权限目录；
- **池侧守卫**：`JdbcUrlGuard011` 管住 JDBC URL —— 内置类型强制自有 scheme 前缀（`jdbc:mysql:` 等）+ 危险连接参数黑名单（`allowLoadLocalInfile` / `autoDeserialize` / `queryInterceptors` 等）；`driverClass` 仅自定义方言类型可覆盖（内置类型锁定默认驱动）。保存时（`JulyDatasource.validate`）与建池时（`DataSourcePools011.build`）双执行点；
- **更细的分接口**（DDL 专用端点等）→ 见 [013 §015](013.topic-architecture.md)；
- **端口**：`SqlRoutingPort` 加**参数化重载**（`sql + params`，PreparedStatement 真绑定）；裸 SQL 变体仅供内部（探针/管理面）。

### 015.3 同步：方向无关

**同步是一个抽象能力，不是一个方向。** `source` 与 `sink` 只是两个端点 + 可动态配置的规则：

- **不分内外、不分方向**：外部库与本地对象表都是 `EndpointSpec`；
- **复用方言**：分页读走 `SqlDialectPort011` 族；**写入走 `WriterDialectPort`**（MySQL `ON DUPLICATE KEY` / Oracle·SQLServer `MERGE` / PostgreSQL `ON CONFLICT`，按目标 ds 类型解析，未知回退 MySQL）；
- **源端防线**：`SyncSource011` 执行咽喉点统一把守 —— `sql` 端点必过 `SqlGuard011.assertReadOnly`（同步读侧同样只读）；`table` 端点标识符过 `[A-Za-z0-9_]+` 白名单（源端可能是任意方言，只校验不包裹）；
- **调度接入（已实现）**：`SyncRuleJobHandler`（`scheduler_handler=syncRule`，任务参数 `{"syncCode":"…"}` 走 `july_scheduler.task_param`）——**需 scheduler starter 在场**（数据源中心条件装配，不强制 Quartz 依赖）；调度触发为系统身份，不走 `RUN` 权限码（启动调度的操作者已需 `julyScheduler:start`）；
- **映射**：`mapping[]` = `sourceColumn → targetColumn`，归同步规则。

### 015.4 边界（不做 / 否定清单）

- 读写：**不做**裸 SQL 无参数的对外暴露；**不做**跨库分布式事务；
- 同步：**不做**调度（复用 [022](../../requirement011/022.topic-july-scheduler.md)）、**不做** CDC/实时（本期批量分页）；
- 管理：**不做**读写分离 / 负载均衡 / 多租户路由。

## 021.设计稿（待评审落码 · 2026.10.05）

### 021.1 checkpoint / 续传

- **新表** `july_sync_checkpoint`：`pk_rule`（主子外键 `pk_rt` 口径）、`last_watermark VARCHAR(100)`（业务键水位）、`last_page INT`、`update_time`——一规则一行。
- **水位语义**：按 `syncKey` 增量拉取（table 端点拼 `WHERE sync_key > ?`；sql 端点要求自带 `{{watermark}}` 占位符模板）。**只 INSERT/UPDATE 安全，DELETE 不捕获**——水位续传仅推荐给 append-heavy 源；全量覆盖模式（现状）仍是默认。
- **推进时机**：每页 upsert 成功后推进水位（同事务）；失败从上次水位重跑。

### 021.2 S2 主子同步

- 规则主子表扩展：`july_sync_rule_child`（子表端点 + 外键列 + 关联键列）；引擎先读主行集，再按外键批量读子行集、按 `pk_mt` 式关联聚合嵌套下发。
- 仅 table 端点支持；冲突策略沿用父规则。

### 021.3 S3 多源 / 多向

- 目标端点走**动态数据源路由**（`SqlRoutingPort.execute` 替代主库 JdbcTemplate——`WriterDialect` 已按目标类型就绪，本步只切换写通道）；
- 多源合并 = 多个 source 端点依序跑同一条规则（先到先占 upsert），不做行级合并。

### 021.4 决策点

1. checkpoint 表放 `july_sync_rule` 主子体系还是独立表（前者可复用主子 API，后者生命周期独立）；
2. 水位列是否要求源端索引（无索引全表扫代价）；
3. S2 子表端点是否允许与父端点跨库（建议第一期禁止，跨库归 S3）。

## 099.怎么接入（注解式）

> **本中心默认关**：jar 在 classpath 上不会自动生效 —— 必须由业务项目**显式开启**（bean 与 mapper 都随注解注册）。

- **依赖**：`center-datasource011-starter`
- **access 可选**：权限种子由 `DatasourcePermCatalogSeedConfig011` 用 `@ConditionalOnClass(name="…JulyPermObjectRepository")`（**字符串形式**）挂条件；不装 `center-access011-starter` 时整段跳过（启动前提见 020 §4：须 permissive 回退或 access 在场；`SqlRoutingPort` 另由 `java17-data-mybatis011-starter` 提供）
- **开启**：启动类加 `@EnableDatasource011Center`
- **不开启**：本中心的 HTTP 全部 404、bean 与 mapper 都不注册（详见 [013 模块清单与怎么用](../013.topic-project-structure.md) §025）
- **注解式而非配置开关**：开关写在代码里（一眼看出装了哪些中心），且"默认关"才是真隔离
