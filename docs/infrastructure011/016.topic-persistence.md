# 016.topic-persistence（持久化体系）

> 阶段：**架构底册（横切视角）** —— 统领持久化层的公共底座：PO 家族、仓库基座家族、链接列规约、审计填充、替换策略。业务表的逐表设计在 requirement011 各主题；编码规则（注释/命名门禁）在 docs/015。

## 011.PO 家族（`infrastructure.persistence.entity`）

| PO | 继承 | 非公共列 | 适用表形态 |
|----|------|----------|------------|
| BasePo | — | — | 全部表的公共底座 |
| BasePo011 | BasePo | sort_order | 手工排序表 |
| TreePo\<T\> | BasePo | parent_id + children（非表列） | 树表 |
| TreePo011\<T\> | TreePo\<T\> | sort_order | 树 + 同级排序 |
| MasterLinked（接口） | — | pkMt 契约 | 一切主子表子表 PO |

- **BasePo 公共列**：id（varchar33，32 位 UUID，ASSIGN_UUID 仅空值兜底）/ status / create_by / update_by / create_time / update_time / dr；
- **逻辑删除**：`@TableLogic(value="0", delval="1")`，查询自动过滤 dr='0'，根节点 parent_id 为空串。

## 013.仓库基座家族（`infrastructure.persistence.repository`）

```text
BaseRepository                 ← BasePo      基础 CRUD/分页/逻辑删/批量（两查询版）/physicalDelete（白名单防注入）
├── BaseRepository011          ← BasePo011   排序层（sortedWrapper）
├── BaseTreeRepository         ← TreePo      树层（selectTree 装配：孤儿回退 + 环可达性回退）
│    └── BaseTreeRepository011 ← TreePo011   树+排序层（@Override treeWrapper 按 sort_order）
└── BaseMasterSubRepository021 ← BasePo      主子表层（级联整存/整查/级联删；子 PO 实现 MasterLinked）
```

**选型是机械动作**：看 DDL 有无 sort_order / parent_id / 主子关系，对号入座：

| 业务表 | PO | 基座 |
|--------|----|------|
| july_scheduler / july_user / july_role | BasePo | BaseRepository（user/role 为 MasterSub 主表） |
| july_menu / july_organization | TreePo011 | BaseTreeRepository011 |
| july_user_role / july_role_permissions / july_user_audit | BasePo + MasterLinked | BaseRepository（关联/审计子表） |

- **挂 pk_mt ≠ 加入级联**：审计表结构上是子表、行为上例外（append-only，不注册进 getChildServices）；
- 业务唯一性断言只是友好预检，真正的保证是数据库唯一索引。

## 015.链接列规约 `pk_<目标表>`

跨表链接列统一 `pk_` 前缀 + 目标表名，PO 字段驼峰：

| 列 | 指向 | PO 字段 |
|----|------|---------|
| pk_mt | 主表 id（MasterLinked） | pkMt |
| pk_menu | july_menu.id | pkMenu |
| pk_role | july_role.id | pkRole |
| pk_org | july_organization.id | pkOrg |
| pk_user | july_user.id | pkUser |

PO 中禁止其他 `*Id` 形态字段（门禁 `pk-mt`；白名单 id / pkMt / parentId / serialVersionUID）。

## 016.关联表替换策略 = toggle dr（不删不插）

UNIQUE 键覆盖全部行（含 dr='1'）——同一组合**永远只有一行**：

```sql
-- 分配：行存在则复活，不存在才插入（Mapper.revive + insert）
UPDATE july_user_role SET dr = '0' WHERE pk_mt = ? AND pk_role = ?;
-- 取消：置 dr='1'（Mapper.stop）
UPDATE july_user_role SET dr = '1' WHERE pk_mt = ? AND pk_role = ?;
```

杜绝"删旧+插新"在唯一键下的第二次整存冲突与行堆积。

## 017.审计填充链路

```text
GlobalAuthFilter 验签 → request.setAttribute(FrameConst011.OPERATOR_ID, userId)
  → AuditMetaObjectHandler（MyBatis-Plus 回调）经 RequestContextHolder 读出
  → create_by / update_by 自动填充（时间列同理）
application 层需要身份时：Controller 读 attribute 显式传参（application 不碰 web 概念）
```

- 自定义 ThreadLocal OperatorContext **已判定不必要并删除**（RequestContextHolder 即 Spring 自带的请求级载体）；
- 审计写入（july_user_audit）走 UserAuditRecorder：REQUIRES_NEW 独立事务——业务回滚绝不吞审计行；append-only 只插不改不删。

## 019.CommonMapper 约束

原生 SQL 仅限维护场景（如 physicalDelete）：`${sql}` 裸拼，**调用点必须白名单校验**（SAFE_ID `[A-Za-z0-9_-]{1,33}`）；表名只能来自开发者常量 getTableName()。
