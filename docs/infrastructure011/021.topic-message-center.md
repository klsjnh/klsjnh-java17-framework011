## 011.命题

**一个消息中心，渠道可插拔。** 框架只提供**统一发送契约 + 渠道注册表 + 表驱动配置**，并内置少量渠道；**站内信 / 短信 / 企业微信 / 飞书 / 钉钉 / 邮件 / 自定义** 由**使用者实现适配器并配置**，不改框架。

> 业务域只管「发什么、给谁、用哪条模板」；**怎么发**交给渠道适配器（与存储中心「厂商分期、适配器可插拔」同思路）。

## 015.领域与技术形态（**出入两套**：SPI + 注册表 + 表驱动）

**出站（outbound）与入站（inbound）各自独立、对称**——渠道/模板/记录各两套，东向（发）与西向（收）不共用实体。

```
domain.messagecenter
  outbound.channel
    MessageChannelPort   channelCode() ；send(MessageCommand) → MessageResult   ★ 出站 SPI
    MessageCommand       record（channelCode / to / messageType / config / payload / templateCode / params / title / content）
    MessageResult        record（success / channelMessageId / error）
    JulyOutboundChannel  渠道配置聚合（+ QuerySpec / Repository）
  outbound.template
    JulyOutboundTemplate 模板聚合（+ QuerySpec / Repository）
  outbound.message
    JulyOutboundMessage  发送记录聚合（+ QuerySpec / Repository；status = MessageStatus011 1/2/3）
  inbound.channel
    MessageInboundPort   channelCode() ；parse(config, rawBody) → InboundMessage ；encodeReply(InboundReply) → String  ★ 入站 SPI
    InboundMessageListener  supports(channelCode) ；onMessage(InboundMessage) → InboundReply（null=不回）  ★ 业务桥接 SPI
    InboundMessage        record（channelCode / providerType / fromId / messageType / payload / content / rawMessageId / remark）
    InboundReply          record（messageType / payload / content）
    JulyInboundChannel    入站渠道配置聚合（+ QuerySpec / Repository）
  inbound.template
    JulyInboundTemplate   入站模板聚合（+ QuerySpec / Repository）
  inbound.message
    JulyInboundMessage    接收记录聚合（+ QuerySpec / Repository；status = MessageInboundStatus011 1/2/3）

application.messagecenter
  outbound.channel : MessageChannelRegistry(List<MessageChannelPort>) · JulyOutboundChannelUseCase
  outbound.message : MessageOutboundUseCase（解析渠道 → 渲染模板 → 发送 → 落记录）
  outbound.template: JulyOutboundTemplateUseCase
  inbound.channel  : MessageInboundRegistry(List<MessageInboundPort> + List<InboundMessageListener>) · JulyInboundChannelUseCase
  inbound.message  : MessageInboundUseCase（解析 → 去重 → 落库 → 分发监听 → 被动回复）
  inbound.template : JulyInboundTemplateUseCase

infrastructure.messagecenter
  outbound.{entity,mapper,repository} : JulyOutbound{Channel,Template,Message}Po/…
  outbound.channel : InAppMessageChannel · WebhookMessageChannel（内置出站渠道）
  inbound.{entity,mapper,repository}  : JulyInbound{Channel,Template,Message}Po/…
  （厂商渠道/接收适配：使用者实现 MessageChannelPort / MessageInboundPort 并 @Component 即注册）
```

### 017.1 报文形态：`messageType` + `payload`（**通用透传位，非厂商标准**）

框架**不认识任何厂商形态**。发送契约只开两个中性字段，原样透传给渠道端口（`MessageCommand`）：

- **`messageType`**（开放字符串）：**渠道自定义**的报文形态名，框架**不校验、不解释**；
- **`payload`**（键值 map，落库为 JSON）：形态专属参数，键由渠道自定。

| 维度 | 谁定义 | 示例（**渠道自定，非框架约定**） |
|------|--------|----------------------------------|
| `messageType` | 渠道插件 | `text` / `image` / `file` / `audio` / `card` …（各厂商叫法不同） |
| `payload` | 渠道插件 | `image_key` / `file_key` / `url` / `btntxt` … |
| `config` | 渠道实例（表） | `url` / `corpId` / `appKey` … |

> **否定清单**：厂商专属形态名、素材上传（换 `media_key`/`image_key`）、消息接收（回调/**长连接 WebSocket**）、回复/撤回/加急/Pin —— **都不是框架能力**，归渠道插件/使用者（见 §025.3）。

## 021.扩展与运行

- **出站扩展**：实现 `MessageChannelPort` + `@Component` + 插一行 `july_message_outbound_channel`；**无需改框架**。
- **入站扩展**：实现 `MessageInboundPort`（解析渠道报文/长连事件）+ `InboundMessageListener`（业务桥接，可返回被动回复）+ 插一行 `july_message_inbound_channel`；**无需改框架**。
- **入站流程**（`MessageInboundUseCase.receive`）：解析 → **去重**（`uk(channel_code,raw_message_id)`）→ 落库（`status=1 已接收`）→ 遍历监听器分发（异常隔离，返回首个非空 `InboundReply`）→ `MessageInboundPort.encodeReply` 写回 HTTP 响应（同步被动回复）；异步回复由监听器自行调**出站 send**。
- **异步/重试**：出站先同步发送 + 记录；`retry_count` 接 [022 julyScheduler] 做定时重试。
- **模板**：轻量 `${var}` 替换，不引模板引擎。
- **密钥**：`config` JSON 中密钥出参打码；加密二期（与存储/AI 密钥同口径）。
- **HTTP**：渠道的 HTTP 调用统一走 `com.klsjnh.common.util.HttpUtil011`（JDK HttpClient 薄封装，`get`/`postJson`，返回 `HttpResponse011(status, body)`）。

## 025.接入指南：实现并注册一个渠道（依赖 + 扫描 + SPI）

使用者挂自己的渠道 = **Maven 依赖 + 组件扫描 + 实现 SPI 端口 + 插一行渠道配置**，**不改框架**。

### 025.1 机制（一句话）
底座只做**路由**：用 `providerType`（字符串 code）到注册表里找到**你注册的实现类**，把请求交给它；
渠道参数（企微 corpId / 短信 ak/sk …）**随 `MessageCommand.config` 整份透传给你**，你**不需要、也不要**回查 `JulyOutboundChannelRepository`。

```
使用者 @Component 实现 MessageChannelPort（channelCode() 返回 "wecom"）
   → Spring 收集进 MessageChannelRegistry
   → 底座 send(channelCode=july_message_outbound_channel.provider_type)
   → 路由到你的实现类 .send(cmd)   // cmd.config() 里有整份渠道配置
```

### 025.2 步骤

**1) 依赖框架构件**（先用 `mvn install` 把框架装进本机 `.m2`）
```xml
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-common011</artifactId><version>1.0.0</version></dependency>
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-domain011</artifactId><version>1.0.0</version></dependency>
<!-- application / infrastructure / web 按需 -->
```

**2) 应用扫描框架包 + 自己的包**（关键：漏了框架包 → 注册表/用例不会被实例化，插件挂不上）
```java
@SpringBootApplication(scanBasePackages = { "com.klsjnh", "com.yourcompany" })
@MapperScan({ "com.klsjnh.infrastructure.iam", "com.klsjnh.infrastructure.persistence.mapper",
        "com.klsjnh.infrastructure.system011", "com.klsjnh.infrastructure.datasource",
        "com.klsjnh.infrastructure.ai011", "com.klsjnh.infrastructure.storagecenter",
        "com.klsjnh.infrastructure.messagecenter", "com.yourcompany.**.mapper" })
public class YourApp { public static void main(String[] a) { SpringApplication.run(YourApp.class, a); } }
```

**3) 实现渠道端口（SPI，自动收集）**
```java
package com.yourcompany.msg;

import com.klsjnh.domain.messagecenter.channel.MessageChannelPort;
import com.klsjnh.domain.messagecenter.channel.MessageCommand;
import com.klsjnh.domain.messagecenter.channel.MessageResult;
import org.springframework.stereotype.Component;

@Component
public class WeComMessageChannel implements MessageChannelPort {

    @Override
    public String channelCode() {
        return "wecom";                       // ← 路由键：与 july_message_outbound_channel.provider_type 一致
    }

    @Override
    public MessageResult send(MessageCommand command) {
        // 整份渠道配置都在这里，无需回查仓储
        String corpId     = command.config().get("corpId");
        String corpSecret = command.config().get("corpSecret");
        String agentId    = command.config().get("agentId");

        try {
            // 调用企业微信 SDK：command.to() / command.title() / command.content()
            String msgId = ...;
            return MessageResult.success(msgId);            // 成功
        } catch (Exception ex) {
            return MessageResult.failure(ex.getMessage());  // 失败（落库 FAILED + error）
        }
    }
}
```
> 框架注册表构造注入 `List<MessageChannelPort>`，Spring 自动把**框架内置（`inapp`/`webhook`）+ 你的插件**一起收集，按 `channelCode()` 路由。

**4) 插一行渠道配置**（纯配置，无需代码）
```sql
INSERT INTO july_message_outbound_channel
  (id, channel_code, channel_name, provider_type, config, status)
VALUES
  (REPLACE(UUID(),'-',''), 'wecom_hr', '企微-人力资源', 'wecom',
   '{"corpId":"ww...","corpSecret":"...","agentId":"1000002"}', '1');
```
- **路由键链路**：`provider_type = "wecom"` → 找到 `WeComMessageChannel`（`channelCode()="wecom"`）；
- `config` 就是 `command.config()` 里那整份 map（webhook 从里面取 `url`，企微取 `corpId/...`）。
- 模板：`july_message_outbound_template`（`${var}` 占位，绑定 `channel_code`）。

**5) 调用底座消息中心**（`messageType` / `payload` 均为**渠道自定义**，透传）
```json
POST /klsjnh/messagecenter/julyMessage/v1/send
{ "channelCode": "wecom_hr", "to": "zhangsan", "messageType": "textcard",
  "payload": { "url": "https://...", "btntxt": "详情" },
  "title": "休假通知", "content": "张三 10-01 休假" }
```
底座解析渠道 → 渲染模板 → **按 `providerType` 路由到你的渠道插件** → 落发送记录（SUCCESS/FAILED + error）。
渠道插件从 `command.config()` 取连接配置、从 `command.messageType()`/`command.payload()` 取形态与载荷。

### 025.3 边界（**厂商渠道 = 使用者插件，非框架能力**）
- 框架只出 `inapp` / `webhook` 两个**通用**内置渠道；**企微 / 飞书 / 钉钉 / 短信 等厂商渠道一律由使用者（或业务底座）实现**，框架**不认识**其形态名、连接方式。
- **禁止**在渠道实现里回查 `JulyOutboundChannelRepository` 取自己的配置——配置已在 `command.config()`。
- **否定清单（框架不做）**：厂商形态名（如 `textcard`/`post`/`interactive`）、**素材上传**（换 `image_key`/`file_key`）、**消息接收**（回调 / **长连接 WebSocket，走厂商 SDK 免公网 URL**）、回复 / 撤回 / 转发 / 加急 / Pin / 群历史 / 通讯录 / 审批。
- 渠道的 HTTP 调用统一用 `com.klsjnh.common.util.HttpUtil011`（勿各自 new HttpClient）。

> **临时说明**：若在框架侧临时验证过某厂商渠道（如飞书），它**不改变上述边界**——最终**移出框架**，由使用者/业务底座承载。

**同款先例**：框架 `ExportProvider` / `ExportProviderRegistry(List<ExportProvider>)`、存储中心适配器工厂，都是同一机制。

## 026.选型：渠道「实现型 SPI」（非工厂型）

| | 工厂型（存储中心 / 数据源） | **实现型（消息中心 · 本选型）** |
|---|---|---|
| 扩展 | 框架按 `providerType` **new 适配器**；加厂商要改框架 | 使用者实现 `MessageChannelPort` + `@Component`；**插件化，不改框架** |
| 适用 | 技术种类少、**每实例一套连接配置** | 厂商多且长尾、**每渠道一份配置、实例单一** |
| 配置 | `july_storage_provider` 每实例一行（`july_storage_provider_bucket` 每桶一行） | `july_message_outbound_channel`（出）/ `july_message_inbound_channel`（入）每 `channelCode` 一行 |
| 发现 | `ObjectStorageProviderRegistry`（查 `ObjectStorageProviderFactory`）+ `StorageResolver011` | `MessageChannelRegistry(List<MessageChannelPort>)` 自动收集 |

**裁定**：消息渠道采用**实现型 SPI**（出站 `MessageChannelPort`、入站 `MessageInboundPort` + 各自注册表 + 各自渠道表配置）；**存储/数据源维持工厂型**（多实例 + 连接配置）。判据 = **是否需要「同技术多实例 + 每实例连接」**：是→工厂型，否→实现型。
