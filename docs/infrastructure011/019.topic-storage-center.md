### 015.1 多厂商策略（2026-09-13 讨论定案）

**每厂商一个适配器（用户定案）**：MinIO011 专门服务自部署场景；各云厂商独立适配器（原生 SDK），保留厂商专属能力（COS 数据万象 / OSS 图片处理等）。命名用 **Adapter**（端口实现惯例；Provider 留给 Spring 供给者语义）。

| 适配器 | 后端 | SDK | 落地节奏 |
|--------|------|-----|----------|
| LocalObjectStorageAdapter | 本地盘 | java.nio.file | ✅ 本期 |
| MinioObjectStorageAdapter | 自部署 MinIO011 | MinIO SDK | ✅ 本期（Docker 可实测） |
| CosObjectStorageAdapter | 腾讯云 | cos_java_sdk | 分期：用到即落 |
| TosObjectStorageAdapter | 火山 TOS | tos-java-sdk | 分期 |
| OssObjectStorageAdapter | 阿里 OSS | oss-java-sdk | 分期 |
| S3ObjectStorageAdapter | AWS / 其他 S3 兼容 | aws-sdk | 分期 |

端口（ObjectStoragePort）与枚举（StorageType011 六个类型位）第一天就定死——架构从第一天是对的，代码按需生长。

### 015.2 端口语义

- put 返回最终 key（含路径规整）；get 缺对象返回 null；list 按 prefix 前缀过滤；
- 存储中心异常统一转 IllegalStateException（适配器层），由全局异常处理器出站。

## 017.关系与联动

- 适配器选择由 `StorageType011` ↔ `krt.storage-center.default-type` 绑定（KrtConfig011 同款绑定 + 启动卫兵风格，未知值启动失败）；
- 业务侧（将来的附件/导出等特性）只依赖 domain 的 `ObjectStoragePort`，不感知具体厂商。

## 021.二期清单（P0 已于 2026-09-13 落地：桶 CRUD + stat + get/delete 语义对齐，双适配器 local/minio E2E 过）

> **管理面整体（存储实例表 + HTTP CRUD + 在线编辑）不在本底册**，见 [037 迁移方案](../requirement013/037.topic-storage-migration.md)。

- **流式上传下载**：端口 byte[] 形态整个对象进堆，大文件 OOM 风险——加 InputStream 形态 put/get；
- **list 分页 + 目录形态**：现 list 一次性拉全桶 key，规模化后需分页 + delimiter（按 `/` 切"文件夹"公共前缀）；
- **copy / rename（move）**：现改名 = get 全量 + put + delete，大文件三次搬运；
- 各厂商**原生 SDK 适配器**（cos011 / tos011 / oss011 / s3011）：用到即落，端口不动。

## 025.边界外（不做）

- 预签名 URL 直传前端、分片上传 / 断点续传、桶生命周期/配额/策略、多 provider 并存路由（java8 providers map 形态）。

## 023.决策点（2026-09-13 讨论定案）

| # | 决策点 | 结论 |
|---|------|------|
| 1 | 架构形态 | ✅ **每厂商一个 Adapter**（不做单 S3 通吃）：MinIO011 专门服务自部署；原生 SDK 保留厂商能力；命名 Adapter 非 Provider |
| 2 | 类型值口径 | ✅ **java8 011 后缀**：local011 / minio011（cos011 / tos011 / oss011 / s3011 预留）；StorageType011 六位全定 |
| 3 | 落地节奏 | ✅ 本期落 local011 + minio011（Docker MinIO 实测）；厂商适配器用到即落，端口不动 |
| 4 | bucket 不存在时自建 vs 报错 | 沿 java17011：**自建**（default-bucket） |
