# 019.topic-storage-center（存储中心）

> 阶段：**架构底册（横切视角）** —— 对象存储统一端口：本地盘 / S3 兼容多厂商。
> 参考来源：java17011 最新 DDD 实现（ObjectStoragePort / StorageProperties / Local / Minio 双适配器）。
> **核心诉求（用户定）**：兼容 local + MinIO + 腾讯 COS + 火山 TOS + 各主流厂商 S3/OSS。
> **管理面迁移方案**：[requirement013/029.topic-storage-migration](../requirement013/029.topic-storage-migration.md) —— 表驱动多实例（`july_storage_provider` 主 + `july_storage_provider_bucket` 子）+ 实例/桶/对象管理 + 在线文本编辑（本底册只含端口层，管理面见 029）。
> **扩展点口径（2026-09-19 定案）**：存储 = **工厂型 + provider 注册表**。provider 是**开放字符串**（`StorageProviderCodes011` 常量，**不再是 `StorageType011` 枚举**）；使用者实现 `ObjectStorageProviderFactory` bean 即插即用，**不改底座**（016 §6.5）。

## 013.配置定义（krt.storage-center）

```yaml
krt:
  storage-center:
    default-type: local011       # 本期：local011 | minio011（cos011 / tos011 / oss011 / s3011 预留位）
    local011:
      base-path: ./storage011    # 本地对象根目录
      default-bucket: backup011  # 本地默认桶（目录名），物理位置 = base-path/default-bucket
    minio011:                    # 自部署 MinIO011
      endpoint: http://192.168.1.88:9000
      access-key: <ak>
      secret-key: <sk>
      default-bucket: klsjnh011  # MinIO 默认桶
```

> 默认桶声明在适配器下（`local011.default-bucket` / `minio011.default-bucket`），按 `default-type` 生效；`backup011` 写的就是它（空白则回退实例行 `july_storage_provider_bucket` 中 `is_default=1` 的桶）。

## 015.方案（沿用 java17011 结构，一处更名）

```
java17-common011
  com.klsjnh.common.constant.StorageProviderCodes011  内置 provider 字符串常量（**非枚举**）：
                                                LOCAL="local011" / MINIO="minio011" / S3="s3011"
                                                （cos011 / tos011 / oss011 等由使用者扩展，无需进底座）
java17-domain011
  com.klsjnh.domain.storagecenter.object.ObjectStoragePort   对象：put / get / delete / exists / stat(元数据) / list(bucket,prefix)
                                                桶：bucketExists / createBucket / deleteBucket(非空大声失败) / listBuckets
  com.klsjnh.domain.storagecenter.object.ObjectStorageFactoryPort   按连接配置构造适配器（工厂端口）
  com.klsjnh.domain.storagecenter.object.ObjectStorageProviderFactory  **SPI（开放扩展点）**：
                                                List<String> providers() 返回厂商 code（开放字符串）+ create(config)
  com.klsjnh.domain.storagecenter.object.ObjectStat          元数据 record（size / lastModified / contentType）
java17-infrastructure011
  com.klsjnh.infrastructure.storagecenter.object.ObjectStorageProviderRegistry  工厂实现：注入 List<ObjectStorageProviderFactory>
                                                → Map<providerCode, factory> 查表构造；未知 code 大声失败
  com.klsjnh.infrastructure.storagecenter.object.provider.LocalStorageProviderFactory  内置 local011（@Component）
  com.klsjnh.infrastructure.storagecenter.object.provider.MinioStorageProviderFactory  内置 minio011 / s3011（@Component）
  com.klsjnh.infrastructure.storagecenter.object.adapter.LocalObjectStorageAdapter   java.nio.file 落盘
  com.klsjnh.infrastructure.storagecenter.object.adapter.MinioObjectStorageAdapter   MinIO SDK（服务自部署 / S3 兼容）
启动
  S3 适配器构造时探活 + 缺桶自建（bucketExists / makeBucket，沿 java17011）
pom
  dependencyManagement + io.minio:minio 8.5.7（infrastructure 引入）
```

> **工厂型 vs 实现型（判据）**：存储需要「同技术多实例 + 每实例连接配置」→ **工厂型**（registry 按 provider 查工厂、工厂 `create(config)` 造有状态适配器）。消息中心/DB 方言是无状态策略 → 实现型（见 021 / 016 §6.5）。

### 015.1 多厂商策略（2026-09-19 修订）

**每个厂商 = 一个 `ObjectStorageProviderFactory`（+ 其适配器）**：底座内置 local011 / minio011 / s3011；其余云厂商（cos011 / tos011 / oss011 …）**由使用者实现 SPI bean 即插，不改底座**。命名：SPI 用 **ProviderFactory**（供给者语义），端口实现用 **Adapter**（六边形惯例）。

| provider code | 工厂 / 适配器 | 后端 | SDK | 落地节奏 |
|---------------|---------------|------|-----|----------|
| local011 | LocalStorageProviderFactory / LocalObjectStorageAdapter | 本地盘 | java.nio.file | ✅ 内置 |
| minio011、s3011 | MinioStorageProviderFactory / MinioObjectStorageAdapter | 自部署 MinIO / S3 兼容 | MinIO SDK | ✅ 内置 |
| cos011 | 使用者实现 | 腾讯云 | cos_java_sdk | 用到即落（**不动底座**） |
| tos011 | 使用者实现 | 火山 TOS | tos-java-sdk | 同上 |
| oss011 | 使用者实现 | 阿里 OSS | oss-java-sdk | 同上 |

端口（`ObjectStoragePort`）与 SPI（`ObjectStorageProviderFactory`）第一天定死；provider code 用**开放字符串**、按需生长，**不再用封闭枚举**。

使用者扩展样例（不改底座）：

```java
@Component
class OssProviderFactory implements ObjectStorageProviderFactory {
    public List<String> providers() { return List.of("oss011"); }
    public ObjectStoragePort create(StorageConnectionConfig c) { return new OssObjectStorageAdapter(c); }
}
// july_storage_provider.provider = 'oss011' → 生效
```

### 015.2 端口语义

- put 返回最终 key（含路径规整）；get 缺对象返回 null；list 按 prefix 前缀过滤；
- 存储中心异常统一转 IllegalStateException（适配器层），由全局异常处理器出站。

## 017.关系与联动

- 适配器选择由 `provider` code ↔ `krt.storage-center.default-type`（引导默认）/ `july_storage_provider.provider`（运行时实例）绑定，经 `ObjectStorageProviderRegistry` 查厂构造；未知 code 在构造时报错（内置引导默认值用 `StorageProviderCodes011` 判断）；
- 业务侧（附件/导出等特性）只依赖 domain 的 `ObjectStoragePort`，不感知具体厂商；
- 消费方注入 `ObjectStorageFactoryPort` 端口（注册表实现该端口），故换注册表实现对调用方零改动。

## 021.二期清单（P0 已于 2026-09-13 落地：桶 CRUD + stat + get/delete 语义对齐，双适配器 local/minio E2E 过）

> **管理面整体（存储实例表 + HTTP CRUD + 在线编辑）不在本底册**，见 [029 迁移方案](../requirement013/029.topic-storage-migration.md)。

- **流式上传下载**：端口 byte[] 形态整个对象进堆，大文件 OOM 风险——加 InputStream 形态 put/get；
- **list 分页 + 目录形态**：现 list 一次性拉全桶 key，规模化后需分页 + delimiter（按 `/` 切"文件夹"公共前缀）；
- **copy / rename（move）**：现改名 = get 全量 + put + delete，大文件三次搬运；
- 各厂商**原生 SDK 适配器**（cos011 / tos011 / oss011 / s3011）：用到即落，端口不动。

## 025.边界外（不做）

- 预签名 URL 直传前端、分片上传 / 断点续传、桶生命周期/配额/策略、多 provider 并存路由（java8 providers map 形态）。

## 023.决策点（2026-09-13 讨论定案）

| # | 决策点 | 结论 |
|---|------|------|
| 1 | 架构形态 | ✅ **每厂商一个 Adapter**（不做单 S3 通吃）：MinIO011 专门服务自部署；原生 SDK 保留厂商能力；命名 Adapter 非 Provider |
| 2 | 类型值口径 | ✅ **java8 011 后缀 + 开放字符串**：内置 local011 / minio011 / s3011（`StorageProviderCodes011` 常量）；cos011 / tos011 / oss011 等由使用者扩展。~~StorageType011 枚举~~ 已删除（2026-09-19） |
| 3 | 落地节奏 | ✅ 本期落 local011 + minio011（Docker MinIO 实测）；厂商适配器用到即落，端口不动 |
| 4 | bucket 不存在时自建 vs 报错 | 沿 java17011：**自建**（default-bucket） |
