## 011.命题

提示词管理开建，采用**主子表**。**提示词编码全局唯一**（不按域隔离，便于跨域引用与检索）。

## 013.两种读法（先对齐）

| 读法 | 主表 | 子表 | 说明 |
|------|------|------|------|
| **A（我推荐）** | **业务域 / 命名空间** | **提示词** | 域是稳定分组；提示词挂域下；`prompt_code` 全局唯一 |
| B | **提示词**（`prompt_code` 全局唯一） | 分域变体 / 内容 | 一条提示词可按业务域出多份内容 |

> 你那句"主表的提示词编码必须全局唯一"两种读法都能满足——**唯一性落在承载 `prompt_code` 的那张表**。

## 015.推荐：A（主 = 业务域，子 = 提示词）

| 列 | 说明 |

## 017.提示词类型：`inline` / `storage`（两种）

| 类型 | `content_mode` | 正文存哪 | 元数据 |
|------|----------------|----------|--------|
| **小（直接写）** | `inline` | 子表 `content` 列（`TEXT`，≈2.1 万汉字 / 64KB） | — |
| **大（落存储）** | `storage` | 对象存储（实例 + 桶 + key） | `storage_code` / `bucket` / `object_key` / `content_hash` / `content_size` |

子表 `july_ai_prompt` 增列：

```
content_mode  inline | storage（默认 inline）
content       正文（`TEXT`；inline 时用；storage 时留空）—— 64KB / ≈2.1 万汉字
storage_code  storage 时选：存储实例（下拉，来自存储中心；缺省=默认实例）
bucket        storage 时选：桶
object_key    平台生成的对象 key（如 prompt/<domain>/<prompt_code>.md）
content_hash  内容 hash（变更检测 / 去重）
content_size  字节数
```

- **阈值**：`inline` 上限 **64KB（TEXT 上限）**，超过才 `storage`——3000–6000 字（≈9–18KB）一律 `inline`；
- **操作流程**：
  1. 新建/编辑先选 `content_mode`；
  2. `inline` → 文本框直接写；
  3. `storage` → 选**存储实例**（下拉：存储中心可用实例）→ 选**桶**（下拉：该实例的桶）→ 平台 `put`，DB 只存指针；正文**平台内编辑**或**上传文件**（`.md`/`.txt`/`.sql`）；读取时平台 `get` 回来渲染；
  4. **内容随元数据由平台管理**：改 → `put` 新对象（带 hash）→ 换指针 → 删旧；删元数据 → 删对象；
- **桶怎么选（待定）**：A 选实例+选桶 / **B（倾向）** 只选实例、桶用约定桶（如 `ai-prompt`，不存在则自建） / C 平台固定桶。
