## 011.问题

提示词会**很多**（多系统、多场景），需要**统一管理**。它是**业务能力**还是**平台能力**？

## 013.两种主张

| 主张 | 理由 |
|------|------|
| **业务能力** | 提示词是业务内容，语义属于具体业务；平台不该掺和 |
| **平台能力** | 机制横切、多系统共用；服务"AI 开发"；集中才管得住 |

## 015.倾向判断：机制归平台，内容归业务

| 维度 | 归属 |
|------|------|
| **管理机制**（存储 / CRUD / 变量渲染 / 启停 / 分区） | **平台能力** |
| **具体提示词内容**（一行行 prompt） | **业务资产**（各系统自填自管） |

理由：

1. **横切**：推理要、图片要（prompt）、以后语音也可能要 → 天生平台件；
2. **服务 AI 开发**：要的是"给 `promptCode` + 参数拿渲染结果"，而不是各自硬编码字符串；
3. **本仓先例**：消息中心 `july_message_outbound_template`（`template_code` + `${var}`）就是平台能力；
4. **一个事实一个家**：提示词散落各业务 → 改不动、查不到；集中才能统一。

> 类比：平台给"仓库"（机制），业务放"货"（内容）——如 `july_config` / `july_dictionary`。

## 016.若做平台件：形态草案

```
july_ai_prompt            提示词模板
  prompt_code   模板编码（命名空间内唯一）
  namespace     命名空间（系统 / 业务域，做隔离）
  prompt_name   名称
  content       模板正文（${var} 占位）
  variables     变量声明（可空）
  scene         适用能力（inference / image / tts，开放字符串，**仅分类**）
  sort_order / status / 审计 / dr
```

- **渲染**：`${var}` 替换（与消息模板同语法，不引模板引擎）；
- **入口**：HTTP CRUD（管理面）+ 程序读入口 `render(promptCode, params)`（供 AI 开发注入）；
- **与 provider 解耦**：模板**不绑定**模型 / provider（遵守"model 由调用方直传"）。

## 017.放哪（候选）

| 方案 | 说明 |
|------|------|
| **A（倾向）** | AI 中心**管理面能力**，与 provider / 密钥管理并列——支撑推理/图片的公共管理件 |
| B | 独立"提示词中心"（自成目录，与存储/消息中心同级） |
| C | 不做平台件，各业务自管 |

## 018.子话题：大提示词的内容存储与 CRUD 拆分

**问题**：提示词可能很大，正文放 MinIO；那"提示词的 CRUD"该怎么拆？

**拆分原则**：按**变化频率 + 存储介质 + 一致性边界**拆成三个内聚子能力。

| 子能力 | 介质 | 职责 |
|--------|------|------|
| **PromptCatalog 目录** | DB | `code / namespace / name / scene / variables / status` + **内容指针**（`content_inline` 或 `storageKey / hash / size`）——**不含正文** |
| **PromptContent 内容** | 对象存储（MinIO） | 大文本读写（复用存储中心 `ObjectStoragePort`；≤1MB 可复用在线编辑）；覆盖 / 删除 |
| **PromptRender 渲染** | 应用层（只读） | 按 code 取指针 → 取内容（inline 或对象）→ `${var}` 替换 |

**大小分流（二选一）**

- **A（倾向）统一走对象存储**：DB 只存指针，一致、无两套路径；小提示词多点 I/O 可接受；
- B 阈值分流：≤N KB inline DB、>N KB 落对象；省 I/O，但两套路径 + 迁移复杂。

**CUD 一致性**

- 写：先 `put` 新对象（key 带 hash）→ 更新 DB 指针（事务）→ 成功后删旧对象；
- 删：逻辑删 DB → 删对象；
- `hash` 防并发覆盖 + 变更检测。

**端点拆分**

- 目录：`julyAiPrompt/v1/insert | update | logicDelete | getById | selectListByPage`
- 内容：`julyAiPrompt/v1/getContent | saveContent`（大文本）
- 渲染：`julyAiPrompt/v1/render`

> **与"产物生命周期归使用方"不冲突**：AI 产物是**用户的东西**（归使用方管）；提示词是**平台自身数据**，其对象**随元数据由平台管理**（删元数据即删内容）。

## 019.待决策

2. **命名空间**：按系统/业务域分区隔离？（倾向要，否则多系统撞 `promptCode`）；
3. **变量语法**：沿用 `${var}`？
4. **`scene` 字段**：要不要（倾向要，纯分类不参与路由）；
5. **归属**：A / B / C；
6. **渲染入口**：是否作为推理模块的公共件暴露给 AI 开发；
7. **大提示词**：统一走对象存储（A）还是阈值分流（B）？
8. **内容存储实例**：提示词正文用哪个存储实例（MinIO / 默认）？

## 020.边界（若做）

- 不做模板引擎（只 `${var}`）；不做 A/B 测试；不做提示词评估/打分；不做多语言版本。
