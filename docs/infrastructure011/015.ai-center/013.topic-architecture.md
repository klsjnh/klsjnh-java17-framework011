## 011.分层总览

```
web          AiInferenceController · AiImageController · AiAudioController · AiModelProviderController
              │
application  AiInferenceUseCase（对 service 开放）· AiImageUseCase · AiTtsUseCase · AiAsrUseCase
             AiModelProviderUseCase · AiProviderResolver · AiCapabilityRegistry · AiMediaStorageGate
              │
domain       AiInferencePort / AiImagePort / AiTtsPort / AiAsrPort（能力 SPI）
             AiCapabilityPort（能力标记）· AiInvokeTarget · AiMedia · AiCapabilityCodes
             AiMediaStorePort（产物落盘端口）· AiModelProvider / AiModelProviderApi
              ▲
                media.AiMediaStore011（→ StorageResolverPort）
                modelprovider.{entity,mapper,repository,probe}
```

依赖铁律不变：`web → application → domain ← infrastructure`；业务侧只依赖 domain 端口。

## 015.能力模块一：推理 `inference`

**定位**：AI 开发的统一入口——给提示词直接出内容。

- **端口**：`AiInferencePort`（`infer` 同步 / `stream` 流式）；
- **双开放**：`AiInferenceController`（HTTP）+ `AiInferenceUseCase`（内部注入）；
- **流式**：`stream(cmd)` 返回分片流，web 层以 **SSE**（`text/event-stream`，Spring MVC `SseEmitter`）输出；
- **不落盘**（纯文本），不受存储闸约束。

```
AiInferenceCommand(baseUrl, apiKey, target, messages, temperature, maxTokens)
   → AiInferencePort.infer(...)  → AiInferenceResult(content, finishReason, usage)
   → AiInferencePort.stream(...) → Stream<AiInferenceChunk> → SSE
```

## 016.能力模块二：图片 `image`

- **文生图**：有 prompt、无输入图；
- **图生图**：带 `imageUrl` / `imageBase64` 即切换（沿用现判据）；
- **产物落盘**：生成结果经 `AiMediaStorePort` 落地，返回引用；**生命周期归使用方**。

## 017.能力模块三：语音 `audio`

- **TTS**：文本 → 音频（产物落盘）；
- **ASR（新增）**：音频 → 文本。输入音频可由使用方提供本地路径 / storage 引用 / base64；识别产物是**文本**（不落盘）；
- 两者都是 `audio` 模块下的能力 code：`tts` / `asr`。

## 018.模型接入（provider + 密钥）

沿用 [requirement013/028](../../requirement013/028.topic-aicenter.md) 的主子表设计，**仅包名归位**：

- `july_ai_model_provider`（主：`provider_code` 不可变 / `provider_name` / `base_url` / `models` / `sort_order` / `status`）；
- `july_ai_model_provider_api`（密钥子表：`pk_mt` / `api_code` / `api_key` / …）；
- 密钥**类型层脱敏**（VO 不定义 `api_key` 字段），`update` 留空保持；
- 程序读入口 `getByCode` / `getApiList` / `getDefaultApi`（无 HTTP）；
- 探测 `testConnection`（HTTP 恒 200，结果在载荷）。

## 019.能力路由（代码承载，不进管理面）

**AI 管理面只管 provider + api key**——一个 api key 可对应多个模型，**模型/能力映射不在管理面建模**。

- **能力不落表、不声明**：provider 支持哪种能力，由**能力端口实现**的 `supports(providerCode)` 在**代码层**决定；
- **路由**：用例按能力找端口，命中即调用，**无实现 → 400**（现有行为）；
- "是否用了生图/生语音"**看调用**，不看配置——本地存储闸挂在图片/语音用例上。

```
AiCapabilityRegistry(List<AiCapabilityPort>)
   port(capabilityCode, providerCode) → 命中的能力端口
       ├─ 无实现 → 400
       └─ 命中 → 用例调用该端口的 invoke
```

> **加能力不改注册表**：注册表按 `(capability, provider)` 通用查表，新能力只需新增端口接口 + 实现 + code。

## 020.产物落盘（生命周期归使用方）

```
AiImageUseCase / AiTtsUseCase
   → 生成 AiMedia（bytes/b64）
   → AiMediaStorePort.save(media) → AiMediaRef(storageKey, url, mime, size)
   → 返回引用给调用方
AiMediaStore011
   → StorageResolverPort.resolve(storageCode).put(bucket, key, bytes, mime)
```

- **落盘走存储中心端口**，存储中心**零改动**；
- **本地存储闸**：调用图片/语音**前**检测本地实例（`provider=local011` 且启用）；无 → **WARN 一次 + 拒绝服务**（快速失败，不关停应用）；
- **生命周期**：AI 中心只**产生并返回引用**，存储中心只**存取**——**何时删由使用方决定**（用完即删 / 留存）。AI 与存储都**不做** TTL、不做定时清理。
