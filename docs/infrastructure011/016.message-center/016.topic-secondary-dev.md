## 013.新出站渠道（最常见）

**实现 `com.klsjnh.domain.messagecenter.outbound.channel.MessageChannelPort`，注册为 bean 即接入**（`MessageChannelRegistry` List 自动收编；管理面建渠道行、config JSON 填参数——**零配置代码**）：

```java
package com.yourcompany.msg;

import com.klsjnh.domain.messagecenter.outbound.channel.MessageChannelPort;
import com.klsjnh.domain.messagecenter.outbound.channel.MessageCommand;
import com.klsjnh.domain.messagecenter.outbound.channel.MessageResult;
import org.springframework.stereotype.Component;

@Component
public class DingTalkMessageChannel implements MessageChannelPort {

    @Override
    public String channelCode() {
        // 开放字符串；与 july_message_outbound_channel.provider_type 一致
        // MessageProviderTypes011 仅登记内置常量，禁封闭枚举做路由键
        return "dingtalk";
    }

    @Override
    public MessageResult send(MessageCommand command) {
        // config JSON 整份在 command.config()；解析失败要有日志
        // HTTP 统一走 common.util.HttpUtil011；响应体大小设上限
        // 返回 MessageResult（成功 / 失败 + 渠道侧回执），记录由 MessageOutboundUseCase 落表
        return MessageResult.success(/* channelMsgId */);
    }
}
```

**纪律与参照**：

- 参照物：`infrastructure.messagecenter.outbound.channel.WebhookMessageChannel`（HTTP 型，**转义回归单测**是渠道测试样板）/ `InAppMessageChannel`（落库型）；
- 活示例（厂商渠道）：兄弟工程 `yw-java17-basemodule011` 的 `WeComMessageChannel` / `FeishuMessageChannel`（依赖 `center-message011-starter`，宿主只扫自己的包）；
- 单测放本模块或业务工程 `src/test`（Mockito，不起 Spring 上下文）；
- gate 强制项：文件头块 / Javadoc 英文 / funcName 日志占位符 / `*011` 命名。

## 015.新入站源

**契约：Port + 至少一个 `supports` 的 Listener**（框架强制）。只实现 Port、只落库不算接完——`MessageInboundUseCase.receive` 在零 Listener `supports` 时抛 `BusinessException.badRequest`。

1. 实现 `domain.messagecenter.inbound.channel.MessageInboundPort`（`channelCode` / `parse` / `encodeReply`）；**验签 / 解密 / 防灌写在 `parse`**（读渠道 config 的 token/secret），框架不代验签，不要另造平行鉴权；
2. 实现 `InboundMessageListener`（**必选**，`supports` / `onMessage` → `InboundReply` 或 `null`）；
3. 插 `july_message_inbound_channel`；厂商 HTTP 回调 → `POST …/julyInboundMessage/v1/receive?channelCode=…`，body=`{ "rawBody": "…" }`（见 [015](015.topic-usage.md)）；
4. 去重：`uk(channel_code, raw_message_id)` 兜底；接收记录落 `july_message_inbound`。
5. 有 supports 但 Listener 全抛异常：现有异常隔离保留，记录标失败（可观测）；HTTP 仍可能带 messageId 返回——以记录 `status` 为准。

> HTTP 适配在 `web.messagecenter.inbound.controller.JulyInboundMessageController`（路径常量 `WebPaths011.MESSAGE_INBOUND_MESSAGE`），勿再引用扁平 `web.messagecenter.controller`。
>
> **JWT / 匿名（用法总览见 [015](015.topic-usage.md)）**：`/receive` **默认**仍要 JWT + `assertHas(RECEIVE)`。厂商匿名 HTTP 回调时，宿主把路径写入白名单（与登录同一套 `shouldNotFilter`，**不要**另造鉴权）：
> ```yaml
> krt:
>   web:
>     auth-whitelist-paths:
>       - /klsjnh/messagecenter/julyInboundMessage/v1/receive   # = WebPaths011.MESSAGE_INBOUND_RECEIVE
> ```
> **安全边界（已拍板）**：白名单旁路后（以及程序内 `receive(null,…)` / 长连）框架不再 JWT/`assertHas`；`operatorId` 为 `null`。**防灌必须由渠道 `MessageInboundPort.parse`（及 config 中的 token/secret）验签**；框架**不代**厂商验签。
>
> **长连（WebSocket）**无独立端点：插件自持连接后调 `MessageInboundUseCase.receive(operatorId, channelCode, rawBody)`（与 HTTP 同一用例）。无登录上下文可传 `null`；有登录操作人时仍走 `assertHas`。活示例：`yw-java17-basemodule011` 飞书长连 + `EchoInboundMessageListener`（[bm 021](../../../../yw-java17-basemodule011/docs/infrastructure011/021.topic-message-center.md)）。
> 出站同理：程序内发送走 `MessageOutboundUseCase.send(operatorId, MessageSendCommand)`，勿再调已删除的单参 `send(command)`。

## 018.管理面 / 表结构扩展

- 六表任何变更走 [july_center_message011.sql](../../sql/july_center_message011.sql)（DDL 单一真源，表名 `july_message_*`）；
- 字段新增全链路：PO（`pkMt` 主链纪律）→ Mapper → RepositoryImpl → UseCase → VO（`*Vo011`）→ Converter；
- **包侧对称**：`domain` / `application` / `infrastructure` / `web` 均已按 `inbound` / `outbound` 切分——改一侧先 grep 另一侧（克隆家族收敛，见 017 技术债）；
- VO 路径：`web.messagecenter.outbound.vo.{channel,template,message}` · `web.messagecenter.inbound.vo.{channel,template,message}`。

## 021.红线（本中心特别三条）

1. **渠道 code 开放字符串 + 注册表**——禁止封闭枚举做路由键（扩展不改底座是本中心的存在理由）；
2. **渠道实现无状态**——差异化全在渠道表 config JSON；config 解析失败要有日志（当前静默默认值已登记 017 债项）；
3. **记录先行**——发送 / 接收先落记录再回填结果；禁止「发送成功才落库」。
