## 011.命题

**消息中心 = 一个 starter。** `center-message011-starter` 自包含消息中心全部代码：出站（渠道 / 模板 / 消息）、入站（渠道 / 模板 / 消息）与各自管理面。消费方**引 starter 得到全部，不引则整个中心不存在**。

**出入两套对称、互不共用实体**：东向（发）与西向（收）各三张表、各一套聚合 / 用例 / HTTP；厂商渠道（企微 / 飞书 / 钉钉 / 短信）由使用者实现 SPI，**非框架能力**。

## 019.装配机制

- starter 代码在 `com.klsjnh.*.messagecenter` 包树下，由 core 的 `CoreAutoConfiguration011` 定向扫描**随 classpath 收编**。
- 出站 `MessageChannelRegistry` / 入站 `MessageInboundRegistry` 以 `List<端口>`（入站另收 `List<InboundMessageListener>`）收集实现——内置出站 `inapp` / `webhook` 随 starter 提供；厂商实现 SPI 即自动注册。
- **路由键**：渠道表 `provider_type` = SPI `channelCode()`；业务侧 `channel_code` 是渠道实例码（可多实例共用同一 SPI）。

## 025.内置渠道与扩展点

| 端口 | 方向 | 内置实现 | 扩展方式 |
|------|------|----------|----------|
| `MessageChannelPort` | 出站 | `InAppMessageChannel`（`inapp`：落库即收件箱，无外部 IO）/ `WebhookMessageChannel`（`webhook`：HTTP POST JSON → `config.url`，走 `HttpUtil011`） | `@Component` 实现端口，Registry 自动收编；插 `july_message_outbound_channel` 行 |
| `MessageInboundPort` + `InboundMessageListener` | 入站 | **无内置**（解析 / 被动回复编码全属厂商插件） | **双 SPI 均必选**（零 supports Listener → 收失败）+ 插 `july_message_inbound_channel`；回调 `julyInboundMessage/v1/receive`（默认 JWT+权限码；匿名可配白名单，**验签归 `Port.parse`**，详见 [015](015.topic-usage.md)） |

> 渠道 endpoint / 认证等参数全部存于渠道表 `config` JSON；敏感键（`secret` / `token` / `password` / `apiKey` / `accessKey` / `secretKey` / `corpSecret` / `appSecret` / `clientSecret` / `privateKey` 等，大小写与下划线不敏感）落库经 [033 SecretCipher](../033.topic-platform-security.md) **B3 字段级加密**（`enc:v1:`）；出参打码 `******`；更新时客户端回传 mask / blank 则保留旧密钥。
