## 011.运行视图（出站发送链路）

```
Client ──JWT──► GlobalAuthFilter
                    │
                    ▼
        JulyOutboundMessageController
        (web.messagecenter.outbound.controller)
                    │
                    ▼
        MessageOutboundUseCase
        (application.messagecenter.outbound.message)
          │            │              │
   模板 render   MessageChannelRegistry   记录落库
   july_message_outbound_template   （provider_type → SPI）  july_message_outbound
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
          InAppMessageChannel           WebhookMessageChannel
          （落库即收件箱，无 IO）        HttpUtil011 → config.url
```

## 013.入站接收链路

```
厂商回调 ──POST──► JulyInboundMessageController.receive
                   (web.messagecenter.inbound.controller)
                   ?channelCode=<实例码>
                   │ 默认 JWT；可配置 krt.web.auth-whitelist-paths 匿名旁路
                              │
                              ▼
                   MessageInboundUseCase.receive
                   (application.messagecenter.inbound.message)
                     │ 查 july_message_inbound_channel（启用）
                     │ MessageInboundRegistry.port(provider_type)
                     ▼
                   MessageInboundPort.parse(config, rawBody)  ← 验签归渠道
                     │
                     ▼ 去重 uk(channel_code, raw_message_id)
                     ▼ 至少一 Listener.supports(实例码) —— 否则 badRequest
                   落库 july_message_inbound
                     │
                     ▼ 遍历 supports 的 InboundMessageListener（异常隔离）
                   首个非空 InboundReply → MessageInboundPort.encodeReply → HTTP 响应
```

> 长连（WebSocket）**无独立端点**：渠道插件自持连接，事件交给同一 `receive` 用例；异步回复由监听器自行调出站 `send`。`operatorId` 可为 `null`（白名单 / `receive(null,…)` / 长连均跳过 JWT/`assertHas`；**防灌归 `Port.parse`**，框架不代验签——[015](015.topic-usage.md)）。

## 015.关键设计件

| 件 | 位置 | 职责 |
|----|------|------|
| `MessageChannelRegistry` | `application.messagecenter.outbound.channel` | `List<MessageChannelPort>` 自动收编（空 = 中心在但无可用出站渠道） |
| `MessageInboundRegistry` | `application.messagecenter.inbound.channel` | `List<MessageInboundPort>` + `List<InboundMessageListener>` 对称收编 |
| `MessageOutboundUseCase` | `application.messagecenter.outbound.message` | 解析渠道 → 渲染模板 → 发送 → 落记录（事务边界） |
| `MessageInboundUseCase` | `application.messagecenter.inbound.message` | 解析 → 去重 → **强制 Listener** → 落库 → 分发 → 被动回复 |
| `InAppMessageChannel` | `infrastructure.messagecenter.outbound.channel` | 出站 `inapp`：发送恒成功，出站记录即收件箱 |
| `WebhookMessageChannel` | `infrastructure.messagecenter.outbound.channel` | 出站 `webhook`：config JSON → `HttpUtil011` |
| `JulyOutbound*UseCase` / `JulyInbound*UseCase` | `application.messagecenter.{outbound,inbound}.{channel,template}` | 管理面 CRUD |

## 016.报文形态：`messageType` + `payload`（开放透传）

框架**不认识任何厂商形态**。发送契约只开两个中性字段，原样透传给 `MessageChannelPort`：

- **`messageType`**（开放字符串）：渠道自定义报文形态名，框架不校验、不解释；
- **`payload`**（键值 map，落库 JSON）：形态专属参数，键由渠道自定；
- **`config`**：渠道实例表驱动，整份透传进 `MessageCommand.config()` / `parse(config, …)`（聚合侧为明文；PO 侧敏感键经 [033](../033.topic-platform-security.md) B3 字段级 `enc:v1:`；出参打码）。

## 027.语义口径

- **渠道无状态**：差异化参数在渠道表 config JSON；实现类不持可变全局状态。
- **幂等**：入站去重靠唯一约束兜底；业务预检查只做友好提示。
- **记录先行**：发送 / 接收都先落记录再回填结果，排查以记录表为准。
- **web 分包**：`web.messagecenter.inbound.*` / `web.messagecenter.outbound.*` —— 勿再引用扁平 `web.messagecenter.controller`。
