# 015 — center-message011-starter · 怎么使用

> 四篇一套：[011 设计](011.topic-design.md) · [013 架构](013.topic-architecture.md) · 本篇使用 · [016 二开手册](016.topic-secondary-dev.md)。

## 011.接入（业务项目）

```xml
<dependencyManagement>
  <dependency>
    <groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId>
    <version>1.0.0</version><type>pom</type><scope>import</scope>
  </dependency>
</dependencyManagement>

<dependency>
  <groupId>com.klsjnh</groupId><artifactId>center-message011-starter</artifactId>
</dependency>
```

随后两步：

1. **建表**：执行 [july_center_message011.sql](../../sql/july_center_message011.sql)（出入两套共 6 表，`july_message_*`）。
2. **配出站渠道**：`POST /klsjnh/messagecenter/julyOutboundChannel/v1/insert`（内置 `provider_type`：`inapp` / `webhook`；`config` JSON 存 endpoint / 认证等；敏感键含 `corpSecret`/`appSecret` 等，落库 SecretCipher，出参 `******`；update 回传 mask/blank 保留旧密钥）。

> 框架 bean 由 starter 自注册；宿主只需扫描**自己的**包。不要手写扁平 `web.messagecenter.controller` 路径——HTTP 适配在 `com.klsjnh.web.messagecenter.outbound|inbound.controller`。

## 013.发消息（出站）

- **模板**：`POST …/julyOutboundTemplate/v1/*` 维护模板（`${var}` 轻量替换，绑定出站 `channel_code`）。
- **发送**：`POST …/julyOutboundMessage/v1/send`

```json
{
  "channelCode": "wecom_hr",
  "to": "zhangsan",
  "messageType": "textcard",
  "payload": { "url": "https://...", "btntxt": "详情" },
  "title": "休假通知",
  "content": "张三 10-01 休假"
}
```

- `channelCode` = 渠道**实例**码（表 `july_message_outbound_channel.channel_code`）；底座用该行的 `provider_type` 找 SPI。
- `messageType` / `payload` 为渠道自定义透传位；结果落 `july_message_outbound`（可 `resend`）。
- webhook 渠道走 `common.util.HttpUtil011`；出站 HTTP 安全治理见 [033](../033.topic-platform-security.md)。

## 015.收消息（入站）

1. 实现 `MessageInboundPort`（`channelCode` + `parse` + `encodeReply`）——包路径：`domain.messagecenter.inbound.channel`；
2. 实现 `MessageInboundProcessor`（**推荐**：`channelCodes()` 显式绑定实例码，`process` → 可选 `InboundReply`）或旧的 `InboundMessageListener`（`supports` + `onMessage`）——**默认每渠道必选**：零个绑定该实例的 Processor/Listener → `badRequest`，仅 Port 落库不算接完；纯接收渠道可在**渠道 config** 设 `listenerRequired=false` 进入 persist-only（按渠道实例生效，不是全局开关）；
3. 插一行 `july_message_inbound_channel`（`channel_code` / `provider_type` / `config`）；
4. 厂商回调指向：

```
POST /klsjnh/messagecenter/julyInboundMessage/v1/receive?channelCode=<实例码>
Content-Type: application/json

{ "rawBody": "<渠道原始报文字符串>" }
```

> HTTP 适配层用 `JulyInboundReceiveVo011.rawBody` 承接；**不是**把厂商原始 body 原样当请求体。

**裸报文回调（厂商原生 body）**：

```
POST /klsjnh/messagecenter/julyInboundMessage/v1/receiveRaw?channelCode=<实例码>
Body = 厂商原始 JSON
```

- 先调 `MessageInboundPort.handshake(...)`：返回非空则**原样应答**（如飞书 `url_verification` 的 `{"challenge":"..."}`），否则进入正常接收；
- 验签 / 解密仍归 `Port.parse` / `handshake`；
- 匿名回调把 `WebPaths011.MESSAGE_INBOUND_RECEIVE_RAW`（`…/receiveRaw`）加入 `krt.web.auth-whitelist-paths`。

**长连接 / SDK / MQ 入口**：不走 HTTP，直接调

```java
messageInboundUseCase.receiveEvent(operatorId, channelCode, inboundMessage);
```

复用同一套去重 → 落库 → listener 分发；`operatorId` 可空。

**多 bot / 多账号装配**：每个 bot 一个渠道实例（`channel_code`），`MessageInboundProcessor.channelCodes()` 返回该实例码；一个应用可注册多个 processor，互不串台。一个 processor 也可绑定多个实例码。

**入站媒体**：实现 `MessageMediaPort`（`channelCode` + `download`），业务用

```java
MessageMedia media = messageMediaService.download(channelCode, messageId, mediaKey, "audio");
```

标准 payload 键见 `MessagePayloadKeys011`（`messageId` / `chatId` / `fileKey` / `imageKey` / `fileName` / `mediaType` / `duration`）。

### 鉴权：何时 JWT、何时匿名

| 场景 | JWT + 权限码 | `operatorId` | 说明 |
|------|--------------|--------------|------|
| 管理面（select / delete 等） | **需要**（非 debug） | 登录操作人 | 走 `assertHas` |
| 厂商 HTTP `/receive`（**默认**） | **需要** | 登录操作人 | JWT + `assertHas(RECEIVE)`，与其它写接口相同 |
| 厂商 HTTP `/receive`（匿名回调） | **可配置旁路** | `null` | 宿主把路径写入 `krt.web.auth-whitelist-paths`（常量 `WebPaths011.MESSAGE_INBOUND_RECEIVE` = `/klsjnh/messagecenter/julyInboundMessage/v1/receive`；或合适前缀写入 `auth-whitelist-prefixes`） |
| 厂商 HTTP `/receiveRaw`（裸报文） | **可配置旁路** | `null` | 常量 `WebPaths011.MESSAGE_INBOUND_RECEIVE_RAW`（`…/receiveRaw`）；handshake 原样应答 |
| 长连 / 程序内 `receiveEvent(...)` | 不经 HTTP Filter | 常为 `null` | 同管道；跳过 JWT/`assertHas`，不做 handshake / encodeReply |

> **安全边界（已拍板）**：白名单打开后，以及程序内 `receive(null,…)` / 长连，框架**不再**做 JWT / `assertHas`；**防灌消息必须由渠道 `MessageInboundPort.parse`（读渠道 config 中的 token/secret）验签**——框架**不代**厂商验签。勿另造平行鉴权体系。配置键见 [015.topic-config](../015.topic-config.md)；契约白名单见 [013.api-contract](../../013.api-contract.md)。
>
> 活示例：兄弟工程 `yw-java17-basemodule011`（飞书长连 `FeishuLongConnectionReceiver` + `EchoInboundMessageListener`），见其 `021.topic-message-center`（外部工程文档，不在本仓）。

底座：解析 → 去重 → **强制至少一个 `InboundMessageListener.supports`**（否则 `badRequest`）→ 落 `july_message_inbound` → 分发监听 → 被动回复编码（结果 VO 的 `responseBody`）。管理面：`…/julyInboundMessage/v1/selectListByPage` 等。

> **入站内置 `webhook` 渠道**（HMAC-SHA256 验签：config `secret` 必配、`signatureHeader` 默认 `X-Signature`，缺配置/缺头/不匹配一律 400；**防重放时间戳**：`timestampHeader` 默认 `X-Timestamp`（epoch 秒或毫秒），默认必带，±`maxAgeSeconds`（默认 300s）窗口外 400，`requireTimestamp=false` 可关（不建议）；body 为平 JSON `fromId/messageType/content/rawMessageId/payload`，`rawBody` 上限 1,000,000 字符；**签名按信封内 `rawBody` 字符串逐字节计算**，厂商应同时送 `rawMessageId` 做幂等去重）；更多厂商渠道 SPI 扩展；出站 `webhook` 是 HTTP **出站**推送，不要与入站回调入口混淆。

### 多 bot / 多账号装配

一个应用可以同时接多个 bot（飞书 / 企微 / 钉钉），**每个 bot = 一个渠道实例码**，处理器显式绑定实例码，互不串台：

```java
@Component
public class FeishuBotAProcessor implements MessageInboundProcessor {

    @Override
    public Set<String> channelCodes() {
        return Set.of("feishu_bot_a");       // 只收 bot A 的消息
    }

    @Override
    public InboundReply process(InboundMessage message) {
        // bot A 的业务；返回 null 表示不同步回复
        return null;
    }
}
```

对应渠道行：

| `channel_code` | `provider_type` | `config` |
|---|---|---|
| `feishu_bot_a` | `feishu` | `{"verificationToken":"...","encryptKey":"..."}` |
| `feishu_bot_b` | `feishu` | `{"verificationToken":"...","encryptKey":"..."}` |

- 一个 processor 可返回多个实例码；同一实例多个 processor 按 bean 顺序执行，首个非空 `InboundReply` 生效；
- 旧 `InboundMessageListener.supports` 仍兼容，但新装配优先用 `MessageInboundProcessor`；
- **persist-only**：渠道 config 加 `"listenerRequired":"false"`，只落库不分发（按实例生效，无全局开关）；
- 长连接 / SDK：把已解析事件交给 `receiveEvent(operatorId, channelCode, event)`，同一实例码路由到同一批 processor。

**入站媒体**（语音 / 图片 / 文件）：

```java
MessageMedia voice = messageMediaService.download(
        message.channelCode(),            // 渠道实例码
        message.rawMessageId(),           // 渠道消息 id
        message.payload().get("fileKey"), // 标准键，见 MessagePayloadKeys011
        "audio");
```

> 多 bot **出站**注意：`MessageChannelPort` 收到的 `MessageCommand.config()` 是渠道实例 config；飞书插件当前仍用全局 `krt.feishu.app-id/app-secret`，多应用凭据需插件按 config 构建 client（框架侧已把 config 透传，无需改底座）。

## 017.扩展：新出站渠道（摘要）

```java
@Component
public class WeComMessageChannel implements MessageChannelPort {
    @Override public String channelCode() { return "wecom"; } // = provider_type
    @Override public MessageResult send(MessageCommand command) { /* config 整份在 command.config() */ }
}
```

插行：`july_message_outbound_channel`（`provider_type='wecom'`）。完整纪律与样板见 [016 二开手册](016.topic-secondary-dev.md)。

## 019.不引本 starter 的行为

- **`/klsjnh/messagecenter/**` 整体 404（路由级）**；
- 不导 6 表；classpath 零消息代码；业务代码**不要**注入消息相关用例（编译期即不可见）。
