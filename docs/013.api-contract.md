# 013 — API 契约（响应信封与状态码）

> 本文档是响应信封与状态码的**事实契约**。`Response011` / `HttpCodeEnum011` 的键名与常量变化必须先修改本文档，代码与文档同步提交。

## 1. 响应信封（Response011）

所有端点统一返回六键信封；JSON 键 **camelCase**，禁止改名、删除或重排：

| key | 类型 | 必出 | 说明 |
|-----|------|------|------|
| statusCode | int | 是 | 业务状态码，与 HTTP 传输状态码保持一致 |
| message | string | 是 | 人读消息：成功为 "<action> success"，失败为安全提示；不含内部细节 |
| errorMessage | string | 是 | 失败详情，**仅非 production（debug / development）填充**，production 恒为 `""`；堆栈/SQL 不出站 |
| timestamp | long | 是 | 信封创建时的服务器时间（epoch 毫秒） |
| traceId | string | 否 | 链路 id；`GlobalAuthFilter` 生成/透传 `X-Trace-Id` 并写 MDC，`TraceIdResponseAdvice` 回填信封（无 MDC 时可为 null） |
| data | object | 否 | 业务载荷；无返回数据的写操作为 null |

## 2. 状态码（HttpCodeEnum011）

| 常量 | code | 默认 message | 场景 |
|------|------|--------------|------|
| SUCCESS | 200 | success | 成功 |
| BAD_REQUEST | 400 | bad request | 参数或校验失败 |
| UNAUTHORIZED | 401 | unauthorized | 缺失 / 无效 / 过期 token；登录失败、账号禁用 |
| FORBIDDEN | 403 | forbidden | 已认证但无权限 |
| NOT_FOUND | 404 | not found | 资源或端点不存在 |
| TOO_MANY_REQUESTS | 429 | too many requests | 触达框架侧限流 / 并发上限；客户端可稍后重试 |
| ERROR | 500 | internal server error | 服务器内部错误 |

**新增常量必须先扩本文档表格。**

> 例外（契约内设计，直接返回文件流/事件流，不走信封）：
> - 二进制下载端点（如数据导出、对象存储下载）；
> - SSE 流式端点（如 `POST /klsjnh/aicenter/julyAiInference/v1/chat/stream`，返回 `text/event-stream`）。

## 3. 鉴权（GlobalAuthFilter）

除白名单外，所有端点要求 `Authorization: Bearer <token>`：

| 项 | 约定 |
|-----|------|
| 请求头 | `Authorization: Bearer <token>`（token 由 `/login`、GET/POST `/loginByUserName` 返回） |
| 白名单 | 登录端点（`/klsjnh/iam/julyUser/v1/login` · GET/POST `/loginByUserName`）+ knife4j/swagger 文档路径（**仅 debug/development 匿名可达；production 封锁为 404 信封，持有效 token 亦不可访问**）+ `/favicon.ico` + `/error` + `/actuator/health`；**OPTIONS 预检整体旁路**。**不再内置 `/klsjnh/open/` 前缀旁路**；开放接口须显式配置 `krt.web.auth-whitelist-paths`（精确路径）/ `krt.web.auth-whitelist-prefixes`（前缀），与内置列表同一 `shouldNotFilter` 旁路（例：厂商入站 `WebPaths011.MESSAGE_INBOUND_RECEIVE`）。**旁路后框架不再 JWT/`assertHas`；防灌验签归渠道 `MessageInboundPort.parse`（config token/secret），框架不代验签**——消息中心边界见 [016.message-center/015](infrastructure011/016.message-center/015.topic-usage.md) |
| 校验失败 | 缺失 / 无效 / 过期 token → 401 信封（过滤器直接写出，不经过全局异常处理器） |
| debug 态 | **完全开放**：所有读写/导入/导出/备份接口免 token；无 token 时自动注入虚拟操作人 `id=dev011`、`account=klsjnh`；带有效 token 时解析真实身份 |
| development 态 | 强制有效 token（无 token → 401）；GET/POST `loginByUserName` 免密拿 token；RBAC no-op |
| production 态 | 强制有效 token；免密登录 401；真实 RBAC + `/klsjnh/**` 读写全量白名单；文档 404；`errorMessage` 恒空 |
| 操作人 | 校验通过后写请求属性 `FrameConst011.OPERATOR_ID` / `OPERATOR_ACCOUNT`，供审计自动填充 create_by / update_by |
| 链路 | 写 MDC `FrameConst011.TRACE_ID`；响应信封由 `TraceIdResponseAdvice` 回填 |

**登录失败口径**：账号密码错误、账号禁用、production 下免密登录被拒，统一返回 **401**（不再用 400）。
