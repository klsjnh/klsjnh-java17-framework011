# 016 — 存储中心 · 对象元数据记录规约

> **本文是规约，不是平台能力交付。** 无 `july_files` 表、无登记 API、无存储中心元数据仓储。
> 归属：[存储中心](011.topic-design.md)。端口与管理面见 [013 架构](013.topic-architecture.md) · [015 怎么使用](015.topic-usage.md)。
> **已归档**（规约仍可备查；现行存储文档 → [015.storage-center](../../../infrastructure011/015.storage-center/011.topic-design.md)）。
> 对齐：[AI 中心 · 产物生命周期归使用方](../../015.ai-center/011.topic-design.md)（§017 / R5）。

## 011.一句话

**字节在对象存储；业务只持久化定位信息。** 存取走 `ObjectStoragePort` / `StorageResolverPort`；「这个文件属于谁、何时删」归**调用域**自己的表与用例。

## 013.推荐持久化字段

调用域在**自己的业务表**里挂指针即可（列名可按域习惯，语义对齐下表）：

| 语义 | 推荐 | 说明 |
|------|------|------|
| 存储实例 | `storageCode`（或等价） | 对应 `july_storage_provider.storage_code`；空白语义同端口 = `default` |
| 桶 | `bucket` | 物理桶名；空白则走该实例默认桶 |
| 对象键 | `objectKey` | 桶内唯一键 |
| 校验 / 体积 / 类型 | `etag` / `size` / `contentType` | **可选**；写入后可由 `stat` 回填，勿当唯一真源 |

> 定位三元组（实例 + 桶 + 键）足够再次 `get` / `delete` / `presignedGetUrl`。etag/size/contentType 便于列表展示与变更探测，不替代定位字段。

## 015.归属与边界

| 归谁 | 做什么 | 不做什么 |
|------|--------|----------|
| **存储中心** | 实例/桶配置、对象存取端口、管理面 CRUD | 不建全站文件登记表；不提供「登记/挂接」业务 API |
| **调用域** | 在本域表持久化上表字段；管生命周期（引用、替换、删除） | 不反向要求存储中心「替你记业务归属」 |

- **何时不要建全站 `july_files`**：附件/导出/备份/AI 产物等各域自管指针即可时——各建各的列或小表，**不要**先造平台统一文件台账。
- **何时可升平台（一句话）**：多域必须共享同一文件实体、统一检索/权限/回收且重复建设成本高于中心化时，再另开架构专题评审；**在此之前本文规约仍成立**。

## 017.与现有口径对齐

- **`ObjectStoragePort`**：业务侧只依赖端口读写；换厂商只动存储实例配置，**不改调用方定位字段语义**。
- **AI 产物**：AI / 存储只交付引用（key / 地址）；**生命周期归调用方**——与本文「元数据表归调用域」同一口径（见 AI 中心 §017 / R5）。
- **架构底册已写明**：对象物理在后端，**不落存储中心业务表**（[013 §015](013.topic-architecture.md)）；本文把「调用域怎么记」写清楚，不扩平台表。

## 019.执行清单（调用方）

1. `put` / `putStream` 成功后，把 `storageCode` + `bucket` + `objectKey`（及可选 etag/size/contentType）写入**本域**表。
2. 读/下/删：用表中定位信息 `resolve(storageCode)` → 端口调用；勿臆造全站文件 ID。
3. 替换：先 `put` 新键（或同键覆盖）→ 更新本域指针 → 按需删旧对象。
4. **不要**向存储中心提「登记文件」「查我的全部附件」类平台需求——那不是本期能力，也不在本文交付范围。
