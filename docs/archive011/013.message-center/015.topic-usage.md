## 011.实现并注册一个渠道（依赖 + 扫描 + SPI）

使用者挂自己的渠道 = **Maven 依赖 + 组件扫描 + 实现 SPI 端口 + 插一行渠道配置**，**不改框架**。

**机制（一句话）**：底座只做**路由**——用 `providerType`（字符串 code）到注册表里找到**你注册的实现类**，把请求交给它；渠道参数（企微 corpId / 短信 ak/sk …）**随 `MessageCommand.config` 整份透传给你**，你**不需要、也不要**回查 `JulyOutboundChannelRepository`。

```
使用者 @Component 实现 MessageChannelPort（channelCode() 返回 "wecom"）
   → Spring 收集进 MessageChannelRegistry
   → 底座 send(channelCode=july_message_outbound_channel.provider_type)
   → 路由到你的实现类 .send(cmd)   // cmd.config() 里有整份渠道配置
```

**步骤**

**1) 依赖框架构件**（先用 `mvn install` 把框架装进本机 `.m2`）
```xml
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-bom011</artifactId><version>1.0.0</version><type>pom</type><scope>import</scope></dependency>
<dependency><groupId>com.klsjnh</groupId><artifactId>java17-core011</artifactId></dependency>
<dependency><groupId>com.klsjnh</groupId><artifactId>center-message011-starter</artifactId></dependency>
```

**2) 应用扫描框架包 + 自己的包**（关键：漏了框架包 → 注册表/用例不会被实例化，插件挂不上）
```java
@SpringBootApplication(scanBasePackages = { "com.klsjnh", "com.yourcompany" })
@MapperScan({ "com.klsjnh.infrastructure.iam", "com.klsjnh.infrastructure.persistence.mapper",
        "com.klsjnh.infrastructure.system011", "com.klsjnh.infrastructure.datasource",
        "com.klsjnh.infrastructure.aicenter", "com.klsjnh.infrastructure.storagecenter",
        "com.klsjnh.infrastructure.messagecenter", "com.yourcompany.**.mapper" })
public class YourApp { public static void main(String[] a) { SpringApplication.run(YourApp.class, a); } }
```

**3) 实现渠道端口（SPI，自动收集）**
```java
package com.yourcompany.msg;

import com.klsjnh.domain.messagecenter.outbound.channel.MessageChannelPort;
import com.klsjnh.domain.messagecenter.outbound.channel.MessageCommand;
import com.klsjnh.domain.messagecenter.outbound.channel.MessageResult;
import org.springframework.stereotype.Component;

@Component
public class WeComMessageChannel implements MessageChannelPort {

    @Override
    public String channelCode() {
        return "wecom";                       // ← 路由键：与 july_message_outbound_channel.provider_type 一致
    }

    @Override
    public MessageResult send(MessageCommand command) {
        // 整份渠道配置都在这里，无需回查仓储
        String corpId     = command.config().get("corpId");
        String corpSecret = command.config().get("corpSecret");
        String agentId    = command.config().get("agentId");

        try {
            // 调用企业微信 SDK：command.to() / command.title() / command.content()
            String msgId = ...;
            return MessageResult.success(msgId);            // 成功
        } catch (Exception ex) {
            return MessageResult.failure(ex.getMessage());  // 失败（落库 FAILED + error）
        }
    }
}
```
> 框架注册表构造注入 `List<MessageChannelPort>`，Spring 自动把**框架内置（`inapp`/`webhook`）+ 你的插件**一起收集，按 `channelCode()` 路由。

**4) 插一行渠道配置**（纯配置，无需代码）
```sql
INSERT INTO july_message_outbound_channel
  (id, channel_code, channel_name, provider_type, config, status)
VALUES
  (REPLACE(UUID(),'-',''), 'wecom_hr', '企微-人力资源', 'wecom',
   '{"corpId":"ww...","corpSecret":"...","agentId":"1000002"}', '1');
```
- **路由键链路**：`provider_type = "wecom"` → 找到 `WeComMessageChannel`（`channelCode()="wecom"`）；
- `config` 就是 `command.config()` 里那整份 map（webhook 从里面取 `url`，企微取 `corpId/...`）；
- 模板：`july_message_outbound_template`（`${var}` 占位，绑定 `channel_code`）。

## 013.内置渠道（inapp / webhook）

框架自带两个**通用**渠道，插一行配置即可用：

| code | 行为 |
|------|------|
| `inapp` | 落库即收件箱（`july_message_outbound` + 收件箱读取），无需外部依赖 |
| `webhook` | HTTP POST JSON 到 `config.url`（走 `HttpUtil011`），可挂签名扩展点；**企微/飞书/钉钉可先用它** |

> 需要厂商专属形态（卡片 / 素材 / 长连）时，才实现自己的渠道插件（见 §011）。

## 015.入站接入

入站 = 接收厂商回调/事件，交给业务监听器，可选被动回复。

**1) 实现入站解析端口** `MessageInboundPort`：`channelCode()` + `parse(config, rawBody) → InboundMessage` + `encodeReply(InboundReply) → String`；
**2) 实现业务监听器** `InboundMessageListener`：`supports(channelCode)` + `onMessage(InboundMessage) → InboundReply`（返回 `null` = 不回）；
**3) 插一行** `july_message_inbound_channel`（`channel_code` / `provider_type` / `config`）；
**4) 厂商把回调指向** `POST /klsjnh/messagecenter/julyInboundMessage/v1/receive?channelCode=xxx`。

底座处理链：解析 → **去重**（`uk(channel_code, raw_message_id)`）→ 落库（`status=1`）→ 遍历监听器分发（异常隔离，取首个非空 `InboundReply`）→ `encodeReply` 写回 HTTP 响应。

> **长连接（WebSocket）** 无独立端点：渠道插件自持连接，把事件交给 `MessageInboundPort.parse(...)`。异步回复由监听器自行调**出站 send**。

## 016.调用示例

**发一条消息**（`messageType` / `payload` 均为**渠道自定义**，透传）：

```json
POST /klsjnh/messagecenter/julyOutboundMessage/v1/send
{ "channelCode": "wecom_hr", "to": "zhangsan", "messageType": "textcard",
  "payload": { "url": "https://...", "btntxt": "详情" },
  "title": "休假通知", "content": "张三 10-01 休假" }
```

底座解析渠道 → 渲染模板 → **按 `providerType` 路由到你的渠道插件** → 落发送记录（SUCCESS/FAILED + error）。渠道插件从 `command.config()` 取连接配置、从 `command.messageType()`/`command.payload()` 取形态与载荷。

**失败重发**：`julyOutboundMessage/v1/resend`（沿用记录的 `messageType`/`payload`）。
