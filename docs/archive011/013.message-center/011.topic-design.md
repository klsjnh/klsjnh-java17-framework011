## 011.命题

**一个消息中心，渠道可插拔。** 框架只提供**统一发送契约 + 渠道注册表 + 表驱动配置**，并内置少量渠道；**站内信 / 短信 / 企业微信 / 飞书 / 钉钉 / 邮件 / 自定义** 由**使用者实现适配器并配置**，不改框架。

> 业务域只管"发什么、给谁、用哪条模板"；**怎么发**交给渠道适配器（与存储中心"厂商分期、适配器可插拔"同思路，但形态不同——见 §015）。

## 015.选型：实现型 SPI（非工厂型）

| | 工厂型（存储中心 / 数据源） | **实现型（消息中心 · 本选型）** |
|---|---|---|
| 扩展 | 框架按 `provider` **new 适配器**；加厂商要改框架 | 使用者实现 `MessageChannelPort` + `@Component`；**插件化，不改框架** |
| 适用 | 技术种类少、**每实例一套连接配置** | 厂商多且长尾、**每渠道一份配置、实例单一** |
| 配置 | `july_storage_provider` 每实例一行 | `july_message_outbound_channel`（出）/ `july_message_inbound_channel`（入）每 `channelCode` 一行 |
| 发现 | `ObjectStorageProviderRegistry`（查工厂）+ `StorageResolver011` | `MessageChannelRegistry(List<MessageChannelPort>)` 自动收集 |

**裁定**：消息渠道采用**实现型 SPI**（出站 `MessageChannelPort`、入站 `MessageInboundPort` + 各自注册表 + 各自渠道表配置）；存储/数据源维持**工厂型**。判据 = **是否需要「同技术多实例 + 每实例连接」**：是→工厂型，否→实现型（详见 [存储中心 011 §017](../infrastructure011/011.storage-center/011.topic-design.md)）。

| 期 | 内容 |

## 017.边界（厂商渠道 = 使用者插件，非框架能力）

- 框架只出 `inapp` / `webhook` 两个**通用**内置渠道；**企微 / 飞书 / 钉钉 / 短信 等厂商渠道一律由使用者（或业务底座）实现**，框架**不认识**其形态名、连接方式。
- **禁止**在渠道实现里回查 `JulyOutboundChannelRepository` 取自己的配置——配置已在 `command.config()`。
- **否定清单（框架不做）**：厂商形态名（如 `textcard`/`post`/`interactive`）、**素材上传**（换 `image_key`/`file_key`）、**消息接收**（回调 / **长连接 WebSocket，走厂商 SDK 免公网 URL**）、回复 / 撤回 / 转发 / 加急 / Pin / 群历史 / 通讯录 / 审批。
- 渠道的 HTTP 调用统一用 `com.klsjnh.common.util.HttpUtil011`（勿各自 `new HttpClient`）。

> **临时说明**：若在框架侧临时验证过某厂商渠道（如飞书），它**不改变上述边界**——最终**移出框架**，由使用者/业务底座承载。
