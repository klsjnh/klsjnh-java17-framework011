## 011.结论（一句话）

**契约用组合，不用继承**：把 `MetaData011` 族从"聚合根"降格为**纯契约（record 值对象）**，`JulyMetadata` **组合**它而非各自维护一套子实体。实现该方向的四步：

1. `model/` 四类转 **record 契约**，`reconstitute(...)` 校验保留（边界卫兵）；
2. `JulyMetadata` 删掉自有 `Field/Display/Service` 三套子实体，改**持 `MetadataContent`**（一处不变量、一个 schema；三表 PO 从 content 取）；
3. `JulyBusinessModeling` 的 `MetaData011` 字段改 `MetadataContent`，`ModelDataCodec011` 编解码换类型（建模 JSON 与引擎同一 schema）；
4. 补 `importFromModeling(modelCode)`：`model_data` JSON → `reconstitute`（校验）→ 建引擎聚合。

> 只在**真出现第二种行为实现**（如只读外部元数据源）时才把 `MetadataContent` 提成 interface；现在上接口是"只付钱不见货"。

## 013.对上述方案的纠偏（不够专业之处）

1. **契约必须真不可变**：`FieldInfo011/DisplayInfo011/ServiceInfo011` 现为**带 setter 的 mutable class**，塞进 record 契约就漏了。子类也转 record，或引擎侧 **copy-on-write**（编辑产生新 `MetadataContent`）。
2. **`reconstitute` 只在边界**：外来 JSON（模板/读库/033 交接）才重放不变量；内部 `create` 走已校验路径；明确失败语义（fail-fast vs repair）。
3. **`MetadataContent` 归属**：它同时被 `lowcode011`（引擎）与 `dataservice011`（033）用 → 是 **published language / shared kernel**，不是 lowcode011 私产。要么放中性契约包，要么**明确 lowcode011 为上游、033 conforming**。
4. **发布态不该与契约同聚合**：`physicalTable/publishStatus/backupTable/version` 是**部署态**，应拆 `Publication`（或至少承认是"指针"）；契约只放内容。

## 015.四条架构级判断（现状问题 + 精确形态）

1. **双聚合根 = context map 没画**。画法：**建模（dataservice011，上游）→ 元数据引擎（lowcode011，拥有 `MetadataContent`）→ 运行时/开放（ACL 适配器）**。MetaData011 降格为契约后，"双聚合根"消失。
2. **运行时内核未成型、以复制粘贴泄漏在应用层**。`fillBaseDefaults / filter / physicalTable / 分页` 在 `JulyMetadataRuntimeUseCase`、`OpenApiUseCase`、`JulyMetadataDataSyncUseCase` 近乎逐行重复。正解分两层：
   - **纯领域策略**（无 IO）：`ObjectTablePolicy`——补公共列、按元数据校验、逻辑删判定、分页规格构造；
   - **应用/基础设施网关**：`ObjectTableGateway`（注入 `MetadataDataAccessPort`）——落 IO、事务、审计。
   三个 UseCase 只留**编排差异**（鉴权/来源）。**此条 ROI 最高，先做。**
3. **`Map<String,Object>` 贯穿三层**。动态性应**收口到一个值对象** `RowValues`（内含 `Map`），而非每层裸 `Map`；web↔application 至少定型（`ObjectQueryCommand` / `RowView`），domain 策略只认 `RowValues`。
4. **横切面（身份/审计/一致性）未接入**：
   - **身份**：`CurrentOperatorPort`（web filter 填充、网关消费），别每个 UseCase 传 `Operator011`；
   - **审计**：**沉到网关**，一处生效（动态 `objectCode` 不应三处各写）；
   - **发布一致性**：现三步（执行 DDL → 落快照 → 推指针）**无补偿** → 改**状态机 + 可重入**（`PENDING→EXECUTING→PUBLISHED`，快照先落、DDL 幂等、失败可重放 + 对账）；
   - **同步断点**：`DataSync` 需 **checkpoint/水位** + 幂等，才叫可续传。

## 017.落地顺序（依赖驱动）

| 序 | 内容 | 理由 |
|----|------|------|
| 1 | 模型层重构（§011 四步 + §013 纠偏） | 内核依赖它 |
| 2 | 内核抽取（`ObjectTablePolicy` + `ObjectTableGateway`） | 收益最大，消灭三处复制 |
| 3 | 边界定型（命令/视图 + `RowValues`） | 编译期可查 |
| 4 | 横切端口化（`CurrentOperatorPort`、审计入网关、发布状态机、同步 checkpoint） | 平台能力 |
