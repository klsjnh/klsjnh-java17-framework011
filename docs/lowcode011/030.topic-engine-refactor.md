## 011.结论（一句话）

**契约用组合，不用继承**：把原 `MetaData011` 族从"聚合根"降格为**纯契约（不可变 record 值对象）**命名 `MetadataContent`，`JulyMetadata` **组合**它而非各自维护一套子实体。

> 只在**真出现第二种行为实现**（如只读外部元数据源）时才把 `MetadataContent` 提成 interface；现在上接口是"只付钱不见货"。

## 013.四条架构级判断

1. **契约必须真不可变**：子类也转 record；引擎侧 **copy-on-write**（编辑产生新 `MetadataContent`）。
2. **`reconstitute` 只在边界**：外来 JSON（模板 / 读库 / 033 交接）才重放不变量，作为 **fail-fast 边界卫兵**；内部 `create` 走已校验路径。
3. **`MetadataContent` 归属**：它同时被 `lowcode011`（引擎）与 `dataservice011`（033）用 → 是 **published language / shared kernel**；明确 **lowcode011 为上游、033 conforming**。
4. **发布态与契约分离**：`physicalTable/publishStatus/backupTable/version` 是**部署态**，留在 `JulyMetadata` 作"指针"，不进契约。

## 015.四个问题与精确形态

1. **双聚合根 = context map 没画**。画法：**建模（dataservice011，上游）→ 元数据引擎（lowcode011，拥有 `MetadataContent`）→ 运行时/开放（ACL 适配器）**。`MetaData011` 降格为契约后，"双聚合根"消失。
2. **运行时内核未成型、复制粘贴泄漏在应用层**。`fillBaseDefaults / filter / physicalTable / 分页` 曾在 Runtime/OpenApi/DataSync 三处近乎逐行重复。正解：
   - **纯领域策略**（无 IO）：`ObjectTablePolicy` —— 补公共列、按元数据校验、逻辑删判定、分页规格构造；
   - **应用/基础设施网关**：`ObjectTableGateway`（注入 `MetadataDataAccessPort`）—— 落 IO、事务、审计。
   三个 UseCase 只留**编排差异**（鉴权/来源）。
3. **`Map<String,Object>` 贯穿三层**。边界定型：web↔application 用 `ObjectQueryCommand` / `RowView`（`@JsonValue` 扁平）；领域策略只认 metadata 契约。
4. **横切面（身份/审计/一致性）**：
   - **身份**：`CurrentOperatorPort`（web filter 填充、网关消费），不再每个 UseCase 传 `Operator011`；
   - **审计**：沉到网关，一处生效；
   - **发布一致性 / 同步断点**：状态机 + checkpoint 列为**后续深水区，默认不启动**。
