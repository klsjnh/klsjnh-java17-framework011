## 011.发布与 DDL

发布 = 把「元数据定义」变成「物理表」：首次 `CREATE TABLE IF NOT EXISTS`，其后仅 `ALTER ... ADD COLUMN`；同时写**发布快照**、递增**版本**、推进**发布指针**。

**端点**（`/klsjnh/lowcode011/julyMetadata/v1`）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/publish` | POST | `{objectName, migrateData?, includeDeleted?}` |

**物理表规则**
- 表名：`<objectName>`（**对象名即物理表名**，不加前缀）。
- 主键：`fieldType=id` 的列；无则自动补 `id VARCHAR(33)`。
- 业务唯一键：`businessField`（如 `sid`）固定 `VARCHAR(33)` + `UNIQUE KEY uk_<table>_<field>`。
- 列类型：`FieldType011` → MySQL（见 [015](015.topic-fieldinfo.md)）。
- **DDL 白名单**：首次 `CREATE TABLE IF NOT EXISTS`；其后仅 `ADD COLUMN`；**禁 `DROP`/`DROP COLUMN`/`MODIFY`/`RENAME`**；标识符 `^[A-Za-z_][A-Za-z0-9_]{0,59}$` + 反引号转义。

**发布流程**
```
load 聚合 → 表是否存在？
  ├─ 否 → generateCreate（CREATE IF NOT EXISTS）
  └─ 是 → 取缺列 → generateAddColumns（ALTER ADD COLUMN）
→ 执行 DDL（受开关）
→ 写快照 july_metadata_version（payload_json + ddl_text + version）
→ 更新 july_metadata 发布指针（publish_status/version/physical_table）
```
- **开关**：`krt.lowcode.ddl-execute.enabled`（默认 false，生产暗发；dev 开）。
- **幂等**：CREATE IF NOT EXISTS + 仅补缺列；失败可重跑（无 PENDING 断点续做）。
- **版本**：`0.0.1` 起递增（字符串）。
- **不可回滚**：DDL 隐式提交，无事务；只能重跑。
- **端口与实现**：`MetadataDdlGeneratorPort`（纯生成）· `MetadataDdlExecutorPort`（`tableExists`/`columnsOf`/`execute`，主数据源）· `JulyMetadataPublishUseCase`。

**物理表生命周期策略（2026-09-17 定）**

| 事件 | 物理表处置 | 理由 |
|------|------------|------|
| 逻辑删**对象**（`logicDelete`） | **保留** `<object>`（不 DROP、不改名） | DDL 白名单禁 `DROP`/`RENAME`；数据可追溯；误删可救 |
| 逻辑删**数据行** | `dr='1'`（表结构不动） | 逻辑删除 |
| 需要回收物理表 | **人工 / DBA**（或后续"归档"能力） | 自动 DROP 风险过高 |

- 未来可选：加"归档/回收"流程（rename 到 `archive_*` + 定期清理，需 DBA 闸门），当前不做。

## 013.数据同步

数据同步 = 把**源（业务库 SQL）**分页读出，`upsert` 进**目标物理表 `<object>`**；按**业务唯一键**去重，可重复执行。

| 端点 | 方法 | 入参 | 说明 |
|------|------|------|------|
| `/importDataFromSql` | POST | `{objectName, dataSourceCode, sqlCode, pageNum, pageSize, forceInit?}` | 单页导入（hasMore/nextPageNum 循环） |
| `/importStatus` | GET | `?objectName=` | `{dataInitialized, physicalTable, publishStatus}` |

**机制**
```
源分页读：dataservice011.executeSqlByPage（方言分页）
  ↓ rows
列名匹配：源结果列 → 目标列（大小写不敏感；不一致用 SQL 别名，如 orgid pk_organization）
  ↓
缺基列补默认：id 随机 UUID / status '1' / dr '0' / create_time·update_time now
  ↓
写：JdbcTemplateMetadataDataWriter.upsert（ON DUPLICATE KEY UPDATE，按业务键）
  ↓
标记已初始化：july_metadata.data_initialized='1' / last_sync_at
```
- **幂等**：重复导同页不翻倍（业务键唯一 + upsert）；`mode`：首次 `init`，其后 `sync`。
- **写前校验（2026-09-17 补）**：每页源行做元数据校验（`MetadataValueValidator`，partial 模式）；**业务键必须存在**（缺 `businessField` → 400）；基列由 writer 补默认故不强制；校验失败**整页拒绝**（`sync validation failed: ...`），不写库。
- **端口与实现**：`MetadataDataWriterPort.upsert(physicalTable, businessField, rows)` → `JdbcTemplateMetadataDataWriter`；源读用 `JulyBusinessModelingUseCase.executeSqlByPage`（app→app 复用）。
- **已知简化**：`updated/unchanged` 以 `processed` 近似；非分页全量 `syncData` 暂以分页循环代替（挂起）。
- **坑**：源列名要与目标一致或用别名，否则列落不进去（被白名单过滤）；业务状态映射平台基列（B 口径）时源带 `status` 会覆盖平台启用位。

## 015.运行时

运行时 = **对象可被使用**：发菜单（挂到 system011 菜单树）+ 面向内部（JWT）的动态数据面（getMeta + CRUD），并对写入做**按元数据的校验**。

**菜单**（挂 `/klsjnh/lowcode011/julyMetadata/v1`）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/publishMenu` | POST | `{objectName, parentMenuCode?}` 幂等发布 `rt_<object>` → `july_menu`（route `/runtime/<object>`，menuType=2） |
| `/listRuntimeMenus` | GET | 列 route 在 `/runtime/` 下的已发布对象（含 version/publishStatus） |

**数据面（JWT，前缀 `/klsjnh/lowcode011/runtime/v1`）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/getMeta` | GET | `?objectName=` 运行时表单用 MetaDTO |
| `/query` | POST | `{objectName, filters, pageIndex, pageSize}`（默认过滤 `dr='0'`；pageSize clamp [1,500]） |
| `/insert` | POST | `{objectName, ...列}`（补基列默认 + 校验） |
| `/update` | POST | `{objectName, id|sid, ...列}`（局部校验） |
| `/delete` | POST | `{objectName, id|sid}`（有 `dr` 走逻辑删） |

**安全与校验**
- **表/列白名单**：以**库表目录**为准（`columnsOf`），值**全绑定**（不拼 SQL）。
- **元数据校验**（`MetadataValueValidator`）：insert 校验必填/类型/长度；update 仅校验出现字段；基列不强制必填。
- **仅已发布对象**可用（物理表取最新快照）。
- **动态 `objectCode` 审计**：运行时 insert/update/delete 落 `july_user_audit`，`object_code = objectName`，操作者取 JWT。
- **挂起**：运行时权限模型（对象级 + 操作级）。

**前端 SSR 表单契约**
- 前端 SSR 按后端 `getMeta`（MetaDTO）动态渲染表单/列表：字段一变，表单自动变，**无需改前端**。
- 用到的段：`fieldData`（`fieldType` 控件 / `notNull` / `defaultValue` / `fieldLength` / `param011`）→ 控件 + 校验；`displayData`（`componentType` / `displayType` / `align` / `width` / `sort`）→ 列与表单项；`serviceData` → 按钮。
- **契约稳定性**：`getMeta` 是 SSR 的输入，**字段/枚举变更即前端契约变更**（向后兼容优先）。

## 016.开放 API

开放 API = 把**已发布对象**以 **`api_key` 鉴权**对外暴露：查询元信息 + 数据 CRUD，供第三方/外部系统（或 AI）调用，**无需 JWT**。

**配置（管理端，JWT，挂 `/klsjnh/lowcode011/julyMetadata/v1`）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/openApiConfig` | GET | `?objectName=` 读配置（apiKey 打码 `****xxxx`） |
| `/saveOpenApiConfig` | POST | `{objectName, enabled, authMode(closed/none/apiKey), allowedOps[]}`；首次生成 apiKey 回明文一次 |
| `/rotateApiKey` | POST | `{objectName}` 轮换，回明文一次 |

**开放端（`X-Api-Key`，`/klsjnh/open/v1`，JWT 白名单）**

| 端点 | 方法 | 说明 |
|------|------|------|
| `/getMeta` | GET | `?objectName=` 对象元信息（MetaDTO） |
| `/query` | POST | `{objectName, filters, pageIndex, pageSize}` |
| `/insert` | POST | `{objectName, ...列}` |
| `/update` | POST | `{objectName, id|sid, ...列}` |
| `/delete` | POST | `{objectName, id|sid}`（有 `dr` 逻辑删） |

**鉴权与规则**
- 鉴权顺序：配置存在且 `enabled` → `authMode=apiKey` 校验 `X-Api-Key` → `allowedOps` 含当前操作；不通过 **401**（无 key / 配置缺失均 401）。
- 仅**已发布**对象；表/列以库表目录为白名单；值全绑定；`insert` 补基列默认。
- apiKey：32 位 hex；读打码；生成/轮换明文仅回一次。
- **动态审计**：insert/update/delete 落审计，`object_code = objectName`，`user_account = open-api`。
- **挂起**：限流 / CORS / 行级权限；apiKey 明文入库（建议加密）。
- **代码位置**：`JulyMetadataOpenApiUseCase`（配置）+ `OpenApiUseCase`（公共面）+ `JulyMetadataOpenApiController` / `OpenApiController`；`GlobalAuthFilter` 白名单 `/klsjnh/open/`。
- **与运行时的区别**：运行时用 JWT（平台内部前端）；开放 API 用 `X-Api-Key`（对外/第三方）。两者共用同一套数据访问端口（`MetadataDataAccessPort`）与校验。

## 017.元数据模板（多格式）

模板 = 对象的**可交换表示**（MetaDTO + `source` + `templateVersion` + `_guide`），**只为导入后发布、不落库**（详细口径 [050](../requirement011/050.topic-template-formats.md)）。格式：**JSON**（完整无损）/ **CSV**（分段单文件）/ **Markdown**（分段表格）/ **XLSX**（占位，暂不支持）。

| 端点 | 方法 | 入参 | 说明 |
|------|------|------|------|
| `/getTemplate011` | GET | `format=json\|csv\|md\|xlsx?` | 默认骨架（json 回信封；其它回文件流） |
| `/downloadTemplate011` | GET | `objectName`，`format?` | 导出（1 主 3 子 + `source`） |
| `/uploadTemplate011` | POST | multipart `file`（按扩展名识别）或 JSON | **审核**：校验 + `previewDdl` + `plan`，**不落库** |
| `/deployObject` | POST | `{template|objectName, overwrite?}` | 落库 + 发布 |

**格式与实现**
- 端口 `TemplateCodec`（domain）+ 实现 `JsonTemplateCodec` / `CsvTemplateCodec` / `MarkdownTemplateCodec` / `XlsxTemplateCodec`（占位）。
- 任意格式 `import` → MetaDTO → **复用同一** `validate` / `reviewTemplate` / `deployObject`（下游唯一）。
- CSV / Markdown 均为**分段**（`## metaData/fieldData/displayData/serviceData/source`）；CSV 导出带 BOM；markdown 表语法工具 `common011.MarkdownUtil011`。
- 表格列/键取自 `MetaDtoKey011`，导入时列名**大小写不敏感归一**；模板导入属**非 AI** → 必须有 `businessField`（[045](../requirement011/045.topic-business-field.md)）。

**形态（JSON）**
```json
{ "templateVersion":"1.0", "_guide":{...},
  "metaData":{ "objectName":"...", "source":{ "dataSourceCode":"bpm011", "probeSql":"..." } },
  "fieldData":[...], "displayData":[...], "serviceData":[...] }
```
- `source` 由 `deployObject` 持久化到 `july_metadata.data_source_code/probe_sql`，`downloadTemplate011` 原样带回。
- 模板**不落库**（靠 `july_metadata_version` 快照复现）；JSON 不支持注释，说明放 `_guide`。

**校验（审核与部署共用）**
- `objectName`：`^[a-z][a-z0-9_]{0,49}$`。
- 子 `code` **大小写不敏感唯一**（同时拦"业务字段重名基列"）。
- 基列**允许一次**、类型归一（`id/create_by/update_by`→33、`status/dr`→3、时间→date）；`businessField` 非基列且 `string(33)`；`pk_*` `string(33)`。
- `fieldType`/`objectType` 过枚举；`display.code` 必须绑字段。
- 失败整单拒绝；`overwrite=false` 且已存在 → 400。

**审核与部署语义**
- `uploadTemplate011`：返回 `{valid, errors[], warnings[], plan(create|alter), previewDdl}`，**零副作用**；multipart 与 json 同一套校验。
- `deployObject`：带 `template` → 校验通过后落库（038 insert/update，三子整替）、持久化 `source`、再发布；只带 `objectName` → 直接发布已存在对象（等价 `publish`）；已存在对象需 `overwrite=true`。
- 发布受开关 `krt.lowcode.ddl-execute.enabled` 约束；首建 `CREATE`、后仅 `ADD COLUMN`。
- **推荐流程（AI 场景）**：`getTemplate011`（或 `downloadTemplate011`）→ 填/改 → `uploadTemplate011` 看 `errors`+`previewDdl`+`plan` → **人确认** → `deployObject` →（可选）`importDataFromSql`。

## 018.多入口建模（intake · 一句话开发）

**一个引擎、N 个门**（043，P1+P2 部分实现）：入口只负责把来源变成共享契约 `MetadataContent`，审核/发布/同步/运行时/开放 API 只有一套。

| kind | 输入 | 实现 |
|------|------|------|
| `copy` | 既有 objectName（可 rename） | 复用设计器 `load` |
| `template` | 模板 JSON | 复用 040 校验 |
| `sql` | 数据源 + SELECT + businessField | 复用 033 `probeAndInfer` |
| `modeling` | 033 modelCode | 复用交接 `content()` |
| `ai` | 自然语言 `prompt`（+ provider/api/model） | 提示词 = `getTemplate011` 骨架 + `_guide`；**校验失败回喂重试 ≤3** |
| `table` | 数据源 + 表名 | ⏳ 未做（P2/P4） |

- 端点：`POST /klsjnh/lowcode011/intake/v1/{review,create}`，body `{kind, objectName?, overwrite?, dataSourceCode/sql/businessField/prompt/ref/provider/api/model/template}`。
- `review` 零副作用；`create` = 适配 → 复用 `reviewTemplate` / `deployObject`（落库 + 发布）。
- 血缘：`metaData.source = {kind, dataSourceCode?, probeSql?}`（ai 存 prompt；更细的结构化待深化）。
- 代码：`domain.lowcode011.{ModelSourcePort, SourceRequest}` + `application.lowcode011.{ModelingIntakeUseCase, *SourceAdapter}`。

## 019.边界与挂起（2026-09-17 用户口径）

- **挂起（价值有限，保持现状、不再扩展）**：运行时权限模型、真字段映射（`sourceColumn→targetColumn`）、开放 API 限流/CORS、`syncData`、模板批量 `templates[]`、`/runtime` 运行页（前端）。（动态 `objectCode` 审计**已实现**，见上文运行时/开放 API 节。）
- **边界外**：模板存储/版本库（不落库）；模板 → 代码/页面生成；跨环境模板迁移编排；子表类型扩展（「多子」固定 field/display/service 三类）；033 → 本模块的元数据导入；对象间关联/外键。
