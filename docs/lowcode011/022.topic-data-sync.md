# 029.topic-data-sync（数据同步 · 分页读 → 幂等 upsert）

> 低代码知识库 · 数据（039 二期）
> 总览：[011](011.topic-metadata011-system.md)；物理表：[028 发布与 DDL](021.topic-publish-ddl.md)；方案：[req013/039](../requirement013/039.topic-lowcode-designer-runtime.md)。

## 011.定位

数据同步 = 把**源（业务库 SQL）**分页读出，`upsert` 进**目标物理表 `lc_<object>`**；按**业务唯一键**去重，可重复执行。

## 013.端点

| 端点 | 方法 | 入参 | 说明 |
|------|------|------|------|
| `/importDataFromSql` | POST | `{objectName, dataSourceCode, sqlCode, pageNum, pageSize, forceInit?}` | 单页导入（hasMore/nextPageNum 循环） |
| `/importStatus` | GET | `?objectName=` | `{dataInitialized, physicalTable, publishStatus}` |

## 015.机制

```
源分页读：dataservice011.executeSqlByPage（方言分页）
  ↓ rows
列名匹配：源结果列 → 目标列（大小写不敏感；不一致用 SQL 别名，如 orgid pk_organization）
  ↓
缺基列补默认：id 随机 UUID / status '1' / dr '0' / create_time·update_time now
  ↓
写：JdbcTemplateMetadataDataWriter.upsert（ON DUPLICATE KEY UPDATE，按业务键）
  ↓
标记已初始化：july_metadata.data_initialized='1' / last_sync_at
```
- **幂等**：重复导同页不翻倍（业务键唯一 + upsert）。
- **mode**：首次 `init`，其后 `sync`。
- **`businessField`**：目标唯一键（如 `sid`）→ upsert 去重依据。

## 017.端口与实现

`MetadataDataWriterPort.upsert(physicalTable, businessField, rows)` → `JdbcTemplateMetadataDataWriter`；源读用 `JulyBusinessModelingUseCase.executeSqlByPage`（app→app 复用）。

## 019.已知简化

- `updated/unchanged` 以 `processed` 近似（未精确区分）。
- 非分页全量 `syncData` 暂以分页循环代替。

## 021.坑

- 源列名要与目标一致或用别名；否则列落不进去（被白名单过滤）。
- 业务状态映射平台基列（B 口径）：源带 `status` 会覆盖平台启用位（见 [022](015.topic-fieldinfo.md)/[011](011.topic-metadata011-system.md)）。
