# 016.topic-displayinfo（展示列与服务定义 · Display + Service）

> 低代码知识库 · 本篇合并原「016 DisplayInfo011 + 017 ServiceInfo011」。
> 引擎 record：`com.klsjnh.domain.lowcode011.JulyMetadataDisplay` / `JulyMetadataService`（`MetadataContent.displays()/services()` 元素）
> 总览：[011 metadata011 体系](011.topic-metadata011-system.md)；上级：[013 契约与数据模型](013.topic-metadata011.md)。

## 011.定位

- **展示列 `JulyMetadataDisplay`**：列表/表单/自定义场景下「怎么显示一个字段」。它**绑定字段**（`displayCode` → `fieldCode`），决定前端表格/表单的列与组件；**不产生物理列**。
- **服务 `JulyMetadataService`**：对象上可执行的一组「动作/方法」（增删改查、导入导出、发布菜单，或自定义 SQL/脚本），描述「**能做什么**」；本期**只描述不生成代码**。

## 013.展示列组成

| 字段 | 说明 | 约束 |
|------|------|------|
| `displayCode` | 列编码（**身份，不可变**，绑定一个 `fieldCode`） | 必填，≤60 |
| `displayName` | 列名称 | 必填，≤60 |
| `align` | 对齐 | `left/center/right`，未知或空默认 `left` |
| `width` | 列宽（px） | 负数归一为 0 |
| `componentType` | 组件类型（前端渲染用，如 input/select/date…） | 必填，≤30 |
| `displayType` | 展示类型（`DisplayType011`） | null 默认 `all` |
| `param011` | 扩展参数 | 可空 |
| `sortOrder` | 排序 | INT |

**展示类型（`DisplayType011`）**

| 值 | 含义 |
|----|------|
| `all` | 全场景（默认） |
| `table` | 列表 |
| `form` | 表单 |
| `custom` | 自定义 |

## 015.展示列在体系中的角色

- **绑字段**：`displayCode` 必须命中一个已存在的 `fieldCode`（038/040 校验：`display code not bound to a field`）。
- **前端渲染**：`componentType` + `displayType` + `align/width` 驱动列表列/表单控件。
- **同步数据里**：只影响展示，不产生物理列。
- **与 MetaDTO**：`displayData` 段即 `displays`：`{ code, name, align, width, componentType, displayType, param011, sort }`。
- **字典字段的展示**（配合 [015](015.topic-fieldinfo.md) 的 `dictionary011`/`dictionary013`）：
  - 字段类型是字典时，`componentType` 建议 **`select` / `radio`**；
  - `dictionary011`：选项来自字段自身的 `param011`（`值|标签;...`）；`dictionary013`：选项来自系统字典（前端调 `system011/julyDictionary/v1/selectItemListByType`）；
  - `displayType` 决定出现场景（`table` 列表 / `form` 表单 / `all`）；列表里通常渲染**标签**（值→label），表单里渲染**下拉/单选**。

## 017.服务组成

| 字段 | 说明 | 约束 |
|------|------|------|
| `serviceCode` | 服务编码（**身份，不可变**，聚合内唯一） | 必填，≤60 |
| `serviceName` | 服务名称 | 必填，≤60 |
| `description` | 描述 | ≤300 |
| `objectType` | 服务对象类型（`ServiceObjectType011`） | null 默认 global |
| `paramType` | 参数类型（`ServiceParamType011`） | null 默认 none |
| `serviceContent` | SQL / 脚本内容 | 必填，≤**20000** |
| `enabled` | 是否启用 | boolean |
| `sortOrder` | 排序 | INT |

**枚举**

`ServiceObjectType011`：`global_method`（全局方法，默认）/ `table_row_method`（行方法，针对单行）。

`ServiceParamType011`：`none`（无参，默认）/ `string` / `object` / `single_file` / `multi_file`。

## 019.服务在体系中的角色

- **默认服务集**（建房/播种时常见）：`insert / update / delete / query`（+ 可选 `import / export / publishMenu`）。
- **运行时**：前端按 `serviceData` 决定显示哪些操作按钮；实际执行落 `runtime/v1/{insert,update,delete,query}` 或开放 API。
- **只描述不生成**：本期不生成服务代码，`serviceContent` 为预留（自定义 SQL/脚本）。
- **与 MetaDTO**：`serviceData` 段即 `services`：`{ code, name, description, objectType, paramType, serviceContent, enabled, sort }`。

## 021.共同约定

- 两个 element 都是 `MetadataContent` 的 record 子类型，**不可变**；编辑走 copy-on-write。
- 子 `code`（`displayCode` / `serviceCode`）在契约内**大小写不敏感唯一**。
- 与字段的差别：字段产生物理列；展示列只影响呈现；服务只描述动作。
