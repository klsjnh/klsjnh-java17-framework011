## 011.定位

运行时 = **对象可被使用**：发菜单（挂到 system011 菜单树）+ 面向内部（JWT）的动态数据面（meta + CRUD），并对写入做**按元数据的校验**。

## 013.菜单

| 端点 | 方法 | 说明 |
|------|------|------|
| `/publishMenu` | POST | `{objectName, parentMenuCode?}` 幂等发布 `rt_<object>` → `july_menu`（route `/runtime/<object>`，menuType=2） |
| `/listRuntimeMenus` | GET | 列 route 在 `/runtime/` 下的已发布对象（含 version/publishStatus） |

## 015.数据面（JWT）

前缀 `/klsjnh/lowcode011/runtime/v1`：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/meta` | GET | `?objectName=` 运行时表单用 MetaDTO |
| `/query` | POST | `{objectName, filters, pageIndex, pageSize}`（默认过滤 `dr='0'`） |
| `/insert` | POST | `{objectName, ...列}`（补基列默认 + 校验） |
| `/update` | POST | `{objectName, id|sid, ...列}`（局部校验） |
| `/delete` | POST | `{objectName, id|sid}`（有 `dr` 走逻辑删） |

## 017.安全与校验

- **表/列白名单**：以**库表目录**为准（`columnsOf`），值**全绑定**（不拼 SQL）。
- **元数据校验**（`MetadataValueValidator`）：insert 校验必填/类型/长度；update 仅校验出现字段；基列不强制必填。
- **仅已发布对象**可用（物理表取最新快照）。
- **动态 `objectCode` 审计**（2026-09-17 补）：运行时 insert/update/delete 落 `july_user_audit`，`object_code = objectName`，操作者取 JWT。
- **挂起**：运行时权限模型（对象级 + 操作级）。

## 018.1 前端 SSR 表单契约（2026-09-17 明确）

- **前端 SSR 按后端 `meta`（MetaDTO）动态渲染表单/列表**：字段一变，表单自动变，**无需改前端**。
- 用到的段：
  - `fieldData`：`fieldType`（控件类型）、`notNull`（必填）、`defaultValue`、`fieldLength`、`param011`（字典等扩展）→ 控件 + 校验；
  - `displayData`：`componentType` / `displayType`（table/form/all）/ `align` / `width` / `sort` → 列与表单项；
  - `serviceData`：可执行动作（增删改查等）→ 按钮。
- **契约稳定性**：`meta` 是 SSR 的输入，**字段/枚举变更即前端契约变更**（向后兼容优先）。
- **字典字段的选项**：[`dictionary011`](026.topic-dictionary-field.md) 选项内联在 `param011`；`dictionary013` 按 `param011` 的字典编码由前端调 `system011/julyDictionary/v1/selectItemListByType` 获取（或后端在 meta 侧解析，待定）。
