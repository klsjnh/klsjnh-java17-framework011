## 011.三种形态

| 形态 | 类型 | 用途 | 落库 |
|------|------|------|------|
| **契约** | `records.MetadataContent` | 一个业务对象的单一 schema（对象属性 + 三集合） | ❌ |

## 013.契约 MetadataContent

**定位**：不可变值对象，描述「一个业务对象长什么样」；对象属性 + 三个 owned 集合（字段 / 展示 / 服务）。它是 `JulyMetadata` 与 `dataservice011`（033 交接产物）**共享的 published language**。

**组成**

| 字段 | 说明 | 约束 |
|------|------|------|
| `objectName` | 对象名（**身份，不可变**） | 必填，`^[a-z][a-z0-9_]{0,49}$` |
| `objectType` | 对象类型（`ObjectType011`） | 枚举 |
| `description` | 描述 | ≤300 |
| `businessField` | 业务唯一键 | 非基列，固定 `string(33)` |
| `packageName` | 目标包名（代码生成预留） | — |
| `routerPath` | 路由 | — |
| `fields` | `List<JulyMetadataField>` | owned |
| `displays` | `List<JulyMetadataDisplay>` | owned |
| `services` | `List<JulyMetadataService>` | owned |

**不变式与工厂**
- 私有构造；只能由 `create(...)` / `reconstitute(...)` 产出（`reconstitute` 校验保留，作为**边界卫兵**：外来 JSON → fail-fast）。
- 三集合元素以其 `code` 在契约内**唯一**（大小写不敏感）。
- `replaceChildren(fields, displays, services)`：**copy-on-write** —— 编辑产生新 `MetadataContent`，不改原实例。
- 访问器：`objectName()/objectType()/description()/businessField()/packageName()/routerPath()/fields()/displays()/services()`。

**编解码与映射**
| 方向 | 实现 |
|------|------|
| 聚合 ↔ 契约 | `records.MetadataContentMapper.from(JulyMetadata)` |
| 契约 ↔ MetaDTO JSON | `records.MetadataContentCodec.toMetaDto(content)` / `fromMetaDto(dto)` |
| JSON 键常量 | `records.MetaDtoKey011` |
| 平台基列常量 | `records.BaseColumn011`（`ALL` / `AUDIT`） |

## 015.持久化聚合 JulyMetadata

**定位**：持久化就绪聚合根，**组合** `MetadataContent`（子集合单一来源），标量属性仍留在聚合；带 `id`/`sortOrder`/审计。038/039/040 全程使用它。

**表结构（一主三子）**
```
july_metadata              主（id/object_name 唯一不可变/object_type/description/business_field/package_name/router_path/remark/发布态列/公共列）
  ├─ july_metadata_field     field_code/field_name/field_type/field_length/required_field/default_value/(+param011 规划中)/sort_order
  ├─ july_metadata_display   display_code/display_name/align/width/component_type/display_type/param011/sort_order
  └─ july_metadata_service   service_code/service_name/description/object_type/param_type/service_content/enabled/sort_order
```
- 四表都带 `sort_order` + 公共列（`id/status/create_by/update_by/create_time/update_time/dr`）；子表 `pk_mt` 关联主表 `id`。
- DDL：`docs/sql/july_metadata.sql`（038）+ `docs/sql/july_metadata_publish.sql`（039 发布态列 + 旁路表）。

**聚合行为**

| 方法 | 语义 |
|------|------|
| `create(...)` / `update(...)` | 新建 / 改标量属性（`objectName` 不可变） |
| `replaceChildren(fields, displays, services)` | **三子整替**（重建 `content`，validate-then-rebuild） |
| `content()` | 取契约 |
| `findField(fieldCode)` | 按 code 找字段 |
| 访问器 | `objectName()/objectType()/description()/businessField()/packageName()/routerPath()/fields()/displays()/services()` |

**主子整替（关键机制）**
- **insert** = 插主 → 插三子。
- **update** = 改主 → **物理删三子** → 重插三子。
- **logicDelete** = 物理清三子 → 逻辑删主（`@TableLogic`）。
- **为什么子行物理删**：子表唯一键 `(pk_mt, code)` 不含 `dr`，逻辑删后重插会同键冲突（实测 400 duplicate key）。
- 实现：`JulyMetadataRepositoryImpl`（master CRUD + `clearChildren`/`insertChildren`）。

**对象删除与物理表（策略）**
- 逻辑删对象 = 清三子（物理删）+ 逻辑删主（`dr='1'`）；**物理表 `<object>` 保留**（见 [021](021.topic-publish-runtime.md)）。
- 原因：DDL 禁 `DROP`/`RENAME`，自动删表风险高；保留以便追溯/误删恢复。回收走**人工 / DBA**。

**发布态列（039 增）**：`publish_status` / `version` / `physical_table` / `probe_sql` / `sql_code` / `data_source_code` / `data_initialized` / `last_sync_at`。它们是**发布指针 + 来源 + 同步状态**，不改变聚合语义。

## 017.MetaDTO（对外形状与映射）

**定位**：对外 JSON 契约（前端/AI/运行时都用它）：`metaData`（主）+ `fieldData` / `displayData` / `serviceData`（三子）。由聚合组装/反解。

```json
{
  "metaData":   { objectName, objectType, description, businessField, packageName, routerPath, remark, sortOrder,
                  publishStatus, version, source? },
  "fieldData":  [ { code, name, fieldType, length, notNull, defaultValue, param011?, sort } ],
  "displayData":[ { code, name, align, width, componentType, displayType, param011, sort } ],
  "serviceData":[ { code, name, description, objectType, paramType, serviceContent, enabled, sort } ]
}
```
- 段 ↔ 表：`metaData`→`july_metadata`；`fieldData`→`_field`；`displayData`→`_display`；`serviceData`→`_service`。
- 模板扩展键：`templateVersion` / `_guide` / `metaData.source`（见 [021](021.topic-publish-runtime.md) 模板节）。

**映射位置**

| 方向 | 实现 |
|------|------|
| 聚合 → MetaDTO | `JulyMetadataDesignerUseCase.load`（`MetadataContentMapper` + `MetadataContentCodec.toMetaDto`） |
| MetaDTO → 契约 | `MetadataContentCodec.fromMetaDto`（**设计器 save** / 模板 deploy 共用同一边界校验） |
| 快照 payload | `JulyMetadataPublishUseCase.toPayload`（写 `july_metadata_version.payload_json`） |

## 019.约定

- **含平台基列**：`fieldData` 里包含 `id/status/create_by/update_by/create_time/update_time/dr`（正常且必需）。
- 排序：各段按 `sort`（DB `sort_order`）。
- 时间：`publishStatus` / `version` 为字符串；时间字段 ISO（`T` 分隔）。
- 前端对接细节见 [infra011/021](../infrastructure011/021.topic-lowcode011-frontend-guide.md)。
