## 015.三条核心决策（2026-09-17 定案）

1. **发布快照 + 编辑态分离**：物理表结构由**发布那一刻**的元数据驱动，落 `july_metadata_version`（`object_name + version + payload_json`(MetaDTO 快照) + `physical_table` + `backup_table` + `ddl_text` + `published_at`）。`july_metadata` 是 DRAFT 编辑态（保留 `publish_status` / `version` 作当前指针）；发版后继续改元数据**不动已发布快照**。
2. **DDL 边界**：首次发布 = `CREATE TABLE IF NOT EXISTS`；其后**仅 `ALTER`**（`ADD COLUMN` / `ADD INDEX` / `ADD UNIQUE`）；**禁 `DROP` / `DROP COLUMN` / `MODIFY` / `RENAME`**（列类型/长度变更走「新列 + 数据迁移」，二期评估）。对象表统一前缀（`lc_`）并隔离库/schema；发布幂等、可重入；带开关 `krt.lowcode.ddl-execute.enabled`（默认 false）。
3. **运行时权限模型单列**（对象级 + 操作级），不夹在运行时段落里做；本期运行时先按「已发布对象 + 白名单操作」收敛，权限模型随后单独一期。

## 017.业务规则

- **探测**：只读连接 + 超时 + `maxRows`；复用 `dataservice011` 的 `executeSql`/探针，按返回推断字段类型（`inferFieldData`）。
- **元数据校验**：`displayCode` 必须绑定已存在 `fieldCode`；类型过 `FieldType011`/`ObjectType011`；`objectName` 唯一不可变。
- **发布**：建表/ALTER + 版本 + 备份表 + **BACKUP 审计**；失败必须可重入，不留半开状态。
- **运行时 CRUD**：仅已发布对象；字段白名单 + 全绑定参数 + 服务端按元数据校验（required / 类型 / 长度 / 唯一）+ 动态 `objectCode` 审计。
- **开放 API**：`apiKey` 打码出参、仅轮换首次回明文一次；`allowedOps` 白名单；限流。

## 018.业务字段映射平台基列（B 口径，2026-09-17 定案）

**场景**：tuser 建模要加 `status` 并映射到系统现有 `status` 列。

- **允许（B 口径）**：业务字段直接落到平台基列 —— 导入 SQL 带上该列（`select ... , status from tuser`），同步按**列名大小写不敏感匹配**写入目标基列。**无需加元数据字段、无需改代码**。
- **禁止**：在元数据里再加一个同名列（哪怕仅大小写不同）——`july_metadata_field` 唯一键 `(pk_mt, field_code)` 排序规则**大小写不敏感**，`STATUS` 与 `status` 撞键直接 400。
- **代价（已知并接受）**：语义合并 —— 平台 `status`（启用/停用 0/1）被业务状态（如 1/2）占用；admin 启停与数据同步会互相覆盖。平台**删除位是 `dr`**，不受影响。
- **类型**：目标列类型以基列为准（`status VARCHAR(3)`），业务值需能装下。
- **实测（2026-09-17）**：`bpm011.tuser` 4579 行，导入后 `lc_bpm_user011.status` 分布 1:1822 / 2:2757，与源一致；元数据/代码零改动。
- **若要“真映射”**（源列名 ≠ 目标列名且不用别名）：需新增 `sourceColumn → targetColumn` 映射配置 + 同步按映射落列 —— 当前模型没有，列后续。

### 018.1 外键 / 引用列（`pk_xxx`，固定 `VARCHAR(33)`）

- **约定**：引用其他对象的列命名 `pk_<实体>`（如 `pk_organization`），类型**固定 `VARCHAR(33)`**（对齐平台 `id`）。
- **用法（A 路径，无需改代码）**：设计器加字段（`fieldType=string, length=33`）→ `publish` 检测缺列自动 `ALTER TABLE ... ADD COLUMN` → 导入 SQL 用**别名**把源列映射进来（`orgid pk_organization`）。
- **实测（2026-09-17）**：`bpm011.tuser` 4579 行，源 `orgid` 非空 4566（13 空）→ `lc_bpm_user011.pk_organization` 非空 4566，**与源一致**；版本 0.0.2（ALTER）。

### 018.2 开放 API（api_key 公共 CRUD + meta，2026-09-17 落地）

**管理端（JWT，挂 `/klsjnh/lowcode011/julyMetadata/v1`）**
- `GET /openApiConfig?objectName=`：读配置（apiKey 打码）。
- `POST /saveOpenApiConfig`：`{objectName, enabled, authMode(closed/none/apiKey), allowedOps[]}`；首次生成 apiKey 时**回明文一次**。
- `POST /rotateApiKey`：`{objectName}` 轮换，**回明文一次**。

**运行时段（JWT）** — `2026-09-17 落地`
- `POST /publishMenu`：`{objectName, parentMenuCode?}` 幂等发布运行时菜单（`july_menu` 建 `rt_<object>` → `/runtime/<object>`）。
- `GET /listRuntimeMenus`：列路由在 `/runtime/` 下的已发布对象（含 version/publishStatus）。
- `/klsjnh/lowcode011/runtime/v1`：`GET /meta?objectName=`、`POST /query|insert|update|delete`（`{objectName, ...}`，JWT 动态 CRUD，列白名单 + 全绑定 + 补基列默认）。

**开放端（`X-Api-Key` 头；JWT 已白名单 `/klsjnh/open/`）**
- `GET  /klsjnh/open/v1/meta?objectName=`：对象元信息（MetaDTO）。
- `POST /klsjnh/open/v1/query`：`{objectName, filters, pageIndex, pageSize}` 分页。
- `POST /klsjnh/open/v1/insert`：`{objectName, ...列}`。
- `POST /klsjnh/open/v1/update`：`{objectName, id|sid, ...列}`。
- `POST /klsjnh/open/v1/delete`：`{objectName, id|sid}`（有 `dr` 走逻辑删）。

**规则**
- 仅**已发布**对象可用（物理表取最新快照）；表/列以**库表目录为白名单**，值全绑定；`insert` 自动补基列默认（id/status/dr/时间）。
- 鉴权顺序：配置存在且 `enabled` → `authMode=apiKey` 校验 `X-Api-Key` → `allowedOps` 含当前操作；不通过 401。
- apiKey：32 位 hex，读打码 `****xxxx`，生成/轮换明文仅回一次。
- 项目 URL 规约：**禁 path variable**，objectName 走 query/body。

## 021.边界外（本期不做）

- 子表类型扩展（「多子」本期仍固定 field/display/service 三类）；
- 033 → 本模块的元数据导入；
- 行级数据权限 / 字段级脱敏；
- 生产 DDL 自动执行（需 DBA 审核/工单，开关默认关）；
- 对象间关联/外键。

## 022.后续与取舍（2026-09-17 用户口径）

- **交付重点 = 核心链路**：设计 → 发布建表 → 数据同步 → 元数据模板 → 开放 API（均已 E2E）。
- **后续功能价值有限，保持现状、不再扩展**（用户评估）：动态 `objectCode` 审计、运行时权限模型、真字段映射（`sourceColumn→targetColumn`）、开放 API 限流/CORS、`syncData`、模板批量 `templates[]`、`/runtime` 运行页（前端）。
- 挂起项按需再启，不影响已交付链路。
