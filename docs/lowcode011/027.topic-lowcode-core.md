## 013.一主三子

| 角色 | 表 | 说明 |
|------|----|------|
| 主 | `july_metadata` | 对象元数据：object_name（唯一不可变）/ object_type / description / business_field / package_name / router_path |
| 子1 | `july_metadata_field` | 字段：field_code / field_name / field_type / field_length / required_field / default_value |
| 子2 | `july_metadata_display` | 显示列：display_code（绑定字段）/ display_name / align / width / component_type / display_type / param011 |
| 子3 | `july_metadata_service` | 服务：service_code / service_name / description / object_type / param_type / service_content / enabled |

> **四表均带 `sort_order`**（`INT DEFAULT 9999`，升序）；三子用 `pk_mt` 链接主表。

## 015.与既有 lowcode011 / 033 的关系（重要）

- 本模块新增**持久化就绪**的核心聚合：`JulyMetadata` + `JulyMetadataField/Display/Service`（record 子实体，带 `sortOrder`）。
- 033 是**供给方**（`getModelData` 交 `metaData + fieldData`），本模块是**独立 CRUD**；两者将来可做「033 → 本模块」导入（本期不做）。
- **2026-09-17 重构（042）**：原「不改 `domain.lowcode011.model` 值对象」约束**已显式解除** —— `model/` 族（`MetaData011` / `FieldInfo011` / `DisplayInfo011` / `ServiceInfo011`）**已删除**，033 与本模块统一到共享契约 [`records.MetadataContent`](013.topic-metadata011.md)（033 conforming，lowcode011 上游）。

## 017.业务规则

- `objectName` 全表唯一、**不可变**；
- 子 `code` 在**同对象内唯一**；display 的 `displayCode` 必须**绑定一个已存在的 field**；
- **主子表整替**：update 时三子**整体替换**（旧子行**物理删除**再插入——子行是主对象所有、无独立生命周期，且唯一键不含 `dr`，逻辑删除会导致重插撞键）；
- 逻辑删除主对象**级联**子表（先物理清子，再逻辑删主）；
- `objectType` 限 `ObjectType011`；`fieldType` 限 `FieldType011`。

## 019.接口清单（前缀 /klsjnh/lowcode011/julyMetadata/v1）

| 端点 | 方法 | 说明 |
|------|------|------|
| /insert | POST | 新增（主 + 三子整体提交） |
| /update | POST | 修改（objectName 不可变；三子整体替换） |
| /logicDelete | POST | 逻辑删除（级联三子，单个） |
| /logicDeleteBatch | POST | 逻辑删除（级联三子，批量） |
| /getById | GET | 主键点查（含三子） |
| /getByObjectName | GET | 按对象名点查（含三子） |
| /selectListByPage | POST | 分页（对象名关键字 + 类型 + 状态） |
