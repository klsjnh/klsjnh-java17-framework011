## 011.一句话

**metadata011 = 用「元数据」描述一个业务对象（字段 / 展示 / 服务），再由元数据驱动「建物理表 → 导数据 → 运行时/开放 API」**。它是低代码的核心：**数据驱动的声明式对象定义**，不生成代码。

## 013.来龙去脉（老 → 新）

| 维度 | 老 runtime（`business/metadata011`） | 本项目 |
|------|--------------------------------------|--------|
| 存储 | **单表** `july_meta_data`，`field_data` 列塞整个 **MetaDTO JSON** | **一主三子**：`july_metadata` + `_field/_display/_service` |
| 服务 | `MetadataDesignerService` / `MetadataPublishService` / `MetadataDataSyncService` / `OpenApiConfigService` / `GenericCrudService` | `JulyMetadataUseCase` / `JulyMetadataDesignerUseCase` / `JulyMetadataPublishUseCase` / `JulyMetadataDataSyncUseCase` / `JulyMetadataRuntimeUseCase` / `JulyMetadataOpenApiUseCase` / `JulyMetadataTemplateUseCase` |
| 血缘 | `july_meta_data.version011/version013(备份表)/publishStatus/probeSql` | `july_metadata_version`（发布快照）+ `july_metadata` 发布态列 |
| 定位 | 设计器 + 发布 + 运行时菜单 + 开放 API | 同左，**重构为 DDD 一主三子 + 声明式模板** |

> 本项目**保留 MetaDTO 形状**（前端/运行时契约不变），但**落地为一主三子**（可索引、可 DDL、可校验）。
> **2026-09-17 内核重构（042）**：值对象族 `domain.lowcode011.model`（`MetaData011` / `FieldInfo011` / `DisplayInfo011` / `ServiceInfo011`）**已删除**，统一为不可变契约 [`records.MetadataContent`](013.topic-metadata011.md)；`JulyMetadata` **组合**契约，不再自持三套子实体。

## 015.数据模型

**主聚合（对象本体）**
```
july_metadata              主（对象）
  ├─ july_metadata_field     子1：字段（field_code/field_name/field_type/field_length/required_field/default_value/sort_order）
  ├─ july_metadata_display   子2：展示列（display_code/display_name/align/width/component_type/display_type/param011/sort_order）
  └─ july_metadata_service   子3：服务（service_code/service_name/description/object_type/param_type/service_content/enabled/sort_order）
```
- 四表都带 `sort_order`；三子用 `pk_mt` 关联主表；公共列 `id/status/create_by/update_by/create_time/update_time/dr`。
- 主表业务键：`object_name`（唯一、**不可变**）。
- 主子关系：**三子整替**（update 时旧子行物理删、重插）。

**旁路表（不属于聚合）**
```
july_metadata_version      发布快照（object_name+version+payload_json+physical_table+ddl_text+published_by/published_at+...）
july_metadata_open_api     开放 API 配置（object_name/enabled/auth_mode/allowed_ops/api_key/...）
```
- `july_metadata` 另有发布态列：`publish_status/version/physical_table/probe_sql/sql_code/data_source_code/data_initialized/last_sync_at`。

**物理表**：发布后生成 `<object_name>`（MySQL），含平台基列 + 业务列 + `UNIQUE KEY uk_<object>_<businessField>`。

## 017.MetaDTO 形状（对外契约）

```json
{
  "templateVersion": "1.0",
  "metaData":   { "objectName":"bpm_user011", "objectType":"type011", "description":"...", "businessField":"sid",
                  "packageName":"...", "routerPath":"...", "remark":"...", "sortOrder":9999,
                  "publishStatus":"draft", "version":"", "source":{ "dataSourceCode":"bpm011", "probeSql":"..." } },
  "fieldData":  [ { "code":"sid","name":"业务ID","fieldType":"string","length":33,"notNull":true,"defaultValue":null,"sort":1 } ],
  "displayData":[ { "code":"sid","name":"业务ID","align":"left","width":140,"componentType":"input","displayType":"all","param011":null,"sort":1 } ],
  "serviceData":[ { "code":"query","name":"查询","description":"","objectType":"type011","paramType":"query","serviceContent":"","enabled":true,"sort":1 } ]
}
```
- `metaData` ↔ 主表；`fieldData/displayData/serviceData` ↔ 三子；`source`/`templateVersion`/`_guide` 为模板扩展。
- **JSON 不支持注释**：说明放 `_guide`（默认骨架提供）。
- 映射实现：`records.MetadataContentMapper`（聚合 ↔ 契约）与 `records.MetadataContentCodec`（契约 ↔ MetaDTO JSON）。

## 021.生命周期

```
(探测) 数据源+SQL ─► DRAFT 元数据 ─(publish)─► PUBLISHED + 快照 + 物理表 <obj>
                         │                          │
                         │ 继续改（DRAFT）            └─(importDataFromSql)─► 数据入表
                         │                          └─(publishMenu)───────► 运行时菜单
                         │                          └─(saveOpenApiConfig)─► 开放 API
                         └─ 已发布快照不被编辑态影响（july_metadata_version 不可变）
```
- **快照与编辑态分离**：`july_metadata` 是当前编辑态；发布时把当次定义写入 `july_metadata_version`，物理表结构由**发布那一刻**的定义驱动。
- **DDL 规则**：首次 `CREATE TABLE IF NOT EXISTS`；其后仅 `ALTER ... ADD COLUMN`；**禁 `DROP`/`DROP COLUMN`/`MODIFY`/`RENAME`**；开关 `krt.lowcode.ddl-execute.enabled`（默认 false）。

## 025.硬约定（血泪清单）

1. **`objectName`**：`^[a-z][a-z0-9_]{0,49}$`，全局唯一、**不可变**；物理表 `<objectName>`。
2. **平台基列**（`id/status/dr/create_by/update_by/create_time/update_time`）：模板 `fieldData` 里**允许一次**、类型归一；**再加同名（含大小写）= 撞键**（子表唯一键排序规则大小写不敏感 → 400）。
3. **业务唯一键** `businessField`（如 `sid`）：固定 `VARCHAR(33)`，数据同步按它 **upsert**（幂等）。
4. **外键/引用列** `pk_<实体>`（如 `pk_organization`）：固定 `VARCHAR(33)`。
5. **业务字段映射平台基列（B 口径）**：要复用平台列（如把业务状态映射到 `status`），做法是**导入 SQL 带该列**（列名大小写不敏感匹配），**不加元数据字段**；代价是语义合并。
6. **同步按列名匹配**：源列名与目标不一致时用 **SQL 别名**（`orgid pk_organization`）。
7. **禁 path variable**：`objectName` 走 query / body（项目 URL 规约）。
8. **删标记是 `dr`**：逻辑删除位；`status` 是启用/停用（被 B 口径复用时要当心）。

## 027.与其它模块的关系

- **dataservice011（033）**：供给方 —— 探针/执行 SQL/方言分页；metadata011 复用其 `probe`/`executeSqlByPage`。
- **system011（011 菜单）**：运行时 `publishMenu` 在 `july_menu` 建 `rt_<object>`（route `/runtime/<object>`）。
- **system011（035 字典）**：字典字段 `dictionary013` 复用 `JulyDictionaryUseCase`（见 [015](015.topic-fieldinfo.md)）。
- **platform011（030 导出/备份）**：对象可导出；备份走存储中心默认桶。
- **存储中心（037）**：备份落点。
