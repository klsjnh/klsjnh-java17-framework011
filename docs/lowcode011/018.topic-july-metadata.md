# 025.topic-july-metadata（JulyMetadata · 持久化聚合）

> 低代码知识库 · 持久化形态：`com.klsjnh.domain.lowcode011.JulyMetadata`
> 总览：[011](011.topic-metadata011-system.md)；值对象形态：[021 MetaData011](013.topic-metadata011.md)；方案：[req013/038](../requirement013/038.topic-lowcode-core.md)。

## 011.定位

`JulyMetadata` 是低代码对象的**持久化就绪聚合根**：一个主对象 + 三个 owned 子集合（字段 / 展示 / 服务）。它是 038/039/040 全程使用的对象（区别于值对象 `MetaData011`，后者仅供 033 交接）。

## 013.表结构（一主三子）

```
july_metadata              主（id/object_name 唯一不可变/object_type/description/business_field/package_name/router_path/remark/发布态列/公共列）
  ├─ july_metadata_field     field_code/field_name/field_type/field_length/required_field/default_value/(+param011 规划中)/sort_order
  ├─ july_metadata_display   display_code/display_name/align/width/component_type/display_type/param011/sort_order
  └─ july_metadata_service   service_code/service_name/description/object_type/param_type/service_content/enabled/sort_order
```
- 四表都带 `sort_order` + 公共列（`id/status/create_by/update_by/create_time/update_time/dr`）。
- 子表 `pk_mt` 关联主表 `id`。
- DDL：`docs/sql/july_metadata.sql`（038）+ `docs/sql/july_metadata_publish.sql`（039 发布态列 + 旁路表）。

## 015.聚合行为

| 方法 | 语义 |
|------|------|
| `create(...)` / `update(...)` | 新建 / 改标量属性（`objectName` 不可变） |
| `replaceChildren(fields, displays, services)` | **三子整替** |
| `findField(fieldCode)` | 按 code 找字段 |
| 访问器 | `objectName()/objectType()/description()/businessField()/packageName()/routerPath()/fields()/displays()/services()` |

## 017.主子整替（关键机制）

- **insert** = 插主 → 插三子。
- **update** = 改主 → **物理删三子** → 重插三子。
- **logicDelete** = 物理清三子 → 逻辑删主（`@TableLogic`）。
- **为什么子行物理删**：子表唯一键 `(pk_mt, code)` 不含 `dr`，逻辑删后重插会同键冲突（实测 400 duplicate key）。

> 实现：`JulyMetadataRepositoryImpl`（master CRUD + `clearChildren`/`insertChildren`）。

## 019.发布态列（039 增）

`july_metadata` 另带：`publish_status` / `version` / `physical_table` / `backup_table` / `probe_sql` / `sql_code` / `data_source_code` / `data_initialized` / `last_sync_at`。它们是**发布指针 + 来源 + 同步状态**，不改变聚合语义。
