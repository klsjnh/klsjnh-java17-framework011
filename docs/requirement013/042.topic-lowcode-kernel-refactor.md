# 042.topic-lowcode-kernel-refactor（技术方案）

> 阶段：**requirement013（技术方案）** —— 上游评审记录 [lowcode011/030.topic-engine-refactor](../lowcode011/030.topic-engine-refactor.md)（2026-09-17 架构评审；同日与用户讨论「`MetaData011` 抽象成接口」的想法，裁定**契约用组合、不用继承**）。
> 定位：**纯内核重构** —— 不新增表、不改对外端点形状；四期各自可独立验证 / 回滚。**已实施（2026-09-17）**。

## 011.结论与范围

**一句话**：把 `domain.lowcode011.model` 族从"聚合根"降格为**内容契约（record 值对象）**，`JulyMetadata` **组合**它而非各自维护一套子实体；运行时逻辑从三个 UseCase 的复制粘贴收敛为**领域策略 + 表网关**两层。

- **范围**：元模型收口（期一）、内核抽取（期二）、边界定型（期三）、横切端口化（期四，裁剪版）。
- **非范围（尊重 039 挂起口径，不翻案）**：运行时权限模型、开放 API 限流、完整动态 `objectCode` 审计、`syncData`、模板批量 `templates[]`、`/runtime` 运行页前端；api_key 加密存储维持 036「加密二期」口径（本方案只修 NPE→401）。
- **⚠️ 显式解除约束**：038 台账承诺「不改 033 依赖的 `domain.lowcode011.model` 值对象」——本方案**必须触碰该族**（record 化），故 033 侧联动文件一并列入影响清单（见 §015），**需评审明示授权**。

## 013.分期设计

### 期一：模型收口（契约化）

1. `model/` 四类 → **record 契约**：主类更名 `MetadataContent`（原 `MetaData011`；JSON 键名不变，仍 `metaData`/`fieldData`）；`FieldInfo011`/`DisplayInfo011`/`ServiceInfo011` 同步 record 化（现为带 `updateBasics` 的 mutable class —— 转 record 后**编辑走 copy-on-write**，`MetaData011.updateField` 等意图方法改为"产出新 content"）。
2. `reconstitute(...)` 保留为**唯一边界卫兵**：外来 JSON（033 交接 / 040 模板 / 读库）重放不变量，fail-fast；内部路径只走已校验工厂。
3. `JulyMetadata` **删自有 `JulyMetadataField/Display/Service` 三套子实体**（3 文件删除），改持 `MetadataContent content()`；`replaceChildren` 改为 `replaceContent(new MetadataContent)`（聚合内一次换内容，不变量由契约构造期保证）。
4. **契约归属**（030 §013.3 裁定）：留在 `lowcode011.model` 包**不搬迁**；声明 context map —— `lowcode011` 为契约 owner（上游），`dataservice011`（033）conforming。
5. **发布态**（030 §013.4 裁定）：本期轻做 —— 契约只放内容，`physicalTable/version/publishStatus` 等指针留在 `JulyMetadata` + `JulyMetadataVersion`（现状列不动）；独立 `Publication` 类列为后续可选。
6. **033 侧联动**：`JulyBusinessModeling.metaData` 字段类型、`ModelDataCodec011`（encode/decode）、`FieldInferencePort`、`FieldTypeInferrer011`、`web/dataservice011/converter/JulyBusinessModelingConverter`、`application/dataservice011/JulyBusinessModelingUseCase` + `BusinessModelingProbeResult` —— 类型替换，**`model_data` JSON schema 双向兼容**（旧 JSON 必须 decode 通过，作为验收项）。

> **过渡路径（2026-09-17 用户裁定：先写契约、不下沉、慢慢过渡）** —— 不搞大爆炸：
> - **S1（已完成，2026-09-17）**：新增 `MetadataContent`（record，不可变；JSON 键同 MetaDTO）+ `reconstitute`（边界卫兵）+ **单一** `MetadataContentMapper`（`JulyMetadata ↔ 契约`、`MetaData011 ↔ 契约`）。**零行为改动**、不碰 033、不解除 038。
> - **S2**：新入口（043 源适配器）与任何新能力**契约优先**（产/收 `MetadataContent`），经 Mapper 落旧 `JulyMetadata`，下游不变。
> - **S3**：读路径反转（`load/meta/快照` 先建契约再派生旧实体），JSON codec 统一到契约。
> - **S4**：全链走契约后，删旧子实体 + 033 联动（**此时才解除 038**、record 化 `model/` 族）。
> - **两条护栏**：① 新代码契约优先（禁止新增代码再碰 `JulyMetadataField/Display/Service` 之外的旧路径）；② 映射只在 `MetadataContentMapper` 一处 —— 这是**迁移**、非并存架构，须跟踪收敛。

### 期二：内核抽取（ROI 最高）

- **`ObjectTablePolicy`（domain，纯策略、无 IO）**：补公共列（现 `fillBaseDefaults`：id/status/dr/审计时间）、按元数据校验（委托 `MetadataValueValidator`）、逻辑删判定（`dr` 在则置 `1`）、分页规格构造（**clamp [1,500]**，对齐 033 `executeSqlByPage` 口径）。
- **`ObjectTableGateway`（application.lowcode011，注入 `MetadataDataAccessPort`）**：落 IO / 物理表解析（现 `physicalTable`）/ 基列补齐 / `update` 刷 `update_time`（现状遗漏）。
- **三个 UseCase 只留编排差异**：`JulyMetadataRuntimeUseCase`（JWT 面）、`OpenApiUseCase`（api_key 鉴权面）、`JulyMetadataDataSyncUseCase`（取数面）—— 各自删除近乎逐行重复的 `fillBaseDefaults`/`filter`/`integer`/`physicalTable`。
- **诚实化返回值**：`DataSyncUseCase` 的 `updated/unchanged/skipped` 恒 0 假字段 → 改真实计数（writer 返回分类统计）或删除字段。

### 期三：边界定型

- web↔application 边界出裸 `Map`：定型 `ObjectQueryCommand`（objectName/filters/pageIndex/pageSize）+ `RowView`（行视图）；domain 策略只认内部 `RowValues`（包一层的 Map）。列动态性只保留在数据层。
- **顺手修**：`meta()` GET 命名 → `getMeta()`（对齐 016 get* 约定，三层同步 + `funcName`）。

### 期四：横切端口化（裁剪版）

- **`CurrentOperatorPort`（domain 端口）**：web filter 填充、网关消费 —— 网关统一补 `create_by`/`update_by`（开放 API 写入以 api_key 对象身份 / `system` 兜底落 `create_by`），**不逐 UseCase 传 `Operator011`**。完整动态审计仍按 039 挂起。
- **约定回归修复**（一次性清账）：`LocalDateTime.now()` 裸调 **9 处** 全部归口 `DateUtil011`；`DatasourceDdlExecutor` 的 `@Value("${krt.lowcode.ddl-execute.enabled}")` → `KrtConfig011` 新增 Lowcode 配置段（`krt.lowcode.*`）；`OpenApiUseCase.authorize` 的 `apiKey.equals(...)` **NPE→401**（header 缺失 + authMode=apiKey 现状 500）。
- **不做**（列为后续深水区，默认不启动）：发布状态机 + 补偿（`PENDING→EXECUTING→PUBLISHED`）、同步 checkpoint/水位。
