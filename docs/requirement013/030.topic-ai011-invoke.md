## 013.解析与调用链

```
provider 入参 ──(先 id 后 providerCode)──► AiModelProvider（baseUrl/models/status）
api 入参     ──(先 id 后 apiCode，缺省默认启用)──► AiModelProviderApi（apiKey/status）
model 入参   ── **必传**（一个 provider 多种模型，无安全默认；空 → 400）
returnType   ── url / bytes / b64（能力默认；厂商尽量满足，否则报错）
能力路由     ── AiProviderRegistry 按 providerCode 找支持该能力的 SPI 实现
```
        │
        ▼
AiChatCommand(baseUrl, apiKey, model, messages, temperature, maxTokens)
        │
        ▼  AiChatPort（OpenAiCompatChatAdapter）
POST {baseUrl}/chat/completions   Bearer <apiKey>   timeout
        │
        ▼
AiChatResult(content, finishReason, usage)  →  出参（apiKey 不出）
```

- **id/code 解析**：`repository.findById(x)` 命中即用；否则 `findByCode(x)`；都无 → 404。
- **默认密钥**：复用 `AiModelProviderUseCase.getDefaultApi(providerCode)`（首个启用）。
- **审计**：`objectCode = providerCode`，内容含 model + token 数（**不含 key**）。

## 021.E2E 计划 / 结果

1. provider/api 传 **id** 与 **code** 结果一致；缺省 api = 首个启用密钥；✅（代码路径）
2. **model 必传**：不传 → 400；✅（代码路径）
3. chat：`step-3.7-flash` 实调返回内容；✅
4. tts：`stepaudio-2.5-tts` 返回 mp3 二进制；✅（53KB）
5. image：`step-image-edit-2` 文生图 —— **StepFun 服务端 503 过载，挂起**；
6. 图生图 `/images/edits`（multipart）—— **未接，挂起**。

## 023.风险

- **超时/限流/费用**：首版超时 + 审计；限流/计费后续。
- **密钥安全**：只在服务端用；不落日志/不出参。（036 已定密钥明文入库、加密二期——调用面同样受此约束）
- **协议差异**：非 OpenAI 兼容厂商需适配器；端口已预留。
- **流式**：首版不做；前端需要流式时再补（SSE）。
