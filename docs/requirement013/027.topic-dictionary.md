## 013.关键机制

### 013.1 主子表落地方式（日常 Incremental vs 导入 Replace）

`BaseMasterSubRepository` 的 `saveChildren` 是**替换式**（旧明细全逻辑删 + 重插），适用于「整单提交」。字典**日常管理**明细是**逐条增改删**，故：

- 主表仓继承 `BaseMasterSubRepository`，复用 `cascadeDelete` / `getWithChildren`；**日常明细走 Incremental**（直调明细仓），**不走** `saveChildren`（口径见 [011/018](../infrastructure011/011.persistence-spec/018.topic-master-sub-api.md) §011.016）；
- **xlsx 导入**例外：对文件中出现过的 `dictionaryCode`，UseCase `importWorkbook` 对该主下明细做 **Replace**（逻辑删旧 + 插新）；文件未出现的其它字典不动；
- 使用用例持有 `@Transactional`（跨主/子两次写必须同一事务；整包导入亦然）。

### 013.2 程序读入口（无 HTTP）

```
getByType(code)              → 主表 findEnabledByCode(code)；null（不存在/停用）直接返回 null
                             → 明细 findByMaster(id) 过滤 status='1'，按 sort_order 升序
getLabel(code, itemCode)     → getByType 后按 itemCode 命中，返回 itemLabel；否则 null
isValidItem(code, itemCode)  → getLabel != null
```

- 与 029 `getByCode` 同口径：**每次查库、无缓存**；
- 停用字典 → `getByType` 返回 null（对其明细同样不可见）。

### 013.3 排序与唯一

- 主表 `dictionaryCode` 唯一（`uk_dictionary_code`）；明细 `(pk_mt, item_code)` 唯一（`uk_pk_mt_item_code`）；
- 所有列表（管理分页 / 明细 / 程序读取）一律 `ORDER BY sort_order ASC`，同值按 `id` 稳定次序。

## 015.DDL 与契约

- DDL：`docs/sql/july_center_platform011.sql`（主表 + 子表，列顺序 `id → 业务字段 → status → 审计四列 → dr`）。
- **无信封 / 状态码增量** —— 复用 `013.api-contract.md` 六键信封与 `HttpCodeEnum011`。
- 错误码映射：

| 场景 | 状态码 |
|------|--------|
| dictionaryCode 重复 / itemCode 同字典内重复 | 400 |
| getById / getLabel 目标不存在 | 404（getById）/ null（getLabel） |
| 删除主表时仍存在存活明细（默认口径） | 400 |
| 导入校验失败（含孤儿明细编码等） | 400（fail-fast；整单回滚） |

| 端点（前缀 /klsjnh/system011/julyDictionary/v1） | 方法 | 请求 | 出参 data |
|--------------------------------------------------|------|------|-----------|
| /insert | POST | Body：dictionaryCode / dictionaryName / sortOrder / remark | IdVo011 |
| /update | POST | Body：id + dictionaryName / sortOrder / status / remark | IdVo011 |
| /logicDelete | POST | Body：id | IdVo011 |
| /getById | GET | Query：id | JulyDictionaryVo011（含明细） |
| /getByCode | GET | Query：code | JulyDictionaryVo011（含明细） |

## 021.E2E 验收清单

1. `insert` 建一条字典（dictionaryCode=demo_dict）→ 200 + IdVo011
2. 同 `dictionaryCode` 再 insert → 400
3. `update` 改名称/排序/状态 → 200
4. `insertItem` 在该字典下建两条明细 → 200 + IdVo011
5. 同字典内重复 `itemCode` → 400；另一字典用同 `itemCode` → 200
6. `updateItem` → 200
7. `getById` → 返回字典 + 明细，明细按 sort_order 升序
8. `selectListByPage` 关键词 + 状态过滤 → 命中正确
9. `selectItemListByType` → 明细按 sort_order 升序、状态过滤生效（Body **无** keyword）
10. `logicDeleteItem` → 该明细消失，主表不受影响
11. 启用字典 + 启用明细 → `getByType` 返回有序明细
12. 明细 `status=0` → `getByType` 不含该明细；`getLabel`/`isValidItem` 返回 null/false
13. 字典 `status=0` → `getByType` 返回 null
14. `logicDelete` 主表时仍存活明细 → 400（默认口径）
15. 明细清空后 `logicDelete` 主表 → 200；`getById` 404
16. `POST .../export` 默认 → JSON `ExportResult`（含主表行）；`format=xlsx` → 二进制两 sheet（master + children）
17. `POST .../import` 上传 xlsx → 200；主表 upsert；文件内出现过的 code 明细 Replace；未出现的字典不动
18. 导入孤儿明细编码 / 坏表头 → 400 且整单回滚
