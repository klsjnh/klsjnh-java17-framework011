## 013.关键机制

- **模板 = MetaDTO + `source` + `templateVersion`（+ 可选 `_guide`）**：`downloadTemplate` 由 `designer.load(objectName)` 加 `metaData.source` 拼出；`deployObject` 反向映射回一主三子，复用 038 `insert/update`（三子整替）。
- **注释形式**：合法 JSON + `_guide` 字段（JW 不支持注释；不引入 JSONC 解析）。
- **校验与归一集中一处**（`validate`）：`reviewTemplate` 与 `deployObject` 共用，避免"审核一套、落库一套"。
  - 基列 `id/status/dr/create_by/update_by/create_time/update_time` **允许出现一次**，类型归一（33/3/date）；**再加同名（含大小写）= 子 code 大小写不敏感重名 → 拦截**。
  - `businessField` 必须存在且**不得为基列**，固定 `string(33)`；`pk_*` 固定 `string(33)`。
- **审核零副作用**：用 `MetadataDdlGeneratorPort` 对**内存 fields** 直接生成 `previewDdl`，用 `MetadataDdlExecutorPort.tableExists` 判 `plan=create|alter`；不落库、不执行。
- **部署**：校验 → 已存在则要求 `overwrite=true`（否则 400）→ 038 保存 → `updateSource` → 039 `publish`（受 `krt.lowcode.ddl-execute.enabled` 约束）。
- **无状态两拍**：`uploadTemplate011` 与 `deployObject` 之间无暂存；deploy 重新校验（幂等）。
- **双入口**：multipart 单文件与 JSON body 映射到同一 `reviewTemplate`（`consumes` 区分）。

## 015.端点与出入参

## 023.风险

- **基列重名**：靠"子 code 大小写不敏感唯一"拦截（039 实测教训）。
- **overwrite 语义**：三子整替 + 子行物理删 → 元数据编辑历史丢失（与 038 一致）。
- **部署高危**：仍受开关 + DDL 白名单（首建 CREATE / 后仅 ADD COLUMN / 禁 DROP）；生产需 DBA 闸门。
- **批量**：本期只做单对象模板；批量 `templates[]` 未做（可后续加，注意发布不在事务内）。
