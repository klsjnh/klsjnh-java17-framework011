## 011.调度引擎选型：Quartz 内存模式

- 依赖：`spring-boot-starter-quartz`（**`java17-scheduler-quartz011-starter`** 引入，版本由 Boot 3.4.5 BOM 管理 = Quartz 2.5.0）
- JobStore：**RAMJobStore（内存）**——`july_scheduler` 表本身是任务事实源，应用启动时按 `status='1'` 重新注册；不引入 JDBC JobStore 的 11 张 QRTZ_* 表
- 引擎 API ↔ 业务动作映射：启动=`scheduleJob`；停止=`deleteJob`；执行一次=`triggerJob`（一次性触发器）；改 cron=`rescheduleJob`；校验=`CronExpression.isValidExpression`
- TaskScheduler 否决：无按名摘除 / 立即触发 / misfire 策略

CREATE TABLE july_scheduler (
    id                 VARCHAR(33)  NOT NULL                COMMENT '主键',
    status             VARCHAR(3)   NOT NULL DEFAULT '0'    COMMENT '运行态（0 停止 / 1 运行）——本表业务约定默认 0',
    remark             VARCHAR(300) NULL                    COMMENT '备注',
    create_by          VARCHAR(33)  NULL                    COMMENT '创建人',
    update_by          VARCHAR(33)  NULL                    COMMENT '最后修改人',
    create_time        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建日期',
    update_time        DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后修改日期',
    dr                 VARCHAR(3)   NOT NULL DEFAULT '0'    COMMENT '删除标记（0 正常 / 1 已删除）',
    scheduler_code     VARCHAR(30)  NOT NULL                COMMENT '任务编码',
    scheduler_name     VARCHAR(60)  NOT NULL                COMMENT '任务名称',
    scheduler_handler  VARCHAR(300) NOT NULL                COMMENT '处理器内容（Spring Bean 名）',
    scheduler_cron     VARCHAR(30)  NOT NULL                COMMENT 'cron 表达式',
    execute_times      INT          NOT NULL DEFAULT 0      COMMENT '执行次数（触发即计）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_scheduler_code (scheduler_code),
    KEY idx_status (status)

- `uk_scheduler_code`：业务唯一兜底（应用层预检仅是友好提示）

### 015.1 handler 解析规则

`scheduler_handler` = **Spring 容器内的 Bean 名**，Bean 本身实现 `JobHandler`（`handlerName` + `execute`）。触发时经 `JobHandlerRegistry` 解析——Bean 缺失或执行异常：`execute_times` 照常 +1（011 §023-2 触发即计），记 WARN 日志，**写 `july_scheduler_audit` FAIL 行**，**不影响调度继续**。

### 015.2 引擎联动规则（update）

update 保存成功后**无条件重同步引擎**（幂等）：先 `deleteJob` 摘除旧注册，再按新 status 决定——'1'（运行）→ `scheduleJob` 重新注册（cron/handler 变更等效于改周期重注册）；'0'（停止）→ 仅摘除。start / stop 端点是同一条重同步逻辑的快捷入口（只翻转 status）。

### 015.3 引擎一致性说明（已知简化）

内存引擎操作在事务方法内执行；若事务回滚，引擎状态可能与 DB 短暂不一致——由"重启自愈 + 下次启动重注册"兜底，本期接受。
