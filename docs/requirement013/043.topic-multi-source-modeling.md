## 013.关键机制

- **kind 路由**：`ModelingIntakeUseCase` 按 `source.kind` 选适配器；**新增入口 = 加适配器**，下游零改（OCP）。
- **类型归一**：适配器把来源类型映射到 `FieldType011`（各源方言差异只在适配器内）。
- **契约过审**：任何入口产出都走「归一 + 校验」（保留基列/大小写唯一/业务键 `businessField` 与 `pk_*` 固定 `VARCHAR(33)`/枚举/display 绑定）。
- **AI 重试环**：`AiPromptSourceAdapter` 的 system prompt = `getTemplate011._guide` + 硬规则；校验失败把 `errors` 回喂重试（≤N 次）。
- **source 落库**：`metaData.source = {kind, dataSourceCode, table|sql|prompt}`；**重同步默认 source 回放**（可复现）。
- **幂等再入**：同 `objectName` → diff → `ALTER ADD COLUMN`；`overwrite` 控制三子整替。
- **数据同步多来源**：`source` 回放 / 显式 SQL / **mock 造数** / 异表直拷 / AI 行；统一「业务键 upsert + checkpoint + 写前校验」。

## 021.E2E 计划

1. `kind=sql`（bpm011 `select id sid,...`）→ create → 审核/建表/导数据全通；
2. `kind=template`（上传既有模板）→ 一致；
3. `kind=copy`（复制 bpm_user011）→ 改 objectName → 建新表；
4. `kind=ai`（"开一个销售订单主表"）→ AI 出 JSON（失败重试）→ 建表；
5. `kind=table`（选 tuser）→ 免 SQL 建表；
6. `mockRows=N` → 造 N 行（明文标注模拟）；
7. 相同 objectName 再入 → ALTER（幂等）。

## 023.风险

- **契约归属**未定 → 必漂（先做 030 P1）。
- **类型映射/方言**：各源归一 + 表结构读方言，工作量集中在适配器。
- **AI 不稳定**：校验+重试+人工确认，禁无人值守建表。
- **可复现**：`source` 必须落库并版本化。
- **安全**：源只读 + 审计 + 限流；AI/表源不越权。
- **范围膨胀**：入口按需加，先 P1（sql/template/copy）验证架构。
