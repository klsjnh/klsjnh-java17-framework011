## 013.关键机制

### 013.1 表驱动多实例（对齐 031/036 口径）

```
解析：storageCode → StorageResolverPort.resolve(code)
  → 缓存命中即返回
  → july_storage.findByCode(code)（缺失/停用 → 400）
  → StorageConnectionConfig（from 聚合）
  → ObjectStorageFactoryPort.create(config) → adapter
  → 入缓存
```

- `krt.storage-center.*`（yaml）降级为**播种来源**：启动把 default 实例写入 `july_storage`（存在即跳，绝不覆盖），此后**表为唯一运行时真源**；
- provider 取值统一 `StorageType011`（local011/minio011/cos011/tos011/oss011/s3011）；老 `LOCAL/S3` 映射：`LOCAL→local011`、`S3→s3011`。

### 013.2 适配器工厂（对现状的改造）

现状：`LocalObjectStorageAdapter` / `MinioObjectStorageAdapter` 是 `@ConditionalOnProperty` 的 **Spring bean**，直接读 `StorageProperties` → **单实例**。

改造：
1. 适配器构造入参改为 `StorageConnectionConfig`（与实例解耦，可多实例）；
2. `ObjectStorageFactory011` 按 `config.provider` 造 adapter（local011→Local、minio011/s3011/…→Minio/S3 系）；
3. 适配器**不再是单例 bean**，由工厂按需造 + Resolver 缓存；`default-type` 只决定播种实例的 provider。

### 013.3 在线编辑（迁 `EditableTextPolicy`）

- `readText(bucket, objectName)`：`stat` 校验 ≤1MB → `get` → UTF-8 解码 → 返回 `{content, editorKind, contentType, size}`；
- `saveText(bucket, objectName, content)`：`content` UTF-8 字节校验 ≤1MB → `put`（contentType 按扩展名）；
- `editorKind`：`.sql`→`sql`，其余→`markdown`；
- 策略落 **domain**（纯 Java），应用层调用。

### 013.4 秘密收口

`secretKey` 与 accessKey 属敏感：`JulyStorageVo011` **类型层不含 `secretKey`**（对齐 dataservice `password` / ai011 `apiKey`）；`update` 留空保持原值。

## 015.DDL 与契约

### 015.1 DDL（新落 `docs/sql/july_storage.sql`，本项目列口径）

```sql
CREATE TABLE IF NOT EXISTS july_storage (
    id                     VARCHAR(33)  NOT NULL                COMMENT '主键',
    sort_order             INT          NOT NULL DEFAULT 9999   COMMENT '排序（越小越靠前）',
    storage_code           VARCHAR(60)  NOT NULL                COMMENT '存储实例编码（全局唯一，不可变）',
    storage_name           VARCHAR(100) NOT NULL                COMMENT '存储实例名称',
    provider               VARCHAR(20)  NOT NULL DEFAULT 'local011' COMMENT '存储类型（StorageType011）',
    base_path              VARCHAR(500) NULL                    COMMENT '本地根目录（local011 必填）',
    endpoint               VARCHAR(300) NULL                    COMMENT 'Endpoint（S3 系必填）',
    access_key             VARCHAR(100) NULL                    COMMENT 'Access Key',
    secret_key             VARCHAR(300) NULL                    COMMENT 'Secret Key（出参不回显）',
    secure                 VARCHAR(3)   NOT NULL DEFAULT '0'    COMMENT 'HTTPS（0 否 / 1 是）',
    default_bucket         VARCHAR(100) NULL                    COMMENT '默认桶',
    presign_expiry_seconds INT          NOT NULL DEFAULT 3600   COMMENT '预签名有效期（秒）',
    remark                 VARCHAR(300) NULL                    COMMENT '备注',
    status                 VARCHAR(3)   NOT NULL DEFAULT '1'    COMMENT '状态（0 停用 / 1 启用）',
    create_by              VARCHAR(33)  NULL                    COMMENT '创建人',
    update_by              VARCHAR(33)  NULL                    COMMENT '最后修改人',
    create_time            DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建日期',
    update_time            DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '最后修改日期',
    dr                     VARCHAR(3)   NOT NULL DEFAULT '0'    COMMENT '删除标记（0 正常 / 1 已删除）',
    PRIMARY KEY (id),
    UNIQUE KEY uk_storage_code (storage_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='存储中心 - 对象存储实例';
```

> 与老表差异：`id VARCHAR(33)`、审计四列本项目口径、`dr '0'/'1'`、`provider` 用 011 类型值；`create_date/modify_date/created_by/updated_by` 老口径**不照搬**。

## 023.风险点

| # | 风险 | 等级 | 对策 |
|---|------|------|------|
| 1 | 适配器改造影响既有端口调用方 | 中 | 端口不变，仅构造入参 + bean 装配方式；既有 `ObjectStoragePort` 注入点需改为经 Resolver（若已有调用方） |
| 2 | 表驱动后 yaml 与表漂移 | 中 | 播种「存在即跳」+ 漂移 WARN（对齐 031 seed） |
| 3 | `secretKey` 泄露 | 高 | VO 类型层剔除 + 日志不打印 |
| 4 | 大对象下载 OOM | 高 | 本期管理面下载**先限大小**或直接列流式二期；见 §023 |
| 5 | bucket/object 操作打真实存储 | 中 | 本地盘/测试 MinIO 验证；生产用只读或独立实例 |
