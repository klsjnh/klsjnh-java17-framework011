# 041.topic-ai011-invoke（技术方案）

> 阶段：**requirement013（技术方案 · 双源合流唯一落点）** —— 合流 [requirement011/041](../requirement011/041.topic-ai011-invoke.md)。
> 定位：在 [036 ai011](../requirement013/036.topic-ai011.md)（模型接入）之上，补「**调用 AI 模型（chat）**」能力：provider/api 支持 **id 或 code**，OpenAI 兼容协议，供平台内部（AI 自开发）与 HTTP。
> **状态：已实现并 E2E（2026-09-17）**。

## 011.技术落点（类清单）

```
java17-domain011（包 com.klsjnh.domain.ai011）
  AiChatPort                       chat(ChatCommand) → ChatResult（端口；HTTP 实现留在 infra）
  AiChatCommand                    record（baseUrl/apiKey/model/messages/temperature/maxTokens）
  AiChatMessage                    record（role/content）
  AiChatResult                     record（content/finishReason/promptTokens/completionTokens/totalTokens）

java17-infrastructure011（包 com.klsjnh.infrastructure.ai011）
  chat/OpenAiCompatChatAdapter     实现 AiChatPort：JDK HttpClient POST {baseUrl}/chat/completions
                                   Authorization: Bearer <apiKey>；解析 choices[0].message.content + usage
  （厂商适配器：非 OpenAI 兼容时另加，端口不变）

java17-application011（包 com.klsjnh.application.ai011）
  AiInvokeUseCase                  resolveProvider(id|code) + resolveApi(id|code|default)
                                   → 组 AiChatCommand → 调 AiChatPort → 结果脱敏 + 审计

java17-web011（包 com.klsjnh.web.ai011.controller）
  AiChatController                 POST /klsjnh/ai011/julyAiChat/v1/chat
  vo/AiChatRequestVo011 / AiChatResponseVo011
```

## 013.解析与调用链

```
provider 入参 ──(先 id 后 providerCode)──► AiModelProvider（baseUrl/models/status）
api 入参     ──(先 id 后 apiCode，缺省默认启用)──► AiModelProviderApi（apiKey/status）
model 入参   ── 缺省取 provider.models 首个
        │
        ▼
AiChatCommand(baseUrl, apiKey, model, messages, temperature, maxTokens)
        │
        ▼  AiChatPort（OpenAiCompatChatAdapter）
POST {baseUrl}/chat/completions   Bearer <apiKey>   timeout
        │
        ▼
AiChatResult(content, finishReason, usage)  →  出参（apiKey 不出）
```

- **id/code 解析**：`repository.findById(x)` 命中即用；否则 `findByCode(x)`；都无 → 404。
- **默认密钥**：复用 `AiModelProviderUseCase.getDefaultApi(providerCode)`（首个启用）。
- **审计**：`objectCode = providerCode`，内容含 model + token 数（**不含 key**）。

## 021.E2E 计划（longcat 为例）

1. 036 建 provider `longcat`（baseUrl OpenAI 兼容）+ api（apiKey）→ `chat` 返回 content；
2. `provider` 传 **id** 与传 **code** 结果一致；`api` 传 id/code/缺省 三种都对；
3. 不传 `model` → 取 `provider.models` 首个；
4. provider 停用 → 400；错误 key → 明确错误；超时 → 超时错误；
5. 审计落 `ai_model_provider`/providerCode，内容**不含 key**。

## 023.风险

- **超时/限流/费用**：首版超时 + 审计；限流/计费后续。
- **密钥安全**：只在服务端用；不落日志/不出参。（036 已定密钥明文入库、加密二期——调用面同样受此约束）
- **协议差异**：非 OpenAI 兼容厂商需适配器；端口已预留。
- **流式**：首版不做；前端需要流式时再补（SSE）。
