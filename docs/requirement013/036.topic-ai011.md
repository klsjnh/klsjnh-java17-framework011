## 013.关键机制

### 013.1 主子表与排序

- 两表 PO 均继承 `BasePo011`（`BasePo` + `sort_order`，默认 9999）；
- 主聚合与密钥实体分离（密钥有独立生命周期），仓储按表拆分；`@Transactional` 在用例层；
- 列表：主表 `ORDER BY sort_order ASC, id ASC`（管理分页）；子表 `ORDER BY sort_order ASC, id ASC`；
- 删除约束：删主表前 `apiRepository.countByMaster(id, enabledOnly=false)` > 0 → 400。

### 013.2 密钥脱敏（收口点唯一）

- 转换到 `AiModelProviderApiVo011` 时**不复制 `apiKey`**，VO 类型层**不定义该字段**（不是置空）；
- `updateApi` 的 `api_key` 留空 → 保持原值；
- 程序读入口 `getApiList` 返回领域实体（含 key），仅在应用内部使用，不经 web。

### 013.3 程序读入口（无 HTTP）

```
getByCode(code)        → 主表 findEnabledByCode(code)；null（不存在/停用）返回 null
getApiList(code)       → getByCode + 子表启用密钥，sort_order 升序
getDefaultApi(code)    → getApiList 的第一条；无返回 null
```

### 013.4 连通性探测

```
testConnection(providerCode)
  → getByCode / getDefaultApi
  → GET {base_url}/models   Authorization: Bearer <apiKey>
  → AiModelProbePort.probe(baseUrl, apiKey)
       ├── JDK HttpClient，5s 连接 / 10s 读超时
       ├── 2xx → success=true, message="HTTP 200"
       └── 非 2xx / 异常 → success=false, message=安全提示（不含 key）
  → HTTP 恒 200，结果在 data（success/message/httpStatus）
```

## 021.E2E 验收清单（Step 5 用）

1. `insert` 建 stepfun → 200 + IdVo011
2. 同 providerCode 再 insert → 400
3. `update` 改名称/排序/models → 200
4. `insertApi` 建两条密钥 → 200 + IdVo011
5. 同提供商内重复 apiCode → 400；另一提供商同 apiCode → 200
6. `getById` / `selectListByPage` → 顺序按 sort_order
7. `selectApiListByProvider` → 有序、**无 apiKey 字段**
8. `updateApi` apiKey 留空 → 库里 key 不变（探测仍通）
9. `logicDeleteApi` → 密钥消失
10. 有存活密钥时 `logicDelete` 提供商 → 400；清空后 → 200
11. `testConnection`（有效 key）→ success=true + httpStatus
12. 程序入口：`getByCode` / `getDefaultApi`（内部）
13. 停用提供商/密钥 → 读入口不可见
