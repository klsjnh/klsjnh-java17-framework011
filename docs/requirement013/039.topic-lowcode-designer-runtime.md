## 013.关键机制

- **MetaDTO 组装**：一主三子 ↔ 老 `MetaDTO` 形状的组装内聚在 `JulyMetadataDesignerUseCase`（load）与 `JulyMetadataPublishUseCase`（快照 payload），未单列 Converter；两处都从同一聚合读出，保持字段一致。
- **发布快照**：`publish` 把当次聚合落 `july_metadata_version`（含 `ddl_text`），并把 `july_metadata` 的 `publish_status=PUBLISHED` / `version` 指向该版本；**DRAFT 编辑不触碰已发布快照**。
- **DDL 生成器**：`previewDdl` 与 `publish` 共用 `MetadataDdlGeneratorPort`（`generateCreate` / `generateAddColumns`）；首次 `CREATE TABLE IF NOT EXISTS lc_<objectName>`（业务键固定 `VARCHAR(33)` + `UNIQUE KEY uk_<table>_<field>`），其后仅 `ALTER ... ADD COLUMN`；**禁止 DROP/DROP COLUMN/MODIFY/RENAME**；标识符正则 `^[A-Za-z_][A-Za-z0-9_]{0,59}$` + 反引号转义。
- **发布幂等**：先判表在否（不在 → `CREATE IF NOT EXISTS`；在 → 仅补缺列 `ADD COLUMN`，天然幂等）→ 执行 DDL → 落快照(PUBLISHED) + 推进发布指针；失败可重跑（无 PENDING 断点续做）。开关 `krt.lowcode.ddl-execute.enabled` 默认 false。
- **探测复用（039 未单独暴露）**：探测走 `dataservice011` 现有 `probe` / `executeSql` 端点（只读 + maxRows + 字段推断 `inferFieldData`）；039 的 `save` 直接接收 MetaDTO。
- **数据同步映射**：源结果列 → 目标列**按列名大小写不敏感匹配**（`JdbcTemplateMetadataDataWriter`）；缺基列补默认（id 随机 UUID / status '1' / dr '0' / 时间 NOW）；按业务唯一键 upsert。因此**「业务字段映射平台基列」= 导入 SQL 带该列**即可（见 req011/039 §018），无需字段/代码改动；同名列（含大小写变体）不可再加元数据字段（唯一键大小写不敏感）。
- **新增业务列（A 路径）**：设计器 `save` 加字段 → `publish` 检测缺列自动 `ALTER ... ADD COLUMN` → 导入按别名映射；外键/引用列命名 `pk_<实体>` 且固定 `VARCHAR(33)`（见 req011/039 §018.1），全程无代码改动。
- **开放 API / 数据访问**：仅 PUBLISHED 对象；表/列以**库表目录为白名单**；值全绑定；`insert` 补基列默认。**按元数据的 required/类型校验与动态审计未做**（运行时段）。

## 020.一期 E2E（助手自测，2026-09-17）

- 用例：数据源 `bpm011`（Oracle），SQL `select id, userid, name from tuser`，对象 `bpm_user011`。
- `POST /save`（MetaDTO：10 字段 / 3 显示 / 4 服务）→ 200 + id；
- `GET /load?objectName=bpm_user011` → metaData + 10/3/4 三子；
- `GET /listModels` → 含 `bpm_user011`（publishStatus=draft）；
- `GET /previewDdl?objectName=bpm_user011` → `CREATE TABLE IF NOT EXISTS lc_bpm_user011(...)`（PK=id、类型映射正确）。
- **遗留（探针）**：033 探针带出伪列 `KLSJNH_RN`（行号）且不回别名（`id sid` 仍得 `ID`）——039 侧保存前手工剔除；建议 033 修复。

### 二期（发布）E2E（2026-09-17）

- `POST /publish`（bpm_user011）首次 → `CREATE TABLE IF NOT EXISTS lc_bpm_user011(...)`，version `0.0.1`；表建成（10 列，PK=id，类型映射正确）；
- 再次 publish → 表已存在且无缺列 → `ddl=null`、version `0.0.2`（幂等）；
- 加字段 `email` 后 publish → `ALTER TABLE lc_bpm_user011 ADD COLUMN email VARCHAR(100)`、version `0.0.3`（**后仅 ADD**）；
- `july_metadata` 指针 `PUBLISHED / 0.0.3 / lc_bpm_user011`；`july_metadata_version` 三条快照（0.0.1/0.0.2/0.0.3）。
- **开关**：`krt.lowcode.ddl-execute.enabled`（dev=true；默认 false，生产暗发）。
- **修正**：`JulyMetadataVersionPo` 继承 `BasePo011` 需 `sort_order`，两张新表已补列（DDL 文件同步）。

### 二期（数据）E2E（2026-09-17）

- **业务键**：`sid` 为业务唯一主键（第三方元数据）；设计器保存时**归一为 `VARCHAR(33)`**，生成器兜底同规则；`CREATE` 附 `UNIQUE KEY uk_<table>_sid (sid)`。
- **导入**：`importDataFromSql` 走 033 `executeSqlByPage`（方言分页）读源，`JdbcTemplateMetadataDataWriter` 按 `sid` 唯一键 `ON DUPLICATE KEY UPDATE` upsert；缺基列自动补默认（id 随机 UUID / status '1' / dr '0' / 时间 NOW）。
- **E2E**：page1 → 100 行；**page1 重导 → 仍 100（幂等）**；page2 → 200；page1 再导 → 仍 200；`mode` init→sync；`importStatus` `dataInitialized=true`。
- **已知简化**：`updated/unchanged` 暂以 processed 近似（未区分），`syncData`（非分页全量）暂以分页循环代替。

## 021.风险（已评审，见 req011/039 §023）

- **DDL 不可逆/半开**：幂等 + 可重入 + 开关 + 独立库/前缀；禁 MODIFY/DROP。
- **注入**：表/列/排序白名单 + 全绑定参数；`escapeIdentifier` 仅标识符。
- **权限/合规**：生产 DDL 走开关（默认关）+ DBA 审核；运行时权限模型单列。
- **探测慢查询**：只读 + 超时 + maxRows + EXPLAIN 预检。
- **version 语义**：对齐老 `version011`（`"0.0.1"` 递增字符串），前端占位递增整数需同步改。
- **E2E 污染**：独立测试库 + `lc_` 前缀隔离。
