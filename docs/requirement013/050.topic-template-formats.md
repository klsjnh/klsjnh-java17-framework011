## 011.结论（一句话）

模板留在 `lowcode011`：抽 **`TemplateCodec` 端口**（导出/导入字节），实现 JSON / **CSV（分段单文件）** / XLSX（占位）；**任意格式解析成 MetaDTO 后复用现有 validate / review / deploy**，下游唯一。

## 015.接口变更

| 端点 | 变更 |
|------|------|
| `GET /downloadTemplate011` | 新增 `format`（`json` 缺省 / `csv` / `xlsx`），非 json 返回文件流（`Content-Disposition`） |
| `POST /uploadTemplate011` | multipart 时按文件扩展名（`.json/.csv/.xlsx`）或 Content-Type 选 codec；JSON body 仍走 json |
| `POST /deployObject` | 不变（接收解析后的模板/对象名） |

## 017.实现要点

- **CSV 分段**：解析器按行扫描，遇 `##<段>` 切换当前段；段内首行表头；`metaData` 段为 `key,value`。
- **归一复用**：CSV/JSON 都产出 **MetaDTO map**（键走 `MetaDtoKey011`），随后完全走 [040] 的 `validate` / `reviewTemplate` / `deployObject`——**不新增校验分支**。
- **严格度**：非 AI 模板导入必须有 `businessField`（[045]）；缺则 400。
- **依赖**：CSV 自研（不引 `commons-csv`）；XLSX 待引入 `apache poi-ooxml`。
- **安全**：上传大小/行数上限；段名/列名白名单（防注入到 DDL 前已被 `validate` 约束）。
