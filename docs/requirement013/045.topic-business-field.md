# 045.topic-business-field（技术方案）

> 阶段：**requirement013（技术方案 · 双源合流唯一落点）** —— 合流 [requirement011/045](../requirement011/045.topic-business-field.md)。
> 状态：**已裁决 · 已实现并 E2E（2026-09-18）**。

## 011.结论（一句话）

**除 AI 外，所有来源必须指定业务字段 `businessField`（`string(33)` + 唯一键 + 同步去重依据）；AI 唯一例外（缺 → 回退 `id`）**。`sid` 不参与规则。

## 013.落点改动（已实现）

| 位置 | 改动 |
|------|------|
| `ModelingIntakeUseCase.intake` | 非 `ai` 的 kind：`content.businessField()` 空 → `BusinessException.badRequest` |
| `AiSourceAdapter` | 提示词要求业务键；`fallbackBusinessField`：`metaData.businessField` 空 → 置 `id` |
| `JulyMetadataDesignerUseCase` / `JulyMetadataTemplateUseCase` | 经 `JulyMetadataUseCase.insert/update` 兜底校验 |
| `JulyMetadataUseCase.insert/update` | `businessField` 空 → 400 |
| `JulyMetadataTemplateUseCase.validate` | 空 `businessField`（非 ai）→ error；`ai` 回退 `id` 时放宽「非基列/需在 fieldData」两条 |
| `blankTemplate` / `_guide` | 示例 `sid` → `order_no`；guide 说明业务键必填、`sid` 不特殊、AI 可回退 `id` |
| `MySqlMetadataDdlGenerator` | `businessField == 主键` 时不建 `uk_`（既有逻辑，满足 AI 回退 `id`） |

## 015.校验矩阵

| 来源 | 缺 `businessField` | 类型 | 唯一键 |
|------|--------------------|------|--------|
| `ai` | 回退 `id` | `string(33)`（若给出） | 给出业务键（非 id）才建 |
| `sql` / `template` / `copy` / `modeling` / 设计器 / 038 CRUD | **400** | 固定 `string(33)` | 建 |
