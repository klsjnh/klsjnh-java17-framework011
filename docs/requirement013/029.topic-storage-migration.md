## 013.关键机制

> **稳态机制已收口至架构底册**（表驱动解析 / 适配器工厂形态 / 启动播种 / 在线编辑 / 密钥收口）→ [archive011/infrastructure011/011.storage-center/013](../archive011/infrastructure011/011.storage-center/013.topic-architecture.md) §017–§020。本节只留**落地改造**要点，完整改造清单见 §017。

- 适配器构造入参由 `StorageProperties` 改为 `StorageConnectionConfig`（与实例解耦，可多实例），**不再是单例 bean**，由 `ObjectStorageProviderRegistry` 按 `config.provider` 现造；

- 启动播种 `StorageSeed011`：yaml → `default` 实例 + 默认桶子行，**存在即跳、绝不覆盖**，此后表为唯一运行时真源。

### 015.2 端点与出入参

前缀：`/klsjnh/storagecenter/julyStorage/v1`（实例+桶）、`/klsjnh/storagecenter/julyObject/v1`（对象）。

| 端点 | 方法 | 说明 |

## 021.与老项目的取舍（不照搬）

| 老做法 | 本期决策 | 原因 |
|--------|----------|------|
| `create_date/modify_date/created_by/updated_by` | ❌ 用本项目公共列口径 | 016 §7 命名规约 |
| `id varchar(32)` | ❌ `VARCHAR(33)` | base-entity 模板 |
| `dr varchar(1)` | ❌ `VARCHAR(3)` '0'/'1' | Status011/Dr 口径 |
| `provider LOCAL/S3` | ⚠ 改造为**开放字符串 code + provider 注册表** | 内置 local011/minio011/s3011，与架构底册一致 |
| 端口 `InputStream` 形态 + `Map<String,Object>` 返回 | ⚠ 保留本项目 `byte[]` + 记录类型；流式列二期 | 架构底册 [011.storage-center/011](../archive011/infrastructure011/011.storage-center/011.topic-design.md) §019 分期 |
| `presignedGetUrl` | ✅ 迁（local→`file:` URI；S3/minio→minio SDK 预签名） | 决策 4 定案做 |
| `R`/`PageSizeResolver`/`PageQuery` 老通用体 | ❌ 用本项目 `Response011`/`PageQuery011`/`PageResult011` | 契约统一 |
| `DomainException` | ❌ 用 `BusinessException` | 全局异常口径 |

## 023.风险点

| # | 风险 | 等级 | 对策 |
|---|------|------|------|
| 1 | 适配器改造影响既有端口调用方 | 中 | 端口不变，仅构造入参 + bean 装配方式；既有 `ObjectStoragePort` 注入点需改为经 Resolver（若已有调用方） |
| 2 | 表驱动后 yaml 与表漂移 | 中 | 播种「存在即跳」+ 漂移 WARN（对齐 031 seed） |
| 3 | `accessKey` / `secretKey` 泄露 | 高 | 出参打码 `******` + 日志不打印明文 |
| 4 | 大对象下载 OOM | 高 | 本期管理面下载**先限大小**或直接列流式二期（见 [架构底册 011](../archive011/infrastructure011/011.storage-center/011.topic-design.md) §019） |
| 5 | bucket/object 操作打真实存储 | 中 | 本地盘/测试 MinIO 验证；生产用只读或独立实例 |
