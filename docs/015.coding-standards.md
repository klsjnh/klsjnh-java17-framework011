# 015 — 编码规则（Coding Standards）

> 编码规则的**事实来源**：`tools/check-klsjnh-standards.mjs` 的每条规则都对应本文档的编号章节。
> 强制方式标注：【AST】tree-sitter 语法树强制 ·【正则】文本扫描强制 ·【评审】人工评审项。
> 门禁环境异常（tree-sitter 不可用）按失败处理，**不允许跳过**。

## 1. 文件头（rule: `file-header`）【正则】

每个 `.java` 文件 `package` 之后是 klsjnh 文件头块：`package` 与头块之间**空一行**，头块 `*/` 与 `import` 之间**空一行**，history 行用**小写描述**（禁止写类名）。

```java
package com.klsjnh.infrastructure.persistence.entity;

/*                BasePo class
 *
 *      @author     xiangrkrs@163.com
 *      @version    ver 0.0.1
 *      @createdate 2026.09.12
 *      @modifydate
 *
 *===========================================
 *          modify history
 *
 *      2026.09.12  base po class
 *
 */

import com.baomidou.mybatisplus.annotation.FieldFill;
```

违规示例（门禁会拦）：history 行写 `BasePo`（类名而非描述）；头块紧贴 `package`；头块后直接 `import`。

## 2. Javadoc

### 2.1 类/接口 Javadoc（rule: `class-javadoc` / `class-javadoc-blank`）【正则】

类型声明前必须有英文 Javadoc，且 Javadoc 结束后**空一行**再接注解或类型声明：

```java
/**
 * Persistence base PO mapped to the base columns
 * (id / status / create_by / update_by / create_time / update_time / dr).
 */

@Data
public class BasePo implements Serializable {
```

### 2.2 Javadoc 一律英文（rule: `javadoc-english`）【正则】

Javadoc 块内禁止中文；中文描述放 web 层 VO 的 `@Schema` 或 DDL 注释。

### 2.3 字段单行注释【评审】

字段用单行 `/** ... */` 英文注释（参照 BasePo 字段风格）：

```java
    /** Primary key, 32-char UUID, auto assigned on insert when blank. */
    @TableId(type = IdType.ASSIGN_UUID)
    private String id;
```

### 2.4 方法 Javadoc（rule: `method-javadoc`）【正则】

方法必须有 Javadoc，参数用 `@param`、返回用 `@return`；`@Override` 方法用 `{@inheritDoc}`；禁止连续重复的 Javadoc 块。

## 3. funcName 模式（rule: `func-name`）【AST】

**作用域**：`BaseRepository` 家族（BaseRepository / BaseRepository011 / BaseTreeRepository / BaseTreeRepository011）子类，或 `persistence.repository` 包内，`public` 非 static、方法体含日志或 `throw` 的方法——方法体第一条语句必须是：

```java
String funcName = "<操作名>";
```

`funcName` 的**值必须是小写空格分隔单词**（如 `re register`、`logic delete`），禁止连字符 / 下划线 / 大写——该格式规则在**全项目范围**强制（不限于基座作用域），违规示例：`re-register`。

`funcName` 复用于错误消息（`funcName + ": ..."`）和日志（第一个占位符）；禁止在多处硬编码操作名。

合规（BaseRepository011.logicDelete）：

```java
public String logicDelete(T entity) {
    String funcName = "logic delete";

    String id = requireId(entity, funcName);
    int rows = mapper.deleteById(id);

    if (rows == 0) {
        throw BusinessException.notFound("record not found, id=" + id);
    }

    logger.info("{} {} {} success ...", funcName, getTableName(), id);

    return id;
}
```

违规：方法里直接写 `logger.info("insert {} ...", ...)`（操作名硬编码在日志模板里）或不定义 `funcName`。

## 4. 日志规范（rule: `log-concat`）【AST】

- 日志一律 `{}` 占位符，**禁止字符串拼接**——跨行拼接同样被语法树规则拦截；
- **日志首占位符 = funcName**（rule: `log-funcname`）【AST】：凡声明了 funcName 的方法，其所有带 `{}` 占位符的 logger 调用，第一个占位符实参必须是 `funcName` 变量；无占位符的调用（如裸消息 + 异常对象）豁免；
- 禁止 `: {}` / `= {}` 键值占位风格（键与值用空格分隔，如 `krt.status = {}`）——【评审】。

```java
// 合规
logger.info("{} {} total {} success {} failed {} ...",
        funcName, getTableName(), result.getTotal(), result.getSuccess(), result.getFailed());

// 违规：拼接（跨行也拦）
logger.info("insert " +
        getTableName());
```

## 5. 结构与空行（rule: `brace-blank` / `control-blank`）【正则】

- `if`/`else` 块内保持紧凑：块内禁止空行、花括号相邻处禁止空行；
- 方法体内"变量声明 → 逻辑 → return"等逻辑块之间留空行（违规由 AI 按门禁输出修复）。

## 6. Controller API（rule: `api-url` / `api-method` / `api-delete-arity` / `api-vo-payload`）【正则】

### 6.1 禁路径参数（rule: `api-url`）

`@*Mapping` 禁止 `/{param}` 路径参数，参数走 Query 或 JSON Body：

```java
// 违规
@PostMapping("/user/{id}")

// 合规
@PostMapping("/user")          // id 在 JSON Body 里，JSON 键 camelCase
@GetMapping("/user")           // 读操作用 GET，id 走 Query：/user?id=xxx
```

### 6.2 HTTP 方法与动作语义匹配（rule: `api-method`）

**HTTP 方法是协议层语义契约（RFC 9110）** —— 方法必须反映动作的真实性质：

| 动作性质 | 方法 | 判据 |
|----------|------|------|
| **safe + idempotent**（读） | `@GetMapping` | 不改变服务端状态、可重复执行 |
| **unsafe**（写） | `@PostMapping` | 有副作用 |

**动作命名与方法的对应（铁律）**：

| 动作形态 | 语义 | 方法 | 参数通道 |
|----------|------|------|----------|
| `getById` / `getByXxx` | **点查**：按键取单条 | **必须 `@GetMapping`** | Query string |
| `selectXxx`（`selectListByPage` / `selectTree` / `selectList` / `selectUserMenuTree`） | **条件查询**：按筛选对象取列表 | **GET 或 POST 均可** | POST 时走 JSON Body（`*QueryVo011`）；GET 时走 Query |
| `insert` / `update` / `upsert` / `logicDelete` / `logicDeleteBatch` / `delete` / `deleteBatch` / `assignRoles` / `assignMenus` / `resetPassword` / `changePassword` / `login` / `loginByUserName` / `logout` / `start` / `stop` / `runOnce` / `export` | **写** | **必须 `@PostMapping`** | JSON Body |

**核心判据是「参数形态」，不是「是否读」**：`getByXxx` 的参数是一个键，天然适合 query string；
`selectXxx` 的参数是一个开放的筛选对象（嵌套集合、日期区间、动态条件），query string 表达不了，
所以 POST + `*QueryVo011` body 是正解 —— 与 Elasticsearch 用 `POST /_search` 是同一个取舍。

> **`selectXxx` 为何豁免**：门禁对 `selectXxx` **不设方法约束**（GET/POST 都放行），
> 因为它的 safe + idempotent 语义不依赖动词，而取决于实现是否只读。
> 若未来某个 `selectXxx` 写成 GET 更合适（参数简单），无需改门禁即可切换。

```java
// 违规：点查用了 POST —— 谎报 unsafe，导致缓存失效 / 网关不敢重试
@PostMapping("/julyUser/v1/getById")

// 合规：点查用 GET，键走 query string
@GetMapping("/julyUser/v1/getById")     // GET /julyUser/v1/getById?id=xxx

// 合规：条件查询用 POST，筛选对象走 body
@PostMapping("/julyUser/v1/selectListByPage")
public Response011<PageResult011<JulyUserVo011>> selectListByPage(
        @RequestBody JulyUserQueryVo011 queryVo) { ... }

// 合规：写动作用 POST
@PostMapping("/julyUser/v1/insert")
```

> **为什么点查用 GET**：GET 承诺 safe + idempotent，使标准缓存层、网关重试、HTTP 预取全部可用；
> POST 则被基础设施假定为不可缓存、不可重试 —— **本可自愈的失败会变成必须上报用户的失败**。
>
> **过渡说明**：本次改造覆盖全部点查（`getById` ×7 + `selectTree` ×2 + `selectUserMenuTree` ×1 已改 GET）。
> `selectXxx` 系列保留 POST，并在门禁中**显式豁免**，不再是「待办违规」。

### 6.3 删除动作分层（rule: `api-delete-arity` / `api-vo-payload`）

**删除按「单个 / 批量」拆成一对动作，不合并、不重载** —— 二者的失败语义与返回结构本就不同。

| 动作名 | 入参 | 返回 | 语义 |
|--------|------|------|------|
| `logicDelete` | `IdVo011`（**单个 id**） | `IdVo011` | 删一条；不存在即抛 `recordNotFound` |
| `logicDeleteBatch` | `IdsVo011`（**id 列表 VO**） | `BatchDeleteResultVo011` | 删多条；部分成功可容忍，逐条回报 |

```java
// 合规：单个 —— 收 IdVo011，抛异常表达失败
@PostMapping("/logicDelete")
public Response011<IdVo011> logicDelete(@RequestBody IdVo011 idVo) { ... }

// 合规：批量 —— 收 IdsVo011，用 BatchDeleteResultVo011 表达部分成功
@PostMapping("/logicDeleteBatch")
public Response011<BatchDeleteResultVo011> logicDeleteBatch(@RequestBody IdsVo011 idsVo) { ... }

// 违规：叫 logicDelete 却收 List —— 名字承诺单个，行为是批量，调用方无从判断该读哪种返回
@PostMapping("/logicDelete")
public Response011<BatchDeleteResultVo011> logicDelete(@RequestBody IdsVo011 idsVo) { ... }

// 违规：@RequestBody 收裸集合 —— 请求载荷必须是具名 *Vo011 类型
@PostMapping("/logicDeleteBatch")
public Response011<BatchDeleteResultVo011> logicDeleteBatch(@RequestBody List<String> ids) { ... }
```

**为什么必须拆**：

1. **返回类型不可兼容** —— 单个失败靠抛异常（`recordNotFound`），批量失败靠 `errors` 列表回报（部分成功是正常结果）；合并后前端拿到 `data` 不知道是 id 还是 result 结构。
2. **`delete` 一词已被「物理删除」占用** —— `mapper.deleteById` / `deleteBatchIds` 都是真删。业务层逻辑删除**必须**保留 `logicDelete` 词根，不得简写为 `delete`，否则语义误导。
3. **物理删除不进业务 Controller** —— 它是基础设施维护动作（见 §7 与 `docs/infrastructure011/011.topic-infrastructure.md`），不进业务 API；未来若暴露，走独立维护入口，不占用业务动作名。

**为什么 `IdsVo011` 而不是 `List<String>`**（rule: `api-vo-payload`）：

请求载荷（入参）**一律是具名 `*Vo011` 类型**，不允许裸集合 / 裸 `Map`。理由：

1. **可演进** —— 裸 `List` 无法在不破坏契约的前提下加字段（如 `dryRun` / `reason`）；VO 加字段是兼容变更。
2. **SpringDoc 可读** —— `List<String>` 生成的 schema 是无名 `array`，Swagger 里显示为一串 `string`，看不出语义；`IdsVo011` 有独立 schema 名与字段说明。
3. **错误信息可定位** —— 参数校验失败时能报 `idsVo.ids[2]`，裸集合只能报「第 3 个元素」。
4. **与出参对称** —— 出参早已统一 `*Vo011`，入参没理由例外。

> **批量端点命名**：动词打头。`logicDeleteBatch` ✅ / `batchLogicDelete` ❌（`batch` 打头偏离「动词开头」规律）。

## 7. DDD 结构规则【评审（规划：ArchUnit / AST 扩展）】

- domain 依赖受限：只允许纯 Java + record；禁 Lombok 与任何框架注解；仅可依赖 common 的**纯 Java 共享内核**（枚举 / 工具类，如 Status011 / StringUtil011），共享内核本身须零框架依赖；
- `@Transactional` 只出现在 application 层；
- PO / Mapper 不出 infrastructure：application、web 不 import 任何 `*Po` / `*Mapper`；
- Controller 只注入 application 服务；RepositoryImpl 实现 domain 仓储接口；
- 业务唯一性断言只是友好预检，真正的保证是数据库唯一索引；
- **禁止魔法值**：状态 / 删除标记等取值比较一律通过枚举（`Status011.ENABLED` 等），代码中不得散落 `'0'` / `'1'` 字符串字面量（DDL 注释除外）；
- **异常消息收敛**：同一措辞出现 ≥2 次才提取为 `BusinessException` 静态工厂（带参模板，如 `recordNotFound(id)` / `wrongAccountOrPassword()`）——**不做消息常量类**（消息带上下文拼接，常量装不下）；funcName 模式不变（操作上下文由调用处 funcName 承担，工厂只管"说什么"）；
- **FrameConst011 准入**（`common.constant`）：只收跨层共享（≥2 层消费）的框架常量；禁收消息文案（funcName / 工厂领域）、状态码（HttpCodeEnum011 + 016 契约领域）、列宽（DDL 模板领域）——防止退化成 KC 式常量大杂烩；
- **链接列规约 `pk_<目标表>`**：主子表的子表用 `pkMt` 链接主表（实现 `MasterLinked`）；其他跨表链接同规约命名——`pk_menu` → `pkMenu`（菜单）、`pk_role` → `pkRole`（角色）等；PO 中禁止其他 `*Id` 形态字段（白名单：`id` / `pkMt` / `parentId`）。

## 8. 命名规则（rule: `naming`）【AST】

按"包 → 必须后缀"检查**顶层类与 record** 名（嵌套类随外部类命名；接口与枚举暂不强制，如 `MasterLinked`）：

| 类别 | 后缀 | 例子 |
|------|------|------|
| 传输载荷（入参/出参 VO） | `*Vo011` | IdVo011 / BatchDeleteErrorVo011 / BatchDeleteResultVo011 |
| 分页对（自带方向语义，**例外**） | `*Query011` / `*Result011` | PageQuery011 / PageResult011 |
| 持久化对象 | `*Po` / `*Po011` | BasePo / BasePo011 |
| 统一响应信封 | `Response011` | Response011 |
| 基座/枚举/配置类 | 语义名 + `011` | BaseRepository011 / FrameworkStatus011 / KrtConfig011 |

- `common.vo` 的载荷类一律 `*Vo011`；web 层专用 VO 放 `web.<域>.vo`，同样 `*Vo011`；
- 分页对例外：`Query` / `Result` 后缀已表达入参/出参方向，不再叠加 `Vo`。

## 9. import 分组与顺序（rule: `import-order`）【正则】

import 按来源分组，**组间恰好一个空行、同组连排、组号只能升序（允许跳号）**。规则源：`tools/klsjnh-standards-lib.mjs` 的 `importGroup()`，与自动重排脚本 `tools/fix-import-order.mjs` 同源，二者不允许出现分歧。

```text
①  org.slf4j.*                    日志（最高优先级，必须打头）
②  lombok.*                       注解类
③  com.klsjnh.common.*            共享内核
④  com.klsjnh.domain.*            领域层
   com.klsjnh.application.*       应用层（与 domain 同组）
⑤  com.klsjnh.web.*.converter.*   Web 转换器
⑥  com.klsjnh.web.*.vo.*          Web 传输对象
⑦  io.swagger.*                   接口文档
⑧  org.springframework.*          框架
⑨  其他三方                        com.baomidou / cn.hutool / …
⑩  java.* / javax.*               JDK（必须垫底）
```

文件只写自己实际用到的组；组号升序即可，不必连续。

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

import lombok.Data;

import com.klsjnh.common.page.PageQuery011;

import com.klsjnh.domain.iam.JulyUser;
import com.klsjnh.application.iam.JulyUserUseCase;

import com.klsjnh.web.system011.converter.JulyUserConverter;

import com.klsjnh.web.system011.vo.julyuser.JulyUserVo011;

import io.swagger.v3.oas.annotations.media.Schema;

import org.springframework.stereotype.Service;

import com.baomidou.mybatisplus.core.mapper.BaseMapper;

import java.util.List;
```

最小例子（VO 类只用到 lombok / swagger / java 三组）：

```java
import lombok.Data;

import io.swagger.v3.oas.annotations.media.Schema;

import java.time.LocalDateTime;
```

**自动修复**：`node tools/fix-import-order.mjs <root> [--write]` —— 干跑打印待改文件，`--write` 落盘。重排只调整分组与空行，**不改变组内原有相对顺序**，避免无关行抖动。
