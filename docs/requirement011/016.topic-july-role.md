## 015.业务规则

- **role_code 全表唯一**（唯一索引兜底），创建后不可修改；
- **内置角色保护（is_builtin='1'）**：内置角色（如超级管理员）禁止逻辑删除、禁止停用（status 置 '0' 拒绝）、禁止修改 role_code；
- 超级管理员角色拥有全部权限（鉴权时特判，不依赖权限明细数据）；
- 逻辑删除前校验：角色下仍有用户关联（july_user_role）时拒绝删除，或级联停用关联——**倾向拒绝删除**，先解绑再删；
- 逻辑删除后同时级联删除其权限明细（july_role_permissions）。

## 017.关系与联动

- **角色授权两通道**（见 [018 · 016 动态权限](../infrastructure011/018.iam-center/016.topic-dynamic-permission.md)）：
  - **菜单通道**：`assignMenus` → `july_role_permissions(pk_menu, permission_code)`——导航 + 按钮显隐；
  - **直授通道**：`assignObjectActions` → 同表按对象勾选动作（`pk_menu` 可空）——无菜单也能授码（如启停）；
- **运行时过滤**：仅当 UseCase 显式 `assertHas` 时按码拦（opt-in）；只授码、用例未挂核对 ≠ 自动过滤；
- **角色下的用户**：通过 `july_user_role` 关联表，角色视角查询/分配走同一张表；
- 角色逻辑删除 → 级联删除其权限明细与用户关联。

### 011.附属表：july_role_permissions（角色-权限）

继承 BasePo 公共列，业务列：

| fieldCode       | fieldName | fieldType | fieldLength | requiredField |
| --------------- | --------- | --------- | ----------- | ------------- |
| pk_mt           | 角色 id   | String    | 33          | true          |
| pk_menu         | 菜单 id   | String    | 33          | false（直授可空） |
| permission_code | 权限标识  | String    | 100         | true          |

- **一行语义**：角色 ×（可选菜单）× 权限标识——菜单通道带 `pk_menu`；直授通道可空 `pk_menu`、以 `permission_code` 为准；
- **链接列规约**：`pk_mt` = `july_role.id`（MasterLinked），`pk_menu` = `july_menu.id`（可空）；
- UNIQUE / toggle-dr 以 DDL 与实现为准；整存替换策略不变；
- 菜单通道：勾选目录/菜单时级联展开子孙 `permission_code`；直授通道：按目录对象动作整存替换（`actionCodes:[]` 撤该对象直授）；
- 鉴权消费：用户权限码集合 = 其全部角色权限明细并集；超级管理员（`is_builtin='1'`）特判全量。
