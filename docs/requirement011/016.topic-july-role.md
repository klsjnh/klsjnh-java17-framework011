## 015.业务规则

- **role_code 全表唯一**（唯一索引兜底），创建后不可修改；
- **内置角色保护（is_builtin='1'）**：内置角色（如超级管理员）禁止逻辑删除、禁止停用（status 置 '0' 拒绝）、禁止修改 role_code；
- 超级管理员角色拥有全部权限（鉴权时特判，不依赖权限明细数据）；
- 逻辑删除前校验：角色下仍有用户关联（july_user_role）时拒绝删除，或级联停用关联——**倾向拒绝删除**，先解绑再删；
- 逻辑删除后同时级联删除其权限明细（july_role_permissions）。

## 017.关系与联动

- **角色授权 = 勾选菜单（权限挂菜单）**：`july_role_permissions` 关联表一行 = 角色 × 菜单 × 权限标识——页面级看 pk_menu，按钮级看 permission_code；整存替换策略；
- **角色下的用户**：通过 `july_user_role` 关联表（见 015 §017.1），角色视角查询/分配走同一张表；
- 角色逻辑删除 → 级联删除其权限明细与用户关联。

### 017.1 附属表：july_role_permissions（角色-权限，挂菜单）

继承 BasePo 公共列，业务列：

| fieldCode       | fieldName | fieldType | fieldLength | requiredField |
| --------------- | --------- | --------- | ----------- | ------------- |
| pk_mt           | 角色 id   | String    | 33          | true          |
| pk_menu         | 菜单 id   | String    | 33          | true          |
| permission_code | 权限标识  | String    | 100         | true          |

- **一行语义**：角色 × 菜单 × 权限标识——`pk_menu` 记录可访问的菜单（页面级），`permission_code` 记录该菜单下授予的权限标识（按钮级，为未来按钮权限控制预留）；
- **链接列规约**：`pk_<目标表>`——`pk_mt` = 主表链接（`july_role.id`，实现 MasterLinked），`pk_menu` = `july_menu.id`，PO 字段驼峰 `pkMt` / `pkMenu`；
- UNIQUE (pk_mt, pk_menu, permission_code)——唯一键覆盖全部行（含 dr='1'），**同一组合永远只有一行**；
- **整存替换 = toggle dr（不删不插）**：授权时行存在则复活（dr='0'），不存在才插入；取消授权时置 dr='1'。杜绝"删旧+插新"在唯一键下的冲突与行堆积；
- pk_menu / permission_code 必须存在于 july_menu（id / permission_code），应用层校验；
- **授权粒度**：勾选目录/菜单时级联展开全部子孙 permission_code 一并入表，取消勾选同理；`permission_code` 为快照语义——菜单改码视为停用+重新授权；
- 鉴权消费：用户权限码集合 = 其全部角色（dr='0' 且 status='1'）的权限明细并集；超级管理员（is_builtin='1'）特判全量。
