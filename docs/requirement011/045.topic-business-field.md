# 045.topic-business-field（业务字段 businessField 口径）

> 阶段：**requirement011（业务设计与业务要求）**。
> 状态：**已裁决（2026-09-18）· 已实现并 E2E**。
> **2026-09-18 收口**：① **不再讨论 `sid`**；② **取消「已存在的表」场景（原场景 8）**；③ 规则极简为一条。

## 011.唯一规则

- **除 AI 外，所有建模场景必须指定业务字段 `businessField`**（`sql` / 前端元数据编辑器 / 手写 JSON / Excel / CSV）。
- **AI 是唯一例外**：未给出时**回退 `id`**（放宽，不 400）。
- `businessField`：类型固定 **`string(33)`**；给了就建 **`UNIQUE KEY uk_<table>_<field>`**；**数据同步按它去重（upsert，幂等）**。
- 业务字段**非空校验在代码层**完成，**不加 DB 约束**（留例外余地）。
- **`sid` 不再讨论**：不特殊、非必填、无规则（仅为历史常用字段名）。

## 013.场景对照

| 场景 | 是否必须指定 `businessField` |
|------|------------------------------|
| `sql` / 前端元数据编辑器 / 手写 JSON / Excel / CSV | ✅ **必须**（缺 → 400） |
| `ai`（一句话开发） | ❌ **例外**（缺 → 回退 `id`） |

## 015.已实现（2026-09-18）

- `ModelingIntakeUseCase`：非 `ai` 的 kind 缺 `businessField` → 400。
- `AiSourceAdapter`：提示词要求业务键；解析后缺 → **回退 `id`**。
- `JulyMetadataUseCase.insert/update`：`businessField` 空 → 400（兜底，覆盖设计器/模板直接落库）。
- `blankTemplate` / `_guide`：去掉 `sid` 必填示例，改中性示例（`order_no`）。
- DDL 生成器：`businessField == 主键 id` 时不另建唯一键（已有逻辑）。
- 门禁 `PASSED`；**E2E 通过（2026-09-18）**：模板 / `sql` / 设计器缺 `businessField` → 400；AI 缺业务键 → 回退 `id`（物理表仅 `PRIMARY`、无多余唯一键）；现有对象发布 200。
