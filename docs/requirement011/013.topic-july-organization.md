# 013.topic-july-organization（组织机构）

> 阶段：**requirement011（业务设计与业务要求）**。总设计见 [018 IAM](../infrastructure011/018.iam-center/011.topic-design.md)。
> 前端业务场景依据：`klsjnh-react-pc011` 组织管理页（树形表格 + 上级组织选择 + 负责人；前端目录名是否仍为 `pages/system011/` 以 PC 仓为准）。

## 013.字段定义（fieldList，继承 **TreePo011** 公共列：id / status / 审计四列 / dr / parent_id / sort_order / children）

| fieldCode | fieldName  | fieldType | fieldLength | requiredField | defaultValue |
| --------- | ---------- | --------- | ----------- | ------------- | ------------ |
| org_code  | 组织编码   | String    | 30          | true          | -            |
| org_name  | 组织名称   | String    | 60          | true          | -            |
| pk_user   | 负责人     | String    | 33          | false         | -            |
| org_level | 组织层级   | Integer   | -           | false         | 1            |

- **树形结构**：parent_id 空串为根（如"华信集团"），sort_order 控同级展示顺序（前端树形表格）；
- **org_code 全表唯一**（唯一索引兜底），对应前端的 `code`（HX / HX-TECH）；
- **pk_user = 负责人**：按 `pk_<目标表>` 链接列规约指向 `july_user.id`，可空（组织可以暂无负责人）；负责人姓名由链接查询得出（前端 leader 字段）；
- **org_level 冗余层级**：根为 1、下级递增，便于按层级过滤（也可由树推导，冗余为查询便利，维护责任在应用层）；
- **count（前端人数角标）不落库**：由 july_user.pk_org 统计得出（见 §017）。

## 015.业务规则

- **org_code 唯一**（唯一索引兜底）；
- **删除约束**：存在子组织或组织下仍挂有用户时，禁止逻辑删除（先迁走/删子级）；
- 组织停用（status='0'）不影响已挂用户的登录，仅作为归属展示与统计维度。

## 017.关系与联动

- **july_user ↔ 组织**：`july_user` 新增 `pk_org` 列（链接 `july_organization.id`，可空：用户可以不属于任何组织），前端"组织人数 count"由 `july_user.pk_org` 统计得出；**方案 A 已于 2026-09-12 定案**，019 + DDL 已同步；
- pk_user（负责人）同样指向 july_user.id，遵循 `pk_<目标表>` 链接列规约（pk_user ≠ MasterLinked 主表链接，不实现 MasterLinked 接口）；
- 与 july_menu 无直接关系（菜单树独立）。

## 019.接口诉求

insert / update / logicDelete（子组织与挂载用户校验）/ getById / selectTree（组织树）/ selectListByPage——均 POST，统一信封。
