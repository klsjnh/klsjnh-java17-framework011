## 015.定位与边界（与 krt.ci011 的分工）

| 数据源来源 | 放什么 | 生效方式 |
|------------|--------|----------|
| **krt.ci011**（yaml，`KrtDatasourceConfig011`） | **一次性种子**：启动时把内容播种进 `july_datasource` | 仅在表里没有该 `dsCode` 时插入一次 |
| **july_datasource（本对象）** | **运行时唯一真源**：新增库、改密码、启停、删除 | 改库 + 重载注册表即生效 |

**播种规则（2026-09-15 定案，取代早期"只允许一个家"的红线）**：启动由 `DatasourceSeedRunner` 逐条比对 `dsCode`：

| 表中状态 | 处理 |
|----------|------|
| 没有该 `dsCode` | INSERT（种子落地） |
| 有该 `dsCode` | 跳过，**不更新不复活**（判重含 `dr='1'` 墓碑行，故管理页删掉的行不会被重启复活） |
| 有但内容不一致（dsName / jdbcUrl / dbType） | **表赢**，记 WARN 列出差异字段，不写库 |

**失败策略**：单条失败只记 ERROR（含 `dsCode` + 异常堆栈）后继续，**绝不抛异常阻断启动** —— 服务必须能起来，人进管理页手工修。无「播种开关」，全自动执行。

## 017.业务规则

- `dsCode` 全表唯一（唯一索引兜底 + 保存预检），**`dsCode` 不可变**（修改只改连接参数）；
- `dsCode` 保守取值校验：字母 / 数字 / 下划线 / 连字符，长度 1–60（它同时是连接池名与日志标识）；
- `dsCode` **保留字**：`master`（主库标识）不可占用 —— 与老项目 `JulyDatasource.validateCode` 口径一致；
- `dbType` 为**开放字符串**（内置 `mysql` / `oracle` / `sqlserver` / `postgresql`，见 `DatabaseTypes011`；接受 `postgres` 别名）；必填且长度 ≤20，**不限定为封闭枚举**（自定义库型由方言 SPI 决定支持与否，2026-09-19 修订）；
- `driverClass` 可空：**为空时按 `dbType` 取 `DatabaseTypes011.driverClass()`** 内置默认驱动；未知库型且未显式配 `driverClass` → 400（禁止在业务代码硬编码驱动字符串）；
- `status`：`1` 启用 / `0` 停用；**停用即从运行时注册表摘除**，路由到该 `dsCode` 抛 400；
- `jdbcUrl` 必填且以 `jdbc:` 开头（保存预检，不做深度解析——方言差异太大）；
- **删除用逻辑删除**（`dr`），不做物理删除；不提供物理删除端点（属基础设施维护动作，见 [016.coding-standards §6.3](../016.coding-standards.md)）；
- **密码不回显**：`getById` / `selectListByPage` 等一切出参**不得返回 `password` 字段**（老项目明文回吐，是安全隐患，本期修正）；仅 `testConnection` 可在请求侧传入明文。

- **`july_sql`（SQL 语句注册）与 `july_model`（业务建模 + 版本）** —— 老项目已有完整实现，属**二期**；

### 023.1 决策 3/5 补充说明（密钥口径）

用户定案原文：「加密密钥来源 由环境变量 存储引擎/路径 跟随现有配置体系」。落地含义：

- **不新增密钥存储介质**（不引入 Vault / 不新增密钥表 / 不写死配置文件）—— 复用 krt 绑定类作为框架配置入口；
- krt 绑定类新增 `datasource` 配置组，持一个 `secretKey`（String，无默认值）；
- 生产环境经环境变量注入（与现有 `krt.jwt.secret` 完全同构的做法）；
- **但是**：本期 §021 已明确「密码加密存储」在边界外 —— 故本决策**同期只预埋配置位**，不实现加解密。二期做加密时，密钥已就位，无需再改配置体系。
