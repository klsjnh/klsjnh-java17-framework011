## 015.功能诉求（用户原始诉求）

1. **CRUD**：新增 / 修改 / 逻辑删除（单条与批量）/ 分页查询 / 主键查询；
2. **任务控制**：**启动** / **停止** / **执行一次** 三个运维动作；
3. 调度引擎按 `scheduler_cron` 周期触发 `scheduler_handler`，每次触发 `execute_times` 累加。

## 017.业务规则与边界

- **任务编码唯一**：`scheduler_code` 全表唯一（数据库唯一索引兜底 + 保存前预检友好提示）；
- **cron 合法性**：保存与修改时必须校验 cron 可解析，非法表达式拒绝保存；
- **status 即运行态**（复用公共 status 列，'1' 运行 / '0' 停止）：
  - **新增后默认为停止态**（status='0'，不入调度引擎），必须显式调用"启动"才参与调度；
  - **启动** = status 置 '1' + 注册到调度引擎；**停止** = status 置 '0' + 从引擎摘除；
  - **修改（update）包含启停**：update 请求携带 status；保存成功后引擎联动重同步——先摘除旧注册，再按新状态决定是否重新注册（'1' 注册 / '0' 仅摘除）；运行中任务的 cron / handler 变更同样触发该联动（等效于改周期后重注册）。
- **执行一次**：立即触发一次 handler，不改变启停状态、不影响 cron 周期；
- **execute_times 计数口径**：触发即计（无论成功失败）——执行成功与否的区分属于"执行日志"范畴，本期边界外；
- **handler 语义**：可被调度引擎执行的处理器标识（Spring 容器内 Bean）；处理器不存在时"执行一次"与周期触发均记录失败但不中断调度；
- **删除即摘除**：逻辑删除（单条/批量）时若任务在运行，先从引擎摘除；
- 逻辑删除走公共 `dr` 列；`status` 与 `dr` 互相独立（删除 ≠ 停止）。

## 021.边界外（本期不做）

- 执行日志 / 触发历史表（含成功失败区分、耗时、异常栈）；
- 分布式调度（多实例协调）——本期单实例内存态，重启后按 status='1' 的记录重新注册；
- cron 可视化编辑器、任务依赖编排、失败重试策略。

## 023.决策点（已定案 2026-09-12）

| # | 决策点 | 结论 |
|---|------|------|
| 1 | 新增后默认停止（status='0'，覆盖公共列默认 '1'） | ✅ 采纳：任务必须显式启动 |
| 2 | execute_times 触发即计，不区分成败 | ✅ 采纳：日志属边界外 |
| 3 | 调度引擎选型 | ✅ **Quartz 内存模式（RAMJobStore）**——spring-boot-starter-quartz，Boot 3.4.5 BOM 管理版本；TaskScheduler 否决（无按名摘除/立即触发/misfire 策略）。技术细节见 `requirement013/022.topic-july-scheduler.md` |
