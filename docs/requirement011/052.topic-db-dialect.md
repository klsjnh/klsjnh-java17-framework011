## 011.问题

**当前主数据（低代码对象表）是 MySQL，且生成/写入语句大量写死 MySQL：**

- `MySqlMetadataDdlGenerator`：反引号、`ENGINE=InnoDB utf8mb4`、`VARCHAR/INT/DECIMAL/TINYINT` 列型。
- `JdbcTemplateMetadataDataWriter`：`ON DUPLICATE KEY UPDATE`（MySQL 专有 upsert）。
- `DatasourceDdlExecutor`：主库 `JdbcTemplate` + `tableExists/columnsOf` 按 MySQL 元数据。
- （源侧已具备：`SqlDialect011` 支持 MySQL/PG/Oracle/SQLServer 分页。）

未来主数据可能是 **Oracle / SQLServer**，故**目标侧必须方言化**，且**自动适配**（按库类型路由，不改调用方）。

## 013.本期口径（用户裁定 2026-09-18）

- **做适配器**：抽目标侧方言端口 + **按 `DatabaseType011` 自动路由**，**MySQL 现有实现保留**（行为不变）。
- **Oracle/SQLServer 本期只留端口位**（不实现）。
- 目标数据源：**本期仍主库**；"对象表落任意动态数据源"留未来。

## 015.范围

| 能力 | 本期 | 未来 |
|------|------|------|
| DDL 方言（建表/加列/列型） | ✅ 端口 + MySQL 实现 | Oracle/SQLServer |
| 写入 upsert 方言 | ✅ 端口 + MySQL 实现 | Oracle/SQLServer `MERGE` |
| schema 方言（tableExists/columnsOf） | ✅ 端口 + MySQL 实现 | Oracle/SQLServer 数据字典 |
| 类型映射（`FieldType011` → 列型） | ✅ 按 `DatabaseType011` 路由 | 各库补齐 |
| 对象表落动态数据源 | ❌ | ✅ |
