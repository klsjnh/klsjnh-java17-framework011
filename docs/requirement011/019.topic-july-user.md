## 015.业务规则

- **user_account 全表唯一**（唯一索引兜底），即登录账号，创建后不可修改；
- **密码安全（红线）**：仅存 bcrypt 哈希（长度 60）；明文 / MD5 禁止；密码不回显、不出站、不写日志；修改密码需旧密码校验；
- **status 即账号状态**：'1' 启用（可登录）/ '0' 禁用（登录被拒，提示账号禁用）；禁用不影响历史审计；
- **last_login_time**：登录成功时刷新；
- 逻辑删除后禁止同名重建（dr='1' 的 user_account 仍占用唯一索引——如需释放属边界外）。

## 017.关系与联动

- **用户-角色（july_user_role 关联表，N:N）**：一张关联表同时服务"用户视角分配角色"与"角色视角查看用户"；整存替换策略；用户删除时级联删除其关联；
- **july_user_audit**：登录 / 登录失败 / 增删改操作均写审计（见总设计 017 §021）；
- 登录失败、禁用账号登录等安全事件全部入审计。

### 017.1 附属表：july_user_role（用户-角色关联）

继承 BasePo 公共列，业务列：

| fieldCode | fieldName | fieldType | fieldLength | requiredField |
| --------- | --------- | --------- | ----------- | ------------- |
| pk_mt     | 用户 id   | String    | 33          | true          |
| pk_role   | 角色 id   | String    | 33          | true          |

- 链接列统一 `pk_<目标表>` 规约：pk_mt → july_user.id、pk_role → july_role.id（PO 字段 pkMt / pkRole，实现 MasterLinked）；
- UNIQUE (pk_mt, pk_role)——唯一键覆盖全部行（含 dr='1'），同一组合永远只有一行；
- **整存替换 = toggle dr（不删不插）**：分配时行存在则复活（dr='0'），不存在才插入；取消分配时置 dr='1'；
- 一用户多角色、一角色多用户；无独立生命周期，随用户删除级联停用（toggle dr='1'）。

### 017.2 附属表：july_user_audit（用户审计，append-only）

继承 BasePo 公共列，业务列：

| fieldCode     | fieldName           | fieldType | fieldLength | requiredField |
| ------------- | ------------------- | --------- | ----------- | ------------- |
| pk_mt         | 主表链接（用户 id） | String    | 33          | false         |
| user_account  | 操作者账号          | String    | 30          | false         |
| audit_type    | 事件类型            | String    | 30          | true          |
| object_code   | 对象编码            | String    | 60          | false         |
| audit_content | 事件描述            | String    | 500         | false         |
| audit_ip      | 客户端 IP           | String    | 50          | false         |

- **pk_mt 按 BaseMasterSubRepository021 规约**：主表链接列固定 `pk_mt`，存操作者的 `july_user.id`（PO 字段 `pkMt`，实现 MasterLinked）；
- **pk_mt ≠ 级联成员**：审计虽挂 pk_mt，但**不注册**为用户的主子级联子表——用户删除时审计必须保留（可追溯），这是它与普通子表的本质区别；
- **append-only 铁律**：只插入，不修改不删除，不参与任何级联删除；
- audit_type：`LOGIN` / `LOGIN_FAILED`（user_account 必记）/ `LOGOUT` / `INSERT` / `UPDATE` / `DELETE` / `EXPORT`；
- user_account 冗余存储（登录失败等无 id 场景只记账号；用户删除后仍可追溯）；事件时间用公共 create_time；
- 审计写入失败仅告警，不回滚业务事务。

## 019.接口诉求

insert / update / logicDelete（批量）/ getById / selectListByPage / **resetPassword**（管理员重置）/ **changePassword**（本人改密，验旧密）——均 POST。

**登录联动诉求**：登录成功后，按登录人角色返回其**全部树状菜单**（用户 → pk_role 角色 → 角色授权菜单 → 去重组装树；超级管理员返回全量菜单树）——接口落在菜单管理（018）上。
