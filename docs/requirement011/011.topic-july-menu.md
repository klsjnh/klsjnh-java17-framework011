## 015.业务规则

- **树形结构**：菜单是树（目录 → 菜单 → 按钮），parent_id 空串为根，sort_order 控同级顺序；
- **menu_type 三类**：'1' 目录（只有下级）、'2' 菜单（绑定 menu_route）、'3' 按钮（绑定 permission_code）；
- **menu_code 全表唯一**（唯一索引兜底）；
- **permission_code 即权限载体**（唯一，非空时）：角色授权最终落到该标识，格式约定 `模块:对象:动作`（如 `system:user:insert`）；
- **删除约束**：存在子菜单时禁止逻辑删除（先删子级）；
- 修改不影响树结构字段以外需整体重排 sort_order 的场景由前端拖拽 + 批量保存承担（本期边界外）。

## 017.关系与联动

- 被引用方：`july_role_permissions.permission_code` 引用本表 permission_code——已授权的菜单/按钮删除前需确认无角色引用（应用层校验）；
- 与 `july_user_audit` 联动：菜单管理操作写审计。

## 019.接口诉求

insert / update / logicDelete（含级联子级）/ getById / selectTree / selectListByPage——均 POST，统一信封。

**登录联动诉求**：新增 `selectUserMenuTree`（POST）——按当前登录人返回其树状菜单：登录人 → pk_role 角色（启用中）→ july_role_permissions 授权菜单（pk_menu 去重）→ 组装树；超级管理员返回全量菜单树。
