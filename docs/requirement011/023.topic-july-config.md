## 015.定位边界（与 krt.* 的分工）

| 配置来源 | 放什么 | 生效方式 |
|----------|--------|----------|
| application.yml / krt.*（krt 绑定类） | 框架自身配置（端口 / JWT / 连接池 / ci011） | 重启生效，绑定类读 |
| **july_config（本对象）** | **运行时可变的业务 / 运维参数**（业务开关、阈值、提示文案、导出上限） | 改库即生效 |

**红线：同一配置只允许一个家**——krt.* 已有的键不得进 july_config，反之亦然。

## 017.业务规则

- code 全表唯一（唯一索引兜底 + 保存预检），**code 不可变**（修改只改 data）；
- 值全 String（300 上限）：布尔 / 数字由消费方解析，复杂结构用 JSON 字符串；**不做类型列**（二期真需要再加 value_type）；
- status='0'（停用）的配置对程序不可见（getByCode 返回 null）；
- **每次查库不缓存**（用户定案）——读路径零额外机制；
- getByCode 是**程序内部读取入口**（UseCase 方法），不提供 HTTP 端点——配置读取不是管理行为。

## 019.接口清单（管理面，全部 POST，统一信封）

| 端点（前缀 /klsjnh/system011/julyConfig/v1） | 说明 |
| ---------------------------------------------- | ---- |
| /insert                                        | 新增（code 查重） |
| /update                                        | 修改（仅 data；code 不可变） |
| /logicDelete                                   | 逻辑删除 |
| /getById                                       | 主键查询 |
| /selectListByPage                              | 分页查询（code/data 模糊） |

程序读取（无 HTTP）：`JulyConfigUseCase.getByCode(code)` → 启用的配置或 null。

## 021.边界外（本期不做）

- 缓存层（读多写少规模化后再议）；
- 多实例缓存广播；
- value_type 类型列 / 分组前缀 / 按租户隔离。
