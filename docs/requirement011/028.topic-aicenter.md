## 015.定位边界

| 对象 | 放什么 | 边界 |
|------|--------|------|
| july_ai_model_provider（本对象） | 一个厂商的接入点：编码 / 名称 / baseUrl / 模型清单 | 一厂商一行，`provider_code` 唯一 |
| july_ai_model_provider_api（本对象子表） | 同一厂商下的多个 API Key（多账号 / 额度） | 一密钥一行，`(pk_mt, api_code)` 唯一 |
| july_config（029） | 运行时键值参数 | 不放密钥（密钥是模型接入域资产） |
| july_datasource（031） | 业务库连接 | 二者互不隶属 |

## 017.业务规则

- `providerCode` 全表唯一（唯一索引兜底 + 保存预检），**不可变**（修改只改名称/baseUrl/models/状态/备注）；
- 子表 `apiCode` 在**同一提供商内唯一**（唯一索引 `(pk_mt, api_code)`）；不同提供商可重名；
- 排序：主表、子表均按 `sort_order` **升序**（同值按 id）；
- `api_key` **出参不回显**：`AiModelProviderApiVo011` 类型层**不含**该字段；入库为明文（加密存储二期，krt 绑定类预埋密钥位）；
- `status='0'` 停用：程序读入口不可见（停用提供商 → 无密钥返回；停用密钥 → 不返回）；
- **密钥选取**（程序调用口径）：`getDefaultApi(code)` 取该提供商下**第一个启用密钥**（sort_order 升序）；多密钥轮询 / 指定留后续；
- **删除约束**：删除提供商时若仍存在存活密钥 → `400`（先清密钥）；密钥可单条逻辑删除；
- 程序读入口（UseCase 方法，**无 HTTP 端点**）：`getByCode` / `getApiList` / `getDefaultApi`；
- `testConnection`：以 `{base_url}` + `/models` 发 GET（`Authorization: Bearer <默认密钥>`），返回连通结果（HTTP 恒 200，结果在载荷内），**不改状态、不落库**。

## 019.接口清单（管理面，统一信封）

**提供商主表**（前缀 /klsjnh/aicenter/julyAiModelProvider/v1）

| 端点 | 说明 |
|------|------|
| /insert | 新增提供商（providerCode 查重） |
| /update | 修改（名称/baseUrl/models/状态/备注/排序；code 不可变） |
| /logicDelete | 逻辑删除（受删除约束） |
| /getById | 主键查询（GET） |
| /selectListByPage | 分页查询（code/name 模糊 + 状态过滤） |

**密钥子表**

| 端点 | 说明 |
|------|------|
| /insertApi | 新增密钥（同提供商内 apiCode 查重；api_key 必填） |
| /updateApi | 修改密钥（apiCode 不可变；api_key 留空保持原值） |
| /logicDeleteApi | 逻辑删除密钥（单个） |
| /selectApiListByProvider | 按提供商取密钥列表（排序 + 状态过滤，**不含 api_key**） |

**其它**

| 端点 | 说明 |
|------|------|
| /testConnection | 探测提供商（GET baseUrl/models，用默认密钥） |

程序读取（无 HTTP）：`getByCode` / `getApiList` / `getDefaultApi`（见 §017）。

## 021.边界外（本期不做）

- `api_key` 加密存储 / 解密（二期，预埋 krt 绑定类密钥位）；
- 多密钥轮询 / 负载均衡 / 失效熔断；
- 模型级子表（本期 `models` 为逗号分隔字符串）；
- 缓存层（每次查库，对齐 029 / 031）；
- 030 子表密钥导出（主表 `julyAiModelProvider` 已接导出；`api_key` 因敏感未导，待脱敏口径）；
- 调用侧 AI 能力（chat / 文生图 / 图生图 / TTS），见 [030.topic-aicenter-invoke](030.topic-aicenter-invoke.md)。
