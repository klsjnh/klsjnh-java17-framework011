## 013.产物形状（本对象的输出契约）

建模的产物是**一份 JSON，顶层只有两个键**：`metaData`（对象级配置）+ `fieldData`（字段级定义）。

```json
{
  "metaData": {
    "objectName": "july_config",
    "description": "系统设置 - 配置管理",
    "objectType": "type011",
    "packageName": "com.klsjnh.business",
    "importField": "code, data",
    "url": "/system/july_config"
  },
  "fieldData": [
    { "code": "id",          "name": "主键",       "fieldType": "id" },
    { "code": "code",        "name": "配置项",     "fieldType": "string", "length": 60, "notNull": true },
    { "code": "data",        "name": "配置值",     "fieldType": "string", "length": 300 },
    { "code": "status",      "name": "状态",       "fieldType": "status" },
    { "code": "create_by",   "name": "创建人",     "fieldType": "create_by" },
    { "code": "update_by",   "name": "最后修改人", "fieldType": "update_by" },
    { "code": "create_time", "name": "创建日期",   "fieldType": "create_time" },
    { "code": "update_time", "name": "最后修改日期", "fieldType": "update_time" },
    { "code": "dr",          "name": "删除标记",   "fieldType": "status" }
  ]
}
```

**`metaData` 字段说明**：

| 键 | 含义 |
| --- | ---- |
| `objectName` | 低代码对象名（表名），全局唯一、不可变 |
| `description` | 对象中文描述 |
| `objectType` | 对象类型，取值 `ObjectType011`（`type011` / `type013` / `type_tree` / `type_tree011` / `type021`） |
| `packageName` | Java 目标包名 |
| `importField` | 参与导入/导出的业务字段清单（逗号分隔） |
| `url` | 前端路由路径 |

**`fieldData` 字段说明**：

| 键 | 含义 |
| --- | ---- |
| `code` | 字段编码（snake_case） |
| `name` | 字段中文名 |
| `fieldType` | 字段类型（见 §015） |
| `length` | 长度（非长度类型省略，如 `id` / `status`） |
| `notNull` | 是否必填 |

> **口径对齐（2026-09-15 修正）**：老项目样例里的 `create_date` / `modify_date` 是**老项目列名**，
> 本项目一律用**自己的公共列口径** —— `create_by` / `update_by` / `create_time` / `update_time`（四列）。

## 015.字段定义（fieldList，继承 BasePo 公共列）

`july_business_modeling` 表自身的列（不是产物 JSON 的字段）：

继承 BasePo 公共列：`id` / `status` / `create_by` / `update_by` / `create_time` / `update_time` / `dr`
（见 [base-entity-columns.sql](../sql/base-entity-columns.sql)）。

| fieldCode | fieldName | fieldType | fieldLength | requiredField | defaultValue |
| --------- | --------- | --------- | ----------- | ------------- | ------------ |
| modelCode | 建模编码 | String | 60 | true | - |
| modelName | 建模名称 | String | 100 | true | - |
| objectName | 低代码对象名 | String | 60 | true | - |
| dataSourceCode | 数据源编码 | String | 60 | true | - |
| sqlContent | 取数 SQL | String | TEXT | false | - |
| modelData | 建模产物 JSON | String | TEXT | false | - |
| remark | 备注 | String | 300 | false | - |

> **落库形态（2026-09-15 定案）**：上一版的 `fieldData` / `description` / `packageName` / `routerPath` /
> `version011` / `publishStatus` **六列全部收敛进 `modelData` 一列 JSON**（它们本就是 `MetaData011`
> 的属性，拆成列是重复存储）。
>
> **保留两个裸列，各有唯一理由**：
> - `object_name` —— 要建**唯一索引**做查重；
> - `sql_content` —— 是**探针 / 执行 / 分页执行三个端点的共同输入**，且管理面要直接编辑（定案 9），
>   与 `model_data`（产物）是**输入 vs 产物**两类不同的东西。

## 017.业务规则

- `modelCode` 全表唯一、**不可变**；
- `objectName` 全表唯一、**不可变**（它在产物里是 `metaData.objectName`，同时建唯一索引）；
- `dataSourceCode` **必填**，且必须指向 `july_datasource` 中**已存在且启用**的 `ds_code`；
- `objectType` 取值限 `ObjectType011` 四值；
- `fieldData` 是 `List<FieldInfo011>` 的序列化；`fieldCode` 集合内**唯一**；
- **`sqlContent` 三条硬校验**（探针 / 执行 / 分页执行共用）：必须以 `SELECT` 开头、禁 `;`、
  禁 DDL/DML 关键字（见方案 §018.4）—— **本期只做读，不做写库**；
- **公共列自动补齐**（定案 4）：产物 `fieldData` 自动补 `id` / `status` / 审计四列 / `dr`，
  顺序对齐 `base-entity-columns.sql`；
- 删除用**逻辑删除**（`dr`），不提供物理删除端点。

## 019.接口清单（管理面，统一信封）

前缀 `/klsjnh/dataservice011/julyBusinessModeling/v1`。

| 端点 | 方法 | 说明 |
| ---- | ---- | ---- |
| `/insert` | POST | 新增建模 |
| `/update` | POST | 修改（`modelCode` / `objectName` 不可变） |
| `/logicDelete` | POST | 逻辑删除（单条） |
| `/logicDeleteBatch` | POST | 逻辑删除（批量） |
| `/getById` | **GET** | 主键点查（**含 `sqlContent`**，定案 9） |
| `/getByCode` | **GET** | 按 `modelCode` 点查 |
| `/selectListByPage` | POST | 分页查询**建模列表** |
| `/probe` | POST | SQL 探针推断（**草稿态可用**，不落库） |
| `/getModelData` | **GET** | ★ 交接产物：返回 `metaData` + `fieldData` 两段 |
| `/executeSql` | POST | ⭐ **执行 SQL**（在 `dsCode` 库上跑，返结果集） |
| `/executeSqlByPage` | POST | ⭐ **分页执行 SQL**（返 `total` + 当页 rows） |

**11 个端点**。相比上一版：**删掉** `/saveDraft` 与 `/publish`；**新增** `/executeSql` 与 `/executeSqlByPage`。

> ⚠️ 别混淆两个 `...ByPage`：
> `/selectListByPage` = **建模记录的**分页（查本表）；
> `/executeSqlByPage` = **业务数据的**分页（在 `dsCode` 库上跑 SQL）。

## 021.边界外（本期不做）

- **`displays` / `services` 进入产物** —— 产物只有 `metaData` + `fieldData`；
- **`vuePath` / `javaPath`** —— 已裁定**干掉**（不进 JSON、不进 Java）；
- **自建物理表**（`DdlBuilder` / 老表改名备份 / 数据迁移）—— 机制已改为交 lowcode；
- **`publish` / 发布语义** —— 定案「不做」；
- **`version011` / `version013` / `publish_status`** —— 老项目的版本号服务于"建表/发布"流程，本期产物是纯 JSON，不需要；
- **抽取同步数据到本地库** —— 用户定为**后期功能**（建表之后 / 指定 SQL 两形态），本期不做；
- **`july_metadata` 运行时注册表**；
- 对外数据服务端点（供第三方调用的动态 SQL 服务）；
- 页面 / 表格 / 表单编排（属 lowcode 域建模面）。
