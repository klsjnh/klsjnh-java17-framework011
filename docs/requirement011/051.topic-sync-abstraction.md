## 011.命题

**同步是一个抽象能力，不是一个方向。** 指定 `source` 与 `sink` 两个端点 + **可动态配置的同步规则**，即可执行——**内→外、外→内、内→内、一对多**都应成立；本期先不做，但**结构上必须留口子**。

## 013.归属（2026-09-18 用户口径 · 待再议）

- **暂时放在数据源（`datasource`）里**：因为同步与数据源**强耦合**（连接/方言/路由都在数据源）。
- **低代码只是使用者**：`importDataFromSql` 是"外部 SQL → 对象表"这一种特化，不该把同步能力私有化在低代码。
- 未来若概念足够重，可再抽独立 `sync` 层；**本期不抽**，但命名/端口按"可抽"设计。

## 015.场景（未来）

| 场景 | source | sink | 说明 |
|------|--------|------|------|
| 外 → 内 | 外部库 SQL | 本地对象表 | 现 `importDataFromSql` |
| 内 → 外 | 本地对象表 | 外部库表 | 反向写出 |
| 内 → 内 | A 对象表 | B 对象表 | 异表直拷 |
| 一对多 | 一个源 | 多个 sink | 广播/分发 |

## 017.关键概念（留口子，不实现）

- **`EndpointSpec`**：`{ ConnectionInfo, dataSet(表或SQL), readOnly }` —— 源/目标同构，**不分内外、不分方向**。
- **`SyncRule`（动态配置）**：`{ source, sink, mapping[], key, mode(full/incr), batch/page, conflict(upsert/append) }`。
- **`SyncTask`**：规则一次执行 + `checkpoint/watermark` + 状态（可续传）。
- **`SyncEngine`**：source 分页读 → 映射 → sink 幂等写。

## 019.本期边界

- **一定不做**：多方向、一对多、动态规则表、调度、checkpoint。
- **只做**：把现有 `importDataFromSql` 视为"同步的第一种特化"，其执行/写入走数据源与方言端口（[052](052.topic-db-dialect.md)），为未来抽象留位。
- 技术方案：[requirement013/051](../requirement013/051.topic-sync-abstraction.md)。
