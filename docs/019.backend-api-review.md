# 019 — 后端接口质量评审（契约层）

> 定位：**契约层的已知缺口清单** —— 回答「Swagger 上看到的，哪些能信、哪些不能信」，以及新接口必须自检的项。
> 契约本体见 [013.api-contract.md](013.api-contract.md)；编码规则见 [016.coding-standards.md](016.coding-standards.md)。
> 本文**只记录评审结论与差距**，不复制契约正文。

## 011.结论速览

| 维度 | 结论 |
|------|------|
| 六键信封 / 状态码 | ✅ 全部端点统一，`statusCode` 与 HTTP 同步 |
| 点查 `getByXxx` 用 GET | ✅ 已达标（`getById` 全改 GET） |
| 条件查询 `selectXxx` 用 POST + `*QueryVo011` | ✅ 达标（门禁显式豁免 GET/POST） |
| 删除动作分层（单个/批量） | ✅ `logicDelete` / `logicDeleteBatch` 分离 |
| 入参具名 VO（禁裸 List） | ✅ 达标（`IdsVo011` 等） |
| **Swagger 鉴权可视化** | ❌ **缺 SecurityScheme** |
| **导出/备份端点鉴权口径** | ⚠️ debug 下仍需操作人，Swagger 直接调会 401 |
| 二进制下载 | ⚠️ 例外已声明（文件流不走信封） |

## 013.Swagger 哪些不能信（真实差异）

1. **无「Authorize」按钮**：`SpringDocConfig011` 未注册 SecurityScheme，Swagger UI 不能注入 `Authorization: Bearer`。在非 debug 环境从 doc.html 直接调用受保护端点会 401。**联调请用 Postman/curl 手工带 token。**
2. **debug 与生产行为不同**：`krt.status=debug` 下 `GlobalAuthFilter` 不拒绝任何请求（方便本地）；生产 `production` 必带有效 token。**doc.html 里试出来的「免 token 可调」不可当作生产契约。**
3. **导出 `/export` 与备份 `/backup011` 例外**：即使 debug，`ExportUseCase` 仍要求已认证操作人（写 EXPORT/BACKUP 审计），无 token 返回 **401**。这是有意设计，但 Swagger 上无提示。
4. **`traceId` 恒为 null**：契约保留键，`GlobalAuthFilter` 暂未写 MDC，勿依赖。
5. **`errorMessage` 仅 debug 填充**：生产恒为 `""`，前端不得依赖其内容定位问题。

## 015.鉴权与操作人

- 白名单（`GlobalAuthFilter`）：两个登录端点 + 文档路径（`/doc.html` `/webjars/` `/v3/api-docs` `/swagger-ui` `/swagger-resources` `/favicon.ico` `/error`）。
- 校验通过后写请求属性 `FrameConst011.OPERATOR_ID` / `OPERATOR_ACCOUNT`（`AuthAttribute011` 口径），供审计自动填充。
- 控制器侧统一经 `Operator011Resolver.resolve(request)` 取操作人，**禁止**自行读 attribute。
- 登录失败口径：账号密码错误 / 禁用 / production 免密被拒 → **401**。

## 017.分页与排序

- 分页入参 `*QueryVo011`，出参 `PageResult011<T>`；分页对名前缀 `Query` / `Result`（不叠 `Vo`）。
- 手工排序表（menu/org/datasource/dictionary/ai provider）统一 `sort_order ASC, id ASC`；PO 继承 `BasePo011`。

## 019.已知缺口（待办）

| # | 缺口 | 影响 | 建议 |
|---|------|------|------|
| 1 | Swagger 无 SecurityScheme | doc.html 不能调受保护端点 | 注册 bearer scheme（`SpringDocConfig011`） |
| 2 | 逻辑删除 + 唯一键 → 重复插入 500 | 删除后同键无法重建 | **已根治（2026-09-16）**：唯一索引改建在生成列 `alive_*`（`dr='0'` 时=业务键，否则 `NULL`，MySQL 允许多个 NULL）——只约束存活行，墓碑保留；`DuplicateKeyException→400` 保留为兜底。迁移见 `sql/logic-delete-unique-fix.sql` |
| 3 | `selectXxx` 用 POST 不可被网关缓存/重试 | 只读查询失去 HTTP 语义 | 有意取舍（见 016 §6.2），维持 |
| 4 | 无速率限制 / 幂等键 | 写端点可重放 | 网关层解决，非本层 |
| 5 | `traceId` 未贯通 | 排障缺链路 id | 后续接 MDC |

## 021.新端点自检清单（提交前逐条核）

1. 走六键信封，`statusCode` 与 HTTP 一致；
2. 点查 `getByXxx` GET（键走 query），条件查询 `selectXxx` POST（`*QueryVo011`）；
3. 写动作 POST；单个 `logicDelete(IdVo011)`、批量 `logicDeleteBatch(IdsVo011)`；
4. 入参一律具名 `*Vo011`，禁裸 `List`/`Map`；
5. 出参写操作返回 `IdVo011`（或 `BatchDeleteResultVo011`）；**查无数据用异常/空语义明确表达**；
6. 敏感字段（密码/密钥）**类型层剔除**，不由 Converter 置空；
7. 需要操作人的端点经 `Operator011Resolver`，并确认 debug 下审计仍写入；
8. 新增 Swagger 分组在 `SpringDocConfig011` 显式登记。
