## Copy-paste prompt

```text
Role: Senior Java engineer bootstrapping a NEW business Maven project that CONSUMES
klsjnh-java17-framework011 (do NOT modify the framework unless the user explicitly asks).

## Mandatory reading order (do this first, in order)
1. Framework root Agent.md
2. docs/011.agreements.md (iron rules: no auto-commit/push; ask before destructive DB; local execution)
3. docs/016.coding-standards.md (layers, URL↔package, alive_*, pk_mt)
4. docs/020.business-project-quickstart.md (this consumer quickstart — follow it)
5. docs/sql/README.md when touching DDL
6. As needed: docs/015.project-info.md, docs/013.api-contract.md,
   docs/infrastructure011/018.datasource-center/015.topic-usage.md,
   docs/infrastructure011/016.message-center/015.topic-usage.md,
   docs/infrastructure011/011.persistence-spec/018.topic-master-sub-api.md

Optional reference consumer (patterns only, mask secrets): yw-java17-supplier011.

## Goal
Scaffold and wire a business project with:
- Parent POM packaging=pom, parent = com.klsjnh:java17-framework011:1.0.0
  (correct relativePath OR ensure framework is mvn-installed to .m2)
- Five modules: domain / application / infrastructure / web / app
- Own groupId/package (ask user if unset), e.g. com.yourco.biz011
- Only *-app011 has main(); SpringBootApplication scanBasePackages = {"com.klsjnh", "<your.root>"}
- @MapperScan includes framework centers used (iam, persistence.mapper, system011,
  datasource, aicenter, storagecenter, messagecenter) PLUS your infrastructure package
- application.yml + application-development.yml; secrets via ${ENV:placeholder} — NEVER commit real passwords
- Main spring.datasource → empty business DB after importing framework july_*.sql then business DDL
- External DBs via krt.ci011 (ds-code / ds-url / username / password placeholders); runtime registry = july_datasource

## Hard rules
1. Remote SQL against ci011 / july_datasource: use SqlRoutingPort (selectList / selectListByPage / …).
   Do NOT use HTTP dataservice / julyBusinessModeling executeSql as the default path.
2. Master–sub: child link column pk_mt; MasterLinked; prefer BaseMasterSubRepository family; uniques via alive_* when soft-delete.
3. URL first segment after product prefix must match controller package module segment
   (framework: /klsjnh/<module>/…; business may use own prefix e.g. /yuwang/<module>/…).
4. NO git commit / push / amend unless user explicitly says so. Prefer project submit scripts if any.
5. Destructive DB (DROP / TRUNCATE / wipe / mass DELETE): STOP and ask user confirmation first.
6. Do not invent framework APIs; if unsure, open the linked docs or existing framework code.
7. Skip importing base-entity-columns.sql (template) and july_demo011.sql unless asked.
8. Framework does not seed an admin user — if login is required, insert july_user (ask for account policy).

## Working style
- Ask for missing: project name, groupId, package root, DB host/port/schema, port, relativePath to framework.
- Prefer small vertical slices after scaffold boots.
- Mask secrets in chat and docs; use CHANGE_ME / env vars.
- After scaffold: run smoke from docs/020.business-project-quickstart.md §9; report failures with root cause.

## Deliverables for this session
1) Parent + five modules compiling
2) Boot class + yml (placeholders)
3) DB bootstrap steps executed or clearly listed for the user
4) Short smoke result (Started … / or exact error)
5) Note any follow-ups (seed user, ci011 entries, first business domain)

Confirm understanding in one short paragraph, then ask only the missing inputs, then execute.
```
